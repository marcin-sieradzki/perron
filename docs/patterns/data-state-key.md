# DataStateKey

The key to how sure the map is: the five data states, each as its dot and word, how many vehicles are in it, and one sentence saying what it means in the app's own thresholds, such as "Live 412, Reported by the vehicle in the last 2.5 min", for the panel that explains how much of what the map shows is live.

<!-- run notes -->

The design is deferred under ADR 0010 (`docs/adr/0010-unattended-runs-with-design-deferred.md`), so there is no read-back, code map or export: this spec decides what the drawing would, the layers, the design states and the token for every part. Its sources are the [contract](../components/README.md) and its Patterns and Words sections, the [foundations](../foundations/README.md), [Data states](../foundations/data-states.md) (the five states and what each means, "Legends list all five states, in this order, even when one has no vehicles", and [Thresholds](../foundations/data-states.md#thresholds): "Where a screen explains the states, it gives the app's own figures, never the defaults' as fixed facts"), [Typography](../foundations/typography.md#roles) (`typography.caption` for "legend descriptions", `typography.data` for counts), [Accessibility](../foundations/accessibility.md), [content design](../content-design.md), `list_tokens`, and the specs of the two entries in its `dependsOn`, [VehicleDotLabel](../components/vehicle-dot-label.md) and [Text](../components/text.md), which it composes for each sentence, and of its neighbours [ReportStrip](report-strip.md) and [VehicleDotLegend](../components/vehicle-dot-legend.md), whose names, order and parts it follows. Its ROADMAP line is ticket #158, part of the spec in #150: Mylder's City pulse screen has "How sure are we?", which shows how many vehicles are in each state and what each state means; ReportStrip gives the dot, word and count, and VehicleDotLegend the dot and word, and neither takes a sentence. The ticket leaves the brief to choose between a new pattern and a sentence slot in ReportStrip, and recommends a pattern, since ReportStrip is one row; this spec takes the pattern, and the registry files it under Data with no `baseUiParts`, beside ReportStrip. SourceLine, the other Data pattern in flight, is registered on its branch with no spec yet, so there is nothing of its to align with, and the extracted prototype is not reachable from this branch, so nothing here rests on it. As a pattern it imports only Perron's components and parts, never `@base-ui/react`.

## Anatomy

Penpot page `Patterns/DataStateKey`. Family: none: it is static content that sits on its container's surface, not a row of the Rows family, which is pressed and takes a hover, and it draws no surface of its own (CR-9). Shared parts: VisuallyHidden, through the `UnknownValue` helper, which says in words an unknown count, or a sentence whose threshold is unknown (CR-5, CR-7).

DataStateKey is a list of five items, one per data state in the order Data states lists them (live, ageing, estimated, timetable only, no signal), always all five, a state with no vehicles showing "0", as ReportStrip and VehicleDotLegend list them. Each item has two lines: the state's VehicleDotLabel at the start of the first, its count at the end of it, and the state's sentence on the second, under the word.

Each item sets its count at the inline end of its first line, with the sentence on a second line under the word, rather than the count straight after the word as ReportStrip sets it: the key is a column of five items, so counts at one edge line up as a table's number column does and compare at a glance, in tabular figures; the sentence is a second line, which the Rows family sets in `typography.caption` and `color.text.secondary`, and starting it under the word, past the dot, keeps the dots in a column of their own; the label before its count and the sentence after both keep the order the ear hears, "Live, 412, Reported by the vehicle in the last 2.5 min".

The drawing will have a `root` board holding five `item` boards, each holding a `label`, an instance of VehicleDotLabel, a `count` text layer and a `description`, an instance of Text, and no variant property, so its one variant is `Default`. There is no `State` property: nothing in the key is interactive, so its one design state is rest; an unknown count is rest with `data-unknown`.

No part has a Base UI part: a pattern builds on Perron's components, never on `@base-ui/react` (the contract's [Patterns](../components/README.md#patterns)), and none of these parts has behaviour of its own for Base UI to give. The root, the items and the counts are plain elements, each `label` is VehicleDotLabel and each `description` is Text, both of which render through `useRender` themselves.

A `<ul>` of `<li>`s is HTML's own element for a set of like things, which the contract's "native semantics first" asks for, and the element ReportStrip and VehicleDotLegend list the same five states in: a screen reader says it is a list of five items and reads each one's word, count and sentence in turn. A `<dl>` would pair each word with its sentence too, but screen readers announce its groups unevenly, and the key would then read unlike its two siblings.

The sentence composes Text rather than a span of the key's own, so it takes the one `caption` and `secondary` treatment every second line in the library takes, as DisruptionCard's stops and time do, with Text's own long-word rule. The registry's `dependsOn` names VehicleDotLabel and Text.

Base UI already does: nothing here. DataStateKey has no `render`, on the root or in `slotProps`, as ReportStrip has none: the contract's `render` is Base UI's, inherited from a Base UI props type, which a pattern cannot import, and declaring it fails the `props` check, so `slotProps.label` and `slotProps.description` leave out the `render` that VehicleDotLabel and Text take from `useRender`.

| Field           | Type             | Description                                                                           |
| --------------- | ---------------- | ------------------------------------------------------------------------------------- |

The counts are ReportStrip's, taken and written the same way: one required object with an optional `number | null` per state, a state left out, `null` or not finite being unknown, and each count written by `grouped`, "1 046", so a key and a strip beside it show one figure alike. The type is the key's own rather than ReportStrip's, since a pattern imports only the patterns its `dependsOn` names, and the two keep the same fields so a caller passes one object to both.

The key takes the app's thresholds as two required numbers in milliseconds, `liveThreshold` and `ageingThreshold`, and writes them into the sentences itself, rather than as words the caller formats, or with the tokens' defaults: Data states makes the thresholds the app's and asks a screen that explains the states to give the app's own figures, never the defaults' as fixed facts, so a default of 60 s would state the very figure an app with a slower feed must not show, and each caller states its own; milliseconds are the unit the `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold` tokens give, so an app that keeps the defaults passes `numeric['vehicle-dot.live-threshold']` and `numeric['vehicle-dot.ageing-threshold']` from `@mylder/perron/tokens.ts`, the tokens' values as numbers (its `base` holds them as the strings "60000ms" and "300000ms"), and an app that works out each vehicle's state compares ages with the same two numbers it passes here; and a pattern takes Mylder's data and writes it, as it writes its counts, so every key writes "2.5 min" alike, in each locale's decimal mark, where words from each caller would drift. The names are the tokens', `live-threshold` and `ageing-threshold`, in camelCase.

The key writes a threshold under 2 min in whole seconds, "60 s", "90 s", and one of 2 min or more in minutes to one decimal place, "2.5 min", "5 min", with the locale's decimal mark ("2,5 min" in Danish, Swedish and Norwegian), each through an owned string with a placeholder named for its unit, "{seconds} s" and "{minutes} min" (CR-7): these are the figures Data states itself writes, "60 s", "150 s at 60 s", "5 min", "at most 4 min", and the ticket's "2.5 min"; under 2 min a whole number of seconds reads more exactly than "1.5 min"; one decimal place is as exact as a threshold set in steps of 30 s needs, and a trailing ".0" is dropped; content design puts a space before the unit, here a no-break space (U+00A0), so a figure and its unit never part at a line's end in a narrow panel; the decimal mark is the locale's, written with `Intl.NumberFormat` in `useLocale()`'s locale, as Slider and Meter write their figures; and the unit is an owned string around its figure, by the contract's Words, so a locale can put it where its grammar needs it. "min" is the unit `minutesUnit` already shows in all four locales, and "s" is the SI symbol, the same in all four.

`className`, `style`, `ref`, `aria-label`, `aria-labelledby` and the other `ul` props reach the root, as the contract's [Root](../components/README.md#root) says. `counts`, the two thresholds, the thirteen `*Label` props and `slotProps` are taken out of the rest props first; the props type leaves out `children`, since the key writes its own five items (CR-11). No `variant`, `color` or `size`: the key has one look, in VehicleDotLabel's one size, and another can join later as an optional prop without a break.

DataStateKey takes VehicleDotLabel's five `*Label` props and Stat's `unknownLabel`, and gives them on, as ReportStrip does: the names stay the components' own, so a caller who overrides a word on the dots or the strip overrides it on the key the same way. Each new owned string has its own `*Label` prop, by the contract's Words, and a sentence's override takes the same placeholders as the sentence.

The key takes a `slotProps` key for each part but the root, `item`, `label`, `count` and `description`, each value given to all five of its parts, as ReportStrip's are: `slotProps.label` takes VehicleDotLabel's props less the ones the key sets, and `slotProps.description` Text's less the ones the key sets.

The counts take ReportStrip's treatment, `typography.data` in `color.text.primary`, with an unknown count's "—" in `color.text.tertiary`, so a count reads the same in a strip and a key. The sentence is the item's second line, which the contract's Rows family sets in `typography.caption` with `color.text.secondary`, and Typography gives `caption` to "legend descriptions"; `color.text.secondary` reaches 4.5:1 on every surface ([Accessibility](../foundations/accessibility.md#text-on-surfaces)).

An item is `space.300` from the next, its sentence `space.050` under its first line, and its count `space.200` from its label: `space.300` is the step Semantic spacing puts between the parts of a detail panel and VehicleDotLegend between its items, enough to read five two-line items as five; `space.050` keeps a sentence close to the word it explains; and `space.200` is ReportStrip's gap between a label and its count, the least the count keeps when the label's column fills the line.

The key draws no surface and places nothing: no `background`, `border`, `radius`, `shadow`, `position`, `inset`, `z-index` or outer `margin` (CR-9). It sits on the surface of the panel, card or DataStatePanel that holds it, as ReportStrip and VehicleDotLegend sit on theirs.

In forced colours the counts and sentences take the system's text colour on their own, and each dot keeps its shape by VehicleDot's CR-9, so the key adds no forced-colours rule.

An item reads "Live 412 Reported by the vehicle in the last 2.5 min", and one with no count "No signal Unknown Moved on by the timetable, with no report for over 5 min".

The root is a list with no name of its own and no live region, as ReportStrip's is: a caller names it with the heading beside it, such as "How sure are we?", through `aria-labelledby`; the counts change every few seconds, which would flood a screen reader, and [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks that only changes of state be announced, in the screen's own polite live region.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: each dot's state is told to the ear by the word beside it, through VehicleDotLabel; each count is read after its word, and an unknown one as "Unknown" in place of the hidden "—" (CR-5); each sentence is visible text, read in place, and one whose threshold is unknown is "—" for the eye and "Unknown" for the ear (CR-7). No colour carries meaning: the dots are one ink, the text's (CR-3), and no signal's grey comes with its cut and its word.
- [ ] Every landmark and named region has an accessible name: none here; the key is a list, not a landmark or region, and a caller names it with `aria-label` or `aria-labelledby` (CR-13).
- [ ] Every default label can be overridden: `liveLabel`, `ageingLabel`, `estimatedLabel`, `timetableOnlyLabel`, `noSignalLabel`, `liveDescriptionLabel`, `ageingDescriptionLabel`, `estimatedDescriptionLabel`, `timetableOnlyDescriptionLabel`, `noSignalDescriptionLabel`, `secondsDurationLabel`, `minutesDurationLabel` and `unknownLabel`.
- [ ] Every shape the type accepts renders, in every variant: `counts` with all five states, with some left out, `null`, `NaN` and `Infinity` (unknown), with `0` (a count) and with a count past a thousand (grouped); thresholds under 2 min, at 2 min, past it with a half minute and whole, and `NaN` or below 0 (unknown); every `*Label` string replaces only its own string, a sentence's override keeps its placeholders filled, and an undefined one keeps the locale's. DataStateKey takes no `ReactNode`.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; nothing animates or collapses. The dots and an unknown figure's "—" are `aria-hidden` because words beside them say them, not for animation.
- [ ] Native semantics first: a `<ul>` of `<li>`s, each with a VehicleDotLabel, a `<span>` of digits and a Text `<span>` of words; no ARIA of the pattern's own beyond the "—"'s `aria-hidden`, which `UnknownValue` sets.
- [ ] Focus moves in reading order and returns on close: nothing takes focus or opens; Tab passes the key by.
- [ ] Every target is at least `size.target-min` square: no target; nothing in the key is pressed.
- [ ] Loops stop when the system asks for less motion: none here; nothing moves, and a count changes its text without a transition.

## Owned strings

Every word the key shows or announces is its own; the caller gives only numbers. The five state words and "Unknown" are keys `packages/perron/src/locale/en.ts` already has. The five sentences and the two durations are new: each sentence is worded from what Data states says the state means, so every screen that explains the states says the same thing in the same four languages, and the thresholds are placeholders the app's figures fill (CR-6, CR-7).

The English sentences are "Reported by the vehicle in the last {liveThreshold}", "Last reported {liveThreshold} to {ageingThreshold} ago", "Placed from the timetable and the latest delay", "No real-time data, placed from the timetable alone" and "Moved on by the timetable, with no report for over {ageingThreshold}", with no full stop: each says one state's "Means" from [Data states](../foundations/data-states.md) in a plain sentence about the vehicle, as content design asks, live in the ticket's own words; "GPS" is left out, since a vehicle's report is its position whatever the source; "{liveThreshold} to {ageingThreshold}" writes each figure with its own unit, "2.5 min to 5 min", rather than content design's range with one unit at its end, "Every 3 to 4 min", since the two thresholds can take different units, "60 s to 5 min"; no signal's "moved on by the timetable" is the foundation's own and says, as [No signal keeps moving](../foundations/data-states.md#no-signal-keeps-moving) asks, that its place is a guess, and it comes first, before the figure, so no punctuation follows a placeholder in any locale: `expectOwnedStrings` reads a comma straight after a filled figure, "5 min,", as a word no dictionary holds; and with one sentence each and no other in the item, a full stop adds nothing, as the library's other owned strings have none.

## Component rules

Rules for this pattern alone, numbered so the build and the review can cite them.

- **CR-1.** The key always renders five items, in the order [Data states](../foundations/data-states.md) lists the states: live, ageing, estimated, timetable only, no signal, whatever `counts` holds, read from `VEHICLE_STATES` in `packages/perron/src/internal/vehicle-states.ts`. No prop picks, hides or reorders them, nothing else renders inside the `<ul>`, and a state with no vehicles shows "0".
- **CR-2.** Each item is `<li className="pn-DataStateKey-item" data-variant={state}>` holding the `label`, a space, the `count`, a space, then the `description`, so the item's text reads "Live 412 Reported by the vehicle in the last 2.5 min" with its three parts apart; a space renders nothing between two grid items. `data-variant` takes VehicleDot's spelling of the state (`'timetable-only'`, `'no-signal'`), so a caller's CSS selects an item as it selects a dot.
- **CR-3.** Each label is `<VehicleDotLabel variant={state} />` with no `line`, so its dot draws in `currentColor`, the label's `color.text.primary`, as ReportStrip's CR-3 decided: the key explains states across many lines, and a line's colour would say it is about that line.
- **CR-4.** Each count's field in `counts` is the state's `STATE_KEY`, from `packages/perron/src/internal/vehicle-states.ts`, and each count is written by `grouped`, from `packages/perron/src/internal/numbers.ts`: "1 046", "412", "0", the same in every locale.
- **CR-5.** A count is unknown when its field is left out, `null`, or a number that is not finite (`NaN`, `Infinity`); `0` is a count. The key asks the `known` helper, from `packages/perron/src/internal/nodes.ts`. An unknown count's item and count both carry the bare `data-unknown` attribute, and the count holds `<UnknownValue label={…} />`, from `packages/perron/src/internal/UnknownValue.tsx`, with `unknownLabel` or the locale's "Unknown", as ReportStrip's CR-5 says it.
- **CR-6.** Each description is `<Text variant="caption" color="neutral" emphasis="secondary">` holding its state's sentence, the owned string `<stateKey>Description` filled by `interpolate`, from `packages/perron/src/internal/strings.ts`, with `{ liveThreshold, ageingThreshold }`, each the threshold as CR-7 writes it. The sentence is never built by joining words in code, and a caller's `*DescriptionLabel` override is filled the same way, so its placeholders take the app's figures too. A sentence without a placeholder, estimated's and timetable only's, is the string as it stands.
- **CR-7.** A threshold is written from its milliseconds, its unit chosen from its seconds rounded to a whole number: under 120 s it is `secondsDuration` with `{seconds}` those seconds, and from 120 s on it is `minutesDuration` with `{minutes}` its minutes rounded to one decimal place, a trailing zero dropped, so 60 000 is "60 s", 119 400 "119 s", 119 500 "2 min", 150 000 "2.5 min" and 300 000 "5 min"; a rounded `-0` is written as `0`, "0 s". The figure and its unit are joined by the strings' no-break space, so they never part at a line's end. The figure is formatted by `Intl.NumberFormat` in the locale `useLocale()` gives, from `packages/perron/src/PerronProvider.tsx`, with at most one fraction digit and no grouping, so a figure past a thousand stays in plain digits, built once per locale with `useMemo`, as Slider builds its own, so it is "2,5 min" in Danish, Swedish and Norwegian. A threshold that is not finite or is below 0 is unknown, by `known` and a test for below 0, and each sentence whose template holds its placeholder, the shown template or its override, is `<UnknownValue label={…} />` with `unknownLabel` or the locale's "Unknown" in place of the whole sentence: a sentence with its figure missing says less than "Unknown" does, and `expectOwnedStrings` refuses a template split by an element, as UnknownValue inside a placeholder would split it. Estimated's and timetable only's sentences, which hold no threshold, stand. The key works out no state and never compares an age with a threshold: the thresholds only fill its words, and the caller gives the counts (VehicleDotLabel's CR-8).
- **CR-8.** The key reads its words with `useOwnedStrings` from `packages/perron/src/PerronProvider.tsx`, with the five `*DescriptionLabel` props, the two `*DurationLabel` props and `unknownLabel` laid over their keys, and gives the five state-word `*Label` props to every VehicleDotLabel, which shows only its own state's word, so each override replaces only its own item's word or sentence.
- **CR-9.** The key draws no surface and places nothing: no `background`, `border`, `radius`, `shadow`, `position`, `inset`, `z-index` or outer `margin`. It sits on the surface of whatever holds it, and its screen places it.
- **CR-10.** At 320 px wide, in every locale, nothing overflows the key's container: the label's column is `minmax(0, 1fr)`, so a long word in a label breaks inside it by VehicleDotLabel's own CR-5; a count's digits stay on one line at the end of the first line (`white-space: nowrap`); and a sentence wraps inside its line by Text's `overflow-wrap: anywhere`.
- **CR-11.** The props type extends `Omit<ComponentPropsWithRef<'ul'>, 'children'>` and declares `counts`, `liveThreshold`, `ageingThreshold`, the thirteen `*Label` props and `slotProps`, each taken out of the rest props before the spread, so none reaches the DOM. The root spreads the rest props, then sets its own class, `pn-DataStateKey` then the caller's `className` by the `classes` helper, its `ref` and its children, so its own win.
- **CR-12.** The key is never interactive: no hover, focus, pressed or selected look, no tab stop, no `tabIndex`. A key the rider can press is a Perron button or link around it, which takes the focus.
- **CR-13.** The list has no name of its own, and neither the root nor any part is a live region. A caller names it with `aria-label` or `aria-labelledby`, which reach the root with the rest props; a screen that must announce a change of state does it in its own polite live region.
- **CR-14.** Each inner part's props are its `slotProps` value with the pattern's own laid over it: the class joins the part's own first, then the caller's, by `classes`, and the children, `data-variant`, `data-unknown`, `variant`, `line`, `color`, `emphasis` and the `*Label` props are the pattern's. A pattern cannot import Base UI's `mergeProps`, so the merge is a spread, then the pattern's own props, as ReportStrip's CR-12 writes it.
- **CR-15.** The pattern imports only VehicleDotLabel, Text, `PerronProvider`, the `classes` and `known` helpers, `grouped`, `interpolate`, `STATE_KEY`, `VEHICLE_STATES` and the `VehicleState` type, the `UnknownValue` helper, React and its own CSS, as the contract's Patterns section says; never `@base-ui/react`. Type-only imports of `VehicleDotLabelProps` and `TextProps` are fine.

## Do and don't

For a caller using the pattern, with the reason.

| Do                                                                                                                                                                                                            | Don't                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Pass the thresholds the app works out its states with, `liveThreshold` and `ageingThreshold`, in milliseconds, so the sentences say the figures the dots follow                                               | Pass the tokens' defaults when the app's feed sets its own thresholds: the key would tell the rider 60 s while the dots fade at 150 s       |
| Work out each vehicle's state from its report's age with those [thresholds](../foundations/data-states.md#thresholds), then count                                                                             | Count a vehicle as live because it is on the map: the key would claim more than the data knows                                              |
| Leave a state's count out, or pass `null`, when the data doesn't say it, so the key shows "—" and says "Unknown"                                                                                              | Pass `0` for a count the data doesn't know: `0` says no vehicle is in that state                                                            |
| Name the key with the heading beside it, such as "How sure are we?", and `aria-labelledby`                                                                                                                    | Pass `aria-hidden` to the key: the eye reads its words, counts and sentences, so the ear gets them too                                      |
| Use [ReportStrip](report-strip.md) where the counts sit in one row and need no explaining, and [VehicleDotLegend](../components/vehicle-dot-legend.md) where the dots need their words and nothing is counted | Write your own sentences beside a ReportStrip or a legend: they drift from the key's, and from the four languages the key says them in      |

| Put the key in a [DataStatePanel](data-state-panel.md) while its counts load                                                                                                                                  | Show five unknown counts while the data loads: the panel says it is loading, the key says the data doesn't know                             |
