# VehicleTable

The vehicles in service as a table, one row each: the vehicle's line, where it is going, how fresh its position is and how late it runs, the map's text alternative.

<!-- run notes -->

The design is deferred under ADR 0010 (`docs/adr/0010-unattended-runs-with-design-deferred.md`), so there is no read-back, code map or export: this spec decides the layers, the design states and the token for every part. Its sources are the [contract](../components/README.md) and its Patterns section, the [foundations](../foundations/README.md), [Data states](../foundations/data-states.md), [Layout](../foundations/layout.md#other-layout-properties), [Typography](../foundations/typography.md#roles), [Accessibility](../foundations/accessibility.md), [content design](../content-design.md), `list_tokens`, and the specs of the three entries in its `dependsOn`, [LineBadge](../components/line-badge.md), [Delay](../components/delay.md) and [VehicleDotLabel](../components/vehicle-dot-label.md). The ROADMAP names it among the patterns (7.2) and no more; the registry files it under Data with no `baseUiParts`. What the foundations already say of it: Accessibility names "the vehicle list" as the map's text alternative, and Layout gives `size.vehicle-row`, the "vehicle table row height (virtualised list relies on it)". [DataStatePanel](data-state-panel.md) is written to hold it while its data loads, and [DetailHeader](detail-header.md) set that the patterns after it, VehicleTable named among them, take a line as `line` and `lineName`. The extracted prototype is not reachable from this branch, so nothing here rests on it. DepartureRow, the sibling in flight when this spec began, has since merged into `main` with its brief, build, review and docs done; this spec keeps its names for the vehicle's data state (`variant`), its delay (`delay`, minutes, `number | null`) and the composed components' labels, and its rule that a timetable-only or no-signal vehicle always shows an unknown delay.

## Anatomy

Penpot page `Patterns/VehicleTable`. Family: Rows, its table rows: no fill, no radius in a table, rows divided by `border.width.025` in `color.border.subtle`; no hover, since the rows are not pressed (CR-7). Shared parts: none of its own; Delay brings VisuallyHidden inside itself.

VehicleTable has no variant property: what each row shows comes from the data, so the drawing has one variant, `Default`, a table of five vehicles, one in each data state. Its layers, in reading order, are the parts below; `row` repeats once per vehicle, holding that vehicle's `lineCell`, `destinationCell`, `positionCell` and `delayCell`.

The table is a native `<table>` of four columns, Line, Destination, Position and Delay, under a visible header row, with each row's line and destination cells its row headers (`<th scope="row">`), and no column for a vehicle number, a data age or an action. A native table is what [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks of the map's text alternative and what native semantics first gives: a screen reader moves down a column and hears each cell with its column's name and its row's line and destination. The badge has a column of its own, so the destinations line up down the table whatever the badge's width ("5C", "150S"), the alignment DepartureRow's rows can't keep; the line and the destination together name a vehicle, where either alone repeats down the table; and the three entries in `dependsOn` fill the other columns. A vehicle number, a "since 08:02" age and an action are what no source asks of the table yet, and each can join later as an optional field without a break.

## Base UI parts

The table and its sections, rows and cells are plain elements, and the line, the state and the delay come from LineBadge, VehicleDotLabel and Delay, which bring their own Base UI underneath.

Base UI already does: nothing here. LineBadge, VehicleDotLabel and Delay render through Base UI's `useRender` inside themselves; VehicleTable adds the table, its headers and its layout.

VehicleTable has no `render`, on the root or on any part: a pattern can't import `useRender`, and declaring `render` itself fails the `props` check, so the root is a `<table>` that never swaps, as StopTimeline's `<ol>` is.

## Props

In MUI's layout. Every prop VehicleTable declares gets this description as its JSDoc. Its props type is the `<table>`'s props, `ComponentPropsWithRef<'table'>`, without `children`, with its own members added; the `<table>`'s other attributes, such as `aria-labelledby`, reach the root and get no row, as in MUI's tables. No `render` (see [Base UI parts](#base-ui-parts)).

The table takes its vehicles as one array, `vehicles`, of `VehicleTableVehicle` objects, each with `id`, `line`, `lineName`, `destination`, `variant` and an optional `delay`, with `variant` required in each. A table lays out many vehicles as data, as StopTimeline lays out `stops` and DisruptionCard `lines`, so an array of a type the pattern exports beside its props is the precedent; the fields keep DetailHeader's `line` and `lineName` and DepartureRow's `variant` and `delay`, so one vehicle is fed to the row and to the table alike; `id` keys each row, since vehicles reorder as their data comes in, where StopTimeline's stops never do; and `variant` is required because a vehicle without its state would default to "Live", claiming more than the data knows ([Data states](../foundations/data-states.md): "never draw a vehicle without its state").

The table shows the vehicles in the order `vehicles` gives them, with no sorting of its own, no sortable column headers and no `aria-sort`. The screen that holds the vehicles chooses their order, by line or by delay, and passes them sorted; sortable headers would be buttons with pointer feedback, a sort state and an event, a prop set that can join later without a break once a design shows them.

VehicleTable takes no `slotProps`, and takes the composed components' labels as its own props: the five state labels for VehicleDotLabel, Delay's five, and its four column labels. The contract keys `slotProps` by inner Base UI part and VehicleTable has none, as StopTimeline has none; its parts repeat once per row, so a `slotProps` value would reach every row alike, where DepartureRow, one row alone, gives each of its parts a key; and StopTimeline and DepartureRow take Delay's labels as top-level props under Delay's names, so a caller learns them once.

The table owns no accessible name: it takes its name from the caller through `aria-labelledby` or `aria-label` on the root. A table sits under the heading of the sheet or Section that holds it, such as "Vehicles on line 5C", which only the caller knows; an owned "Vehicles" would repeat or contradict that heading, and a visible `<caption>` would draw it twice.

## Tokens

One row per part, state and property. VehicleTable is not interactive, so its one design state is rest (CR-7); a row's `data-variant` changes only its VehicleDotLabel and, for two states, its Delay. LineBadge, VehicleDotLabel and Delay keep their own tokens, as their specs give them; rows marked "through" are theirs, listed so the drawing has them.

Each row is at least `size.vehicle-row` tall, set as the `<tr>`'s `height`, which a table row treats as its least height, so a row grows only when its content is taller than `size.vehicle-row`, such as a destination wrapped onto three lines, and the pattern renders every vehicle it is given, with no virtualisation of its own. Layout gives `size.vehicle-row` so that a virtualised list and the row agree on its height, and every row whose destination fits one or two lines is exactly that tall; a fixed height that never grows would cut off a long destination at 320 px or 200% zoom, which [Accessibility](../foundations/accessibility.md#what-a-person-checks) forbids; and a pattern that can import nothing but Perron and React has no virtualiser to build on, so a screen with more vehicles than it can render windows them itself, using `size.vehicle-row` as each row's height.

The header cells are in `typography.label-sm` and `color.text.secondary`, the destination in `typography.label` and `color.text.primary`; every cell has `space.200` above and below and `space.300` from the cell before it, the first column flush with the table's start edge; the delay column's header and cells sit at the end of their column; a `border.width.025` divider in `color.border.subtle` runs under the header row and between rows but not after the last; and there is no fill, radius or hover. `typography.label-sm` is the role for field and stat labels, what a column's name is, and secondary text keeps the headers behind the data while reaching 4.5:1; `typography.label` is the role for names in lists, as DepartureRow's destination; `space.300` is what Semantic spacing gives between the parts of a detail panel and what DepartureRow sets between its columns, and `space.200` keeps a wrapped row's text off its dividers; delays are figures compared down a column, so they line up at the end; the Rows family divides table rows with that hairline and gives a table's rows no radius, and the panel around the table draws its own edge, so no divider follows the last row.

## Keyboard and ARIA

No Base UI part, so nothing from Base UI here: the table is read, not operated. It takes no focus, and no key does anything of its own (CR-7). A screen reader's table keys, which move from cell to cell, are the screen reader's.

| `Tab` | Passes the table by to the next focusable element, or reaches a caller's link in a `destination`, row by row in reading order | The browser |

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the line's colour is named by `lineName`, read from the badge; the dot's shape by the state's word beside it, the dot `aria-hidden` (VehicleDotLabel's CR-2); the delay's figure and colour by Delay's words, and an unknown one's "—" by "Delay unknown" (CR-4); each column's meaning by its header, which a screen reader reads with each cell.
- [ ] Every landmark and named region has an accessible name: the table is not a landmark; it takes its name from the caller, through `aria-label` or `aria-labelledby` on the root, and has none of its own (CR-5): every story names it with `aria-label`, and `Default`'s `play` names one from a heading through `aria-labelledby`, as Do and don't asks of a screen.
- [ ] Every default label can be overridden: `lineColumnLabel`, `destinationColumnLabel`, `positionColumnLabel`, `delayColumnLabel`, the five state labels from `liveLabel` to `noSignalLabel`, and Delay's five, `minutesUnitLabel`, `minutesLateLabel`, `minutesEarlyLabel`, `onTimeLabel` and `delayUnknownLabel`.
- [ ] Every shape the type accepts renders, in every variant: `lineName` and `destination` render a string, an element and a list alike; `vehicles` renders empty, with one vehicle and with many; `delay` a number, `null` and left out, in every `variant` (CR-4); a long destination wraps inside its column (CR-8).
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; nothing animates or collapses. The dot and the delay's figure are `aria-hidden` inside their components because words say them, not for animation.
- [ ] Native semantics first: a native `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th scope>` and `<td>`, whose roles no CSS `display` overrides (CR-1); no ARIA of the table's own.
- [ ] Focus moves in reading order and returns on close: the table takes no focus and opens nothing; a caller's link in a `destination` is reached in row order, its DOM order.
- [ ] Every target is at least `size.target-min` square: no target of the table's own (CR-7); a caller's link in a `destination` is `typography.label` text in a row at least `size.vehicle-row` tall, with that much room around it.
- [ ] Loops stop when the system asks for less motion: none here; nothing moves. A vehicle whose data changes is new props from the screen, not an animation.

## Owned strings

The line's name and the destination are the caller's data, and so is the table's accessible name (see [Props](#props)); the column headers are the table's own, and the state's words and the delay's are VehicleDotLabel's and Delay's, overridable here through the props above.

The table adds four owned strings for its column headers, `lineColumn` "Line", `destinationColumn` "Destination", `positionColumn` "Position" and `delayColumn` "Delay", outside content design's table. No key in `packages/perron/src/locale/en.ts` says any of them: `delays`, "Delays", is the heading of a line's delays and the name of a kind of disruption, plural, not a column's name. "Position" names what the five data states measure, how fresh a vehicle's reported position is, in a word a rider knows, where "Data state" is the system's own term; and the four are a table's headers rather than data-state, delay or disruption words, as DepartureRow's "Now" and StopTimeline's "Next stop" stayed out of content design's table.

## Component rules

Rules for this pattern alone, numbered so the build and the review can cite them.

- **CR-1.** The pattern imports only `LineBadge`, `VehicleDotLabel` and `Delay`, `classes` from `packages/perron/src/internal/`, `useOwnedStrings` from `PerronProvider`, React and its own CSS, as the contract's [Patterns](../components/README.md#patterns) section says; never `@base-ui/react`. The types of `line` and `variant` come through type-only imports of `LineBadgeProps` and `VehicleDotLabelProps`. The root is a `<table>` holding a `<thead>` and a `<tbody>`, and no CSS sets `display` on the table, its sections, rows or cells, since a table part whose `display` changes loses its role in some browsers.
- **CR-2.** The root's `className` is `pn-VehicleTable` then the caller's. The caller's rest props are spread on the root and the table's own class after them, so the table's wins; every prop the props type declares, `vehicles`, every `*Label` prop, is taken out of the rest, so none reaches the DOM. Each `row` is keyed by its vehicle's `id` and carries `data-variant` with the vehicle's `variant`; no part takes a caller's props but the root, and the props type declares no `slotProps`.
- **CR-3.** Each row holds, in this order, the `lineCell` with a LineBadge (`line`, `lineName` as its children, `size='medium'`), the `destinationCell` with `destination`, the `positionCell` with a VehicleDotLabel (`variant`, `line` and the five state labels) and the `delayCell` with a Delay (CR-4) and Delay's five labels. The two `<th>`s take `scope="row"` and the four header cells `scope="col"`; the table has these four columns and no other. The rows follow the order `vehicles` gives: the table sorts nothing, and its header cells are text, never buttons, with no `aria-sort`.
- **CR-4.** A vehicle whose `variant` is `timetable-only` or `no-signal` renders its Delay with `minutes={null}`, whatever `delay` holds, as [Data states](../foundations/data-states.md#delays) says those states always show an unknown delay. Any other vehicle renders its Delay with `minutes={delay}`, and with `minutes={null}` when `delay` is left out, so every row's delay cell shows a figure, "On time" or "—", never an empty cell.
- **CR-5.** The header cells show the four column strings, read with `useOwnedStrings({ lineColumn: lineColumnLabel, destinationColumn: destinationColumnLabel, positionColumn: positionColumnLabel, delayColumn: delayColumnLabel })`, each with `data-column` `line`, `destination`, `position` or `delay`. The state and delay labels pass to every VehicleDotLabel and Delay unchanged, an undefined one leaving the locale's word. The table owns no name: it sets no `aria-label`, `aria-labelledby` or `<caption>` of its own, and takes the caller's through the root's rest props.
- **CR-6.** With an empty `vehicles`, the table renders its header row and an empty `<tbody>`, and says nothing more: a screen that has no vehicles to show, or none yet, holds the table in [DataStatePanel](data-state-panel.md), whose `empty` and `loading` statuses say so.
- **CR-7.** The table is text: no row or cell is a link or a button, it has no hover, pressed, focus or selected look, no tab stop and no role but the table's own, so it has no pointer feedback to draw. A caller that opens a vehicle passes a Perron Link as its `destination`. VehicleTable is not a live region either: a screen that updates its vehicles announces a change of state, such as a vehicle going silent, in its own polite live region, never every delay's change ([Accessibility](../foundations/accessibility.md#what-a-person-checks)).
- **CR-8.** The table is as wide as its container and uses the browser's automatic table layout: no cell sets its own width, so the browser gives each column its content's width when the table has room for all four on one line, as a panel at `size.detail-width` has for the `Default` vehicles, and a state's word such as "Timetable only" stays on one line there; in a table too narrow for that, each column gives up width in proportion to its content, so beside a long destination the state's word can wrap at its space too. The destination cell wraps a long destination with `overflow-wrap: anywhere`, so its column can narrow below its longest word, and at 320 px nothing runs past the table's edge. The badge and the delay never wrap; the state's word wraps at its spaces and keeps whole words by VehicleDotLabel's CR-5; a header wraps at its spaces and keeps whole words, since `break-word` makes its longest word its column's least width. Each row is at least `size.vehicle-row` tall, as the `<tr>`'s `height`, and grows only when its content is taller than that, such as a destination wrapped onto three lines; the pattern renders every vehicle it is given, with no windowing of its own.
- **CR-9.** The stories use only lines whose badge pairs reach 4.5:1 (M2, M3, E, F, H, bus and regional), so axe's `color-contrast` rule stays on in every story; M1, M4, A, B and C miss it by rule, as LineBadge's CR-6 says.

## Do and don't

For a caller using the pattern, with the reason.

| Do                                                                                                                           | Don't                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Name the table from the heading above it, through `aria-labelledby`, such as a Section's "Vehicles on line 5C"               | Leave the table without a name: a screen reader's list of tables can't tell it from another                    |
| Work out each vehicle's `variant` from its last report, with `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold` | Pass `live` for a vehicle placed from the timetable: the table would claim more than the data knows            |
| Keep each vehicle's `id` the same from one update to the next                                                                | Key the vehicles by their place in the array: a row would keep another vehicle's state while the list reorders |
| Sort the vehicles before you pass them, such as by line and then by delay, and keep the order steady between updates         | Reorder the rows on every update: the rows jump under the rider's eye and a screen reader's place              |
| Hold the table in DataStatePanel while its vehicles load or when there are none                                              | Show an empty table as the only answer to "no vehicles": a header row says nothing about why                   |
| Announce a vehicle's change of state in the screen's own polite live region, once                                            | Put the table in a live region: every delay's change would be read                                             |
| Make a vehicle openable by passing a Perron Link as its `destination`                                                        | Add `onClick` to a row: it has no focus, role or pressed look, and a keyboard can't reach it                   |
| Keep `lineName` the short name riders know and `destination` the place: "5C" to "Husum Torv"                                 | Put the line in `destination`, "5C Husum Torv": the line column already reads "5C"                             |
