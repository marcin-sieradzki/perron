# DisruptionCard

A card for one disruption on Copenhagen's network: its kind, the lines it touches, a short title and a plain sentence on what is happening, set as a raised card in a list of disruptions or in a line's detail panel.

## Anatomy

Penpot page `Patterns/DisruptionCard`, not drawn yet: the design is deferred (`docs/adr/0010-unattended-runs-with-design-deferred.md`), so this spec decides the drawing. Its sources are the [contract](../components/README.md), the foundations, the tokens and the specs of the components it composes: [SeverityLabel](../components/severity-label.md), [LineBadge](../components/line-badge.md), [Surface](../components/surface.md) and [Text](../components/text.md), the four its `dependsOn` lists once the build adds Surface and Text to the registry (CR-1). Family: none. Shared parts: `VisuallyHidden`, which says "Affected lines" before the line badges (CR-4).

DisruptionCard is a [pattern](../components/README.md#patterns): it builds only on Perron's components, takes Mylder's domain props, and imports nothing from `@base-ui/react`, so none of its parts is a Base UI part.

The words come from the sources: [Typography](../foundations/typography.md) gives `typography.heading-sm` to "card titles, such as a disruption" and `typography.body-sm` to "disruption details"; [Content design](../content-design.md) asks for what is happening in plain sentences, "Signal fault at Danshøj. Trains between Flintholm and Ny Ellebjerg run slower than planned."; SeverityLabel heads "a disruption card"; and [Elevation](../foundations/elevation.md) sets cards inside a panel on `color.surface.raised`, which is Surface's `raised` variant.

The card is drawn as a header row, holding the SeverityLabel at the start and the affected lines' LineBadges at the end (wrapping under it when they don't fit), then the title, then the sentence, with no icon, time or action of its own: the kind and the lines are what a rider scans a list for, the title and the sentence say the rest, and a time or an action can join later without a break.

The card's root is a Surface in its `raised` variant, and Text sets the title and the sentence, so `Surface` and `Text` join DisruptionCard's `dependsOn` in `packages/perron/components.json` (CR-1): Surface already draws the raised card from the tokens and gives the root its `render` and `ref`, which a pattern cannot get from `useRender` itself, and Text sets each typography role, so the pattern draws no fill, edge or font of its own.

The Penpot component has one variant property, `severity`, with the values `delay`, `data`, `diversion` and `planned` in that order, SeverityLabel's own; the variants are `Delay`, `Data`, `Diversion` and `Planned`. There is no `State` property: the card is at rest unless the caller makes it a link (see [Component rules](#component-rules), CR-8).

## Base UI parts

DisruptionCard imports no Base UI component and no Base UI utility: the contract's [Patterns](../components/README.md#patterns) section keeps a pattern to Perron's components, its parts, `PerronProvider` and React, and the `patterns` check fails any import from `@base-ui/react`, a type-only one included. Base UI reaches it only inside the components it composes, so the table names those.

Base UI already does, inside those components: swapping the root element for the one `render` gives while keeping the class and the data attributes, merging the caller's `ref` with the element's, and joining `className` and `style` and chaining event handlers through `mergeProps`. DisruptionCard merges its own `slotProps` by hand (CR-6), since it cannot import `mergeProps`.

## Props

In MUI's layout. Every prop DisruptionCard declares gets this description as its JSDoc. Its props type is Surface's without `variant`, `children` and the HTML `title` attribute, with its own members added: it inherits `render` from Base UI through Surface, and `className`, `style` and `ref` from Surface, so each keeps its JSDoc.

DisruptionCard takes the disruption as flat domain props, `severity` (SeverityLabel's name and type, required), `lines` (an array of `{ line, name }`, optional), `title` (required) and `children` for the sentence, rather than one `disruption` object: flat props read like MUI's (`<Alert severity>`, `CardHeader`'s `title`, the message as `children`), match SeverityLabel and EmptyState, and each one has its own row, JSDoc and default, where an object would hide them in one type.

A pattern has no Base UI parts to key `slotProps` by, so DisruptionCard takes `slotProps` keyed by its inner parts, each the props of the Perron component or element that part renders (`header`, `severity`, `lines`, `title`, `description`): it is the contract's one way inside, it lets a caller make the title a heading (`slotProps: { title: { render: <h3 /> } }`) and override SeverityLabel's words, and the patterns that follow take the same shape.

## Tokens

DisruptionCard draws no colour of its own: the fill, the edge, the radius and the padding are Surface's `raised`, the kind's colour is SeverityLabel's, the line colours are LineBadge's, and the typography is Text's. Its own CSS lays the parts out, with the one look it adds, a hover layer when the caller makes the card a link (CR-8). Rows marked "through" are set by the composed component and are listed so the drawing has them.

The spacing is 8 px from the header to the title (`space.100` row gap plus a `space.100` margin under the header), 4 px from the title to the sentence (`space.100`), 8 px between the SeverityLabel and the badges (`space.200`) and 4 px between badges and between wrapped rows (`space.100`), inside Surface's `space.300` padding: it is EmptyState's 4 px from title to sentence and the 4 px badge gap of a row of LineBadges, and 8 px sets the header apart from the title without a divider.

## Keyboard and ARIA

At rest DisruptionCard is text: it takes no focus and no key does anything. Made a link through `render={<a href="…" />}` (CR-8) it is one tab stop, with the browser's own keys.

| Key     | Does                                                   | From                       |
| ------- | ------------------------------------------------------ | -------------------------- |
| none    | At rest the card is not focusable or operable          | Perron                     |
| `Tab`   | Moves focus to the card, when `render` makes it a link | The browser, on `<a href>` |
| `Enter` | Follows the link, when `render` makes the card a link  | The browser, on `<a href>` |

| Element       | Role                                                                      | Accessible name from                                                                                                                 | States announced |
| ------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------- |
| `root`        | none: a generic `<div>`; `listitem`, `article` or `link` through `render` | Not named at rest; as a link, its whole text content: the kind, "Affected lines", each line's short name, the title and the sentence | none             |
| `severity`    | none: SeverityLabel's `<span>`, its icon `aria-hidden`                    | Its text, the kind's owned name: "Delays", "Diversions", "Planned works", "Data feed problems"                                       | none             |
| `lines`       | `list`                                                                    | Not named: the owned string "Affected lines", overridden by `affectedLinesLabel`, is read just before it as `VisuallyHidden` text    | none             |
| `line`        | `listitem`                                                                | Its text, the line's short name from `lines`                                                                                         | none             |
| `title`       | Paragraph, or a heading when `slotProps.title.render` makes it one        | Its text, from `title`                                                                                                               | none             |
| `description` | none: a generic `<div>`                                                   | Its text, from `children`                                                                                                            | none             |

The line badges are an unnamed list after a new owned string, "Affected lines", in a `VisuallyHidden` span inside the header, so a screen reader hears "Affected lines, list, 2 items, M2, M3" rather than two bare names after the kind: the eye reads the badges' place in the card as "these lines are affected", and the ear needs the same in words, as the contract's first checklist line asks. The words are text, not the list's `aria-label`, because a name replaces the content it names: a card made a link takes its name from its text, and an `aria-label` on the list would put "Affected lines" in that name in place of "M2" and "M3".

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the kind is SeverityLabel's word as well as its icon and colour; the badges' place in the card is said by "Affected lines", read just before the list, and each badge's colour by its short name, so a card made a link is named with the kind, "Affected lines", every line's short name and the title; with no `lines`, neither the words nor the list renders and nothing is announced for them.
- [ ] Every landmark and named region has an accessible name: the card is no landmark by default; a caller who renders it as `<article>` or `<section>` names it from its title, through `aria-labelledby` and `slotProps.title.id`. The `lines` list is no region and has no name: its owned string is read just before it.
- [ ] Every default label can be overridden: `affectedLinesLabel`, and SeverityLabel's `delaysLabel`, `diversionsLabel`, `plannedWorksLabel` and `dataFeedProblemsLabel` through `slotProps.severity`.
- [ ] Every shape the type accepts renders, in every variant: `title` and `children` render a string, an element and a list alike, the title as a `<p>` holds phrasing content and the sentence as a `<div>` holds block content too; `lines` renders none, one and many, wrapping onto new rows; every `severity` has its story.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the card does not animate. SeverityLabel's icon is `aria-hidden` because its word speaks for it.
- [ ] Native semantics first: a `<ul>` of `<li>` for the lines, a `<p>` for the title made a native `h2` to `h6` through `render`, a `<div>` for the sentence, and a native `<a href>` when the caller makes the card a link; no ARIA attribute, "Affected lines" being `VisuallyHidden` text.
- [ ] Focus moves in reading order and returns on close: at rest the card takes no focus; as a link it is one tab stop in the document's order, and it opens or closes nothing.
- [ ] Every target is at least `size.target-min` square: at rest none; as a link the whole card is the target, far larger than `size.target-min`.
- [ ] Loops stop when the system asks for less motion: none here; the card has no motion.

## Component rules

- **CR-1.** The root is a Surface with `variant='raised'`, and the build adds `Surface` and `Text` to DisruptionCard's `dependsOn` in `packages/perron/components.json`, beside `SeverityLabel` and `LineBadge`, then runs `npm run registry`. The props type is `Omit<SurfaceProps, 'variant' | 'children' | 'title'>` with DisruptionCard's own members, so `render`, `className`, `style` and `ref` reach the Surface unchanged and `render` stays Base UI's, inherited, as the `props` check asks. `severity`, `lines`, `title`, `children`, `affectedLinesLabel` and `slotProps` are taken out of the rest before it reaches the Surface, so the HTML `title` attribute never reaches the element.
- **CR-2.** The root carries `data-severity` with the `severity` value, after the caller's props, so a list can select on it; the card's CSS sets no colour from it (CR-3).
- **CR-3.** The kind's colour appears only on the SeverityLabel. The card is never tinted, edged or striped in a `color.transit.severity.*` or status colour: colour never carries meaning alone, and the card stays on the calm, neutral surface the brand asks for.
- **CR-4.** Each entry of `lines` renders one LineBadge at `size='medium'` with `render={<li />}`, `line={entry.line}` and `entry.name` as its children, keyed by `` `${entry.line}-${entry.name}` ``, inside the `lines` `<ul>`, in the order given. The `<ul>` has no `aria-label`: just before it, inside the header, a `VisuallyHidden` span holds the owned string `affectedLines`, or `affectedLinesLabel`, so a screen reader hears "Affected lines" then the list, and a card made a link keeps every line's short name in its name. An empty or missing `lines` renders neither the span nor the `<ul>`, so no empty list is announced.
- **CR-5.** The `title` is a Text with `variant='heading-sm'` and `render={<p />}`, and the sentence a Text with `variant='body-sm'`, `emphasis='secondary'` and `render={<div />}`; `slotProps.title.render` and `slotProps.description.render` replace those elements. A `children` that renders nothing renders no `description`: left out, `null`, a boolean, `''`, or an array of only such values, so no empty `<div>` takes up the gap under the title.
- **CR-6.** Each inner part's props are its `slotProps` value with DisruptionCard's own laid over them: its `className` joins after the part's class (`pn-DisruptionCard-<part> <caller's>`), and its other own props (`severity`, `variant`, `emphasis`, the children) win. The pattern joins them by hand, since it cannot import `mergeProps`.
- **CR-7.** DisruptionCard reads its one string with `useOwnedStrings({ affectedLines: affectedLinesLabel })` from `packages/perron/src/PerronProvider.tsx`; SeverityLabel reads its own, with the `*Label` props `slotProps.severity` passes it.
- **CR-8.** The card draws a hover look only when the caller makes the whole card a link with `render={<a href="…" />}`, as SeverityLabel's Do and don't advises ("Make the whole disruption card the link or button"): `.pn-DisruptionCard[href]` loses the underline and, inside `@media (hover: hover)`, lays `color.surface.hover` over the fill, with `perron.css`'s focus ring and no pressed look, as the Fields have none; a `<button>` is left out because the card's `<p>`, `<div>` and `<ul>` are not allowed inside one.
- **CR-9.** The card sizes to its container, with no width of its own, and long words wrap (Text's `overflow-wrap: anywhere`, the root's `min-inline-size: 0`), so a long Danish stop name fits a 320 px screen; the header wraps the badges under the SeverityLabel when both don't fit on one row.
- **CR-10.** DisruptionCard is not a live region. A screen that adds or changes a disruption announces it in its own polite live region, as [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks.
- **CR-11.** The stories use only lines whose badge pairs reach 4.5:1 (M2, M3, E, F, H, bus and regional), so axe's `color-contrast` rule stays on in every story; M1, M4, A, B and C miss it by rule, as LineBadge's CR-6 says.

## Do and don't

For a caller using the pattern, with the reason.

| Do                                                                                                                                                 | Don't                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Name the lines in words in the title or the sentence, "M2 and M3 trains…", as well as in the badges.                                               | Let the badges be the only mention of a line: five official badge pairs miss 4.5:1, and LineBadge asks for the name in words beside them.                 |
| Say what is happening, then where, how long and how sure we are, in plain sentences: "Signal fault at Kongens Nytorv" over its sentence.           | Repeat the kind in the title ("Delays on M2"): the SeverityLabel already says it, in the content-design word every screen shares.                         |
| Set a list of disruptions as a `<ul>` of cards, each rendered as `<li>`, or make each card a link with `render={<a href="…" />}` to open the line. | Make the card a `<button>`, or put a link or button inside a card that is itself a link: the card's blocks are invalid in a button, and links can't nest. |
| Make the title a heading with `slotProps.title.render` at the level the panel around it needs.                                                     | Pass a heading element as `title`: the title part is a `<p>` until `render` swaps it, and a heading inside a `<p>` is invalid.                            |
| Leave `lines` out for a disruption across the whole network, such as a data feed problem.                                                          | Pass every line on the network, or a placeholder badge, to fill the header.                                                                               |
| Put DisruptionCards inside a panel, which supplies the glass or opaque surface they sit on.                                                        | Tint or stripe the card in the kind's colour with `className`: the colour belongs to the SeverityLabel and never carries meaning alone.                   |
