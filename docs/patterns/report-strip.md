# ReportStrip

How a set of vehicles is reporting right now: how many are in each of the five data states, each count beside its state's dot and word, in one row, for the data views and panels that say how much of what the map shows is live.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`), so there is no read-back, code map or export: this spec decides what the drawing would, the layers, the design states and the token for every part. Its sources are the [contract](../components/README.md) and its Patterns section, the [foundations](../foundations/README.md), [Data states](../foundations/data-states.md) ("Always write the state in words next to the dot. Legends list all five states, in this order, even when one has no vehicles"), [Typography](../foundations/typography.md#roles) (`typography.data` for "counts … in lists and tables"), [Accessibility](../foundations/accessibility.md), [content design](../content-design.md), `list_tokens`, and the specs of [VehicleDotLabel](../components/vehicle-dot-label.md), the one entry in its `dependsOn`, of [VehicleDot](../components/vehicle-dot.md), which that label composes, and of its neighbours [VehicleDotLegend](../components/vehicle-dot-legend.md), [KioskBar](kiosk-bar.md), [DayProfileChart](day-profile-chart.md) and [FactList](../components/fact-list.md). The ROADMAP names it among the patterns (7.2), and the registry files it under Data with no `baseUiParts`, beside VehicleTable and DayProfileChart, the views [DataStatePanel](data-state-panel.md) holds while their data loads. VehicleDotLabel's spec leaves this spec one decision: a label that stands for a state across many lines "has no line to give", and a neutral dot is "decided before ReportStrip is built". VehicleTable, the other Data pattern that composes VehicleDotLabel, has no spec on `main` or on a branch, and the extracted prototype is not reachable from this branch, so nothing here rests on either. As a pattern it imports only Perron's components and parts, never `@base-ui/react`.

## Anatomy

Penpot page `Patterns/ReportStrip`. Family: none: it is static content that sits on its container's surface, not a row of the Rows family, which is pressed and takes a hover, and it draws no surface of its own (CR-8). Shared parts: VisuallyHidden, through the `UnknownValue` helper, which says an unknown count in words (CR-5).

ReportStrip is one row of five items, one per data state in the order Data states lists them (live, ageing, estimated, timetable only, no signal), each the state's VehicleDotLabel then its count, wrapping between items when its container is narrow, and always all five, a state with no vehicles showing "0": Data states asks that a state always come with its word beside its dot, which VehicleDotLabel draws, and that a legend list all five states in this order even when one has none, which a count of the states owes the reader as much, since a missing state reads as one nobody checked; the label before its count is the order Stat and FactList read in, name then figure, so the ear hears "Live, 1 046" in the order the eye reads it; and a row that wraps between items is VehicleDotLegend's layout, which keeps a 320 px container free of sideways scrolling ([Accessibility](../foundations/accessibility.md#what-a-person-checks)).

The drawing will have a `root` board holding five `item` boards, each holding a `label`, an instance of VehicleDotLabel, and a `count` text layer, and no variant property, so its one variant is `Default`. There is no `State` property: nothing in the strip is interactive, so its one design state is rest; an unknown count is rest with `data-unknown`.

| Part (Penpot layer) | What it is                                                                                                                                                                                     | Base UI part                                          | Class                  | `slotProps` key |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ---------------------- | --------------- |
| `root`              | A `<ul>` laying the five items out in one row that wraps between items in a narrow container                                                                                                   | None: a pattern never imports Base UI; a plain `<ul>` | `pn-ReportStrip`       | none            |
| `item`              | An `<li>` holding one data state's label and count, in the order live, ageing, estimated, timetable only, no signal (CR-1)                                                                     | None: a plain `<li>`, no behaviour to borrow          | `pn-ReportStrip-item`  | `item`          |
| `label`             | A [VehicleDotLabel](../components/vehicle-dot-label.md) with the item's `variant` and no `line`: the state's dot, drawn in the text's ink (CR-3), beside its word, "Live" to "No signal"       | None: Perron's VehicleDotLabel                        | `pn-ReportStrip-label` | `label`         |
| `count`             | A `<span>` holding how many vehicles are in the state, such as "1 046", grouped as CR-4 writes it. With no count it holds "—", hidden from screen readers, and "Unknown" for them alone (CR-5) | None: a plain `<span>`                                | `pn-ReportStrip-count` | `count`         |

No part has a Base UI part: a pattern builds on Perron's components, never on `@base-ui/react` (the contract's [Patterns](../components/README.md#patterns)), and none of these parts has behaviour of its own for Base UI to give. The root, the items and the counts are plain elements, and each `label` is VehicleDotLabel, which renders through `useRender` itself.

A `<ul>` of `<li>`s is HTML's own element for a set of like things, which the contract's "native semantics first" asks for, and it is the element VehicleDotLegend, which lists the same five states in the same order, and KioskBar's figures use: a screen reader says it is a list of five items and reads each one's word, then its count.

The strip shows the five counts alone, with no bar drawn in proportion to them, no total and no share in per cent: a proportional bar needs a fill for each state, and the tokens give one only to no signal, `color.data-state.no-signal`, while a ring or a dashed ring cannot fill a segment and Data states forbids reusing those shapes to mean anything else, so a bar is five new tokens through the `design-tokens` skill and a drawing the maintainer approves first; the counts in tabular figures already let the eye compare the states; and a total or a share is a figure of its own, which the screen shows beside the strip in a Stat, as KioskBar shows "Vehicles on the map", and either can join later as an optional prop without a break.

The strip takes its counts as data, one required `counts` object with an optional `number | null` field per state, a state left out, `null` or not finite being unknown, and writes each count itself in digits grouped in threes by a no-break space, "1 046", the same in every locale, as DayProfileChart writes its counts: a pattern takes Mylder's data and lays it out, as DayProfileChart takes `points` and StopTimeline `stops`, so every strip writes its counts alike; an object keyed by state can't list a state twice or out of order, where an array could, and the pattern sets the order itself (CR-1); a number is what a count is, where KioskBar's `figure` is a ReactNode it only shows; an unknown count shows "—" and says "Unknown", as Stat, FactList and DayProfileChart do, since the brand never shows a guess and `0` is a count, not unknown; and the grouping is the one KioskBar's figures and DayProfileChart's counts show, so "1 046" reads the same in a strip, a kiosk and a chart in all four locales.

`className`, `style`, `ref`, `aria-label`, `aria-labelledby` and the other `ul` props reach the root, as the contract's [Root](../components/README.md#root) says. `counts`, the six `*Label` props and `slotProps` are taken out of the rest props first; the props type leaves out `children`, since the strip writes its own five items (CR-9). No `variant`, `color` or `size`: the strip has one look, in VehicleDotLabel's one size, and a larger one can join later as an optional prop without a break.

ReportStrip takes VehicleDotLabel's five `*Label` props and Stat's `unknownLabel`, and gives them on, as KioskBar and StopTimeline give on their components' labels: the contract's checklist asks that every default label the pattern shows can be overridden on one instance, and the names stay the components' own, so a caller who overrides a word on the dots overrides it on the strip the same way.

The strip takes a `slotProps` key for each part but the root, `item`, `label` and `count`, each value given to all five of its parts, `slotProps.label` taking VehicleDotLabel's props less the ones the strip sets: the skill that writes this spec asks for one per part, KioskBar and DataStatePanel do the same, and each composed component's key takes that component's props less the ones the pattern sets, as KioskBar's `slotProps.stat` does; a key per state would be fifteen keys for five copies of one part.

The counts are set in `typography.data` and `color.text.primary`, with an unknown count's "—" in `color.text.tertiary`: [Typography](../foundations/typography.md#roles) gives `typography.data` to "counts … in lists and tables", in JetBrains Mono with tabular figures, at 12 px beside VehicleDotLabel's 12 px `typography.label-sm`, so the word and its count read as one line of one size; a count is the strip's figure, so it takes the full-strength ink, 11.21:1 or more on every surface ([Accessibility](../foundations/accessibility.md#text-on-surfaces)); and `color.text.tertiary` is the colour Accessibility keeps for the "—" of an unknown figure next to stronger text, as FactList's unknown value takes it.

A label is `space.200` from its count, an item `space.400` from the next, and a wrapped row `space.100` from the one above: `space.200` keeps a count close to the word it counts, a step past the `space.100` between VehicleDotLabel's dot and word, so dot, word and count read as one pair; `space.400` sets each pair a step further apart than VehicleDotLegend's `space.300` between its items, since a strip's item ends in a count and the next one starts with a dot, which would otherwise read as the count's mark; and `space.100` is the legend's row gap, which keeps two wrapped rows close enough to read as one strip.

The strip draws no surface and places nothing: no `background`, `border`, `radius`, `shadow`, `position`, `inset`, `z-index` or outer `margin` (CR-8). It sits on the surface of the panel, card or DataStatePanel that holds it, as VehicleDotLegend sits on its container's.

In forced colours the counts take the system's text colour on their own, and each dot keeps its shape by VehicleDot's CR-9, so the strip adds no forced-colours rule.

## Component rules

Rules for this pattern alone, numbered so the build and the review can cite them.

- **CR-1.** The strip always renders five items, in the order [Data states](../foundations/data-states.md) lists the states: live, ageing, estimated, timetable only, no signal, whatever `counts` holds. No prop picks, hides or reorders them, nothing else renders inside the `<ul>`, and a state with no vehicles shows "0".
- **CR-2.** Each item is `<li className="pn-ReportStrip-item" data-variant={state}>` holding the `label`, a space, then the `count`, so the item's text reads "Live 1 046" with the word and the figure apart; the space renders nothing between two flex items. `data-variant` takes VehicleDot's spelling of the state (`'timetable-only'`, `'no-signal'`), so a caller's CSS selects an item as it selects a dot.
- **CR-3.** Each label is `<VehicleDotLabel variant={state} />` with no `line`, so its dot draws in `currentColor`, the label's `color.text.primary`: the strip counts vehicles across many lines, and a line's colour would say it is about that line. VehicleDotLabel's spec left this to ReportStrip, and the decision follows.

  The build makes `line` optional on VehicleDot and VehicleDotLabel, with no default, so a dot given no line sets no `data-line` and draws in the colour of the text around it, and ReportStrip passes no line: VehicleDotLabel's spec names this change, "an optional `line` with an ink default, which only widens its API", as the one to decide before ReportStrip is built; VehicleDot already draws in `currentColor` from its root's `color`, so with no line rule matching, the dot takes its container's ink with no new CSS; the brand keeps colour for the map and the vehicles and the interface around them ink; and it only widens both APIs, which the contract's Change rule allows, where the other way, passing `line='m1'` and recolouring the dot from the strip's CSS as VehicleDotLegend recolours its own, would reach into VehicleDotLabel's inner dot, which the contract's Customising rule keeps a caller out of. The build then changes VehicleDot's and VehicleDotLabel's props types, JSDoc and specs (their Props rows, VehicleDot's CR-7 and VehicleDotLabel's CR-3, which say `data-line` is always set), checks that a dot with no line keeps the system's text colour in forced colours (VehicleDot's CR-9), adds a story to each showing a dot with no line in the text's ink, runs `npm run api`, and adds a changeset for `@mylder/perron`.

- **CR-4.** Every count the strip writes is its digits grouped in threes from the right by a no-break space (U+00A0): "1 046", "112", "0", the same in every locale. DayProfileChart already writes its counts this way with a `grouped` function of its own folder; a helper a second component needs joins the contract's [Shared helpers](../components/README.md#shared-helpers) table first, so the build moves `grouped` into a new file in `packages/perron/src/internal/` that reads no Base UI, adds its row to that table, and imports it in both patterns.
- **CR-5.** A count is unknown when its field is left out, `null`, or a number that is not finite (`NaN`, `Infinity`); `0` is a count. The strip asks the `known` helper, from `packages/perron/src/internal/nodes.ts`, which says exactly this, rather than a test of its own, which the `shared-parts` check fails. An unknown count's item and count both carry the bare `data-unknown` attribute, and the count holds `<UnknownValue label={…} />`, from `packages/perron/src/internal/UnknownValue.tsx`, with `unknownLabel` or the locale's "Unknown": "—" for the eye, `aria-hidden`, and the words for the ear in VisuallyHidden, as Stat and FactList say an unknown value.
- **CR-6.** The strip reads its words with `useOwnedStrings({ unknown: unknownLabel })` from `packages/perron/src/PerronProvider.tsx` for the unknown count, and gives the five `*Label` props to every VehicleDotLabel, which shows only its own state's word, so each override replaces only its own item's word.
- **CR-7.** At 320 px wide, in every locale, the strip wraps onto more rows and never overflows its container: the root wraps between items (`flex-wrap: wrap`), an item is never wider than its container (`max-inline-size: 100%`), a count's digits stay on one line (`white-space: nowrap`), and a long word in a label breaks inside it by VehicleDotLabel's own CR-5: the label's `min-inline-size: 0` lets it shrink below that word in its item, since VehicleDotLabel's `break-word` keeps whole words in its min-content width, so the gap and the count keep their room.
- **CR-8.** The strip draws no surface and places nothing: no `background`, `border`, `radius`, `shadow`, `position`, `inset`, `z-index` or outer `margin`. It sits on the surface of whatever holds it, and its screen places it.
- **CR-9.** The props type extends `Omit<ComponentPropsWithRef<'ul'>, 'children'>` and declares `counts`, the six `*Label` props and `slotProps`, each taken out of the rest props before the spread, so none reaches the DOM. The root spreads the rest props, then sets its own class, `pn-ReportStrip` then the caller's `className` by the `classes` helper, its `ref` and its children, so its own win.
- **CR-10.** The strip is never interactive: no hover, focus, pressed or selected look, no tab stop, no `tabIndex`. A strip the rider can press, such as to open a fuller report, is a Perron button or link around it, which takes the focus.
- **CR-11.** The list has no name of its own, and neither the root nor any part is a live region. A caller where the strip stands alone names it with `aria-label` or `aria-labelledby`, which reach the root with the rest props; a screen that must announce a change of state, such as a feed going silent, does it in its own polite live region.
- **CR-12.** Each inner part's props are its `slotProps` value with the pattern's own laid over it: the class joins the part's own first, then the caller's, by `classes`, and the children, `data-variant`, `data-unknown`, `variant` and the `*Label` props are the pattern's. A pattern cannot import Base UI's `mergeProps`, so the merge is a spread, then the pattern's own props, as KioskBar's CR-7 writes it.
- **CR-13.** The pattern imports only VehicleDotLabel, `PerronProvider`, the `classes` and `known` helpers, the `UnknownValue` helper, CR-4's helper, React and its own CSS, as the contract's Patterns section says; never `@base-ui/react`. A type-only import of `VehicleDotLabelProps` is fine.

## Do and don't

For a caller using the pattern, with the reason.

| Do                                                                                                                                                                                                                | Don't                                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Work out each vehicle's state from its report's age with the app's [thresholds](../foundations/data-states.md#thresholds), by default `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold`, then count | Count a vehicle as live because it is on the map: the strip would claim more than the data knows                  |
| Leave a state's count out, or pass `null`, when the data doesn't say it, so the strip shows "—" and says "Unknown"                                                                                                | Pass `0` for a count the data doesn't know: `0` says no vehicle is in that state                                  |
| Name the strip with a heading beside it and `aria-labelledby`, such as one per operator under "Reporting live, by operator"                                                                                       | Pass `aria-hidden` to the strip: the eye reads its words and counts, so the ear gets them too                     |
| Show a total or a share beside the strip in a [Stat](../components/stat.md)                                                                                                                                       | Add a sixth item or a total inside the list through `slotProps`: the strip holds the five states and nothing else |
| Use [VehicleDotLegend](../components/vehicle-dot-legend.md) where the dots need explaining and nothing is counted                                                                                                 | Use the strip as a legend with made-up counts: a count is a claim about the vehicles                              |
| Put the strip in a [DataStatePanel](data-state-panel.md) while its counts load                                                                                                                                    | Show five unknown counts while the data loads: the panel says it is loading, the strip says the data doesn't know |
| Announce a change of state, such as a feed going silent, in the screen's own polite live region                                                                                                                   | Make the strip a live region: its counts change every few seconds and would flood a screen reader                 |
