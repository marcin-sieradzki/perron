# A component is built by three agent contexts in sequence, with two human gates

After the design step in Penpot, a component goes through three agent contexts, run one after another: brief, build, and an independent reviewer that never sees the builder's conversation. Current models hold analysis, API design and implementation in one context each, so more roles would only pass context along. Running them in sequence rather than as an agent team keeps one writer for the state: the orchestrator skill is the only one that writes `components/<name>/pipeline.yaml`. The maintainer holds two gates: approving the design in Penpot before any code, and signing off the visual result. Code checks everything between them (`npm run check`, story tests, the Penpot checks), and each stage has a fixed budget of attempts before it stops and asks.
