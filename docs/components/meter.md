# Meter

A bar that shows where one measured value sits within a known range, with the words that name it and the figure it reaches, such as "Reporting live" at "82%", for the share of a network's vehicles that report their position.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), [content design](../content-design.md), the tokens and the Base UI reference for `@base-ui/react` 1.9.0. Meter has nothing in `dependsOn`, and the extracted prototype is not reachable from this branch, so nothing here rests on it. The [Semantic colours](../foundations/semantic-colours.md#status) page gives the one meter Mylder already names, the live share, its thresholds, and [Motion](../foundations/motion.md) gives meters their fill change.

## Anatomy

Penpot page `Components/Meter`. Family: none, since it is a static display that sits on its container's surface and joins no family's treatment: it is not pressed, takes no hover and is not one of the Rows, Fields, Popups, Panels or Tooltips. Shared parts: none; the words for an unknown value reach the ear through `aria-valuetext`, not through VisuallyHidden (CR-5).

The drawing will have a `root` board holding three layers, `label`, `value` and `track`, with `indicator` inside `track`, and one variant property, `color`, whose values name its variants `Neutral`, `Success`, `Warning`, `Danger` and `Info` (`penpot/README.md`, "Conventions"). There is no `State` property: Meter is not interactive and has only its rest state.

| Part (Penpot layer) | What it is                                                                                                                                                                               | Base UI part      | Class                | `slotProps` key |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | -------------------- | --------------- |
| `root`              | A `div` with `role="meter"`, a two-column grid: the label and the figure on the first row, the track across both columns on the second                                                   | `Meter.Root`      | `pn-Meter`           | none            |
| `label`             | A `span` holding the caller's `label`, what the meter measures, such as "Reporting live"; the meter's accessible name                                                                    | `Meter.Label`     | `pn-Meter-label`     | `label`         |
| `value`             | A `span` at the inline end of the first row holding the figure Base UI formats, "82%", or "—" when the value is unknown (CR-5); `aria-hidden`, since the root's `aria-valuetext` says it | `Meter.Value`     | `pn-Meter-value`     | `value`         |
| `track`             | A `div` across the second row: the whole range, from `min` to `max`, in an inset pill                                                                                                    | `Meter.Track`     | `pn-Meter-track`     | `track`         |
| `indicator`         | A `div` inside `track`, from its inline start: the share of the range the value reaches, its width set by Base UI as a percentage, in the colour of the meter's `color`                  | `Meter.Indicator` | `pn-Meter-indicator` | `indicator`     |

Every part has its Base UI part, so each one's props come through its `slotProps` key and the root takes the component's own. Base UI's root also appends a `span` with `role="presentation"`, its own `visuallyHidden` style (`position: fixed`, `clip-path: inset(50%)`) and the text "x" after its children. It is no part of Perron's: it has no class, no layer and no `slotProps` key, and its fixed position takes it out of the grid (CR-9).

The label comes first in the DOM and on screen, then the figure, then the track: the eye reads the name before the number, as Stat does, and the screen reader hears the root's name and `aria-valuetext` whatever the order, since Base UI hides the figure from it and the meter role's children are presentational.

`MeterProps` extends `Meter.Root.Props` without `value` and `children`, and declares `label`, `value`, `color`, `locale`, `unknownLabel` and `slotProps`; `min`, `max`, `format`, `getAriaValueText`, `aria-valuetext` and `render` are inherited as they are, with Base UI's JSDoc and `@default`. Meter takes no `children`: its content is its four parts, and a caller's children would land after the track inside the `meter` role, where a screen reader never reads them.

`value` is the measured value of a display, not a control's: Meter has no `defaultValue` and no `onChange`, since nothing the person does changes it. It keeps Base UI's name, as MUI's `LinearProgress` does, rather than Stat's `children`, because it is a number Meter draws and formats, not text the caller writes.

`value` can be unknown: it is `number | null`, and `null` or a number that is not finite is unknown: Meter passes `min` to Base UI, so the fill is empty, shows "—" in place of the figure and sets `aria-valuetext` to the owned "Unknown" (CR-5). Base UI takes `NaN` as `min` and `Infinity` as `max` and would show "0%" or "100%", a figure no data gave, where the brand says no more than the data knows; Stat, Count and FactList show an unknown the same way.

Meter takes a `color` prop, with the intents the contract gives meters a mark for, and leaves the choice to the caller: `'neutral' | 'success' | 'warning' | 'danger' | 'info'`, default `'neutral'`, as Count offers, and no thresholds of its own: the live share's 70% and 40% are one measure's, which the screen that shows the live share maps to `success`, `warning` and `danger`, while another meter's good and bad lie elsewhere or nowhere. `brand` has no mark, so Meter doesn't offer it.

Meter formats the figure in the PerronProvider's locale when the caller gives no `locale`, through a `useLocale()` hook added beside `useOwnedStrings` in `packages/perron/src/PerronProvider.tsx` and left out of the barrel: Base UI's own default, the runtime locale, shows "82%" on a Danish screen in an English browser and can differ between the server's render and the browser's, while Perron's locales `en`, `da`, `sv` and `nb` are each a tag `Intl.NumberFormat` takes. A caller's `locale` still wins.

Meter has no `size` and no `variant`: one track height and one layout serve a report, a panel and the kiosk, and either can join later as an optional prop without a break. The figure is always shown; a caller that wants other words in it, such as "1 046 of 1 204", writes them through `slotProps.value.children` and says the same to the ear through `getAriaValueText`.

The root is `display: grid` with `grid-template-columns: minmax(0, 1fr) auto` and `align-items: baseline`, keywords and fractions all; the label sits in the first column, the figure in the second at the inline end, and the track spans both on the second row (`grid-column: 1 / -1`). The root takes its container's inline size, with no width, fill, border, radius, padding or shadow of its own: Meter is content on the surface of the report, panel or kiosk bar that holds it, like Stat. Every part resets the margins its element may bring.

The label takes Stat's and FactList's label look, `typography.label-sm` ("field and stat labels") in `color.text.secondary`, and the figure `typography.data`, the role for "percentages in lists and tables", a monospaced face with tabular figures, so meters stacked in a list line their figures up. `space.100` (4 px) sets the track close to the words above it, as Stat spaces its label and figure; `space.200` (8 px) keeps a long label from touching the figure.

The track is `color.surface.inset`, the surface [Elevation](../foundations/elevation.md#surfaces) gives tracks, which stands apart from `color.surface.raised` without a border. The fill takes the mark column of the contract's [Intents](README.md#intents): `color.text.primary` for `neutral`, `color.status.*` for the rest, each at least 3:1 on `color.surface.inset` in both themes ([Accessibility](../foundations/accessibility.md)), so the fill's end reads against the empty part of the track. Both ends are round (`radius.full`) and the track clips the fill (`overflow: hidden`), so a fill near 0% or 100% keeps the pill's shape. Base UI's inline `height: inherit` gives the indicator the track's `block-size`.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the eye gets the label, the figure and the fill's length; the ear the label as the name and the figure as `aria-valuetext`, which Base UI keeps the same text as the shown figure, or a fuller one from `getAriaValueText`. An unknown value is "—" and an empty track for the eye, "Unknown" for the ear (CR-5). A status `color` says good or bad by colour alone, so the caller says it in words too, in the label or beside the meter ([Do and don't](#do-and-dont)); in forced colours the tint goes and the figure and the words still carry it.
- [ ] Every landmark and named region has an accessible name: none here; the root is a `meter`, named by its label, not a landmark or region.
- [ ] Every default label can be overridden: `unknownLabel`.
- [ ] Every shape the type accepts renders, in every variant: `label` is a `ReactNode`, and a string, a number, an element and a list each render in every `color`; `value` renders `0`, `min`, `max`, a value outside the range (clamped), a fraction, `null`, `NaN` and `Infinity` (the last three unknown), which `Meter.test.tsx` renders each of. The `Danger` story gives a string label and a number.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the fill's transition moves one element, and nothing collapses. The figure is `aria-hidden` because `aria-valuetext` says it, not for animation.
- [ ] Native semantics first: no native element says "a value in a range" with Perron's look and Base UI's API (`<meter>` draws its own bar), so Base UI's `role="meter"` with its `aria-value*` attributes, and no ARIA of Perron's beyond the `aria-valuetext` of an unknown value.
- [ ] Focus moves in reading order and returns on close: Meter takes no focus and opens nothing.
- [ ] Every target is at least `size.target-min` square: no target; Meter is not pressed.
- [ ] Loops stop when the system asks for less motion: no loop; the fill's change is a transition over `duration.meter`, which the tokens shorten to 0.01 ms under reduced motion (CR-6).

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Meter composes Base UI's five parts in one order, `Meter.Root` holding `Meter.Label`, `Meter.Value` and `Meter.Track`, with `Meter.Indicator` in the track, and never rebuilds what Base UI does: the role, the `aria-value*` attributes, the clamping, the formatting and the label's `id` are Base UI's.
- **CR-2.** The root always carries `data-color` with the `color` value, `neutral` included, and the indicator's fill reads it as `.pn-Meter[data-color='success'] .pn-Meter-indicator`. The tints are the contract's mark column of [Intents](README.md#intents), as [Tokens](#tokens) gives them, and Meter maps no value to a colour itself.
- **CR-3.** Each inner part's props are its `slotProps` value merged with `mergeProps` from `@base-ui/react/merge-props`, the component's own props last, so its class and data attributes stay while the caller's `className` joins after it, through the `usePart` shared helper.
- **CR-4.** `label`, `value`, `color`, `locale`, `unknownLabel` and `slotProps` are taken out of the rest props before they reach the root, and `{...rest}` comes before Meter's own props, as the contract's [Root](README.md#root) says; the rest, `min`, `max`, `format`, `getAriaValueText` and `aria-valuetext` among them, reach `Meter.Root`.
- **CR-5.** The value is unknown when `value` is `null` or a number that is not finite. Meter then passes `min` to Base UI as the value, so the fill is empty; sets the bare attribute `data-unknown` on the root and on the value part; renders "—", the character U+2014, as the value part's children in place of the figure; and sets the root's `aria-valuetext` to the owned "Unknown", or `unknownLabel`, after the caller's rest props, so it wins over a caller's `aria-valuetext` and `getAriaValueText`, which describe a known value. The CSS reads the "—" colour as `.pn-Meter-value[data-unknown]`. `0` is a value, not unknown.
- **CR-6.** The fill's change eases: the indicator transitions `width` over `duration.meter` with `easing.standard`, as [Motion](../foundations/motion.md) gives meters, and under reduced motion the token is 0.01 ms, so the CSS needs no query of its own. The first render does not animate, since a transition only runs on a change.
- **CR-7.** The label wraps and breaks a word longer than its column (`overflow-wrap: anywhere` on `.pn-Meter-label`, a box that takes its column's width); the figure never wraps (`white-space: nowrap`); the root sizes to its container, so a long label never pushes the figure past the inline end.
- **CR-8.** Inside `@media (forced-colors: active)`, the track draws an `outline` of `border.width.025` in `CanvasText`, and the indicator sets `forced-color-adjust: none` and `background-color: CanvasText`: forced colours drop backgrounds, so without these the track and its fill would vanish and the meter would show only its words. An outline takes no space, so the geometry holds.
- **CR-9.** Base UI's `Meter.Root` appends the text "x" in a visually hidden `span role="presentation"`. It has a letter, so `expectOwnedStrings` would fail every Meter render on it, and Meter can't leave it out without replacing Base UI's root children, so `expectOwnedStrings`, in `packages/perron/src/testing/owned-strings.ts`, skips the text of an element that has `role="presentation"` and an inline style with `clip-path:inset(50%)`, Base UI's `visuallyHidden`, with a test of its own; the same `span` comes with Base UI's Progress, and nothing a Perron component writes looks like it. A test that reads Meter's words through the `heard` helper reads the label part, not the root, which holds the "x".
- **CR-10.** Meter is not a live region and never moves focus. A screen whose meters update announces changes of state in its own polite live region, as [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks.
- **CR-11.** The figure is formatted in `locale`, the caller's or the nearest PerronProvider's, so a Danish screen reads "82 %" and an English one "82%"; Meter passes it to `Meter.Root`'s `locale` and never formats the number itself.

## Stories

One per variant the deferred design will draw, named by the Penpot convention: the `color` value in PascalCase. `Unknown` is the neutral variant with no value, and proves CR-5. With no `Default` story, the [subject story](README.md#root) is the alphabetically first export, `Danger`. Each story's args are Meter's alone, so the subject story's args render it alone, and each status story's label is the measure whose value the foundations give that intent, so the label says in words what the tint marks: the live share for `success`, `warning` and `danger` ([Semantic colours](../foundations/semantic-colours.md#status)), and the share of trips running early for `info`, which the foundations give early running.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                     | Don't                                                                                                                                                   |
| -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Meter for a measure within a known range that changes on its own, such as the share of vehicles reporting live                     | Use it for the progress of a task, such as a load: a `meter` is a measurement, and a task's progress is a `progressbar`, which Perron does not have yet |
| Pick `color` from the value on the screen that knows what good is, such as the live share's 70% and 40%, and say it in words beside it | Let the tint alone say good or bad: colour tells no screen reader and no colour-blind person, and forced colours drop it                                |
| Pass `null` when no data gives the value, so Meter shows "—" and says "Unknown"                                                        | Pass `0` or a guess when the value is unknown: an empty fill at "0%" claims a figure the data never gave                                                |
| Name the meter in a few words in `label`: "Reporting live", "Trips run today"                                                          | Leave the name to the layout: a meter with no name tells the ear a number and nothing about it                                                          |
| Give `getAriaValueText` the fuller words when the figure shows them, such as "1 046 of 1 204" through `slotProps.value.children`       | Change the shown figure and leave the ear on the percentage: the eye and the ear then hear different numbers                                            |
| Use Stat for a key figure on its own, and Count for a tally beside words                                                               | Draw a meter for a number with no range: the fill's length means nothing without a `max`                                                                |
| Announce a change of state in the screen's own polite live region                                                                      | Make a Meter a live region: a share that updates every few seconds floods the screen reader                                                             |
