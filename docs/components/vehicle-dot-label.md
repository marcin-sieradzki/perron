# VehicleDotLabel

A vehicle's data state as its dot and its word side by side, such as a solid dot and "Live", for rows, tables and strips that say how fresh a vehicle's data is.

<!-- run notes -->

The design is deferred under ADR 0010 (`docs/adr/0010-unattended-runs-with-design-deferred.md`), so there is no read-back, code map or export: this spec decides the variant property, the layers, the design states and the token for every part. Its sources are the [contract](README.md), [Data states](../foundations/data-states.md), [Accessibility](../foundations/accessibility.md), [Typography](../foundations/typography.md#roles), [Icons](../foundations/icons.md#sizes), [Content design](../content-design.md#data-state-delay-and-disruption-words), `list_tokens`, the installed `@base-ui/react` types for `useRender` (the bundled Base UI docs have no page for the hook), and the merged specs of [VehicleDot](vehicle-dot.md), its one entry in `dependsOn`, and of [SeverityLabel](severity-label.md), the Transit category's other mark-and-word label. The ROADMAP names it in wave 2, Mylder's vocabulary, and VehicleDot's spec promises it: "a screen writes the state in words next to it, as VehicleDotLabel and VehicleDotLegend will" (VehicleDot's CR-5). The extracted prototype component is not in any branch this run can reach, so nothing here rests on it. VehicleDotLegend, its sibling, is on its branch with no spec yet, so there is nothing of its to align with.

## Anatomy

Penpot page `Components/VehicleDotLabel`. Family: none, a mark and its word in one inline run, as SeverityLabel is. Shared parts: none: the word is visible text, so the dot needs no VisuallyHidden copy.

The drawing is a `root` board holding, in reading order, the `dot`, an instance of [VehicleDot](vehicle-dot.md), and the `label` text layer. Its one variant property is `variant`, with VehicleDot's five values, `live`, `ageing`, `estimated`, `timetable-only` and `no-signal`, so its variants are `Live`, `Ageing`, `Estimated`, `TimetableOnly` and `NoSignal`. There is no `State` property: the label is not interactive.

| Part (Penpot layer) | What it is                                                                                                                                                                                       | Base UI part                                   | Class                                                    | `slotProps` key |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- | -------------------------------------------------------- | --------------- |
| `root`              | The whole label, one inline run: an inline-block `<span>`, the dot in its inline-start padding beside the word                                                                                   | none: a `<span>` rendered by `useRender`       | `pn-VehicleDotLabel`                                     | none            |
| `dot`               | A [VehicleDot](vehicle-dot.md) at `size='small'`, with the label's `variant` and `line`, hidden from screen readers by `aria-hidden`, since the word beside it says the same (VehicleDot's CR-6) | none: the VehicleDot component                 | `pn-VehicleDotLabel-dot`, beside its own `pn-VehicleDot` | none            |
| `label`             | The state's word, "Live", "Ageing", "Estimated", "Timetable only" or "No signal", the words the eye and the ear both get                                                                         | none: a plain `<span>`, no behaviour to borrow | `pn-VehicleDotLabel-label`                               | none            |

No part has a `slotProps` key: the contract keys `slotProps` by inner Base UI part, and VehicleDotLabel has none; the dot is a Perron component, as FilterChip's count is a [Count](count.md) with no key. A caller restyles the label through `className` on the root.

The dot composes VehicleDot rather than drawing a circle of its own, so every data state in a label has the one shape [Data states](../foundations/data-states.md) gives it, its forced-colours look included.

## Base UI parts

VehicleDotLabel imports no Base UI component: `baseUiParts` is empty in `packages/perron/components.json`, and a label has no behaviour to borrow. It uses two Base UI utilities, at the version pinned in `packages/perron/package.json`: `useRender` (`@base-ui/react/use-render`) for the root, so the contract's `render` prop works, and `mergeProps` (`@base-ui/react/merge-props`) to merge the caller's props with its own.

| Base UI part                     | Renders  | Perron sets                                                                                                                                                                        | Passed through                                                                          |
| -------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `useRender` (a hook, not a part) | `<span>` | `defaultTagName: 'span'`; `className`, `pn-VehicleDotLabel` then the caller's; `data-variant` and `data-line` from the props; the children, the `dot` and the `label` (CR-2, CR-3) | `render`, `ref`, `className`, `style`, `aria-hidden` and every other `<span>` attribute |

Base UI already does: swapping the root element for the one `render` gives, keeping the class, the data attributes and the children; merging the caller's `ref` with the element's under React 19; and joining `className` and `style` and chaining event handlers in `mergeProps`.

## Props

In MUI's layout. Every prop here gets this description as its JSDoc. VehicleDotLabel has no slots (see [Anatomy](#anatomy)).

`variant` and `line` are VehicleDot's, by name, type and default, since the label passes both to its dot: one data state and one line spelled the same across the Transit components. The five `*Label` props are VehicleDot's too, for the same five owned strings.

VehicleDotLabel takes no `children`: its word is always the state's owned string, overridden on one instance by its `*Label` prop, and a caller's further words, such as "since 08:02" after "No signal", go beside the label rather than in it. As SeverityLabel takes none: the five words stay [content design](../content-design.md#data-state-delay-and-disruption-words)'s on every screen, and a time beside the label is the caller's own text, such as a `typography.data` figure, where a `children` slot would let a screen rename a state.

VehicleDotLabel comes in one size, with no `size` prop: the dot at VehicleDot's `size='small'` (`icon.size.325`, the icon step "inline with label and caption text") and the word in `typography.label-sm`. SeverityLabel and Delay come in one size too: `typography.label-sm` is the role for "legend items, field and stat labels", the short names a label sits among in a row, table or strip, and a `size` can join later without a break, once a screen needs the label beside larger text.

`line` is optional, with no default, as on VehicleDot: the label passes it to its dot, and a dot in a wrong default colour would name the wrong line. A label for one vehicle always takes its line. A label that stands for a state across many lines, such as a count of live vehicles in ReportStrip, has no line to give, so it leaves `line` out: neither the root nor the dot sets `data-line`, and the dot draws in the word's own `color.text.primary`, the ink the brand keeps for the interface around the map. ReportStrip's spec decided this, and making `line` optional only widened the API.

## Tokens

One row per part, state and property. VehicleDotLabel has one design state, rest: it is not focusable, hoverable or pressable (CR-6). It is not one of the contract's families, so it draws no fill, border or radius. The dot's own tokens, its line colours, shapes and forced-colours rules, are VehicleDot's, by [its spec](vehicle-dot.md#tokens); the label sets only the dot's `size` and its place in the root's padding.

The word is set in `color.text.primary` for every state: it is the one place the state is told without relying on colour or shape (several line colours miss 3:1 on the light surfaces, and the dot is a 9 px mark), so it reads at full strength, 11.21:1 or more on every surface in both themes ([Accessibility](../foundations/accessibility.md#text-on-surfaces)); no signal's word is never greyed like its dot, since `color.text.tertiary` misses 4.5:1, and a line colour is never set on text.

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the dot's shape says the state, and the `label` says it in words for every `variant`; the dot is `aria-hidden` because the word beside it carries the same meaning. The line colour is not named: the caller names the line in words nearby, as [Semantic colours](../foundations/semantic-colours.md#line-colours) asks.
- [ ] Every landmark and named region has an accessible name: none here; the label is inline text, not a region.
- [ ] Every default label can be overridden: `liveLabel`, `ageingLabel`, `estimatedLabel`, `timetableOnlyLabel` and `noSignalLabel`.
- [ ] Every shape the type accepts renders, in every variant: every `variant` has its story, and a label with no `line` has `NoLine`; a `*Label` string replaces only its own state's word, and an undefined one keeps the locale's (CR-4); a long word wraps inside the label in the `Wrapping` story. - [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; nothing animates or collapses. The dot is `aria-hidden` because the word speaks for it, not for animation.
- [ ] Native semantics first: a `<span>` holding the dot and a `<span>` of text, no role, and no ARIA beyond the dot's `aria-hidden`.
- [ ] Focus moves in reading order and returns on close: the label takes no focus and opens nothing; Tab passes it by.
- [ ] Every target is at least `size.target-min` square: no target; a pressable vehicle is the caller's button or link around the label, which meets the minimum itself.
- [ ] Loops stop when the system asks for less motion: none here; the label has no motion.

## Component rules

- **CR-1.** Each `variant` has one shape and one word, never mixed: the dot is a VehicleDot with the same `variant`, and the `label` shows that state's owned string. The label never draws a dot, ring or slash of its own.
- **CR-2.** The `dot` is `<VehicleDot variant={variant} line={line} size="small" aria-hidden className="pn-VehicleDotLabel-dot" />`, given the shown state's `*Label` override as well, so the hidden dot's `aria-label` and the visible word are one string in the markup. It comes before the `label` in reading order, so it sits on the start side in right-to-left text.
- **CR-3.** The root always carries `data-variant`, its default included, and `data-line` when a line is given, as VehicleDot's root does, so a caller's CSS selects a label by its state or line as it selects a dot. With no `line`, the dot draws in the root's `color.text.primary` (VehicleDot's CR-7).
- **CR-4.** VehicleDotLabel reads its words with `useOwnedStrings({ live: liveLabel, ageing: ageingLabel, estimated: estimatedLabel, timetableOnly: timetableOnlyLabel, noSignal: noSignalLabel })` from `packages/perron/src/PerronProvider.tsx`, and shows only the one its `variant` names.
- **CR-5.** The word never wraps between the dot and itself: the root is an `inline-block` whose inline-start padding holds the dot, placed out of the word's flow and centred on one line of `typography.label-sm` (`1lh`), so a long override or translation wraps inside `label` and the dot stays beside its first line. A word longer than its line breaks inside it by `overflow-wrap: break-word`, the contract's choice for a box that sizes to its content beside others in a row: the label's narrowest is its longest word plus the padding, so a row that never wraps, or an auto-layout table cell beside longer text, keeps whole words. The root is never wider than its container (`max-inline-size: 100%`, as Tag's is), so in a container narrower than the longest word that word breaks inside it rather than running past.
- **CR-6.** The label is never interactive: no hover, focus, pressed or selected look, no tab stop, no `tabIndex`. A vehicle the rider can press is a Perron button or link with the label inside it.
- **CR-7.** The props type declares `variant`, `line` and the five `*Label` props, and leaves out `children`; each declared prop is taken out of the rest props before the merge, so none reaches the DOM. The root renders through `useRender` with `mergeProps(rest, own)`: the caller's rest props, then the component's own class, data attributes and children, so its own win, while a caller's `aria-hidden` still reaches the root, as VehicleDot does.
- **CR-8.** VehicleDotLabel draws the state it is given. It never works one out from a timestamp: the caller compares a report's age with `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold`, as VehicleDot's CR-3 says.
- **CR-9.** VehicleDotLabel is not a live region. A screen that announces a vehicle's change of state does it in its own polite live region, as [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                            | Don't                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Use VehicleDotLabel wherever a vehicle's data state is shown, so its dot and its word always come together    | Set a VehicleDot beside your own word for the state: the word could drift from content design's, and be heard twice      |
| Name the line in words nearby, such as in a LineBadge                                                         | Let the dot's colour be the only sign of the line: several line colours miss 3:1 on the light surfaces                   |
| Put a time beside the label, such as "since 08:02" after "No signal", in your own text                        | Override a `*Label` to add the time or to rename a state: the five words are the same on every screen, in every language |
| Work out the state from the report's age with `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold` | Pass `live` for a vehicle whose last report is minutes old: the label would claim more than the data knows               |
| Use VehicleDotLegend to explain all five states together                                                      | Stack VehicleDotLabels as a legend: a legend lists all five states in Data states' order, even one with no vehicles      |
| Wrap the label in a Perron button or link when the rider can open the vehicle                                 | Add `onClick` or `tabIndex` to the label: it has no focus ring, role for a control or target size                        |
| Use SeverityLabel for a kind of disruption on a line                                                          | Use VehicleDotLabel's no signal for a feed problem across a line: that is SeverityLabel's "Data feed problems"           |
