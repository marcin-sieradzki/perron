# VehicleDotLegend

The key to the vehicle dots: the five data states, each as its dot's shape beside its word, in the order [Data states](../foundations/data-states.md) lists them, for the bottom of the map and for any panel that explains the dots.

<!-- run notes -->

The design is deferred under ADR 0010 (`docs/adr/0010-unattended-runs-with-design-deferred.md`), so there is no read-back, code map or export: this spec decides the variant property, the layers, the design states and the token for every part. Its sources are the [contract](README.md), [Data states](../foundations/data-states.md) ("Legends list all five states, in this order, even when one has no vehicles"), [Typography](../foundations/typography.md) (`typography.label-sm` for "Legend items"), [Layout](../foundations/layout.md) (the legend at the bottom centre of the map, stacked at `z-index.map-controls`, gone under `breakpoint.tablet`), [Accessibility](../foundations/accessibility.md), [Content design](../content-design.md#data-state-delay-and-disruption-words), `list_tokens`, the installed `@base-ui/react` types for `useRender`, the spec of the one entry in its `dependsOn`, [VehicleDot](vehicle-dot.md), and the merged specs of its Transit and Display neighbours, [SeverityLabel](severity-label.md), [FactList](fact-list.md) and [Attribution](attribution.md). The ROADMAP names it in wave 2, Mylder's vocabulary. Its sibling VehicleDotLabel has no spec yet, on `main` or on a branch, and the extracted prototype is not reachable from this branch, so nothing here rests on either.

## Anatomy

Penpot page `Components/VehicleDotLegend`. Family: none: it is static content that sits on its container's surface, not a row of the Rows family, which is pressed and takes a hover, and it draws no surface of its own (CR-5). Shared parts: none: every word is shown, so nothing needs VisuallyHidden.

The drawing will have a `root` board holding five `item` boards, one per data state, each holding a `dot`, an instance of VehicleDot, and a `label` text layer, and no variant property, so its one variant is `Default`. There is no `State` property: the legend is not interactive and has only its rest state.

| Part (Penpot layer) | What it is                                                                                                                                                                                | Base UI part                                   | Class                       | `slotProps` key |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | --------------------------- | --------------- |
| `root`              | A `<ul>` laying the five items out in one row that wraps between items when its container is narrower                                                                                     | none: a `<ul>` rendered through `useRender`    | `pn-VehicleDotLegend`       | none            |
| `item`              | An `<li>` holding one data state's dot and word, in the order Live, Ageing, Estimated, Timetable only, No signal (CR-1)                                                                   | none: a plain `<li>`, no behaviour to borrow   | `pn-VehicleDotLegend-item`  | none            |
| `dot`               | A [VehicleDot](vehicle-dot.md) at `size='small'` with the item's `variant`, hidden from screen readers, since the word beside it names the state (CR-2), drawn in the legend's ink (CR-3) | none: Perron's VehicleDot, from its folder     | `pn-VehicleDotLegend-dot`   | none            |
| `label`             | A `<span>` holding the state's word, the owned string: "Live", "Ageing", "Estimated", "Timetable only" or "No signal"                                                                     | none: a plain `<span>`, no behaviour to borrow | `pn-VehicleDotLegend-label` | none            |

No inner part has a `slotProps` key: the contract keys `slotProps` by inner Base UI part, and the legend has none, as its Transit siblings VehicleDot and SeverityLabel have none. A caller restyles it through `className` on the root.

A `<ul>` of `<li>`s is HTML's own element for a set of like things, which the contract's "native semantics first" asks for: a screen reader says it is a list of five items and reads each word in turn. The dot comes first in each item, in the DOM and on screen, so the eye meets the shape and then its name; the ear, which hears no shape, hears the word alone.

The legend has one layout, a single row of five items that wraps between items in a narrow container, with no `variant`, `size`, `color` or `orientation` prop: the one place the foundations put a legend is the bottom centre of the map, a row; a row that wraps also serves a narrow panel; one look keeps every legend alike, as FactList and SeverityLabel ship one; and a stacked column can join later as an optional `variant` without a break.

The legend draws no surface and places nothing itself: the screen that holds the map puts it on a glass Surface at the bottom centre and stacks it. The registry's `dependsOn` names VehicleDot alone, not Surface; `z-index.map-controls` and the placement tokens are the pattern row's, not the component's, as Attribution's CR-6 says of its own place on the map; and a legend in a panel sits on that panel's surface, where a glass of its own would be a box inside a box.

## Base UI parts

No Base UI component: `baseUiParts` is empty in `packages/perron/components.json`, and a legend has no behaviour to borrow. The root renders through Base UI's `useRender` hook, from `@base-ui/react/use-render` at the version pinned in `packages/perron/package.json`, so the contract's `render` prop works, and the component's props are merged with `mergeProps` from `@base-ui/react/merge-props`, as VehicleDot's are.

| Base UI part                     | Renders | Perron sets                                                                                                                                                        | Passed through                                                                                          |
| -------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `useRender` (a hook, not a part) | `<ul>`  | `defaultTagName: 'ul'`; `className` `pn-VehicleDotLegend` then the caller's; the five `item` `<li>`s as the children, each with its `dot` and `label` (CR-1, CR-2) | `render`, `ref`, `className`, `style`, `aria-label`, `aria-labelledby` and every other `<ul>` attribute |

Base UI already does: swapping the root element for the one `render` gives, keeping the class and the children; merging the caller's `ref` with the element's under React 19; and merging `className`, `style` and event handlers in `mergeProps`.

| -------------------- | ----------------------- | ------------ | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `liveLabel`          | `string`                | The locale's | none         | Overrides "Live", the word shown beside the live dot                                                                                                                                      |
| `ageingLabel`        | `string`                | The locale's | none         | Overrides "Ageing", the word shown beside the ageing dot                                                                                                                                  |
| `estimatedLabel`     | `string`                | The locale's | none         | Overrides "Estimated", the word shown beside the estimated dot                                                                                                                            |
| `timetableOnlyLabel` | `string`                | The locale's | none         | Overrides "Timetable only", the word shown beside the timetable-only dot                                                                                                                  |
| `noSignalLabel`      | `string`                | The locale's | none         | Overrides "No signal", the word shown beside the no-signal dot                                                                                                                            |
| `className`          | `string`                |              | none         | Merged after `pn-VehicleDotLegend` on the root                                                                                                                                            |
| `style`              | `CSSProperties`         |              | none         | Reaches the root                                                                                                                                                                          |
| `ref`                | `Ref<HTMLUListElement>` |              | none         | Reaches the root                                                                                                                                                                          |

The five `*Label` props are VehicleDot's, the same names for the same five owned strings, so a caller who overrides a word on the dots overrides it on the legend the same way.

The legend takes no prop that picks the states or their order: [Data states](../foundations/data-states.md) asks every legend to list all five, in this order, even when one has no vehicles (CR-1).

The legend shows only each state's dot and word, with no count of vehicles, no description of what the state means and no title of its own: the registry's `dependsOn` names VehicleDot alone, not Count; a description per state would be five new owned strings in four languages and would crowd the one row at the bottom of the map, where the words alone are what [Typography](../foundations/typography.md) gives `typography.label-sm` for; a title would sit above a row whose dots already say what it is for the eye; and counts or descriptions can join later as optional props without a break.

| `label`               | rest  | `color`                       | none: inherits the root's                                                                                                                           |

The words and the dots are one ink, `color.text.primary`, with every dot but no signal's drawn in it in place of a line's colour: the legend passes VehicleDot a `line` of `'m1'`, which VehicleDot required when the legend was built, and its own `.pn-VehicleDotLegend-dot[data-line][data-variant]` rule sets `color: inherit` over the line colour, with `CanvasText` in forced colours. The legend explains shapes, not lines, and a dot in M1's green would say the legend is about M1; [the brand](../foundations/README.md) keeps colour for the map and the vehicles and the interface around them ink; `color.text.primary` reaches 11:1 or more on every surface, as [Accessibility](../foundations/accessibility.md#text-on-surfaces) gives it, which ageing's 1.3 px rim, estimated's 1.8 px ring and timetable only's 1.6 px dashed ring need more than the words do; one ink lets a caller recolour the whole legend through `className` on the root; and the rule's one class and two attributes outweigh VehicleDot's `.pn-VehicleDot[data-line='…']`, one class and one attribute, whatever order the stylesheets load in, while keeping the contract's "one class, then attributes".

The space is `space.100` between a dot and its word, `space.300` between items and `space.100` between wrapped rows: `space.100` is SeverityLabel's gap between its icon and its name, the same pairing of a 13 px mark and a `typography.label-sm` word; `space.300` sets each pair well apart from the next, so the eye reads five pairs, not one run of dots and words; and `space.100` keeps two wrapped rows close enough to read as one legend.

The no-signal dot keeps VehicleDot's grey, about 2.4:1 on the light surfaces: its cut tells its state by shape and its word sits beside it, as [VehicleDot](vehicle-dot.md#tokens) says of the dot anywhere.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: each dot's state is told to the ear by the word beside it, which the eye reads too; the dot's shape is what the legend teaches the eye, and the ear, which never meets the shapes, gets the five words in the same order.
- [ ] Every landmark and named region has an accessible name: none here; the legend is a list, not a landmark or region, and a caller where it stands alone names it with `aria-label` or `aria-labelledby` (CR-7).
- [ ] Every default label can be overridden: `liveLabel`, `ageingLabel`, `estimatedLabel`, `timetableOnlyLabel` and `noSignalLabel`.
- [ ] Every shape the type accepts renders, in every variant: the legend takes no `ReactNode`; every `*Label` string replaces only its own state's word, an undefined one keeps the locale's, and the `Default`, `Narrow` and `ForcedColours` stories render all five items.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; nothing animates or collapses. The dots are `aria-hidden` because their words speak for them, not for animation.
- [ ] Native semantics first: a `<ul>` of `<li>`s, each with a hidden VehicleDot and a `<span>` of text; no ARIA beyond the dots' `aria-hidden`.
- [ ] Focus moves in reading order and returns on close: the legend takes no focus and opens nothing; Tab passes it by.
- [ ] Every target is at least `size.target-min` square: no target; the legend is not pressed.
- [ ] Loops stop when the system asks for less motion: none here; the legend has no motion.

## Component rules

- **CR-1.** The legend always renders five items, in the order [Data states](../foundations/data-states.md) lists the states: live, ageing, estimated, timetable only, no signal, even when a screen has no vehicle in one of them. No prop picks, hides or reorders them, and nothing else renders inside the `<ul>`.
- **CR-2.** Each item holds a VehicleDot, then its word. The dot takes the item's `variant`, `size='small'`, `line='m1'` (its colour replaced, CR-3), `aria-hidden`, which VehicleDot passes to its root (VehicleDot's CR-6), and the class `pn-VehicleDotLegend-dot`, merged after `pn-VehicleDot`. The word is a `<span class="pn-VehicleDotLegend-label">` holding the state's owned string, read with the overrides laid over it: `useOwnedStrings({ live: liveLabel, … })`.
- **CR-3.** One ink: the root sets `color` to `color.text.primary`, the words inherit it, and `.pn-VehicleDotLegend-dot[data-line][data-variant]` sets the dot's `color` to `inherit`, outweighing VehicleDot's line rules, so every dot but no signal's draws in the legend's ink; no signal keeps VehicleDot's `color.data-state.no-signal` fill. Inside `@media (forced-colors: active)` the same selector sets `color: CanvasText`, after the rest rule, so the dots keep the system's text colour that VehicleDot's own forced-colours rule gives them.
- **CR-4.** The legend is never interactive: no hover, focus, pressed or selected look, no tab stop, no `tabIndex`.
- **CR-5.** The legend draws no surface and places nothing: no `background`, `border`, `radius`, `shadow`, `position`, `inset`, `z-index` or outer `margin`. The screen that holds the map puts it on a glass [Surface](surface.md) at the bottom centre, stacks it at `z-index.map-controls` and drops it under `breakpoint.tablet`, as [Layout](../foundations/layout.md) says; in a panel it sits on the panel's surface.
- **CR-6.** The props type declares the five `*Label` props, and each is taken out of the rest props before the merge, so none reaches the DOM; the root merges the rest props first and its own class and children after them, with `mergeProps`, as VehicleDot does, and the root's class is `pn-VehicleDotLegend`, then the caller's `className`.
- **CR-7.** The list has no name of its own, as StopTimeline's has none: its five words say what it holds. A caller where the legend stands alone, as at the bottom of the map, names it with `aria-label` or `aria-labelledby`, which reach the root with the rest props.
- **CR-8.** Each state's word stays whole on one line (`white-space: nowrap` on the root), and the row wraps between items (`flex-wrap: wrap`), so at 320 px wide, in every locale, the legend wraps onto more rows and never overflows its container: the longest word, Swedish "Endast tidtabell", with its dot, is far narrower than 320 px.
- **CR-9.** The `ForcedColours` story applies the stylesheets' `(forced-colors: active)` rules for `.pn-VehicleDot` and `.pn-VehicleDotLegend` as an adopted stylesheet while its `play` runs, since a play test cannot turn forced colours on, and takes the sheet off after, pass or fail. It reads the sheets with `forcedColourSheet('pn-VehicleDot', 'pn-VehicleDotLegend')`, and checks each dot's shape with `expectVehicleDotShape`, both in the contract's [Shared helpers](README.md#shared-helpers) table and in `packages/perron/src/testing/stories.ts`, which VehicleDot's stories import too.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                  | Don't                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Show the legend wherever vehicle dots appear without their words, such as at the bottom centre of the map           | Build a legend of your own from VehicleDots and words: it drifts from the five states' order and words                         |
| Keep all five states, even when no vehicle on screen is in one                                                      | Hide a state with `className` or CSS because no vehicle has it: [Data states](../foundations/data-states.md) asks for all five |
| Put the legend on a glass Surface over the map, or straight on a panel's surface                                    | Expect the legend to bring its own glass, place itself or stack itself over the map                                            |
| Name the list with `aria-label` or `aria-labelledby` where it stands alone, as on the map                           | Pass `aria-hidden` to the legend: the eye reads its words, so the ear gets them too                                            |
| Keep `render` on the root to another list element, `<ol>` or a component that renders one                           | Swap the root for a `<div>` through `render`: its `<li>`s would sit outside a list, which HTML and axe both fail               |
| Override a word with its `*Label` prop when a screen's copy needs it, and the same prop on the screen's VehicleDots | Change one word on the legend and leave the dots' names, so the eye and the ear are told two names for one state               |
