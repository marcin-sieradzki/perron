# MapControls

The map's zoom in, zoom out and centre buttons, and a pause button for the map's motion when the screen handles one, in one glass bar that is one tab stop, named and labelled in the reader's language.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the contract, the foundations, the tokens, the Base UI reference and the spec of [Toolbar](toolbar.md), the one entry it depends on, and of [IconButton](icon-button.md), which it does not use (see Anatomy). The extracted prototype component is not in any branch this run can reach.

## Anatomy

Penpot page `Components/MapControls`. Family: none (the contract's [Families](README.md#families) have no bar of actions; the bar is Toolbar's, on the Popups' glass). Shared parts: none (each button is an icon-only `ToolbarButton`, named by its `aria-label` from an owned string, as Toolbar's icon-only buttons are).

MapControls renders Perron's `Toolbar`, vertical by default, holding three icon-only `ToolbarButton`s in the order zoom in, zoom out, a `ToolbarSeparator`, centre the map, with no `ToolbarGroup` and no IconButton, so its `dependsOn` in `packages/perron/components.json` names `Toolbar` alone. The Toolbar spec's Do and don't says an IconButton inside a Toolbar "falls out of the arrow-key order and adds a tab stop", and the IconButton spec says a `neutral` icon button floated over the map "disappears on the land and water", so the controls are Toolbar's buttons on Toolbar's glass; this is the column Toolbar's `Vertical` story draws ("zoom in, zoom out, a separator, locate"); and a group would only need a name of its own for two buttons the separator already sets apart.

Given `onPausedChange`, the bar adds a fourth icon-only `ToolbarButton` after the centre button, past a second `ToolbarSeparator`: zoom in, zoom out, a separator, centre the map, a separator, pause. The pause button stops and starts the vehicles moving, where the other three move the view, so a hairline sets it apart as the first one sets the zoom pair apart from the centre button; it comes last because it acts on what the map shows, not where it looks, and an existing bar's three buttons keep their places. Without `onPausedChange` there is no second separator and no fourth button, and the bar renders as it did before the pause button joined it. Mylder's map put the pause in a Toolbar of its own beside the controls, two bars and two tab stops for one set of map tools; in MapControls it is one bar and one tab stop.

## Props

In MUI's layout. Every prop MapControls declares gets this description as its JSDoc; the inherited rows keep Base UI's. Slots come last.

MapControls takes `orientation`, `'horizontal' | 'vertical'`, default `'vertical'`, passed to `Toolbar`, and redeclares it in `MapControlsProps` so its JSDoc gives that default. [Layout](../foundations/layout.md#page-shell) puts the controls at the bottom right, beside the scale, where the Toolbar spec gives `orientation` "for the map's vertical column of controls"; a screen that lays them along an edge, such as a phone's above the bottom sheet, sets `'horizontal'`.

MapControls takes one handler per button, `onZoomIn(event)`, `onZoomOut(event)` and `onCenterMap(event)`, each given to that `ToolbarButton`'s `onClick`, always renders those three buttons, adds the pause button only with `onPausedChange`, and takes no `children`. The map, not the controls, holds the zoom level, so the screen does the zooming in a handler; three buttons always in one order keep every screen's controls alike, a button with no handler does nothing rather than vanish; the pause button is a choice a screen makes, not a control every map has, so it shows only when the screen handles it and an existing bar stays as it was. The pause belongs inside the bar, where another map action doesn't, because it is the map's own control of its motion, as zoom and centre are its own control of the view: every live map has the motion it stops, so it is part of the controls rather than a screen's addition. Another map action, such as a layers switch, depends on what a screen shows, so it goes in a Toolbar of its own, and the bar stays closed to `children`. Code names take the American spelling, as `color` does, and the English words the British, "Centre the map", as [Content design](../content-design.md) writes.

MapControls takes `paused`, a boolean default `false`, and `onPausedChange(event, paused)`, which adds the pause button and is called on each press with the state the press asks for: `true` while the map moves, `false` while it is paused. The screen, not the controls, holds whether the map moves, as it holds the zoom, so `paused` is controlled and has no `defaultPaused`; the button follows `paused`, and a press that the screen doesn't answer with a new `paused` changes nothing on the button. The pair follows VehicleTable's `sort` and `onSortChange(event, sort)`, Perron's other controlled value of a pattern or component beside its main one, which also adds its buttons only when the handler is given. The contract's two-event shape for a boolean, `onOpen` and `onClose`, would here be `onPause` and `onResume`, and `onPause` is React's media event, which `MapControlsProps` already inherits from the root `<div>`'s props: retyping it would narrow an inherited prop, which [Change](README.md#change) counts as a break, and leave one name meaning two events. A `pauseDisabled` is left out: `disabled` dims the pause button with the rest, while the map loads, and a screen that keeps the pause pressable then sets `zoomInDisabled`, `zoomOutDisabled` and `centerMapDisabled` instead; a map that can always pause needs no limit of its own; one can join later as a new optional prop.

MapControls takes `zoomInDisabled` and `zoomOutDisabled`, booleans default `false`, that disable the one button at the map's zoom limits, leaving it focusable (`ToolbarButton`'s default `focusableWhenDisabled`). At the closest or farthest zoom a button that still looks pressable misleads; kept focusable, the button keeps the focus a keyboard user pressed it with, stays in the arrow-key order, and is announced as dimmed through `aria-disabled`.

MapControls takes `centerMapDisabled`, a boolean default `false`, that disables the centre button alone in the same way. A screen whose map can't yet be moved, before it has loaded, sets it with `zoomInDisabled` and `zoomOutDisabled` rather than `disabled`, so the pause button stays pressable while the rest of the bar is dimmed.

MapControls takes no `slotProps`, and puts a `pn-MapControls-<part>` class on each button and each separator for a caller's CSS. The contract keys `slotProps` by Base UI part; the buttons, three or four, share one, `Toolbar.Button`, and the two separators another, `Toolbar.Separator`; every per-button need the sources name (handler, limit, words) is a prop above; and a `slotProps` key can join later as a new optional prop, which [Change](README.md#change) allows.

## Keyboard and ARIA

From the Base UI reference for `Toolbar.Root`, `Toolbar.Button` and `Toolbar.Separator`, as the [Toolbar](toolbar.md) spec gives them. "From" says who does it.

| Key                       | Does                                                                                                                                                                                                            | From        |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `Tab`, `Shift+Tab`        | Moves focus into the bar, to the button that last had it (zoom in at first), and out again: the bar is one tab stop                                                                                             | Base UI     |
| `ArrowDown`, `ArrowUp`    | In the vertical bar, the default, move focus to the next and the previous button, skipping the separators, wrapping while `loopFocus` is on: zoom in, zoom out, centre, then pause when it is there             | Base UI     |
| `ArrowRight`, `ArrowLeft` | In a horizontal bar, move focus to the next and the previous button, wrapping while `loopFocus` is on                                                                                                           | Base UI     |
| `Enter`, `Space`          | Press the focused button: call its `onZoomIn`, `onZoomOut` or `onCenterMap`, or `onPausedChange` with the state it asks for, unless it is disabled; focus stays on the pause button as its icon and name change | The browser |

`Home` and `End` do nothing, as on Toolbar. `+` and `−` zoom the map from the map canvas ([Accessibility](../foundations/accessibility.md#rules)), not from these controls.

MapControls listens to no keys of its own and sets no `aria-keyshortcuts`, leaving `+` and `−` to the map. Accessibility gives those keys to the screen ("+ and − zoom, arrow keys pan"), the map canvas has focus when they are pressed, and the controls can't know that the screen binds them, so announcing a shortcut could promise one that does nothing.

The pause button swaps its name, "Pause" or "Resume", and sets no `aria-pressed`. The [APG's button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) gives a two-state button one of two forms: a toggle whose label stays the same while `aria-pressed` says its state, such as "Mute", pressed or not; or a button whose label changes with the state, such as Play and Pause, which then has no `aria-pressed`, since "Pause, pressed" says the opposite of what it means. The icon swaps between `pause` and `play`, each naming the action a press takes, and the contract asks that everything the eye is told the ear is told, so the name swaps with the icon: a fixed "Pause" with `aria-pressed` would be heard as "Pause, pressed" while the eye sees play. The name says what the press does, as zoom in and zoom out do, and it is the name Mylder's map already gives the button. A screen reader may not announce the new name on the press itself; the vehicles stopping or moving is the press's feedback, and the name is read the next time focus reaches the button.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: each icon is `aria-hidden` inside its button, and the button's `aria-label` says the action it shows ("Zoom in", "Zoom out", "Centre the map", and "Pause" or "Resume" as the `pause` or `play` icon shows); a dimmed button is announced through `aria-disabled`; the separator is announced as one.
- [ ] Every landmark and named region has an accessible name: the bar is a `toolbar` named "Map controls" by its owned string, so it tells itself apart from the top bar's toolbars.
- [ ] Every default label can be overridden: `mapControlsLabel`, `zoomInLabel`, `zoomOutLabel`, `centerMapLabel`, `pauseLabel` and `resumeLabel`.
- [ ] Every shape the type accepts renders, in every variant: the props take no `ReactNode`; both orientations, every `…Disabled` combination and `disabled` render all three buttons, square, in the same order, and the pause button after them in either state of `paused` when `onPausedChange` is given.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the controls keep no hidden copy and collapse nothing.
- [ ] Native semantics first: native `<button>`s from `Toolbar.Button`, Base UI's `toolbar` and `separator` roles, with ARIA only for the names an icon can't give.
- [ ] Focus moves in reading order and returns on close: the arrow keys move zoom in, zoom out, centre, then pause, in document order; the controls open nothing; a button that hits a zoom limit stays focusable, and the pause button stays the same element as its icon and name swap, so focus never jumps away from the key a person pressed.
- [ ] Every target is at least `size.target-min` square: each button is `size.control` (34 px) square.
- [ ] Loops stop when the system asks for less motion: none here; the controls have no loop and no transition.

## Owned strings

Every word MapControls announces is its own; it shows none. No key in `packages/perron/src/locale/en.ts` says any of these, so all six are new, each with a JSDoc line like its neighbours, and agents write the Danish, Swedish and Norwegian.

The four new keys are `mapControls` "Map controls", `zoomIn` "Zoom in", `zoomOut` "Zoom out" and `centerMap` "Centre the map", overridden by `mapControlsLabel`, `zoomInLabel`, `zoomOutLabel` and `centerMapLabel`. They are the words the Toolbar spec's map stories and the IconButton spec's examples already use, `packages/perron/icons/icons.json` gives `locate` the use "Centre the map on the network", each names the action as a verb and what it acts on, in sentence case ([Content design](../content-design.md)), and the keys take the American spelling of code names.

The pause button's two keys joined later: `pause` "Pause" and `resume` "Resume", overridden by `pauseLabel` and `resumeLabel`. They are the names Mylder's map gives the button in English, and in Danish, "Pause" and "Fortsæt", from its dictionary; the Swedish, "Pausa" and "Fortsätt", and the Norwegian, "Pause" and "Fortsett", were written for Perron, since Mylder has no Swedish or Norwegian. Each is the verb of the press, and `packages/perron/icons/icons.json` gives `pause` and `play` the uses "Stop the vehicles moving on the map" and "Set the vehicles moving again". "Resume" rather than "Play": the map isn't media, and the press resumes the motion the reader paused.

| `zoomOut`     | "Zoom out"       | `zoomOutLabel`     | `zoomOut`, heard as the button's name through `aria-label`                         |

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Perron's Toolbar already gives the one tab stop, the roving `tabIndex`, the arrow keys, the wrap, the disabled cascade and a disabled button that stays focusable, through Base UI, so MapControls rebuilds none of it, adds no key handler and sets no `aria-keyshortcuts`.
- **CR-2.** MapControls renders Perron's `Toolbar`, and in it, in this order, a `ToolbarButton` for zoom in, one for zoom out, a `ToolbarSeparator`, and one for centring the map, then, only when `onPausedChange` is given, a second `ToolbarSeparator` and a `ToolbarButton` for pausing, each button `color="neutral"` and icon-only (a `startIcon` and no `children`). It imports `Toolbar`, `ToolbarButton` and `ToolbarSeparator` from `packages/perron/src/components/Toolbar/Toolbar.tsx`, never `@base-ui/react/toolbar` or IconButton.
- **CR-3.** The root's `className` is `pn-MapControls` then the caller's, given to `Toolbar`, which puts `pn-Toolbar` first. Each button takes `pn-MapControls-zoomIn`, `pn-MapControls-zoomOut`, `pn-MapControls-centerMap` or `pn-MapControls-pause`, and the separators `pn-MapControls-separator` and `pn-MapControls-pauseSeparator`, after the class of its own component.
- **CR-4.** `{...rest}` reaches `Toolbar` before MapControls' own attributes, and its own props are taken out of `rest` first (`orientation`, `zoomInDisabled`, `zoomOutDisabled`, `centerMapDisabled`, `onZoomIn`, `onZoomOut`, `onCenterMap`, `paused`, `onPausedChange` and the six `…Label` props), so none reaches the DOM. `disabled`, `loopFocus`, `render`, `style`, `aria-labelledby` and `ref` pass through to `Toolbar`, and `ref` lands on the `role="toolbar"` element. The root's `aria-label` is set after `rest` from the `mapControls` string, so a caller renames the bar with `mapControlsLabel`.
- **CR-5.** `orientation` defaults to `'vertical'` in MapControls' own destructuring and is passed to `Toolbar`; `MapControlsProps` redeclares it with `@default 'vertical'`. The root carries Base UI's `data-orientation`; MapControls has no `variant`, `color` or `size` prop, so it sets no `data-variant`, `data-color` or `data-size`.
- **CR-6.** The words come from `useOwnedStrings({ mapControls: mapControlsLabel, zoomIn: zoomInLabel, zoomOut: zoomOutLabel, centerMap: centerMapLabel, pause: pauseLabel, resume: resumeLabel })`. Each button's `aria-label` is its string; the component shows no text and sets no `title`.
- **CR-7.** Each icon is an inline `<svg>` with the `perron-icon` class, `viewBox="0 0 16 16"`, `fill="none"`, `stroke="currentColor"`, round caps and joins, and the stroke width and path data of its file in `packages/perron/icons/` (`plus.svg`, `minus.svg` and `pause.svg` at 1.8, `locate.svg` and `play.svg` at 1.6), with no `width`, `height` or colour of its own: `ToolbarButton`'s icon span sets `--perron-icon-size` to `icon.size.400` and hides it from screen readers.
- **CR-8.** `zoomInDisabled`, `zoomOutDisabled` and `centerMapDisabled`, or `disabled`, set `disabled` on that `ToolbarButton`, which stays focusable (`focusableWhenDisabled` left at its `true` default), carries `aria-disabled` and `data-disabled`, and stops the click, so its handler never fires. None of the three disables another button or the pause button; `disabled` disables the pause button with the rest.
- **CR-9.** `MapControls.css`, imported by the TSX as the contract asks, sets no colour, size, spacing or state: every look is Toolbar's, so the controls match every other toolbar, and a change to Toolbar's look reaches them.
- **CR-10.** MapControls sizes to its content, as Toolbar does, and places nothing: no `position`, `inset`, `margin` or `z-index`. The screen puts it at the bottom right, `size.panel-gap` from the edges, at `z-index.map-controls` ([Layout](../foundations/layout.md#stacking)), a token outside a component's [Token families](README.md#token-families).
- **CR-11.** Each handler is given as its button's `onClick` and called once per press, by click, Enter or Space, with the click event; no handler is called on focus, hover or an arrow key.
- **CR-12.** Changes of state are immediate, as on Toolbar: MapControls adds no transition, and the pause button swaps its icon and name in the render that takes the new `paused`.
- **CR-13.** The pause button follows `paused` alone: the `pause` icon and the `pause` string while it is `false`, the `play` icon and the `resume` string while it is `true`, with no `aria-pressed`, `data-pressed` or look of its own for either state. Its `onClick` calls `onPausedChange(event, !paused)`; MapControls keeps no state of its own, so a press the screen doesn't answer leaves the button as it was.

## Stories

MapControls' deferred drawing has one variant property, `orientation` (`vertical`, `horizontal`), and no `State`, leaving the buttons' hover, focus, pressed and disabled looks to ToolbarButton's variants on the Toolbar page, with the zoom limits, `disabled`, the pause button moving and paused, and the label overrides as stories beside the two variants. The buttons are ToolbarButtons, already drawn and storied in every state, so redrawing them here would only be a second copy to keep alike; the limits and the overrides are behaviour, which the `play` tests check.

The stories render the bar on its own, in a `PerronProvider` in English unless the story says otherwise, with `fn()` handlers for `onZoomIn`, `onZoomOut` and `onCenterMap`, and for `onPausedChange` in the stories that show the pause button. The contract story's subject is `Default`, which renders the three buttons with no words of the caller's. The pause button's words are checked by `CustomLabels`' own `expectOwnedStrings` calls, in Danish with the overrides, moving and paused, and in Danish with none.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                        | Don't                                                                                                                                                                        |
| --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use MapControls for the map's zoom and centre buttons, once per map                                       | Build the same bar from IconButtons or from your own Toolbar: an IconButton in a toolbar adds a tab stop, and a second copy drifts from this one                             |
| Place it from the screen, at the bottom right, `size.panel-gap` from the edges, at `z-index.map-controls` | Expect MapControls to position itself, or give it a `z-index` through the component: it sizes to its content and the screen places it                                        |
| Set `zoomInDisabled` or `zoomOutDisabled` when the map reaches a zoom limit                               | Hide or unmount a button at a limit: focus on it is lost and the bar changes shape under the pointer                                                                         |
| Centre the map on the whole network in `onCenterMap`, as its words promise                                | Wire it to the reader's own location: its words, "Centre the map", and the `locate` icon's use promise the network                                                           |
| Rename the bar or a button with its `…Label` prop, such as `zoomInLabel`                                  | Pass `aria-label` to the root: the bar's own name is set after it and replaces it                                                                                            |
| Bind `+` and `−` on the map canvas, where Accessibility puts them                                         | Expect MapControls to listen for keys: it adds none beyond the toolbar's arrows                                                                                              |
| Give `onPausedChange` and `paused` to add the pause button, and set `paused` from the handler             | Put the pause in a Toolbar of its own beside MapControls: it is the map's own control, and a bar of its own adds a second bar and a second tab stop                          |
| Put another map action, such as a layers switch, in a Toolbar of its own beside it                        | Wrap MapControls to add buttons inside it: it takes no `children`, so its buttons stay the same on every screen; only the pause, the map's own motion control, joins the bar |
