# MapControls

The map's zoom in, zoom out and centre buttons, and, when the screen handles them, a 3D toggle, a compass that turns the map back to north and a pause button for the map's motion, in one glass bar that is one tab stop, named and labelled in the reader's language.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the contract, the foundations, the tokens, the Base UI reference and the spec of [Toolbar](toolbar.md), the one entry it depends on, and of [IconButton](icon-button.md), which it does not use (see Anatomy). The extracted prototype component is not in any branch this run can reach.

The 3D toggle and the compass joined in a later unattended run, with the design still deferred, for GitHub issue perron#186 ("MapControls: a 3D toggle and a compass"), which gives the two buttons, their icons, the compass's English and the acceptance; the `cube` and `compass` icons and their uses come from `packages/perron/icons/` and [Icons](../foundations/icons.md), merged in perron#188. MapControls is `stable`, so the run adds only optional props and keeps every earlier decision: a bar given none of the new props renders as it did before. Mylder's 3D view, which the issue cites (Mylder's ADR 0016), is not in any branch this run can reach.

## Anatomy

Penpot page `Components/MapControls`. Family: none (the contract's [Families](README.md#families) have no bar of actions; the bar is Toolbar's, on the Popups' glass). Shared parts: none (each button is an icon-only `ToolbarButton`, named by its `aria-label` from an owned string, as Toolbar's icon-only buttons are).

MapControls renders Perron's `Toolbar`, vertical by default, holding three icon-only `ToolbarButton`s in the order zoom in, zoom out, a `ToolbarSeparator`, centre the map, with no `ToolbarGroup` and no IconButton, so its `dependsOn` in `packages/perron/components.json` names `Toolbar` alone. The Toolbar spec's Do and don't says an IconButton inside a Toolbar "falls out of the arrow-key order and adds a tab stop", and the IconButton spec says a `neutral` icon button floated over the map "disappears on the land and water", so the controls are Toolbar's buttons on Toolbar's glass; this is the column Toolbar's `Vertical` story draws ("zoom in, zoom out, a separator, locate"); and a group would only need a name of its own for two buttons the separator already sets apart.

Given `onPausedChange`, the bar adds a fourth icon-only `ToolbarButton` after the centre button, past a second `ToolbarSeparator`: zoom in, zoom out, a separator, centre the map, a separator, pause. The pause button stops and starts the vehicles moving, where the other three move the view, so a hairline sets it apart as the first one sets the zoom pair apart from the centre button; it comes last because it acts on what the map shows, not where it looks, and an existing bar's three buttons keep their places. Without `onPausedChange` there is no second separator and no fourth button, and the bar renders as it did before the pause button joined it. Mylder's map put the pause in a Toolbar of its own beside the controls, two bars and two tab stops for one set of map tools; in MapControls it is one bar and one tab stop.

Given `onTiltedChange`, `onResetNorth` or both, the 3D toggle and the compass sit after the centre button and before the pause button, past a third `ToolbarSeparator`, `angleSeparator`, the 3D toggle first and then the compass: zoom in, zoom out, a separator, centre the map, a separator, 3D, compass, a separator, pause. The two set the map's angle, its tilt and its heading, where zoom and centre set where it looks and pause what it shows, so a hairline sets the pair apart as the other two set theirs; they act on the view, so they come before the pause, which acts on the vehicles; the toggle comes first because it changes the view most, and the compass, which undoes a turn, sits beside it; a bar given only one of the two still draws `angleSeparator` before it; and the zoom pair, the centre button and the pause keep their places, so an existing bar's buttons don't move.

The 3D toggle and the compass belong inside the bar, as the pause does, because they are the map's own control of its camera, as zoom and centre are: every map that can tilt and turn needs a way back to flat and to north. Without `onTiltedChange` there is no 3D toggle, without `onResetNorth` no compass, and without both no `angleSeparator`: the bar renders as it did before the two joined it.

The compass stays in the bar while the map faces north, `heading` 0, rather than hiding until the map is turned. A button that comes and goes as the map turns moves the pause button and changes the bar's length under the pointer, and the Do and don't already keeps buttons in place at the zoom limits for the same reason; north-up is the map's usual state, so a compass that hid would be missing when a rider first looks for it; a press at north does no harm, since the screen turns the map to where it already is.

The 3D toggle is a `ToolbarButton` given `aria-pressed`, not Base UI's `Toggle` from `@base-ui/react/toggle`: the installed `Toggle` (1.9.0) sets the native `disabled`, with no `focusableWhenDisabled`, so a disabled toggle would leave the bar's arrow-key order where every other button stays in it; its `onPressedChange(pressed, details)` would be one more shape to adapt; and it keeps uncontrolled state the screen's `tilted` makes needless.

Base UI already does: one tab stop for the whole bar with a roving `tabIndex`, so Tab enters at the button last focused (zoom in at first) and leaves in one step; the arrow keys of the bar's orientation move between the buttons, skipping the separator, and wrap at the ends while `loopFocus` is on; a disabled `Toolbar.Root` disables every button; a disabled `Toolbar.Button` stays focusable by default (`focusableWhenDisabled` is `true`), with `aria-disabled` in place of `disabled` and its clicks stopped, so it stays in the arrow-key order; `Toolbar.Separator` takes the orientation across the bar's.

## Props

In MUI's layout. Every prop MapControls declares gets this description as its JSDoc; the inherited rows keep Base UI's. Slots come last.

MapControls takes `orientation`, `'horizontal' | 'vertical'`, default `'vertical'`, passed to `Toolbar`, and redeclares it in `MapControlsProps` so its JSDoc gives that default. [Layout](../foundations/layout.md#page-shell) puts the controls at the bottom right, beside the scale, where the Toolbar spec gives `orientation` "for the map's vertical column of controls"; a screen that lays them along an edge, such as a phone's above the bottom sheet, sets `'horizontal'`.

MapControls takes one handler per button, `onZoomIn(event)`, `onZoomOut(event)` and `onCenterMap(event)`, each given to that `ToolbarButton`'s `onClick`, always renders those three buttons, adds the pause button only with `onPausedChange`, and takes no `children`. The map, not the controls, holds the zoom level, so the screen does the zooming in a handler; three buttons always in one order keep every screen's controls alike, a button with no handler does nothing rather than vanish; the pause button is a choice a screen makes, not a control every map has, so it shows only when the screen handles it and an existing bar stays as it was. The pause belongs inside the bar, where another map action doesn't, because it is the map's own control of its motion, as zoom and centre are its own control of the view: every live map has the motion it stops, so it is part of the controls rather than a screen's addition. Another map action, such as a layers switch, depends on what a screen shows, so it goes in a Toolbar of its own, and the bar stays closed to `children`. Code names take the American spelling, as `color` does, and the English words the British, "Centre the map", as [Content design](../content-design.md) writes.

MapControls takes `paused`, a boolean default `false`, and `onPausedChange(event, paused)`, which adds the pause button and is called on each press with the state the press asks for: `true` while the map moves, `false` while it is paused. The screen, not the controls, holds whether the map moves, as it holds the zoom, so `paused` is controlled and has no `defaultPaused`; the button follows `paused`, and a press that the screen doesn't answer with a new `paused` changes nothing on the button. The pair follows VehicleTable's `sort` and `onSortChange(event, sort)`, Perron's other controlled value of a pattern or component beside its main one, which also adds its buttons only when the handler is given. The contract's two-event shape for a boolean, `onOpen` and `onClose`, would here be `onPause` and `onResume`, and `onPause` is React's media event, which `MapControlsProps` already inherits from the root `<div>`'s props: retyping it would narrow an inherited prop, which [Change](README.md#change) counts as a break, and leave one name meaning two events. A `pauseDisabled` is left out: `disabled` dims the pause button with the rest, while the map loads, and a screen that keeps the pause pressable then sets `zoomInDisabled`, `zoomOutDisabled` and `centerMapDisabled` instead; a map that can always pause needs no limit of its own; one can join later as a new optional prop.

MapControls takes `tilted`, a boolean default `false`, and `onTiltedChange(event, tilted)`, which adds the 3D toggle and is called on each press with the state the press asks for, `true` while the map is flat and `false` while it is tilted. The screen, not the controls, holds whether the map is tilted, as it holds `paused`, and the rider tilts it with gestures too, so `tilted` is controlled, with no `defaultTilted`, and the toggle's `aria-pressed` follows `tilted` however the map came to be tilted; a press the screen doesn't answer with a new `tilted` changes nothing on the toggle. The pair follows the pause button's `paused` and `onPausedChange(event, paused)` and VehicleTable's `sort` and `onSortChange(event, sort)`, Perron's other controlled values beside a component's main one, each adding its buttons only when the handler is given. `tilted` is the adjective of the state the screen holds, as `paused` is, an adjective as the contract's booleans are, rather than `threeD` or `pitched`, which name a mode or a camera number the rider doesn't see. The contract's `selected` and `onChange(event, value, details)`, which FilterChip takes, would claim the component's one `onChange` for one button of six and leave no `details` to pass, since no Base UI part changes the state.

MapControls takes `heading`, a number in degrees default `0`, the map's bearing clockwise from north, and `onResetNorth(event)`, which adds the compass and is called on each press with the click event. The screen holds the map's heading, as it holds the zoom, so the compass follows `heading` alone and keeps no state; its needle turns by minus `heading` so it points to north on the map; any number turns it, beyond 360 and below 0 alike, and one that isn't finite, such as `NaN`, draws the needle pointing up, as at north, rather than an angle no one gave. `heading` is the issue's word and the one bearing-from-north means on a map; `onResetNorth` names the press as `onZoomIn` and `onCenterMap` name theirs, an action with no value to pass, and the screen turns the map back to north in it. The compass fires `onResetNorth` at north too, where the screen's turn does nothing.

MapControls takes `zoomInDisabled` and `zoomOutDisabled`, booleans default `false`, that disable the one button at the map's zoom limits, leaving it focusable (`ToolbarButton`'s default `focusableWhenDisabled`). At the closest or farthest zoom a button that still looks pressable misleads; kept focusable, the button keeps the focus a keyboard user pressed it with, stays in the arrow-key order, and is announced as dimmed through `aria-disabled`.

MapControls takes `centerMapDisabled`, a boolean default `false`, that disables the centre button alone in the same way. A screen whose map can't yet be moved, before it has loaded, sets it with `zoomInDisabled` and `zoomOutDisabled` rather than `disabled`, so the pause button stays pressable while the rest of the bar is dimmed.

MapControls leaves out a `tiltDisabled` and a `compassDisabled`, as it leaves out `pauseDisabled`, so `disabled` dims the 3D toggle and the compass with the rest of the bar. A map that can tilt and turn has no limit at which either press stops making sense: flat and north are always reachable; a screen that keeps them pressable while the map loads sets the three `…Disabled` props instead of `disabled`; and a prop for either can join later as a new optional prop, which [Change](README.md#change) allows.

MapControls takes no `slotProps`, and puts a `pn-MapControls-<part>` class on each button and each separator for a caller's CSS. The contract keys `slotProps` by Base UI part; the buttons, three to six, share one, `Toolbar.Button`, and the separators, one to three, another, `Toolbar.Separator`; every per-button need the sources name (handler, limit, words) is a prop above; and a `slotProps` key can join later as a new optional prop, which [Change](README.md#change) allows.

## Tokens

The buttons are `neutral`; every `color` row sets the button's `color`, which the icon takes through `currentColor`.

The pause button swaps its name, "Pause" or "Resume", and sets no `aria-pressed`. The [APG's button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) gives a two-state button one of two forms: a toggle whose label stays the same while `aria-pressed` says its state, such as "Mute", pressed or not; or a button whose label changes with the state, such as Play and Pause, which then has no `aria-pressed`, since "Pause, pressed" says the opposite of what it means. The icon swaps between `pause` and `play`, each naming the action a press takes, and the contract asks that everything the eye is told the ear is told, so the name swaps with the icon: a fixed "Pause" with `aria-pressed` would be heard as "Pause, pressed" while the eye sees play. The name says what the press does, as zoom in and zoom out do, and it is the name Mylder's map already gives the button. A screen reader may not announce the new name on the press itself; the vehicles stopping or moving is the press's feedback, and the name is read the next time focus reaches the button.

The 3D toggle takes the APG's other form: its name, "3D view", stays the same while `aria-pressed` says whether the map is tilted, heard as "3D view, toggle button, pressed" or "not pressed". Its icon, the `cube`, stays the same too, and its on fill is what the eye is told. The state is the map's, which a gesture changes as well as a press, so it is a state to announce rather than an action to name, as "Pause" is: a name that swapped, "Tilt the map" and "Lay the map flat", would leave the ear without the map's state once a gesture had tilted it. `aria-pressed` follows `tilted`, so a gesture the screen passes on is heard the next time focus reaches the toggle.

The compass's name says what a press does, "Reset to north", at every heading, as the zoom and centre buttons name theirs, and it sets no `aria-pressed`: the press is an action, not a state.

The compass's turn is left unannounced, so its name stays "Reset to north" with no heading in it, as an exception to the contract's "everything the eye is told, the ear is told". The needle shows the eye where north is so it can tell the map is turned; the ear learns the map's heading from the map, which the screen describes, as it does the zoom the controls don't announce either; a heading in the name ("Reset to north, map turned 45°") would need an owned string with a placeholder, a number format and a word for "not turned", and would change the name at every frame of a turn, which a screen reader repeats or drops; and the press says what it does at any heading.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: each icon is `aria-hidden` inside its button, and the button's `aria-label` says the action it shows ("Zoom in", "Zoom out", "Centre the map", "Reset to north", and "Pause" or "Resume" as the `pause` or `play` icon shows), or, for the 3D toggle, the view it turns on, "3D view"; the toggle's on fill is its `aria-pressed`; the compass's needle angle is left to the map to announce, as the paragraph above says; a dimmed button is announced through `aria-disabled`; the separators are announced as such.
- [ ] Every landmark and named region has an accessible name: the bar is a `toolbar` named "Map controls" by its owned string, so it tells itself apart from the top bar's toolbars.
- [ ] Every default label can be overridden: `mapControlsLabel`, `zoomInLabel`, `zoomOutLabel`, `centerMapLabel`, `view3dLabel`, `resetNorthLabel`, `pauseLabel` and `resumeLabel`.
- [ ] Every shape the type accepts renders, in every variant: the props take no `ReactNode`; both orientations, every `…Disabled` combination and `disabled` render all three buttons, square, in the same order, and the 3D toggle in either state of `tilted`, the compass at any `heading`, 0, negative, past 360 or not finite, and the pause button in either state of `paused` after them when their handlers are given.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the controls keep no hidden copy and collapse nothing.
- [ ] Native semantics first: native `<button>`s from `Toolbar.Button`, Base UI's `toolbar` and `separator` roles, with ARIA only for the names an icon can't give.
- [ ] Focus moves in reading order and returns on close: the arrow keys move zoom in, zoom out, centre, then the 3D toggle, the compass and pause, in document order; the controls open nothing; a button that hits a zoom limit stays focusable, the 3D toggle stays the same element as `tilted` changes, the compass stays in the bar at north, and the pause button stays the same element as its icon and name swap, so focus never jumps away from the key a person pressed.
- [ ] Every target is at least `size.target-min` square: each button is `size.control` (34 px) square.
- [ ] Loops stop when the system asks for less motion: none here; the controls have no loop and no transition, and the compass's needle jumps to each `heading` it is given, so the motion is the screen's own turn of the map, which reads the motion tokens' reduced values (CR-12).

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Perron's Toolbar already gives the one tab stop, the roving `tabIndex`, the arrow keys, the wrap, the disabled cascade and a disabled button that stays focusable, through Base UI, so MapControls rebuilds none of it, adds no key handler and sets no `aria-keyshortcuts`.
- **CR-2.** MapControls renders Perron's `Toolbar`, and in it, in this order, a `ToolbarButton` for zoom in, one for zoom out, a `ToolbarSeparator`, and one for centring the map; then, only when `onTiltedChange` or `onResetNorth` is given, a `ToolbarSeparator` (`angleSeparator`) followed by a `ToolbarButton` for the 3D toggle when `onTiltedChange` is given and one for the compass when `onResetNorth` is given, in that order; then, only when `onPausedChange` is given, a `ToolbarSeparator` (`pauseSeparator`) and a `ToolbarButton` for pausing, each button `color="neutral"` and icon-only (a `startIcon` and no `children`). It imports `Toolbar`, `ToolbarButton` and `ToolbarSeparator` from `packages/perron/src/components/Toolbar/Toolbar.tsx`, never `@base-ui/react/toolbar` or IconButton.
- **CR-3.** The root's `className` is `pn-MapControls` then the caller's, given to `Toolbar`, which puts `pn-Toolbar` first. Each button takes `pn-MapControls-zoomIn`, `pn-MapControls-zoomOut`, `pn-MapControls-centerMap`, `pn-MapControls-tilt`, `pn-MapControls-compass` or `pn-MapControls-pause`, and the separators `pn-MapControls-separator`, `pn-MapControls-angleSeparator` and `pn-MapControls-pauseSeparator`, after the class of its own component.
- **CR-4.** `{...rest}` reaches `Toolbar` before MapControls' own attributes, and its own props are taken out of `rest` first (`orientation`, `zoomInDisabled`, `zoomOutDisabled`, `centerMapDisabled`, `onZoomIn`, `onZoomOut`, `onCenterMap`, `paused`, `onPausedChange`, `tilted`, `onTiltedChange`, `heading`, `onResetNorth` and the eight `…Label` props), so none reaches the DOM. `disabled`, `loopFocus`, `render`, `style`, `aria-labelledby` and `ref` pass through to `Toolbar`, and `ref` lands on the `role="toolbar"` element. The root's `aria-label` is set after `rest` from the `mapControls` string, so a caller renames the bar with `mapControlsLabel`.
- **CR-5.** `orientation` defaults to `'vertical'` in MapControls' own destructuring and is passed to `Toolbar`; `MapControlsProps` redeclares it with `@default 'vertical'`. The root carries Base UI's `data-orientation`; MapControls has no `variant`, `color` or `size` prop, so it sets no `data-variant`, `data-color` or `data-size`.
- **CR-6.** The words come from `useOwnedStrings({ mapControls: mapControlsLabel, zoomIn: zoomInLabel, zoomOut: zoomOutLabel, centerMap: centerMapLabel, view3d: view3dLabel, resetNorth: resetNorthLabel, pause: pauseLabel, resume: resumeLabel })`. Each button's `aria-label` is its string; the component shows no text and sets no `title`.
- **CR-7.** Each icon is an inline `<svg>` with the `perron-icon` class, `viewBox="0 0 16 16"`, `fill="none"`, `stroke="currentColor"`, round caps and joins, and the stroke width and path data of its file in `packages/perron/icons/` (`plus.svg`, `minus.svg` and `pause.svg` at 1.8, `locate.svg`, `cube.svg`, `compass.svg` and `play.svg` at 1.6), with no `width`, `height` or colour of its own, but for `compass.svg`'s north half, whose path keeps its file's `fill="currentColor"`: `ToolbarButton`'s icon span sets `--perron-icon-size` to `icon.size.400` and hides it from screen readers.
- **CR-8.** `zoomInDisabled`, `zoomOutDisabled` and `centerMapDisabled`, or `disabled`, set `disabled` on that `ToolbarButton`, which stays focusable (`focusableWhenDisabled` left at its `true` default), carries `aria-disabled` and `data-disabled`, and stops the click, so its handler never fires. None of the three disables another button or the pause button; `disabled` disables the 3D toggle, the compass and the pause button with the rest.
- **CR-9.** `MapControls.css`, which otherwise sets no colour, size, spacing or state, sets the 3D toggle's on look alone, from Tokens' selected rows and their forced colours, selected by `.pn-MapControls-tilt[aria-pressed='true']`, as an exception to the contract's [Design states](README.md#design-states) table, which reads selected from `[data-selected]` or `[data-checked]`. ToolbarButton draws no selected state (the [Toolbar](toolbar.md) spec's Do and don't), so the toggle's on look is MapControls' to draw or nobody's, and the contract asks the eye be told what `aria-pressed` tells the ear. Reading `aria-pressed` keeps one attribute for both, where a `data-selected` of MapControls' own would be a second copy of `tilted` to keep alike, and Base UI's `data-pressed`, which FilterChip reads, comes only from the `Toggle` the Base UI parts section leaves out. The hover rule sits inside `(hover: hover)` and the pressed rule after it, both excluding `[data-disabled]`, by the contract's [Pointer feedback](README.md#pointer-feedback). Every other look stays Toolbar's, so the controls match every other toolbar, and a change to Toolbar's look reaches them.
- **CR-10.** MapControls sizes to its content, as Toolbar does, and places nothing: no `position`, `inset`, `margin` or `z-index`. The screen puts it at the bottom right, `size.panel-gap` from the edges, at `z-index.map-controls` ([Layout](../foundations/layout.md#stacking)), a token outside a component's [Token families](README.md#token-families).
- **CR-11.** Each handler is given as its button's `onClick` and called once per press, by click, Enter or Space, with the click event; no handler is called on focus, hover or an arrow key, and none is called when `tilted` or `heading` changes.
- **CR-12.** Changes of state are immediate, as on Toolbar: MapControls adds no transition, and the pause button swaps its icon and name in the render that takes the new `paused`, and the 3D toggle its `aria-pressed` and fill in the render that takes the new `tilted`.

  The compass's needle turns to each `heading` in the render that takes it, with no transition, in full and reduced motion alike. The screen already animates the map's turn, by a gesture or by the fly-to back to north, reading the motion tokens' reduced values as [Motion](../foundations/motion.md#reduced-motion) asks, and passes `heading` at each frame, so the needle follows the map's own motion and stops when it stops; a transition of the needle's own would lag the map it points on, and turn the long way round from 359° to 1°; and with none, reduced motion needs no rule of the needle's, since the motion it shows is the screen's.

- **CR-13.** The pause button follows `paused` alone: the `pause` icon and the `pause` string while it is `false`, the `play` icon and the `resume` string while it is `true`, with no `aria-pressed`, `data-pressed` or look of its own for either state. Its `onClick` calls `onPausedChange(event, !paused)`; MapControls keeps no state of its own, so a press the screen doesn't answer leaves the button as it was.
- **CR-14.** The 3D toggle follows `tilted` alone: `aria-pressed="true"` and the on look while it is `true`, `aria-pressed="false"` and the neutral rest look while it is `false`, with the `cube` icon and the `view3d` string in both. MapControls passes `aria-pressed` to the toggle's `ToolbarButton` from `tilted` and sets no `data-pressed` or `data-selected`. Its `onClick` calls `onTiltedChange(event, !tilted)`; MapControls keeps no state of its own, so a press the screen doesn't answer leaves the toggle as it was, and a gesture the screen passes on as `tilted` presses it with no press.
- **CR-15.** The compass follows `heading` alone: its icon's `<svg>` takes an inline `transform` of `rotate(${-heading}deg)` about its centre, the CSS box's default `transform-origin` of 50% 50%, where the `compass` icon's needle is drawn, so the filled north half points to north on the map; a `heading` that isn't finite draws it unturned. Its name stays the `resetNorth` string at every heading, and it stays in the bar at north. Its `onClick` calls `onResetNorth(event)`.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                                                                                                                                               | Don't                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use MapControls for the map's zoom and centre buttons, once per map                                                                                                                                                                                              | Build the same bar from IconButtons or from your own Toolbar: an IconButton in a toolbar adds a tab stop, and a second copy drifts from this one                                                     |
| Place it from the screen, at the bottom right, `size.panel-gap` from the edges, at `z-index.map-controls`                                                                                                                                                        | Expect MapControls to position itself, or give it a `z-index` through the component: it sizes to its content and the screen places it                                                                |
| Set `zoomInDisabled` or `zoomOutDisabled` when the map reaches a zoom limit                                                                                                                                                                                      | Hide or unmount a button at a limit: focus on it is lost and the bar changes shape under the pointer                                                                                                 |
| Centre the map on the whole network in `onCenterMap`, as its words promise                                                                                                                                                                                       | Wire it to the reader's own location: its words, "Centre the map", and the `locate` icon's use promise the network                                                                                   |
| Rename the bar or a button with its `…Label` prop, such as `zoomInLabel`                                                                                                                                                                                         | Pass `aria-label` to the root: the bar's own name is set after it and replaces it                                                                                                                    |
| Bind `+` and `−` on the map canvas, where Accessibility puts them                                                                                                                                                                                                | Expect MapControls to listen for keys: it adds none beyond the toolbar's arrows                                                                                                                      |
| Give `onPausedChange` and `paused` to add the pause button, and set `paused` from the handler                                                                                                                                                                    | Put the pause in a Toolbar of its own beside MapControls: it is the map's own control, and a bar of its own adds a second bar and a second tab stop                                                  |
| Put another map action, such as a layers switch, in a Toolbar of its own beside it                                                                                                                                                                               | Wrap MapControls to add buttons inside it: it takes no `children`, so its buttons stay the same on every screen; only the map's own controls, the 3D toggle, the compass and the pause, join the bar |
| Give `onTiltedChange` and `tilted` to add the 3D toggle, and set `tilted` from the map's own tilt, whether the rider tilted it with the toggle or a gesture                                                                                                      | Set `tilted` only in the handler: a gesture that tilts the map then leaves the toggle off, and the ear hears "not pressed" over a tilted map                                                         |
| Give `onResetNorth` and `heading` to add the compass, pass the map's bearing in degrees clockwise from north at each frame of a turn, and turn the map back to north in the handler, with the motion tokens' reduced values when the system asks for less motion | Pass the needle's own angle, a counter-clockwise or radian value, or only the heading the turn ends at: the needle turns by minus `heading` and jumps to each value it is given                      |
| Keep the compass in the bar at north                                                                                                                                                                                                                             | Unmount the compass or drop `onResetNorth` while the map faces north: the pause button moves under the pointer and the rider can't find the compass when the map is first turned                     |
