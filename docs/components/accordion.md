# Accordion

A stack of headed sections, each opening and closing its own content under its heading, such as the questions on a help panel or the details of each planned work on a line.

## Anatomy

Penpot page `Components/Accordion`. Family: none: the contract's [Families](README.md#families) have no disclosure row; an item's heading is a quiet button on whatever surface holds the accordion, its items divided by the Rows family's line, `border.width.025` in `color.border.subtle`, the line [Separator](separator.md) draws. Shared parts: `Chevron`, new, for the chevron at the end of the trigger: Select drew `chevron-down` first, in its own folder, so the contract moves the drawing into the part, which Select and Accordion both compose. No other: every word is the caller's, and the chevron is decoration beside a button whose state Base UI announces.

The `Accordion` folder holds two components, `Accordion` and `AccordionItem`, each exported with its props type from `Accordion.tsx`, as an exception to the contract's "one component per folder", as Tabs' four are. `Accordion` renders `Accordion.Root`; `AccordionItem` renders `Accordion.Item` and, inside it, `Accordion.Header`, `Accordion.Trigger` and `Accordion.Panel`, from its `title` and its `children`. Base UI's item, header, trigger and panel read the root's context, so they can't be built or shown apart; the caller writes many items, so the item is a component of its own; and every item has exactly one heading, one button and one panel, in that order, so the item draws all three and offers the header, the trigger and the panel through `slotProps`, rather than the caller assembling them each time. The `props` check reads both props types, and the `api-compatibility` check only `AccordionProps`, so the review holds `AccordionItemProps` to the contract's Change rules.

Accordion is two components, `Accordion` (the root) and `AccordionItem` (an item that renders its own heading, button and panel from `title` and `children`, with `slotProps.header`, `slotProps.trigger` and `slotProps.panel`), rather than five that mirror Base UI's parts: the item's three inner parts never change order or count, so a caller assembling them is only room for mistakes, such as a panel without a heading, and each stays reachable through `slotProps`.

Base UI already does: a press, Enter or Space on a trigger opens or closes its panel, the keys through the native `<button>`; with `multiple` off, its default, opening one item closes the one that was open, and pressing an open item's trigger closes it, leaving none open; each trigger is a Tab stop of its own, in document order, with no roving focus and no arrow, Home or End keys (Base UI removed them in 1.9.0, following the APG's update to the accordion pattern, and deprecated `orientation` and `loopFocus`, which no longer do anything); the trigger's `aria-expanded` and, while open, `aria-controls`; the panel's `region` role named by its trigger through `aria-labelledby`, with the two `id`s generated unless the caller gives one; a closed panel is unmounted, or with `keepMounted` kept `hidden`, so nothing in it can be focused or heard; with `hiddenUntilFound`, a closed panel stays mounted with `hidden="until-found"`, and the browser's find in page opens the item that holds a match, calling `onValueChange` with the reason `'none'`; a disabled item, or every item of a disabled root, gives its trigger the native `disabled`, so it leaves the Tab order and ignores presses; an item given no `value` gets a generated one; the panel's height and width as `--accordion-panel-height` and `--accordion-panel-width`, `auto` at rest and the measured pixels while the panel opens or closes; `data-starting-style` on a panel as it starts to open and `data-ending-style` while it closes, which Accordion reads to ease the panel's height (CR-10); a closing panel kept mounted, with `data-ending-style`, until its transitions end, read through `getAnimations`, then unmounted or hidden; a panel open at first, or opened by find in page, shown at once with no motion, Base UI setting the transition's duration to `0s` for the find-in-page reveal.

## Props

In MUI's layout. Every prop here gets this description as its JSDoc. Slots come last.

Accordion leaves out Base UI's `orientation` and `loopFocus`: both are deprecated in the installed 1.9.0 and do nothing, so a prop for either would promise a behaviour the component doesn't have. `AccordionItem` leaves out Base UI's `onOpenChange`, a name the contract's [Names from other libraries](README.md#names-from-other-libraries) table rules out, and the HTML `title` attribute, whose name it takes for the heading's words.

The item values are strings: `value` and `defaultValue` are `string[]` on Accordion, `onChange` reports a `string[]`, and `value` is an optional `string` on AccordionItem, Base UI generating one when it is left out: an item's value names what it holds (`'shapes'`, `'freshness'`), a name survives the items being reordered, a string union narrows in the caller's `onChange`, as Tabs' values do, and an accordion that no one controls or opens at first needs no values at all.

Accordion inherits Base UI's `multiple` with its default, `false`, so opening one item closes the one that was open: Base UI's default, kept unchanged, means its JSDoc and the docs page agree with Base UI's own; a caller whose items are read side by side, such as several planned works, sets `multiple`.

`AccordionItem` takes no open props of its own (no `open`, `defaultOpen`, `onOpen` or `onClose`): which items are open is only the root's `value`, `defaultValue` and `onChange`. One place holds the open items, as Tabs holds the selected tab at its root, and the API only grows, so `onOpen` and `onClose` on the item can join later without a break.

`AccordionItem` takes `title: ReactNode`, required: the words of its heading and its button, such as "What the dot shapes mean". Dialog and Section name their heading's words `title` too, and the trigger's accessible name is the title's text, so an item can't be left nameless. The heading is an `h3`, its level changed through `slotProps.header.render` (`render: <h2 />`), with no `level` prop, by [Section](section.md)'s rule: the detail panel's own title is an `h2`, so `h3` is the level the commonest use needs, and `render` is the contract's one way to swap an element.

## Tokens

One row per part, state and property. States are the contract's design states: rest is no selector, hover is `:hover` inside `@media (hover: hover)`, pressed is `:active`, focus is `:focus-visible`, disabled is `[data-disabled]`, and open is Base UI's `[data-panel-open]` on the trigger and `[data-open]` on the item and the panel. Opening and closing are the panel's motion, not design states, so their rows are rest rows qualified as Sheet's are: "as it opens" is Base UI's `[data-starting-style]` on the panel, and "as it closes" its `[data-ending-style]`.

The item's look is a quiet row: a hairline (`border.width.025` in `color.border.subtle`) between items and none at the accordion's outer edges; the trigger at least `size.button` tall, its title in `typography.label` and `color.text.primary`, padded `space.300` at its sides, with no fill at rest, `color.surface.hover` on hover and `color.surface.selected` while pressed, and no radius; the chevron at the row's end in `color.text.secondary`; the panel padded `space.300` at its sides, with `space.300` of room below its content, so its content starts under the title. `typography.label` is the contract's type for rows and buttons, which the trigger is; `size.button` is a button of label text, as Tabs takes for its tabs; the quiet hover and pressed layers are the contract's [Pointer feedback](README.md#pointer-feedback) for a quiet part; the hairline is the Rows family's divider and the line Separator draws, and the accordion's outer edges belong to the panel or card that holds it; the chevron sits at the end as Select's and Menu's do; and the panel's `space.300` keeps its words in the title's column.

The panel sets its text in `typography.body` and `color.text.primary`, which the caller's content inherits unless it sets its own: an open panel's content is most often sentences, such as a help answer or a planned work's details, `typography.body` is "Sentences and inputs", and a panel that set nothing would take whatever the page around it set.

The chevron reuses the set's `chevron-down` at `icon.size.400`, its `use` in `packages/perron/icons/icons.json` widened to "Open a select's list, or an accordion's panel", and turns upside down while the panel is open (`scale: 1 -1`). The panel's height and the chevron's turn ease over `duration.switch`, Base UI's `--accordion-panel-height` with `data-starting-style` and `data-ending-style` at height `0`: the Motion page gives `duration.switch` to a control pressed many times in a row, which a trigger is, and motion explains the change of place as the content below the item moves; under reduced motion the token is 0.01 ms, so the panel and the chevron change at once with no extra rule. The down chevron is drawn on the 16 px grid for `icon.size.400`, the step for icons inside controls; a second chevron drawing would be a copy, so the `Chevron` shared part draws it once for both; a chevron that points down at rest and up while open says which way the panel will go, as most disclosures do; and `scale: 1 -1` turns it with unitless numbers, where a rotation would need an angle the contract's [CSS](README.md#css) rules don't list.

## Keyboard and ARIA

From the Base UI reference for `Accordion` and the installed `AccordionRoot`, `AccordionItem`, `AccordionTrigger` and `AccordionPanel`. "From" says who does it.

| Key              | Does                                                                                                                          | From                                                   |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `Tab`            | Moves focus to the next trigger, or into an open panel's first focusable element, in document order; skips a disabled trigger | The browser                                            |
| `Shift+Tab`      | Moves focus back the same way                                                                                                 | The browser                                            |
| `Enter`, `Space` | Open the focused trigger's panel, or close it while open; with `multiple` off, opening one closes the other                   | The browser's click; Base UI for a non-button `render` |

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: whether a panel is open, which the chevron shows, is the trigger's `aria-expanded`; a disabled trigger's tertiary colour is the native `disabled`; the chevron itself is `aria-hidden`.
- [ ] Every landmark and named region has an accessible name: each open panel is a `region` named by its trigger through Base UI's `aria-labelledby`, so its name is the item's `title`, which is required.
- [ ] Every default label can be overridden: none here; Accordion owns no strings.
- [ ] Every shape the type accepts renders, in every variant: `title` renders a string, an element and a list alike, as phrasing content in the button; `children` renders a string, an element and a list alike in the panel's `<div>`.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: a closed panel is unmounted, or with `keepMounted` or `hiddenUntilFound` kept `hidden`, which takes it out of the accessibility tree and the Tab order as `inert` would; Accordion keeps no copy for animation: a closing panel is the panel itself, shrinking for `duration.switch` under a trigger that already says `aria-expanded="false"`, then unmounted or hidden by Base UI.
- [ ] Native semantics first: a native `<h3>` holding a native `<button>`, with Base UI's `aria-expanded`, `aria-controls` and the panel's `region` named by `aria-labelledby`; no ARIA from the caller.
- [ ] Focus moves in reading order and returns on close: Tab goes from a trigger into its open panel and on to the next trigger, in document order; closing a panel leaves focus on the trigger that closed it.
- [ ] Every target is at least `size.target-min` square: the smallest target is a trigger with a one-word title, `size.button` (36 px) tall and the accordion's full width.
- [ ] Loops stop when the system asks for less motion: no loop; the panel's height and the chevron's turn are transitions over `duration.switch`, which the tokens shorten to 0.01 ms under reduced motion, so both change at once with no query in the component (CR-10).

## Owned strings

No owned strings: every word comes from the caller, as an item's `title` and its `children`.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's accordion already gives the toggling, the single-open behaviour while `multiple` is off, the `aria-expanded`, `aria-controls` and `aria-labelledby` wiring, the generated `id`s and values, the unmounting or hiding of closed panels and the find-in-page reveal, so the components rebuild none of it and add no key handlers.
- **CR-2.** `AccordionItem` only renders inside an `Accordion`: Base UI's item reads the root's context. Every story renders items in one, and the `Default` story's args hold a whole set, the root with three items, so the contract story renders it alone.
- **CR-3.** Each of the two takes `{...rest}` before its own attributes and its own props out of `rest` first (`value`, `defaultValue` and `onChange` on Accordion; `title`, `value`, `children` and `slotProps` on AccordionItem; an inherited Base UI prop such as `multiple`, `disabled` or `keepMounted` stays in `rest`, keeping Base UI's default), and merges `className` after its own `pn-` class; `ref` reaches its one element. AccordionItem's props type leaves out the HTML `title` attribute and Base UI's `onOpenChange`, and Accordion's leaves out `orientation`, `loopFocus` and the `<div>`'s own `onChange`, so none reaches the DOM or the docs page.
- **CR-4.** `Accordion` adapts Base UI's `onValueChange(value, details)` into `onChange(details.event, value, details)` inside itself and exposes neither `onValueChange` nor `onOpenChange`. It gives `defaultValue` no destructuring default: Base UI's own empty list holds when it is left out, and its JSDoc says `@default []`, as the Props table gives it.
- **CR-5.** `AccordionItem` renders, inside `Accordion.Item`, an `Accordion.Header` holding an `Accordion.Trigger`, whose children are the title span and the chevron span in that order, then an `Accordion.Panel` holding `children`. `slotProps.header`, `slotProps.trigger` and `slotProps.panel` merge onto their parts with `mergeProps`, the component's own props last, so each part's class stays while the caller's `className` joins and its `render` swaps the element, such as the header's level.
- **CR-6.** The chevron is the `Chevron` shared part inside its span: an inline `<svg>` drawn from `chevron-down.svg` in `packages/perron/icons/`, with the classes `perron-icon` and `pn-Chevron`, `aria-hidden="true"` and `focusable="false"`, in `currentColor`; the span carries `aria-hidden="true"` too, and sets the icon's size, colour and turn, never the `<svg>`, as [Icons](../foundations/icons.md) asks. Select drew the chevron first, so the build moves that drawing out of Select's folder into `packages/perron/src/parts/Chevron/`, adds its row to the contract's [Shared parts](README.md#shared-parts) table, composes it in Select too, widens the icon's `use` in `packages/perron/icons/icons.json` to name an accordion's panel too, and draws no new chevron.
- **CR-7.** The trigger is a flex row, `align-items: flex-start`, its title growing (`flex: 1`) and the chevron keeping its size (`flex: none`); a title that wraps, such as a long Danish word in a 320 px container, keeps the chevron level with its first line, and the row grows a line at a time from its `size.button` least height. The trigger is the header's full width (`inline-size: 100%`), its text starting at the inline start (`text-align: start`).
- **CR-8.** Hover is read inside `@media (hover: hover)`; pressed (`:active`) takes `color.surface.selected` in a rule after it and outside the query, so a touch press shows. Neither applies to a disabled trigger: both rules exclude `[data-disabled]`, since a native `disabled` button still matches `:hover`. Open is `.pn-AccordionItem-trigger[data-panel-open]`, one class then attributes, and changes only the chevron (`.pn-AccordionItem-trigger[data-panel-open] .pn-AccordionItem-chevron`).
- **CR-9.** No rule sets `display` on the panel: Base UI hides a kept-mounted closed panel with the `hidden` attribute, or `hidden="until-found"`, and a `display` would show it. The panel's `height` is `var(--accordion-panel-height)`, which Base UI sets to `auto` at rest, so an open panel is as tall as its content and never a fixed height; only `[data-starting-style]` and `[data-ending-style]` set it to `0`. It clips its overflow (`overflow: clip`) only while it moves: at once as it closes, and from its start until its opening ends, so at rest a focus ring or anything wider or taller than the panel is never cut. The room below the content is a `::after` block `space.300` tall, not `padding-block-end`: under the global `border-box` a padded panel can't shrink below its padding, so `0` would leave a strip, and Base UI's measured height leaves the bottom padding of a clipped box out, so the opening would stop short and jump.
- **CR-10.** The panel's height and the chevron's turn ease over `duration.switch` with `easing.standard`: the panel transitions `height` from `0` on `[data-starting-style]` to Base UI's measured `--accordion-panel-height` as it opens, and back to `0` on `[data-ending-style]` as it closes, and the chevron transitions `scale`. The clip of CR-9 rides the same transition: `overflow` transitions over `duration.switch` with `step-end` and `transition-behavior: allow-discrete`, so `clip` holds until the height arrives, and `[data-ending-style]` sets its timing to `step-start`, so it clips at once. Under reduced motion `duration.switch` is 0.01 ms, so both change at once with no `prefers-reduced-motion` query, and the transitions still run and finish, so Base UI's wait for the close still ends. No rule styles a keyframe `animation`: Base UI warns of a panel with both a transition and an animation. A panel open at first renders open with no motion, since a transition runs only on a change, and Base UI opens a find-in-page match at once.
- **CR-11.** Focus uses the ring `perron.css` draws on `:focus-visible`, on the trigger; the component draws no ring of its own and never removes the outline.
- **CR-12.** The states keep the trigger's geometry: hover, pressed, focus, open and disabled change colours and the chevron's direction only, never the height, padding, gap, typography or weight, so opening an item never moves its title; what moves is the panel under it and the items below.
- **CR-13.** The divider between items is a `border-block-start` on `.pn-AccordionItem + .pn-AccordionItem`, never a `separator` element between them, so a screen reader hears each heading after the last without a break in between; its two tokens are the ones [Separator](separator.md)'s CR-7 names, so a change to Separator's line is a change to this one, in the same pull request.
- **CR-14.** In `@media (forced-colors: active)`, a disabled trigger and its chevron take `GrayText`, so the disabled state still shows; the hover and pressed layers drop out, as Windows' forced colours draw no backgrounds, and the focus ring stays.
- **CR-15.** Accordion sizes to its container: the root and its items are as wide as the box that holds them, and the accordion's outer edges, its padding and its place in a panel belong to the screen or the pattern that uses it.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                                               | Don't                                                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Use Accordion for sections a person reads one or two of, such as help questions or the details of each planned work                                              | Hide what most people need behind a heading, such as a stop's next departures: show it, under a [Section](section.md)               |
| Use [Tabs](tabs.md) to switch between views of one thing                                                                                                         | Use Accordion as tabs stacked down the page: an accordion's sections are read in place, one under another                           |
| Write each `title` as a few words or a short question in sentence case, saying what the panel holds: "What the dot shapes mean"                                  | Write "Read more" or "Details" on every item: each trigger and its region are named by the title, so every one would sound the same |
| Keep a title to words: an icon or a badge beside it is fine, a link or a button is not                                                                           | Put a link or a button in a `title`: it renders inside the trigger's `<button>`, where nothing else can be pressed                  |
| Give items a `value` when the accordion opens one at first or the caller controls it                                                                             | Read a generated value from `onChange` and store it: it changes from one mount to the next                                          |
| Set `multiple` when people compare items side by side                                                                                                            | Leave items that are read together closing each other                                                                               |
| Set the heading level with `slotProps.header.render` (`render: <h4 />`) when the accordion sits under an `h3`; under a panel's or a dialog's `h2`, keep the `h3` | Leave the outline skipping a level, or wrap the title in a heading of your own inside the button                                    |
| Use `hiddenUntilFound` on long help pages, so the browser's find in page reaches closed answers                                                                  | Use `keepMounted` to make closed content searchable: a `hidden` panel is out of find in page as well                                |
| Leave out an item whose panel would have nothing in it, or open it to an [EmptyState](empty-state.md) that says why                                              | Disable an item because its panel has nothing to show: a disabled trigger can't say why, and it leaves the Tab order                |
