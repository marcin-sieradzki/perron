# Slider

A control for choosing a number, or a range between two numbers, along a track by dragging a thumb or pressing the arrow keys, such as how many minutes of movement the map draws behind each vehicle, with its label, its line of help and its error from Field.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), [content design](../content-design.md), the tokens, the Base UI reference for `Slider` (`@base-ui/react` 1.9.0, installed) and the spec of the one entry in `dependsOn`, [Field](field.md). Three shipped specs in this branch set the precedents the slider follows where it meets them: [TextField](text-field.md), the first control framed by Field, for the frame and its `slotProps.field`; [Meter](meter.md), the other bar along a track, for the track, the fill, the figure and its locale; and [Switch](switch.md), the other control with a thumb, for the thumb's size. ## Anatomy

Penpot page `Components/Slider`. Family: none for the slider itself, which draws no box: its track, fill and thumb join none of the Rows, Fields, Popups, Panels or Tooltips. Its frame, the label, the line of help and the error, is [Field](field.md), shared with every member of the Fields family. Shared parts: `VisuallyHidden`, through Field, for a hidden label.

Slider composes Perron's [Field](field.md) as its frame, as [TextField](text-field.md) does: its root is Base UI's `Slider.Root` (the `role="group"` `<div>` that holds the value), Field is rendered round it and reached through `slotProps.field`, and Base UI's `Slider.Label` is left out although the registry entry listed it. Field's `Field.Label` already names the group and every thumb, since Base UI's `Slider.Root` takes the field's label id before its own `Slider.Label`'s (`resolveAriaLabelledBy`), so a `Slider.Label` beside it would never be heard and would draw a second label; Field brings the description, the error and the invalid state through `aria-describedby` and `aria-invalid` on the group and each thumb's input, which Base UI's `Slider.Thumb` takes from the field; the root being the slider keeps `ref`, `className` and the value's props on the element that holds the value, as TextField's root is its input; and the registry entry's `baseUiParts` drops `Slider.Label` and lists Field's parts, as TextField's entry does.

The figure, Base UI's `Slider.Value`, always shows, at the inline end of the track's row, its column held as wide as the widest of the formatted `min` and `max` by `aria-hidden`, `visibility: hidden` copies of those two figures stacked in the same grid cell, so the track never changes width while the thumb moves. The figure beside the track is read in the same glance as the thumb, as a meter's figure is read beside its bar; Field's label row belongs to Field, and a figure inside the label would join the control's name and change it at every step; without a held width the track would grow or shrink by a digit under the pointer as the value passes from 9 to 10; a figure on a line of its own would put an empty line beside the label; and the brand's "honest" asks the screen to say the number the person has chosen, never only a thumb's place. A prop that hides the figure can join later without a break.

The parts in DOM and reading order: Field's label, its description, then the root, which holds the control (the track, the fill and the thumbs) and then the figure, then Field's error.

Base UI already does: it keeps the value controlled or uncontrolled, clamps it to `min` and `max` and sorts a range; it moves the nearest thumb to a press on the control and follows the drag with the pointer captured, focusing the thumb it moves; it steps the value by `step` with the arrow keys and by `largeStep` with Shift and an arrow key or Page Up and Page Down, goes to `min` or `max` with Home and End (to the other thumb's value in a range, less `minStepsBetweenValues`), and swaps the left and right arrows in right-to-left text; it pushes, swaps or stops thumbs that meet, by `thumbCollisionBehavior`; it formats the figure and each thumb's `aria-valuetext` with `Intl.NumberFormat` in `locale` and `format`; it renders one hidden range input per thumb, with the field's `name`, so a native form's `FormData` holds the value, or one entry per thumb for a range; it gives each `onValueChange` an event whose `target` holds `value` and `name`, for a form library; it calls `onValueCommitted` once a drag ends, a key is pressed or the track is pressed, and not when the value is unchanged or the change was cancelled; it takes the label, the description, the error, `disabled` and `name` from a `Field.Root` round it, marks the field dirty and touched, and runs its checks; it blurs a thumb that becomes disabled; and it sets every part's state attributes from the slider's state.

## Props

In MUI's layout. Every prop here gets its description as its JSDoc. Slots come last.

The value is a number, or a range of exactly two numbers typed `readonly [number, number]`, so `value` and `defaultValue` are `number | readonly [number, number]` and Slider renders one thumb per value, with no generic type parameter. Base UI and MUI's Slider both take a number or an array of them; Mylder's filters need at most "between this and that", and a pair lets the two thumbs be named "Minimum" and "Maximum" (see Owned strings), where three or more thumbs would have no owned names; `onChange` then gives `number | readonly [number, number]`, which the caller narrows by its own value's shape, as with MUI's; and a generic parameter with a default, or a wider array, can join later without a break.

Slider takes MUI's event names: `onChange(event, value, details)` for Base UI's `onValueChange`, and `onChangeCommitted(event, value, details)` for Base UI's `onValueCommitted`, each with `event` being `details.event`. The contract's [State and events](README.md#state-and-events) gives `onChange` and bans `onValueChange`; `onChangeCommitted` is MUI's Slider's name for the change a person ends by releasing the thumb, which a screen uses to fetch once rather than at every step of a drag; and Base UI's `details`, with its `reason` and `cancel()`, is passed unchanged as the last argument, as the contract asks.

Slider takes no `variant`, `size`, `color`, `orientation`, `thumbAlignment`, `optional` or `required`; it inherits `min`, `max`, `step`, `largeStep`, `minStepsBetweenValues`, `format`, `thumbCollisionBehavior`, `name` and `form` from `Slider.Root` with Base UI's JSDoc, and declares `locale`, defaulting to the nearest PerronProvider's, as Meter does. The brand keeps controls ink and neutral and a slider has one look; the control is `size.target-min` tall, the smallest target, so a smaller size would fail [Accessibility](../foundations/accessibility.md#rules) and a larger one has no screen yet; a vertical slider has no place on Mylder's screens and would need its own CSS, so `orientation` is left out until one does; Perron insets the thumb itself (CR-10), and Base UI's `'edge'` alignment would inset it a second time; a slider always holds a value, so it is never empty, Field's "(optional)" would say nothing, and a `required` check could never fail; Base UI's own `locale` default is the browser's, which shows "1.5 km" on a Danish screen in an English browser, where Meter's CR-11 formats in the PerronProvider's; and each left-out prop can join later without a break.

`SliderProps` extends `Slider.Root.Props` without `value`, `defaultValue`, `onChange`, `onValueChange`, `onValueCommitted`, `orientation`, `thumbAlignment`, `locale`, `disabled`, `children` and `ref`. `value`, `defaultValue` and `locale` are declared again with Perron's types and default; `onValueChange` and `onValueCommitted` become `onChange` and `onChangeCommitted`, the declared `onChange` taking the place of the `<div>`'s own React change handler; `disabled` is declared again because it goes to the frame (CR-5); and `children` is left out because Slider renders its own parts, so a caller's children would land inside the `group` beside them. Slider takes no `variant`, `size` or `color`, so its root carries no `data-variant`, `data-size` or `data-color`, and Base UI's state attributes are its data attributes.

## Tokens

One row per part, state and property. The design states the deferred drawing shows are rest, hover, focus, pressed, disabled and invalid, read from these selectors: hover is the thumb's `:hover` inside `@media (hover: hover)`, not while `[data-disabled]`; pressed is the thumb's `:active`, and `[data-dragging]:focus-within`, the thumb being dragged, since a press on the track starts a drag the thumb's `:active` never sees (Base UI's own note in `Slider.Root`); focus is the thumb's `:has(:focus-visible)`, since the input that takes focus is visually hidden (CR-9); disabled is `[data-disabled]`; and invalid is `[data-invalid]`, which Base UI sets inside an invalid field. Highlighted, open and selected don't apply: the slider opens nothing and its value is its place, not a selection.

The control is `size.target-min` tall, padded at each inline end by half the thumb; the track is `size.meter-track` tall, reusing Meter's token with its description widened to "Height of a meter's or a slider's track" through the `design-tokens` skill; and the thumb is a circle the size of Switch's thumb, `size.target-min` less twice `space.050` and twice `border.width.025` (18 px), as `calc()`. The control is the press target, and `size.target-min` meets [Accessibility](../foundations/accessibility.md#rules) across its whole width while the thumb fits inside it; the inline padding keeps the thumb's centre on the track's ends at `min` and `max`, so the thumb never leaves the field's box, where Base UI's default centres it on the control's edge, half outside; a slider's track and a meter's bar side by side on one panel read as the same kind of bar at one height, so one token holds both; and the thumbs of a slider and a switch in one settings panel match, from the same `calc()`, where a `size.thumb` token for both could follow if a third thumb appears.

The track is `color.surface.inset` with no edge, as Meter's; the fill is `color.text.primary`, Meter's neutral fill; the thumb is `color.surface.raised` with a `border.width.050` edge in `color.surface.inverse`, and no shadow; on hover a `color.surface.hover` layer lies over the thumb's fill, and pressed a `color.surface.selected` layer, the contract's quiet-part step; the figure is `typography.data` in `color.text.primary`; and nothing moves with a transition. [Elevation](../foundations/elevation.md#surfaces) puts tracks on `color.surface.inset`, which stands apart from `color.surface.raised` without a border; the ink fill and the thumb's ink edge (17.92:1 on raised, 15.32:1 on inset in light) show the value's place well past 3:1 ([Accessibility](../foundations/accessibility.md#controls-focus-and-status-fills-on-surfaces)), so the track needs no edge of its own; a raised thumb with an ink edge is Switch's on look, a raised thumb on an ink track, turned round; [Elevation](../foundations/elevation.md#shadows) gives `shadow.thumb` to the selected segment alone; the contract's [Pointer feedback](README.md#pointer-feedback) gives a quiet or outline part `color.surface.hover`, then `color.surface.selected`; `typography.data` is Meter's figure, tabular, so a figure keeps its width from one value to the next; and the thumb and the fill follow the pointer at once, where a transition on Base UI's inline place would lag behind a drag, and [Motion](../foundations/motion.md) has no duration for a value the person moves by hand.

Disabled and invalid are states Base UI produces. A disabled slider's fill is `color.text.tertiary`, its thumb's edge `color.text.tertiary` on the `color.surface.raised` fill, its figure `color.text.tertiary` and its cursor `default`, with no hover or pressed layer; an invalid one's thumb edge is `color.status.danger`, its fill and figure unchanged, and a disabled slider keeps its disabled look inside an invalid field. The contract makes disabled a colour, `color.text.tertiary`, never an opacity, and a disabled slider still shows its value by the thumb's place and the fill; the thumb's edge is the slider's edge, which the Fields family turns `color.status.danger` when invalid, as Switch's track edge does, and the error's words beside it say why, so colour is never alone; and Base UI drops `aria-invalid` while the control is disabled, so a disabled slider shows no error, as Switch's does.

## Owned strings

In a range, the two thumbs are named by new owned strings, `minimum` "Minimum" and `maximum` "Maximum", given to Base UI's `Slider.Thumb` through `getAriaLabel` and overridden by `minimumLabel` and `maximumLabel`; and each range thumb's `aria-valuetext` is its formatted value alone, through `getAriaValueText`, in place of Base UI's default, which appends the English words "start range" and "end range". Base UI's guidance names each thumb of a range with its own `aria-label` beside the group's visible label, and the ear hears "Departures per hour, group" then "Minimum, slider, 4"; "Minimum" and "Maximum" fit any quantity, where "From" and "To" fit a time but not a count; Base UI's "start range" is English in every locale, which the owned-strings check would fail in Danish; and a single thumb needs no owned word, since the field's label names it.

| Key       | English   | Override       | Seen or heard where                                                               |
| --------- | --------- | -------------- | --------------------------------------------------------------------------------- |
| `minimum` | "Minimum" | `minimumLabel` | Heard as the name of a range's lower thumb, as "Minimum, slider, 4"; never shown  |
| `maximum` | "Maximum" | `maximumLabel` | Heard as the name of a range's upper thumb, as "Maximum, slider, 12"; never shown |

Both keys are new, described in `en.ts` as `A range slider: the name of its lower thumb, heard as "Minimum, slider, 4".` and `A range slider: the name of its upper thumb, heard as "Maximum, slider, 12".`, with the Danish, Swedish and Norwegian written by the build.

Every other word is the caller's, through `label`, `description` and `error`, or comes from `Intl.NumberFormat` in the slider's `locale` and the caller's `format`, such as the unit in "1.5 km", or is Base UI's message for a failing check, as Field's spec says.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's Slider and Field already move, step, clamp, format and submit the value, name the slider, tie the help and the error to it and mark it invalid, so Slider rebuilds none of it and adds no key, pointer, focus or validation handler.
- **CR-2.** Slider renders Field, from `packages/perron/src/components/Field/Field.tsx`, with `slotProps.field` spread first, then `className` (`pn-Slider-field` before the caller's, with the shared `withClass` helper from `packages/perron/src/internal/nodes.ts`), `disabled`, `label`, `hiddenLabel`, `description` and `error`, and its `slotProps` `label`, `description` and `error` each with its class set the same way, `pn-Slider-<part>` before the caller's, as TextField's CR-2 does. Field's one child is `Slider.Root`. Slider never renders `Field.Root`, `Field.Label`, `Field.Description`, `Field.Error` or `Slider.Label` itself, and passes Field no `optional`.
- **CR-3.** `Slider.Root` holds `Slider.Control`, which holds `Slider.Track`, which holds `Slider.Indicator` and then one `Slider.Thumb` per value, with `index` 0 for a number and 0 and 1 for a pair; then, after the control, `Slider.Value`. The thumbs are counted from `value`, or from `defaultValue` when `value` is left out, and a single thumb for neither.
- **CR-4.** `{...rest}` reaches `Slider.Root` before Slider's own attributes, and every prop `SliderProps` declares is taken out of `rest` first: the frame's (`label`, `hiddenLabel`, `description`, `error`, `disabled`, `slotProps`), none of which reaches the `<div>`, and the slider's (`value`, `defaultValue`, `onChange`, `onChangeCommitted`, `locale`, `minimumLabel`, `maximumLabel`), each passed by name after the spread. `name`, `form`, `min`, `max`, `step`, `largeStep`, `minStepsBetweenValues`, `format`, `thumbCollisionBehavior` and `render` stay in `rest` for `Slider.Root`; `ref`, `style`, `id` and `data-testid` land on the root, and `className` is merged after `pn-Slider` with `withClass`. A slider prop the caller leaves out is left out of `Slider.Root`'s props, never set to `undefined` beside a set one, so an uncontrolled slider stays uncontrolled.
- **CR-5.** `disabled` goes to Field, and so to `Field.Root`, never to `Slider.Root` directly: Base UI then disables every thumb and marks the label, the description, the error and every slider part `data-disabled`, so the whole field turns to the tertiary ink together, as TextField's CR-5 says. `slotProps.field` takes no `disabled` and no `name`.
- **CR-6.** `onChange` and `onChangeCommitted` are adapted once, inside Slider: `onValueChange(value, details)` calls `onChange(details.event, value, details)`, and `onValueCommitted(value, details)` calls `onChangeCommitted(details.event, value, details)`. Base UI's `details.event` for a change carries a `target` with `value` and `name`, so a form library's controller reads `event.target.value`. `details.cancel()` reaches Base UI unchanged.
- **CR-7.** In a range, Slider gives each `Slider.Thumb` a `getAriaLabel` that returns the owned `minimum` for index 0 and `maximum` for index 1, read with `useOwnedStrings({ minimum: minimumLabel, maximum: maximumLabel })` from `packages/perron/src/PerronProvider.tsx`, and a `getAriaValueText` that returns the formatted value alone. Each is set only when the caller's `slotProps.thumb` gives none of `getAriaLabel`, `aria-label` and `aria-labelledby` (for the name) or of `getAriaValueText` and `aria-valuetext` (for the value text), so a caller's own words win; a key Slider doesn't set is left out of the thumb's props. A single thumb gets neither: the field's label names it, and Base UI says its value as a number, or formatted when `format` is given.
- **CR-8.** `Slider.Value`'s children are a function of the formatted values that renders the `valueText` span, the formatted values joined by " – " (Base UI's own join), then the two `aria-hidden` `valueSizer` spans: the formatted `min` and `max` in `locale` and `format`, each written twice with " – " between in a range. The figure's column is then as wide as its widest end, so the track keeps its width while the value moves; a value whose formatted width passes both ends, such as a decimal between two whole ends, may widen it by a digit.
- **CR-9.** The input that takes focus is Base UI's visually hidden `<input type="range">` inside the thumb, so the page's `:focus-visible` ring from `perron.css` would be clipped with it. The thumb draws the ring round itself on `.pn-Slider-thumb:has(:focus-visible)`, with the three tokens the contract names ([Semantic spacing](../foundations/semantic-spacing.md#focus-ring)), and follows the thumb's radius. A thumb focused by a pointer press shows no ring, since Base UI focuses it with `focusVisible: false`; a key press after it brings the ring back, as Base UI restores `:focus-visible`.
- **CR-10.** The control's inline padding is half the thumb, so Base UI's default `thumbAlignment` of `'center'`, which centres a thumb on the control's content edge at `min` and `max`, keeps the thumb inside the field's box. Base UI measures the control's content box, past its padding, so a press in the padding moves the thumb to the nearer end. Slider leaves `thumbAlignment` out of its props (see Props).
- **CR-11.** The control carries `data-base-ui-swipe-ignore="x"`, so inside a bottom [Sheet](sheet.md), Base UI's Drawer ignores a pointer drag that starts on the slider and a touch drag along the slider's axis, and the drag moves the thumb rather than the sheet; a touch drag across it still swipes the sheet. A horizontal slider handles drags along x alone, the value Base UI's Drawer reference gives for one axis. The Sheet's Do and don't row that asks the caller to mark a slider then holds for Slider on its own.
- **CR-12.** Hover and pressed change the thumb alone. The control has a `pointer` cursor and no hover look of its own, as the contract's [Pointer feedback](README.md#pointer-feedback) allows with a reason: a press on the control moves the nearest thumb, which then takes the pressed look while it is dragged, so the press shows on the part that moves; a hover layer across the whole track would read as a change to the range; and in a range, a hover on the track would light both thumbs where one will move. The hover rule excludes `[data-disabled]`.
- **CR-13.** The figure is formatted in `locale`, the caller's or the nearest PerronProvider's from `useLocale()` in `packages/perron/src/PerronProvider.tsx`, as Meter's CR-11 says, so a Danish screen reads "1,5 km"; Slider passes it to `Slider.Root`'s `locale` and to the sizers' formatting, and never formats a number in its own way.
- **CR-14.** The subject story is a single thumb, so the contract story's owned-strings check never hears "Minimum" or "Maximum": the `Range` story's render gets its own test, which runs `expectOwnedStrings` (`packages/perron/src/testing/owned-strings.ts`) on its server-rendered markup in `en`, `da`, `sv` and `nb`, with the label and the description as the caller's words, as Field's CR-12 does.
- **CR-15.** The thumb and the fill change place at once, and the hover, pressed, disabled and invalid looks change at once: no `duration.*` token fits a value the person moves by hand, and a transition on Base UI's inline place would trail behind the pointer, so the CSS has no transition or animation.
- **CR-16.** The track reuses `size.meter-track`, so the build widens that token's description in `packages/perron/tokens/base.tokens.json` from "Height of a meter's track" to "Height of a meter's or a slider's track", through the `design-tokens` skill, and changes no value: one token then holds both bars' height, and its description says who reads it.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                      | Don't                                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use a slider for a number where the place in a range matters more than the exact figure, such as a trail's length or a walking distance | Use a slider for an exact number the person knows, such as a stop number or a year: a number field takes it in one step, where a slider takes many key presses |
| Give a `label` that names the quantity, "Trail length", and put its unit in `format`, so the figure says "1.5 km"                       | Write the unit into the `label` alone ("Walking distance in km"): the figure and the ear then say a bare number                                                |
| Keep the range short enough that each `step` is a place the thumb can be put by hand: a few dozen steps across the field                | Set a `step` so fine that a drag skips values the person wants; give a `largeStep` for long ranges, so Page Up and Shift with an arrow cross them              |
| Act on `onChangeCommitted` when a change starts work, such as a fetch or a redraw of the map                                            | Fetch on every `onChange`: a drag calls it at every step                                                                                                       |
| Give a range as a pair, `[4, 12]`, and let Slider name its thumbs "Minimum" and "Maximum", or give `minimumLabel` and `maximumLabel`    | Name a range's thumbs with `aria-label` on `slotProps.thumb`, which gives both thumbs the same name; use `getAriaLabel` there, which takes each thumb's index  |
| Word an `error` as what to do, "Choose 8 minutes or fewer"                                                                              | Blame the person or say only that it failed ("Invalid value"), against [Content design](../content-design.md)                                                  |
| Put a slider in a bottom [Sheet](sheet.md) as it is: it keeps its drags from swiping the sheet (CR-11)                                  | Wrap it in another element with `data-base-ui-swipe-ignore`, or remove the control's own, which would let a drag along the slider move the sheet               |
| Use a [Meter](meter.md) to show a value the person can't change                                                                         | Use a disabled slider as a meter: it reads as a control that is switched off                                                                                   |
