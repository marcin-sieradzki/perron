# VehicleDot

One vehicle drawn as a dot in its line's colour, its shape saying how fresh the vehicle's data is, one of the five states on [Data states](../foundations/data-states.md), for rows, lists and legends beside the map.

<!-- run notes -->

The design is deferred under ADR 0010 (`docs/adr/0010-unattended-runs-with-design-deferred.md`), so there is no read-back, code map or export: this spec decides the variant property, the layers, the design states and the token for every part. Its sources are the [contract](README.md), [Data states](../foundations/data-states.md), [Accessibility](../foundations/accessibility.md), [Semantic colours](../foundations/semantic-colours.md#line-colours), [Icons](../foundations/icons.md#sizes), [Content design](../content-design.md#data-state-delay-and-disruption-words), `list_tokens`, the installed `@base-ui/react` types for `useRender`, and the merged specs of its siblings in the Transit category, [LineBadge](line-badge.md), [StationIcon](station-icon.md) and [Delay](delay.md). The ROADMAP names it in wave 2, Mylder's vocabulary. An earlier draft of this component was closed; its review's lessons are carried here: the data state is the prop `variant`, since the contract gives `state` to CSS states, the root's forced-colours `color` has its Tokens row, and no signal gets a shape of its own, so it no longer looks like live in forced colours. The maintainer settled the name, the `variant` prop and a shape of no signal's own, with its own `vehicle-dot.no-signal.*` token, added with this spec and recorded on [Data states](../foundations/data-states.md) and [Accessibility](../foundations/accessibility.md#what-a-person-checks).

## Anatomy

Penpot page `Components/VehicleDot`. Family: none, a glyph sized like an icon. Shared parts: none: the dot names its state itself, through the root's `aria-label` (CR-6), so it needs no VisuallyHidden.

The drawing is a `root` board, the glyph box, holding the `dot` and, on the `no-signal` variant, the `cut` through it.

No inner part has a `slotProps` key: the contract keys `slotProps` by inner Base UI part, and VehicleDot has none. A caller restyles it through `className` on the root.

The root is a `<span role="img">` rendered through `useRender`, holding an `<svg>` with the one `<circle>`, so the `render` prop is inherited as on LineBadge, StationIcon and Delay, and a caller who writes the state in words beside the dot passes `aria-hidden` to the root: every merged Transit sibling renders its root as a `<span>` through `useRender` and inherits `render`, a `<span>` can carry `role="img"` and `aria-label`, and the `<svg>` inside is still needed for the timetable-only dash, which a CSS border can't draw from `vehicle-dot.timetable.dash`.

`variant` is the contract's prop for the Penpot `variant` property, its default the first value; the contract gives `state` to CSS states, so the data state is never a prop named `state`. `size` is StationIcon's, the same three values at the same three icon sizes, since both are glyphs set beside text.

`line` is named and typed as LineBadge's and StationIcon's `line`, and optional with no default, as StationIcon's is: one name and type across the three keeps the family consistent, and a default line would draw a dot in a wrong colour and name the wrong line. A dot for one vehicle always takes its line. A dot that stands for a state across many lines, such as ReportStrip's count of live vehicles, has no line to give, so it leaves `line` out and draws in the colour of the text around it: the root sets no `data-line`, no line rule matches, and the dot's `currentColor` is the colour the root inherits, the ink the brand keeps for the interface around the map. It was required until ReportStrip's spec decided this, and making it optional only widens the API.

`size` maps `small`, `medium` and `large` to `icon.size.325`, `icon.size.400` and `icon.size.450`, set as `--perron-icon-size` on the root, default `medium`: `vehicle-dot.inset` is the gap inside a glyph box, the icon steps are the glyph boxes the system has, and StationIcon already takes the same three for the same reason.

The `cut` runs corner to corner of the glyph box, so it crosses the whole dot at every size; at `small`, a 9 px dot, it leaves two halves about 3.7 px wide.

Not read: `vehicle-dot.halo`, `color.data-state.halo` and `color.data-state.outline` are for the map canvas alone, and `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold` are for whoever decides the state (CR-3).

VehicleDot leaves out the `color.data-state.outline` hairline, so a light line colour (M2, F, bus) shows its ring or ageing rim without an outline on a light surface, and the grey of no signal (about 2.4:1 on the light surfaces) stays as the token gives it: the token's description keeps the outline to the map, the state's word always sits next to the dot (CR-5), so the dot is not the only place the state is told, and no signal's cut now tells it by shape as well; a wider outline is a change through the `design-tokens` skill if the drawing shows the faint rings need it.

The timetable-only ring takes `vehicle-dot.timetable.dash` as the token gives it, at every size, though at `medium` its 2.1 px dash and 1.7 px gap fit the 32 px ring about 8.4 times, so the last dash runs into the first: the build reads the token and adds no length of its own, and a dash that closes evenly at each size is a token change of its own, through the `design-tokens` skill, for the design run to decide.

## Component rules

- **CR-1.** Every state keeps one outer size. Each state's radius is `calc(50% - vehicle-dot.inset)` less its own `stroke-inset`, and no signal keeps live's radius, so swapping the state never moves or resizes the dot, and a column of dots lines up.
- **CR-2.** The dot is never interactive: no hover, focus, pressed or selected look, no tab stop, no `tabIndex`. A vehicle the rider can press is a Perron button or link with the dot inside it.
- **CR-3.** VehicleDot draws the state it is given. It never works one out from a timestamp: the caller compares a report's age with `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold`.
- **CR-4.** No halo, outline, trail or pulse: those belong to the map canvas, which draws its vehicles itself and never renders this component.
- **CR-5.** VehicleDot is never the only place a state is told to the eye: a screen writes the state in words next to it, as VehicleDotLabel and VehicleDotLegend will ([Data states](../foundations/data-states.md)).
- **CR-6.** The root is `role="img"` with `aria-label` set to the state's owned string, so a dot on its own is never silent. A caller that shows the same word next to it passes `aria-hidden`, which reaches the root with the rest props, so the word is heard once. The `glyph` is `aria-hidden="true"`.
- **CR-7.** The line colour is set once, as the root's `color`, and the dot draws in `currentColor`; `variant='no-signal'` fills with `color.data-state.no-signal` whatever the line, because a silent vehicle is grey. With no `line`, no line rule matches, and the dot draws in the colour the root inherits, the text's around it. The root always carries `data-variant` and `data-size`, defaults included, and `data-line` when a line is given, and the CSS selects on them: `.pn-VehicleDot[data-variant='ageing'] .pn-VehicleDot-dot`.
- **CR-8.** No signal is a grey dot cut by a slash: the root's `mask-image` leaves a diagonal gap `vehicle-dot.no-signal.cut-width` wide from the top left of the glyph box to the bottom right, so the surface beneath shows through it, whatever that surface is. No other state has a cut, and no signal never takes a ring or a dashed ring, which mean estimated and timetable only. The cut is not mirrored in right-to-left text: it is a mark, not a direction.
- **CR-9.** In forced colours each state keeps a shape of its own. Inside `@media (forced-colors: active)` the root sets `forced-color-adjust: none` and `color: CanvasText`, with a line or without one, so live, ageing, estimated and timetable only keep their fills, opacity and rings in the system's text colour, and no signal's dot fills with `currentColor`, cut by its slash: a cut dot beside live's whole one, apart without relying on one system colour against another.
- **CR-10.** The props type declares `variant`, `line`, `size` and the five `*Label` props, and each is taken out of the rest props before the merge, so none reaches the DOM; the root merges the rest props first and its own class, role, `aria-label` and data attributes after them, as LineBadge and StationIcon do with `mergeProps`.
- **CR-11.** The `ForcedColours` story reads the stylesheets' `(forced-colors: active)` rules for `.pn-VehicleDot` and applies them as an adopted stylesheet while its `play` runs, since a play test cannot turn forced colours on, and takes the sheet off after, pass or fail.

No signal's shape is a dot cut by a diagonal slash, from the top left to the bottom right, `vehicle-dot.no-signal.cut-width` (1.6 px) wide, drawn as the root's mask (CR-8): a cut reads at the smallest dot, the 9 px one at `small`, where a cross would leave four specks and a hollow square would read as a ring and change the dot's outline; it reuses neither ring nor dashed ring; a slash is the common sign for "off", as on a muted microphone or a lost connection; and a mask cuts it to whatever surface lies beneath, in a row, a panel or a legend, with no colour of its own.

The cut shows in every theme, not only in forced colours, so the [Data states](../foundations/data-states.md) table reads "A grey dot cut by a slash" for the map canvas too: the cut takes ink away rather than adding it, so the map grows no busier, and outside forced colours the grey alone leaves no signal close to an ageing regional train (`#232C31` at 0.42 over a light surface is about `#A3A6A8`, beside no signal's `#9AA4A9`), told apart only by the ageing rim; one shape everywhere keeps the legend and the map saying the same thing.

In forced colours, no signal's dot fills with `CanvasText`, like every other state, rather than `GrayText` (CR-9): the cut carries the state, and `GrayText` can sit close to `Canvas` in a custom contrast theme, where a grey dot would fade, while `GrayText` against `CanvasText` measures about 1.5:1, too close to tell apart.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                   | Don't                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Write the state in words next to the dot, or use VehicleDotLabel, which will                                         | Show a dot alone in a list and trust its shape to carry the state: a state is always written in words beside it    |
| Pass `aria-hidden` when the state's word is already beside the dot                                                   | Let a screen reader hear "Live" twice, once from the dot and once from the text                                    |
| Name the line in words nearby, such as in a LineBadge                                                                | Let the dot's colour be the only sign of the line: several line colours miss 3:1 on the light surfaces             |
| Leave `line` out for a dot that stands for a state across many lines, such as a count of live vehicles               | Leave `line` out of one vehicle's dot: it would lose its line's colour, which the map and the rows share           |
| Work out the state from the report's age with `vehicle-dot.live-threshold` and `vehicle-dot.ageing-threshold`        | Pass `live` for a vehicle whose last report is minutes old: the dot would claim more than the data knows           |
| Keep the ring, the dashed ring, the cut dot and `color.data-state.no-signal` for a vehicle's data state              | Draw a ring, a dashed ring or a slashed dot to mean anything else, such as a stop, an option or a disabled control |
| Pick the `size` that matches the text beside it: `small` for captions, `medium` for labels, `large` for panel titles | Resize it with `className` or a raw width, which breaks its stroke widths against its icon-sized neighbours        |
| Draw vehicles on the map canvas with the map's own dot sizes and halo                                                | Render a VehicleDot per vehicle on the map: it is for rows, lists and legends                                      |
| Wrap the dot in a Perron button or link when the rider can open the vehicle                                          | Add `onClick` or `tabIndex` to the dot: it has no focus ring, role for a control or target size                    |
