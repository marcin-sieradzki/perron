# FilterChip

A pill that turns one filter on and off, such as "Delays" in the top bar's filters, with an optional icon before its words and a count after them, drawn in ink when it is on.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens, the Base UI reference for `Toggle` and the ROADMAP line that names it (`ROADMAP.md`, "Wave 3, interactive, on Base UI": "FilterChip and HighlightChip (Toggle)"). The extracted prototype component is not in any branch this run can reach, so nothing here rests on it. The foundations already name much of its look: [Layout](../foundations/layout.md#other-layout-properties) gives `size.control` to "icon buttons and filter chips", [Semantic spacing](../foundations/semantic-spacing.md#radius) rounds "chips" with `radius.full`, [Typography](../foundations/typography.md#roles) sets "chips" in `typography.label` and "counts in chips" in `typography.data-sm`, and [Elevation](../foundations/elevation.md#surfaces) makes `color.surface.inverse`, with `color.text.inverse`, the fill of "pressed toggles".

## Anatomy

Penpot page `Components/FilterChip`. Family: none (the contract's [Families](README.md#families) have no chips; a chip is a pill-shaped toggle button, and takes Button's ink treatments on a `radius.full` edge, see Tokens). Shared parts: none (every word is the caller's, and the count is text the chip is named by).

The drawing has a `root` board holding, in reading order, a `startIcon` layer, a `label` text layer and a `count` layer, an instance of [Count](count.md). Its one variant property is `State`, with the values `default`, `hover`, `focus`, `selected` and `disabled`, so its variants are `Default`, `Hover`, `Focus`, `Selected` and `Disabled`. There is no `variant`, `color` or `size` property (see [Props](#props)).

| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ | ------------------------- | --------------- |

| `startIcon`         | A `<span>`, `aria-hidden`, that holds the caller's `startIcon` before the label; only rendered when `startIcon` is given                                                                   | none: a span inside `Toggle`, which has no parts | `pn-FilterChip-startIcon` | none            |

The count composes Count rather than drawing a pill of its own, so every count in a chip has Count's one shape.

FilterChip takes `count?: number`, typed as Tab's `count` is, and renders it as a neutral Count, so `Count` joins its `dependsOn` in `packages/perron/components.json`: Count's own spec names "the '3' after 'Delays' in a filter chip" as its use, and a count the caller builds into `children` would differ from screen to screen.

## Base UI parts

Imported from `@base-ui/react/toggle`, at the version pinned in `packages/perron/package.json` (1.9.0 installed).

| Base UI part | Renders                                                                                                                                                                                                                | Perron sets                                                                                                                                                                                                                                                | Passed through                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `Toggle`     | `<button type="button">`, with `aria-pressed` (`"true"` or `"false"`), `data-pressed` while on and `data-disabled` and the native `disabled` while disabled; with `render` and `nativeButton={false}`, `role="button"` | `className` (`pn-FilterChip`, then the caller's), `style`, `ref`, `pressed` from `selected`, `defaultPressed` from `defaultSelected`, `onPressedChange` adapted from `onChange`, `disabled`, and the children: the icon span, the label span and the Count | `render`, `nativeButton`, `onClick`, `aria-label` and every other prop of a native `<button>`, through `{...rest}` |

Base UI already does: it renders a native `<button>` with `type="button"`, and drops a caller's `type` and `form`, so a chip never submits or joins a form; a click, or Enter or Space through the browser's click, flips the pressed state and calls `onPressedChange(pressed, details)` with `details.reason` `'none'` before it commits, so `details.cancel()` keeps the state as it was; `pressed` given controls the state and `defaultPressed` (default `false`) seeds it uncontrolled; it sets `aria-pressed` from the state and `data-pressed` while pressed; when disabled it sets the native `disabled` and `data-disabled`, so the chip leaves the tab order and its clicks are stopped (Toggle has no `focusableWhenDisabled`: the installed `Toggle` sets `focusableWhenDisabled: false` in its metadata); with `render` and `nativeButton={false}` it gives a non-button element `role="button"`, a `tabIndex` and Enter and Space activation; inside a Base UI `ToggleGroup` it reads the group's value by its `value` prop instead, which FilterChip does not offer (see [Props](#props)).

## Props

In MUI's layout. Every prop here gets this description as its JSDoc. No slots: Toggle is the root and has no inner parts, and the icon span, the label span and the Count are not Base UI parts.

FilterChip's state is `selected`, `defaultSelected` and `onChange(event, value, details)`, mapped onto Toggle's `pressed`, `defaultPressed` and `onPressedChange`, with none of Toggle's three names exposed: `selected` is MUI's ToggleButton prop and the contract's design state for a chosen item, where `pressed` is the contract's name for a momentary press (`:active`); `onChange` with `(event, value, details)` is the contract's event shape, its `value` the new `selected` state, a boolean, and `event` being `details.event`, as Tabs adapts `onValueChange`; the contract's [Names from other libraries](README.md#names-from-other-libraries) leave all three free, and `value` and `defaultValue` are kept for a string a group chooses.

FilterChip leaves out Toggle's `value`, which only identifies a toggle inside a Base UI `ToggleGroup`: Perron offers no group of filter chips, a top bar's chips each filter on their own, and outside a group `value` does nothing, so a caller who sets it would be misled; the API only grows, so a group can bring it later.

FilterChip takes `startIcon` alone, with no `endIcon`: the count is what follows the words, an icon after them would sit between the label and the count, and the disruption icons a filter shows go before its name, as the contract's `startIcon` does; `endIcon` can join later without a break.

FilterChip comes in one look, with no `variant`, `color` or `size`: [Layout](../foundations/layout.md#other-layout-properties) gives filter chips one height, `size.control`, the [brand](../foundations/README.md#the-brand) keeps the interface ink and glass with yellow for the one main action, which a filter never is, and status colours belong to the Count's figure and the caller's words, not to the chip; each prop can join later without a break.

FilterChip has no `name`: Base UI's Toggle drops `form` and has no hidden input, so a chip's state never reaches a native form, and the contract asks `name` only of a control whose value a form submits.

## Tokens

One row per part, state and property. States are the contract's design states; the deferred design's `State` values map so: `default` is rest, `hover` is `:hover` inside `@media (hover: hover)`, `focus` is `:focus-visible`, `selected` is Base UI's `[data-pressed]`, `disabled` is `[data-disabled]`; pressed, which the design doesn't draw, is `:active`. Every `color` row but the `count` rows sets the root's `color`, which the label and the icon take, since icons draw in `currentColor`; a `count` row sets the Count's own `color` (CR-9).

The selected design state is read from Toggle's `[data-pressed]`, the momentary press from `:active` alone, and FilterChip sets no `data-selected` of its own: on Base UI's Toggle `data-pressed` means "on", not the press the contract's [Design states](README.md#design-states) table files it under, Base UI sets it in both controlled and uncontrolled use where a `data-selected` of Perron's would need the state FilterChip doesn't keep when uncontrolled, and the selector stays one class then an attribute, `.pn-FilterChip[data-pressed]`.

The chip takes Button's two neutral treatments on a pill: off, Button's `outline` (transparent, a `border.width.025` edge in `color.border.control`, `color.text.primary`, `color.surface.hover` on hover and press); on, Button's `solid` (`color.surface.inverse` with `color.text.inverse`, `color.surface.inverse-hover` on hover and press); disabled, Button's disabled outline when off and disabled solid when on. [Elevation](../foundations/elevation.md#surfaces) gives `color.surface.inverse` to pressed toggles, `color.border.control` is the edge "that shows where a control is" and reaches 3:1 where an off chip on the top bar's glass would otherwise not show at all, and borrowing Button's rows keeps one ink language across the library.

The chip's icon is `icon.size.325`: [Icons](../foundations/icons.md#sizes) gives it to icons "inline with label and caption text: the disruption icons", the icons a filter of disruption kinds shows, drawn on that grid, and an icon is never scaled off its grid; a chip with a 16 px control icon is a later `size` or a new drawing.

A selected chip shows its state by its fill alone, with no tick before the label: the inverse fill moves the chip from about 1:1 to 17:1 against its surface, a change of lightness rather than hue, `aria-pressed` says the state to the ear, Windows' forced colours get a `Highlight` fill, or a `GrayText` one when the chip is disabled too (CR-11), and a tick that appears would widen the chip and move its neighbours, which CR-5 forbids.

- [ ] Every landmark and named region has an accessible name: none here; a chip is neither. The group of chips that holds them is the pattern's, which names it.
- [ ] Every default label can be overridden: none here; FilterChip owns no strings.
- [ ] Every shape the type accepts renders, in every variant: `children` and `startIcon` render a string, an element and a list alike, on and off and disabled; `count` renders `0` and larger numbers alike, and nothing for `undefined`, `NaN` or `Infinity`.

## Owned strings

No owned strings: every word comes from the caller, as `children`, the `count`, or an `aria-label`. FilterChip renders its Count only for a finite number (CR-9), so Count's own "Unknown" never shows inside a chip.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's Toggle already gives the native button, the click, Enter and Space toggling, `aria-pressed`, `data-pressed`, the controlled and uncontrolled state, the cancelable change and the disabled behaviour, so FilterChip rebuilds none of it and adds no key handlers.
- **CR-2.** FilterChip adapts Base UI's `onPressedChange(pressed, details)` into `onChange(details.event, pressed, details)` inside itself, passes `selected` on as `pressed` and `defaultSelected` as `defaultPressed`, and exposes none of `pressed`, `defaultPressed`, `onPressedChange` or `value`: its props type omits them from `Toggle.Props`, with the native `onChange`. It takes no `endIcon`, `variant`, `color`, `size` or `name`.
- **CR-3.** It takes `{...rest}` before its own attributes and its own props out of `rest` first (`selected`, `defaultSelected`, `onChange`, `disabled`, `startIcon`, `count`, `children`; an inherited Base UI prop such as `nativeButton` stays in `rest`, keeping Base UI's default), and merges `className` after `pn-FilterChip`; `ref` reaches the root.
- **CR-4.** The selected look reads Base UI's attribute, `.pn-FilterChip[data-pressed]`, and the momentary press `:active`; FilterChip sets no `data-selected`, `data-variant`, `data-color` or `data-size`, having none of those props.
- **CR-5.** The states keep the chip's geometry: hover, pressed, focus, selected and disabled change colours only, never the height, padding, gap, border width, radius, typography or weight, so turning a filter on never moves its neighbours. Every state draws the `border.width.025` border, `transparent` when selected, so on and off share one box. In Windows' forced colours an off chip's border takes the system's edge, while a selected one, which keeps its `transparent` border under `forced-color-adjust: none`, shows by its fill (CR-11). The selected state is the fill alone: no tick or other mark appears before the label.
- **CR-6.** Hover is read inside `@media (hover: hover)`; pressed (`:active`) takes the hover tokens of the chip's state, off or on, in a rule outside it, so a touch press shows. Neither applies to a disabled chip: both rules exclude `[data-disabled]`, since a native disabled button still matches `:hover`.
- **CR-7.** Focus uses the ring `perron.css` draws on `:focus-visible`; the component draws no ring of its own and never removes the outline.
- **CR-8.** The colour is set on the root's `color`; the label and the icon take it through `currentColor`, and no rule sets a colour on an icon. The icon span is `aria-hidden="true"`, rendered only when `startIcon` is given, and sets `--perron-icon-size` to `icon.size.325`.
- **CR-9.** The count is a [Count](count.md) with its default `color`, given `className="pn-FilterChip-count"`, rendered only when `count` is a finite number, `0` included, after the label with a space between in the markup, not only the CSS gap, so the chip's name is "Delays 3", which a `play` test checks. `.pn-FilterChip[data-disabled] .pn-FilterChip-count` sets its `color` to `color.text.tertiary`; besides it, only CR-11's forced-colours rules reach inside the Count, setting its `forced-color-adjust`, `color` and `outline-color`. `Count` joins FilterChip's `dependsOn` in `packages/perron/components.json`, and `npm run registry` runs after.
- **CR-10.** The label stays on one line (`white-space: nowrap`), the chip growing with it, rather than wrapping inside the fixed `size.control` height: a chip sizes to its content beside others in a row, and the row that holds the chips wraps (`flex-wrap: wrap`), which is the caller's or the pattern's.
- **CR-11.** In `@media (forced-colors: active)`, a selected chip that is not disabled takes `Highlight` with `HighlightText` and `forced-color-adjust: none`, on hover and press too, since forced colours drop its inverse fill and the selected state would vanish ([Accessibility](../foundations/accessibility.md#what-a-person-checks)), and its focus ring takes `CanvasText`, since `none` would leave the ring in the theme's ink, which a dark contrast theme's `Canvas` hides, where that page asks the ring to show. A disabled chip that is off takes a `GrayText` edge and words on `Canvas`; a disabled chip that is on takes a `GrayText` fill with `Canvas` words, under `forced-color-adjust: none`, so the selected state still shows when the chip is disabled. Since `forced-color-adjust` is inherited, the count of a selected chip sets it back to `auto`, and the system draws it as every Count, in system colours; a disabled chip's count takes `GrayText` for its figure and the outline that is its edge in forced colours.
- **CR-12.** Changes of state are immediate: no `duration.*` token fits a chip's state change, so the CSS has no transition.
- **CR-13.** The chip sizes to its content (`display: inline-flex`, `align-items: center`), with `box-sizing: border-box`, so the border sits inside `size.control`. Placing chips in the top bar and hiding the "Later" ones under `breakpoint.desktop` belong to the pattern that uses them.

## Stories

| `Disabled`         | Off, disabled                                                                                                                                                                                 | The chip has the native `disabled` and `data-disabled`, Tab skips it, and a click neither changes `aria-pressed` nor calls `onChange`                                                                                                                                                                                                                                                                                                                                  |
| `SelectedDisabled` | On and disabled                                                                                                                                                                               | The chip keeps `aria-pressed="true"` and `data-pressed`, has `data-disabled`, its computed background is `color.surface.inset`, and a click changes nothing                                                                                                                                                                                                                                                                                                            |
| `Controlled`       | A chip given `selected` and `onChange` from the story's state                                                                                                                                 | A click calls `onChange` with `true` and `details.reason` `'none'`; `aria-pressed` changes only once the story sets `selected`, and a chip whose caller ignores the change, given `selected` of `false`, stays off; an `onChange` that calls `details.cancel()` keeps the state; the story ends off                                                                                                                                                                    |
| `LabelOnly`        | "Planned works", with no icon and no count                                                                                                                                                    | No icon span and no count render, nor does a count for a `count` of `NaN` or `Infinity`; the name is "Planned works"; the chip is at least `size.target-min` square                                                                                                                                                                                                                                                                                                    |
| `Row`              | Three chips in a 320 px container that wraps: "Delays" with a count of 3 and the `warning` icon, "Diversions" with 2 and the `diversion` icon, "Planned works" with 0 and the `calendar` icon | Each label stays on one line; the chips wrap onto a second row rather than overflow (the container's `scrollWidth` equals its `clientWidth`); the count of 0 shows; Tab moves through the three chips in reading order                                                                                                                                                                                                                                                 |

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                       | Don't                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Use FilterChip for a filter people turn on and off on its own, such as showing delays on the map                                         | Use it to pick one of several views or modes: that is one choice, a SegmentedControl's, and chips would let two be on at once   |
| Keep the label the filter's name, the same on and off, in sentence case: "Delays", "Planned works"                                       | Change the label to say the state ("Delays on"): `aria-pressed` and the fill already say it, and a changing label moves the row |
| Give the count as `count`, so every chip's count has Count's shape and is heard after the label                                          | Build a count into `children`, or pass a guess when the number is unknown: leave `count` out, and the chip shows none           |
| Use the [content design](../content-design.md) words for kinds of disruption and data states, so the chips agree with the rest of Mylder | Coin a filter name of your own for a kind the table names                                                                       |
| Lay a row of chips out with `flex-wrap: wrap` and a gap, and name the group in the pattern that holds it                                 | Put chips in a [Toolbar](toolbar.md) or make them one tab stop: each is a filter of its own, reached with Tab                   |
| Use a [Tag](tag.md) to mark a property that can't be pressed                                                                             | Use a FilterChip as a label: a chip invites a press, and one that does nothing misleads                                         |
| Disable a chip only while its filter can't apply, and say why nearby                                                                     | Disable a chip to show a count of 0: show the 0, since a disabled chip leaves the tab order and can't explain itself            |
| Keep `onChange` for the filter's state, and cancel it with `details.cancel()` when the change must not happen                            | Set `aria-pressed` yourself or toggle a class: Base UI keeps the state and the attribute in step                                |
