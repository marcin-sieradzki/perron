# Checkbox

A box with its words beside it that turns one setting or one answer on and off, such as "Show planned works on the map", ticked when it is on and dashed when it stands for a set that is partly on, and submitted with a form.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens and the Base UI reference for `Checkbox` (`@base-ui/react` 1.9.0, installed). No ROADMAP wave line names Checkbox; the contract names it twice, as a composite control that carries a `name` ([State and events](README.md#state-and-events)) and as the first user of the `CheckboxIndicator` shared part ([Shared parts](README.md#shared-parts)). The extracted prototype component is not in any branch this run can reach, so nothing here rests on it. Its registry entry lists `Checkbox.Root` and `Checkbox.Indicator` and depends on nothing; CheckboxGroup, which depends on it, composes Checkboxes inside a Fieldset.

## Anatomy

Penpot page `Components/Checkbox`. Family: none (the contract's [Families](README.md#families) have no checkable control; the box borrows the Fields family's edge and hover, see [Tokens](#tokens)). Shared parts: `CheckboxIndicator`, the box with its tick or dash.

The drawing has a `root` board holding, in reading order, an `indicator` layer, an instance of the `CheckboxIndicator` part, and a `label` text layer. Its one variant property is `State`, with the values `default`, `hover`, `focus`, `checked`, `indeterminate`, `disabled` and `invalid`, so its variants are `Default`, `Hover`, `Focus`, `Checked`, `Indeterminate`, `Disabled` and `Invalid`. There is no `variant`, `color` or `size` property (see [Props](#props)).

The label is the caller's `children`, rendered inside the root, Base UI's `<span role="checkbox">`, after the box, so the whole row is one control, named by its own text, toggled by a click anywhere on it and ringed as one when focused. A role of `checkbox` takes its name from its content, so the label needs no `<label>` element, `id` or `aria-labelledby`, and Base UI finds no label to wire; the row, not the 16 px box, is the target, so it meets `size.target-min` with any label; and the contract has visible content come from the caller as `children`. The cost is that a checkbox's content is presentational: a link inside the label would be flattened into its name and can't be reached, so a link goes beside the checkbox (see [Do and don't](#do-and-dont)). The alternative, MUI's bare box with a separate label component, would need a second component Perron doesn't have. A checkbox with no `children` is the box alone and takes its name from `aria-label`, `aria-labelledby` or a `<label htmlFor>` on its `id`.

The box is drawn by the new `CheckboxIndicator` shared part, in its own folder under `packages/perron/src/parts/`, which Checkbox renders through `Checkbox.Indicator`'s `render` callback with `keepMounted` on, passing the part a `mark` of `'tick'` while checked, `'dash'` while indeterminate and none otherwise, read from the indicator's state. The contract's [Shared parts](README.md#shared-parts) table gives the box with its tick or dash to `CheckboxIndicator`, composed in `Checkbox.Indicator` and later in `Menu.CheckboxItemIndicator`, and says the first part that needs the tick adds it; Base UI's `Checkbox.Indicator` unmounts while unchecked unless `keepMounted` is set, and the part has to stay to draw the empty box; Base UI passes the indicator's `data-checked`, `data-unchecked`, `data-indeterminate`, `data-disabled`, `data-readonly` and `data-invalid` onto the element the callback returns, so the part's CSS reads its states from them with no props for each; and a `mark` read from the state renders one icon, not two with one hidden. Checkbox's own CSS sets only the indicator's place in the row, on its own class `pn-Checkbox-indicator`, never a fill, edge, radius or mark, which the shared-parts check keeps in the part's folder.

## Props

In MUI's layout. Every prop Checkbox declares gets this description as its JSDoc; every one it inherits from Base UI keeps Base UI's, which the inherited rows give. Slots come last.

Checkbox's state takes Base UI's and MUI's names, `checked`, `defaultChecked` and `indeterminate`, inherited as they are, and the contract's `onChange(event, value, details)`, adapted from Base UI's `onCheckedChange`, its `value` the new checked state, a boolean, and `event` being `details.event`. `value` stays Base UI's and MUI's: the string a checked box submits, as on a native checkbox, since a checkbox's state is `checked`, not a value.

Checkbox takes no `variant`, `color` or `size`, and leaves out Base UI's `parent`, inheriting the rest of `Checkbox.Root`'s props as they are. One look keeps the box's ink and its 16 px with `typography.body` text everywhere a setting or an answer is asked: the [brand](../foundations/README.md#the-brand) keeps yellow for the one main action, which ticking a box never is, and a status colour on a box would say something the label should; `parent` only works inside a Base UI Checkbox Group, which CheckboxGroup brings with its own spec and can add then; and the API only grows, so each can join later without a break.

## Tokens

One row per part, state and property. States are the contract's design states; the deferred design's `State` values map so: `default` is rest, `hover` is `:hover` inside `@media (hover: hover)` on the root, `focus` is `:focus-visible` on the root, `checked` is Base UI's `[data-checked]`, the selected design state, `indeterminate` is `[data-indeterminate]`, `disabled` is `[data-disabled]` and `invalid` is `[data-invalid]`; pressed, which the design doesn't draw, is `:active` on the root. The `indicator` rows are the `CheckboxIndicator` part's CSS, reading the attributes Base UI puts on it, its hover and press read from the element that holds it (CR-6); the `root` and `label` rows are Checkbox's.

The box's side is `size.checkbox`, a new base token of `16px`, "The box of a checkbox, and of a menu's checkbox item", added through the `design-tokens` skill and listed in the size marker on [Layout](../foundations/layout.md#other-layout-properties). No `size.*` token holds a box this small, and an `icon.size.*` token would size a control by an icon's step; 16 px is a little taller than the 14 px text of `typography.body` and fits inside its 21 px line, and with the row as the target (CR-9) it needs no extra room of its own.

The tick and the dash are two new icons, `tick` and `dash`, drawn on the 14 px grid with a 1.8 px round stroke and shown at `icon.size.325` inside the box, each a file in `packages/perron/icons/` that joins `icons.json` under a new "Controls" category, with the contract's [Shared parts](README.md#shared-parts) row naming "the dash icon" beside "the tick icon", so both stay in the part's folder. The contract says the first part that needs the tick adds it, following [Icons](../foundations/icons.md); `icon.size.325` is the step for marks inline with text, and on its grid the tick leaves a clear margin inside a 16 px box, where a 16 px control icon would touch the edge; `minus`, the zoom-out icon, is drawn on the 16 px grid, and scaling it to the tick's step would break the rule that an icon is never scaled off its grid; and a dash drawn beside the tick keeps one stroke weight in the box.

The box takes the Fields family's edge and hover while unticked, a `color.surface.raised` fill with a `border.width.025` edge in `color.border.control`, `color.surface.hover` laid over the fill as a `linear-gradient` background-image on hover and press, and `radius.xs`, and turns ink while ticked or indeterminate, `color.surface.inverse` with its mark in `color.text.inverse` and a `transparent` edge, `color.surface.inverse-hover` on hover and press. [Elevation](../foundations/elevation.md#surfaces) sets inputs on `color.surface.raised`, and `color.border.control` is the edge "that shows where a control is", 3:1 or better on every surface; `radius.xs` is the radius for "small marks and ticks", where `radius.md` would round a 16 px box into a circle's look; ink, not yellow, is the [brand](../foundations/README.md#the-brand)'s interface colour and the fill [Elevation](../foundations/elevation.md#surfaces) gives pressed toggles, as FilterChip's on state is, and moves the box from about 1:1 to 17:1 against the surface; and a `transparent` edge keeps one box size while forced colours still draw it.

A disabled checkbox is drawn as FilterChip's disabled states are: unticked a `transparent` fill with a `color.border.subtle` edge, ticked or indeterminate a `color.surface.inset` fill with its mark in `color.text.tertiary` and a `transparent` edge, and its label in `color.text.tertiary`, with no hover or press. The contract makes disabled a colour, `color.text.tertiary`, never an opacity; a faint edge and an inset fill keep the ticked state readable while disabled; and FilterChip has drawn the same pair for the same states since Wave 3, so one disabled language runs across the library.

An invalid checkbox, inside a Base UI `Field.Root` that marks it so, is drawn with a `color.status.danger` edge, ticked or not, keeping its fill and mark, and no change to its label. The Fields family draws an invalid field's edge in `color.status.danger`, and a ticked box's `transparent` edge takes the same colour, so a required box ticked and still invalid on a later rule shows it; `color.status.danger` reaches 3:1 on every surface; and the error words are the field's, Field's description and error parts, never the box's colour alone.

A read-only checkbox keeps its rest look, unticked or ticked, with no hover or press, and a `default` cursor. The contract's design states have no read-only state; Base UI keeps a read-only checkbox focusable and says `aria-readonly`, so it reads as it is; and a hover that answers a pointer would promise a change the click won't make.

The label is set in `typography.body` with its tracking twin and `color.text.primary`, `space.200` after the box, breaking a word longer than its line with `overflow-wrap: anywhere`, with the root a `max-inline-size: 100%` inline flex row that wraps the label onto more lines beside the box, which stays on the first. [Typography](../foundations/typography.md#roles) sets "sentences and inputs" in `typography.body`, and a checkbox's label is a sentence about a setting rather than a button's name; `space.200`, 8 px, sets the words apart from a 16 px box, a step wider than FilterChip's `space.150` beside a 13 px icon; and HighlightChip's CR-7 found that in an inline flex row `break-word` leaves the words' box as wide as its longest word, where `anywhere` lets a Danish compound break inside a 320 px container.

The root's focus ring is `perron.css`'s, round the box and the label together, on a `radius.xs` root, with the root at least `size.target-min` tall and wide, its block padding `calc((size.target-min - 1lh) / 2)` so one line of label sits centred in it, and the box centred on the label's first line with a block margin of `calc((1lh - size.checkbox) / 2)`. The row is the control (the label question in [Anatomy](#anatomy)), so the ring shows what Space will toggle, and `perron.css`'s ring needs no ring of Checkbox's own; `1lh`, which the contract allows, is the root's own `typography.body` line, 21 px, so one line makes the row 24 px tall and a label-less box keeps that height; and the box on the first line stays beside the start of a label that wraps.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the tick is `aria-checked="true"`, heard as "checked", the dash `aria-checked="mixed"`, heard as "mixed" or "partially checked", the empty box `aria-checked="false"`; the marks are `aria-hidden`, since the state says them; the tertiary colour of a disabled checkbox is `aria-disabled`; the danger edge of an invalid one is the field's error text and `aria-invalid`, never the edge alone.
- [ ] Every landmark and named region has an accessible name: none here; a checkbox is neither. The group of checkboxes is CheckboxGroup's, inside a Fieldset whose legend names it.
- [ ] Every default label can be overridden: none here; Checkbox owns no strings.
- [ ] Every shape the type accepts renders, in every variant: `children` renders a string, an element and a list alike, ticked, unticked, indeterminate and disabled, and nothing at all when it renders nothing, leaving the box alone.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the box kept mounted is the box itself, not a copy, and nothing collapses.
- [ ] Native semantics first: Base UI's `role="checkbox"` on a `<span>`, with a native `<input type="checkbox">` beside it for the form; with `render` and `nativeButton`, a native `<button>`.
- [ ] Focus moves in reading order and returns on close: each checkbox is one tab stop in document order, focus stays on the checkbox it toggles, and it opens nothing to return from.
- [ ] Every target is at least `size.target-min` square: the smallest target is a checkbox with no label, its root `size.target-min` (24 px) square round the 16 px box; with a label, the whole row is the target.
- [ ] Loops stop when the system asks for less motion: none here; Checkbox has no loop and no transition.

## Owned strings

No owned strings: every word comes from the caller, as `children` or an `aria-label`, and the state is heard from `aria-checked`, in the screen reader's own words.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's Checkbox already gives the `role="checkbox"`, the click and Space toggling, Enter submitting the form, `aria-checked` with `mixed`, the hidden input and its form value, the controlled and uncontrolled state, the cancellable change, and the disabled, read-only and required behaviour, so Checkbox rebuilds none of it and adds no key or click handlers.
- **CR-2.** Checkbox adapts Base UI's `onCheckedChange(checked, details)` into `onChange(details.event, checked, details)` inside itself, and exposes neither `onCheckedChange` nor the `<span>`'s native `onChange`: its props type omits `onCheckedChange`, `onChange`, `parent`, `children`, `className`, `style` and `ref` from `Checkbox.Root.Props` and declares its own `onChange`, `children`, `className` (a string), `style` and `ref`, inheriting every other Base UI prop as it is. It takes no `variant`, `color` or `size`, and sets no `data-variant`, `data-color` or `data-size`.
- **CR-3.** It takes `{...rest}` before its own attributes and its own props out of `rest` first (`onChange`, `children`, `className`, `style`, `slotProps`; an inherited Base UI prop such as `checked`, `name` or `nativeButton` stays in `rest`, keeping Base UI's default), and merges `className` after `pn-Checkbox`; `ref` reaches the root, the `<span role="checkbox">`.
- **CR-4.** The indicator is `Checkbox.Indicator` with `keepMounted` and a `render` callback that returns the `CheckboxIndicator` part with the props Base UI passes and a `mark` of `'tick'` while `state.indeterminate` is false and `state.checked` is true, `'dash'` while `state.indeterminate` is true, and none otherwise; `slotProps.indicator` is merged under these with `mergeProps` (`@base-ui/react/merge-props`) through `usePart`, Checkbox's own last, and its class set after the merge by `withClass`, `pn-Checkbox-indicator` first. Checkbox's CSS sets only the indicator's `margin-block` and `flex` on `.pn-Checkbox-indicator`; the box's size, fill, edge, radius, mark and their states are the part's, in its own folder, which no other file names (`npm run gates -- shared-parts`).
- **CR-5.** The `CheckboxIndicator` part draws the box and its mark, the `tick` or the `dash` icon inlined as JSX from its file, unchanged but for `width` and `height`, with the classes `perron-icon` and `pn-CheckboxIndicator-mark`, `aria-hidden="true"` and `focusable="false"`, and draws no mark for none. It sets `--perron-icon-size` to `icon.size.325` and centres the mark (`display: inline-flex`, `align-items: center`, `justify-content: center`). The mark draws in `currentColor`, its colour set on the box. The part takes no state props of its own beyond `mark`, reading its states from Base UI's attributes, so `Menu.CheckboxItemIndicator` can render it the same way later. The build adds both icon files following [Icons](../foundations/icons.md), joins them to `icons.json`, adds "the dash icon" to the contract's `CheckboxIndicator` row, and runs `npm run tokens` to rebuild the set's table.
- **CR-6.** Hover lays its colour on the box when the pointer is over the element that holds it, the whole row, read in the part's CSS as `:hover > .pn-CheckboxIndicator` inside `@media (hover: hover)`; pressed takes the same tokens on `:active > .pn-CheckboxIndicator`, in a rule outside the media query, so a touch press shows. Neither applies to a disabled or read-only box: both rules exclude `[data-disabled]` and `[data-readonly]`.
- **CR-7.** Focus uses the ring `perron.css` draws on the root's `:focus-visible`; the component draws no ring of its own and never removes the outline.
- **CR-8.** The states keep the geometry: hover, pressed, focus, ticked, indeterminate, disabled, read-only and invalid change colours only, never the box's size, the edge's width, the radius, the gap, the padding or the typography, so ticking a box never moves its label. Every state draws the `border.width.025` edge, `transparent` while ticked or indeterminate, so every state shares one box.
- **CR-9.** The root is the target: an inline flex row, `align-items: flex-start`, `justify-content: center`, at least `size.target-min` tall and wide, its block padding `calc((size.target-min - 1lh) / 2)` over its own `typography.body` line, and `max-inline-size: 100%`. The box keeps its size (`flex: none`) and sits centred on the label's first line through its block margin, `calc((1lh - size.checkbox) / 2)`; the label wraps beside it (`min-inline-size: 0`, `overflow-wrap: anywhere`). With no label, the box sits centred in its 24 px square.
- **CR-10.** The label span renders only when `children` renders something (the `given` helper), after the indicator in reading order, so the box sits on the start side in right-to-left text. Its colour is the root's: `color.text.primary`, and `color.text.tertiary` while `[data-disabled]`; read-only and invalid don't change it.
- **CR-11.** In `@media (forced-colors: active)`, a ticked or indeterminate box that is not disabled takes `Highlight` with its mark in `HighlightText` and `forced-color-adjust: none`, since forced colours drop its ink fill and leave a `CanvasText` tick on `Canvas`, where `Highlight` keeps the ticked state as plain as the selected state [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks to show. A disabled box takes a `GrayText` edge, or, ticked or indeterminate, a `GrayText` fill with a `Canvas` mark under `forced-color-adjust: none`, so a disabled ticked box still shows it is ticked; a disabled root's label takes `GrayText`, since the `<span>` isn't natively disabled and the system can't tell. An unticked box keeps the edge the system draws for its border.
- **CR-12.** Changes of state are immediate: no `duration.*` token fits a box's state change, so the CSS has no transition, and the kept-mounted indicator never animates in or out.
- **CR-13.** The cursor is `pointer` on the root, as on SegmentedControl's segments and Tabs' tabs, and `default` while `[data-disabled]` or `[data-readonly]`.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                            | Don't                                                                                                                             |
| --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Use Checkbox for an answer or a setting that is on or off on its own, applied when the form is sent, such as agreeing to a notice             | Use it for a filter on the map that takes effect at once: that is a FilterChip's, pressed and seen at once                        |
| Write the label as what ticking it turns on, in sentence case, the same ticked or not: "Show planned works on the map"                        | Write it as a question or a negative ("Don't show planned works?"): a tick on a negative reads backwards                          |
| Put a link about the setting next to the checkbox, outside its `children`                                                                     | Put a link inside the label: a checkbox's content is flattened into its name, so the link can't be reached or pressed             |
| Give `name`, and `value` where the form needs more than `"on"`, so the answer reaches the form; connect a form library through its controller | Read the state back from the DOM or keep a hidden input of your own: Base UI's hidden input already carries it                    |
| Use `indeterminate` for a box that stands for a set partly on, such as "All lines" over the lines below it, and set it from the set's state   | Use it as a third answer to one question: "mixed" says some of a set, and Space always turns it to ticked or unticked             |
| Show why a box is invalid in words, from its field                                                                                            | Rely on the danger edge alone: colour is never the only sign ([Accessibility](../foundations/accessibility.md#rules))             |
| Group related checkboxes in a CheckboxGroup, whose legend names the group                                                                     | Make a list of checkboxes one tab stop, or use them for one choice among several: that is a radio group's or a SegmentedControl's |
| Keep `onChange` for the box's state, and cancel it with `details.cancel()` when the change must not happen                                    | Set `aria-checked` yourself or toggle a class: Base UI keeps the state, the attribute and the input in step                       |
