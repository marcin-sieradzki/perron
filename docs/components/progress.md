# Progress

A bar that shows how far a task has got, such as an export, with the words that name the task and the share done, such as "Exporting the report" at "45%", or, while how far is not known, that the task is under way.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), [content design](../content-design.md), the tokens and the Base UI reference for `Progress` (`@base-ui/react` 1.9.0, installed, its source read in `node_modules/@base-ui/react/progress/`). Progress has nothing in `dependsOn`, no ROADMAP line names it (it joined the registry with the other feedback components, under Feedback), and the extracted prototype is not reachable from this branch, so nothing here rests on either.

[Meter](meter.md), the other bar along a track on Base UI's same five parts, sets the precedent Progress follows where they meet: the layout, the figure, its locale, the track and its forced-colours rule. Meter's own Do and don't sends a task's progress here. The tokens were read from this branch's `packages/perron/tokens/` files, since the Perron MCP's `list_tokens` lacks `size.meter-track`, added since the main checkout it reads.

## Anatomy

Penpot page `Components/Progress`. Family: none, since it is a static display that sits on its container's surface and joins no family's treatment: it is not pressed, takes no hover and is not one of the Rows, Fields, Popups, Panels or Tooltips. Shared parts: none; the words for a task under way reach the ear through `aria-valuetext`, not through VisuallyHidden (CR-5).

Progress takes Meter's anatomy and layout unchanged: a `root` grid with `label` and `value` on the first row and `track` across both columns on the second, `indicator` inside `track`, the label first in the DOM and on screen. A meter and a progress bar on one panel then read as the same kind of bar, and the figure sits where Meter's does.

The drawing will have a `root` board holding three layers, `label`, `value` and `track`, with `indicator` inside `track`, and one variant property, `State`, whose values `progressing`, `complete` and `indeterminate` map in the code map to Base UI's `[data-progressing]`, `[data-complete]` and `[data-indeterminate]`, and name its variants `Progressing`, `Complete` and `Indeterminate` (`penpot/README.md`, "Conventions"). They are not a prop: Base UI sets them from `value`.

The deferred design draws those three Base UI statuses as its `State` values, `progressing`, `complete` and `indeterminate`, and no other variant property: each is a look Base UI produces from `value` alone, and the contract maps a `State` value to an attribute, never to a prop.

| Part (Penpot layer) | What it is                                                                                                                                                                              | Base UI part         | Class                   | `slotProps` key |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ----------------------- | --------------- |
| `root`              | A `div` with `role="progressbar"`, a two-column grid: the label and the figure on the first row, the track across both columns on the second                                            | `Progress.Root`      | `pn-Progress`           | none            |
| `label`             | A `span` holding the caller's `label`, the task in a few words, such as "Exporting the report"; the progress bar's accessible name                                                      | `Progress.Label`     | `pn-Progress-label`     | `label`         |
| `value`             | A `span` at the inline end of the first row holding the figure Base UI formats, "45%", and nothing while indeterminate (CR-5); `aria-hidden`, since the root's `aria-valuetext` says it | `Progress.Value`     | `pn-Progress-value`     | `value`         |
| `track`             | A `div` across the second row: the whole task, from `min` to `max`, in an inset pill                                                                                                    | `Progress.Track`     | `pn-Progress-track`     | `track`         |

Every part has its Base UI part, so each one's props come through its `slotProps` key and the root takes the component's own. Base UI's root also appends a `span` with `role="presentation"`, its own `visuallyHidden` style (`position: fixed`, `clip-path: inset(50%)`) and the text "x" after its children, as Meter's does. It is no part of Perron's: it has no class, no layer and no `slotProps` key, its fixed position takes it out of the grid, and `expectOwnedStrings` already skips it (CR-9).

`ProgressProps` extends `Progress.Root.Props` without `children` and the members it declares again, and declares `label`, `value`, `locale`, `inProgressLabel`, React's `className`, `style` and `ref`, and `slotProps`; `min`, `max`, `format`, `getAriaValueText`, `aria-valuetext` and `render` are inherited as they are, with Base UI's JSDoc and `@default`. Progress takes no `children`: its content is its four parts, and a caller's children would land after the track inside the `progressbar` role, where a screen reader never reads them.

`label` is required: it is the progress bar's accessible name, and a `progressbar` with no name fails axe's `aria-progressbar-name`. `value` is required too, as Base UI's is, so a caller says `null` on purpose when how far is not known, rather than leaving it out by mistake.

`value` is how far a task has got, not a control's value: Progress has no `defaultValue` and no `onChange`, since nothing the person does changes it. It keeps Base UI's name, as Meter and MUI's `LinearProgress` do.

Progress takes no `color`, `size` or `variant`, its fill always the neutral mark `color.text.primary`: how far a task has got is neither good nor bad news, so no status intent has a meaning to carry, `brand` has no mark, a task that fails is told by the screen's own message in its place, and one track height and one layout serve a panel and a report, as Meter's do; each can join later as an optional prop without a break.

Progress formats the figure in the PerronProvider's locale when the caller gives no `locale`, through the `useLocale()` hook in `packages/perron/src/PerronProvider.tsx`, as Meter does: Base UI's own default, the runtime locale, shows "45%" on a Danish screen in an English browser and can differ between the server's render and the browser's. A caller's `locale` still wins.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the eye gets the label, the figure and the fill's length; the ear the label as the name and the figure as `aria-valuetext`, which Base UI keeps the same text as the shown figure, or a fuller one from `getAriaValueText`. While indeterminate the eye gets the sweeping segment and no figure, the ear "In progress" in place of Base UI's English "indeterminate progress" (CR-5); under reduced motion the resting segment and the words carry it.
- [ ] Every landmark and named region has an accessible name: none here; the root is a `progressbar`, named by its label, not a landmark or region.
- [ ] Every default label can be overridden: `inProgressLabel`.
- [ ] Every shape the type accepts renders, in every variant: `label` is a `ReactNode`, and a string, a number, an element and a list each render in every status; `value` renders `0`, `min`, `max`, a value outside the range (clamped), a fraction, `null`, `NaN` and `Infinity` (the last three indeterminate), which `Progress.test.tsx` renders each of.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the sweep moves one element, and nothing collapses. The figure is `aria-hidden` because `aria-valuetext` says it, not for animation.
- [ ] Native semantics first: no native element says "a task's progress" with Perron's look and Base UI's API (`<progress>` draws its own bar), so Base UI's `role="progressbar"` with its `aria-value*` attributes, and no ARIA of Perron's beyond the `aria-valuetext` of an indeterminate value.
- [ ] Focus moves in reading order and returns on close: Progress takes no focus and opens nothing.
- [ ] Every target is at least `size.target-min` square: no target; Progress is not pressed.
- [ ] Loops stop when the system asks for less motion: the indeterminate sweep, the one loop, stops inside `@media (prefers-reduced-motion: reduce)` in a rule for `.pn-Progress-indicator[data-indeterminate]` that sets its `animation` (CR-6); the fill's change is a transition over `duration.meter`, which the tokens shorten to 0.01 ms.

## Owned strings

Every word Progress shows comes from the caller, through `label`, or from Base UI's formatting of the number, but for the one it announces while how far is not known.

| Key          | English     | Override          | Seen or heard where                                                                        |
| ------------ | ----------- | ----------------- | ------------------------------------------------------------------------------------------ |
| `inProgress` | In progress | `inProgressLabel` | The root's `aria-valuetext` while the value is indeterminate, heard after the label (CR-5) |

The word heard while indeterminate is a new key `inProgress`, "In progress", rather than the existing `loading` ("Loading") or `unknown` ("Unknown"): a progress bar tracks exports and downloads as well as loads, so "Loading" would say more than the screen knows, and "Unknown" would tell the ear the task's state is unknown when only its share is; after the label it reads "Exporting the report, In progress". Agents write its Danish, Swedish and Norwegian in the locale files, and its JSDoc in `packages/perron/src/locale/en.ts` names Progress.

The figure's digits and percent sign carry no letter, so `expectOwnedStrings` passes them in every locale; Base UI's "x" it already skips, and Base UI's English "indeterminate progress" and "indeterminate" never reach the markup (CR-5).

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Progress composes Base UI's five parts in one order, `Progress.Root` holding `Progress.Label`, `Progress.Value` and `Progress.Track`, with `Progress.Indicator` in the track, and never rebuilds what Base UI does: the role, the `aria-value*` attributes, the clamping, the status attributes, the formatting and the label's `id` are Base UI's.
- **CR-2.** Progress sets no `data-color`, `data-size` or `data-variant`: it has none of those props. Its CSS reads Base UI's `data-progressing`, `data-complete` and `data-indeterminate` and nothing of its own.
- **CR-3.** Each inner part's props are its `slotProps` value merged with `mergeProps` from `@base-ui/react/merge-props`, the component's own props last, so its data attributes and children stay, and its class is set after the merge with the `withClass` shared helper, so the caller's `className`, a string or Base UI's function of the part's state, joins after its own, as Meter's parts do. The `usePart` helper renders a plain element, not a Base UI part, so Progress's parts, which read `Progress.Root`'s context, don't go through it.
- **CR-4.** `label`, `value`, `locale`, `inProgressLabel` and `slotProps` are taken out of the rest props before they reach the root, and `{...rest}` comes before Progress's own props, as the contract's [Root](README.md#root) says; the rest, `min`, `max`, `format`, `getAriaValueText` and `aria-valuetext` among them, reach `Progress.Root`.
- **CR-5.** The value is indeterminate when `value` is `null` or a number that is not finite, what the `known` shared helper in `packages/perron/src/internal/nodes.ts` says is no value and what Base UI takes as indeterminate, so Progress tests it with `known` and writes no test of its own; it passes `value` to Base UI as it is. While indeterminate it sets the root's `aria-valuetext` to the owned "In progress", or `inProgressLabel`, after the caller's rest props, so it wins over Base UI's English "indeterminate progress" and over a caller's `aria-valuetext` and `getAriaValueText`, which describe a known value; and it gives the value part a function `children` that returns nothing, after the caller's `slotProps.value`, so Base UI's English "indeterminate" never reaches a caller's function and the row shows the label alone. `0` is a value, not indeterminate.
- **CR-6.** While the value is known, the fill's change eases: the indicator transitions `width` over `duration.meter` with `easing.standard`, which the tokens shorten to 0.01 ms under reduced motion, and the first render does not animate. While indeterminate, the indicator is a segment `40%` of the track wide that runs the `pn-Progress-sweep` keyframes, `inset-inline-start` from `-40%` to `100%`, over `duration.progress-sweep` with `easing.standard`, `infinite`; inside `@media (prefers-reduced-motion: reduce)` a rule for `.pn-Progress-indicator[data-indeterminate]` sets `animation: none` and rests it at `inset-inline-start: 30%`.
- **CR-7.** The label wraps and breaks a word longer than its column (`overflow-wrap: anywhere` on `.pn-Progress-label`, a box that takes its column's width); the figure never wraps (`white-space: nowrap`); the root sizes to its container, so a long label never pushes the figure past the inline end.
- **CR-8.** Inside `@media (forced-colors: active)`, the track draws an `outline` of `border.width.025` in `CanvasText`, and the indicator sets `forced-color-adjust: none` and `background-color: CanvasText`, as Meter's do: forced colours drop backgrounds, so without these the track, the fill and the sweep would vanish. An outline takes no space, so the geometry holds.
- **CR-9.** Base UI's `Progress.Root` appends the text "x" in a visually hidden `span role="presentation"`, which `expectOwnedStrings` in `packages/perron/src/testing/owned-strings.ts` already skips, as it does Meter's. A test that reads Progress's words through the `heard` helper reads the label part, not the root, which holds the "x". `expectOwnedStrings` reads `aria-valuetext`, so the owned "In progress" is held to the dictionary in every locale.
- **CR-10.** Progress is not a live region, sets no `aria-busy` and never moves focus. A screen announces the start and the end of a task in its own polite live region, as [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks, and marks the region the task fills `aria-busy` itself if it needs to.
- **CR-11.** The figure is formatted in `locale`, the caller's or the nearest PerronProvider's, so a Danish screen reads "45 %" and an English one "45%"; Progress passes it to `Progress.Root`'s `locale` and never formats the number itself.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                              | Don't                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Use Progress for a task the person waits on that ends, such as an export or a download                                          | Use it for a measure within a range, such as the share of vehicles reporting live: that is a Meter, a measurement rather than a task      |
| Pass `null` while how far is not known, so Progress sweeps and says "In progress"                                               | Pass `0` or a guess: an empty fill at "0%" claims a figure the task never gave                                                            |
| Name the task in a few words in `label`: "Exporting the report", "Loading the network"                                          | Leave the name to the layout: a progress bar with no name tells the ear a number and nothing about the task                               |
| Announce the start and the end of the task, such as "Report ready", in the screen's own polite live region                      | Make a Progress a live region: a figure that counts up every moment floods the screen reader                                              |
| Replace the bar with the screen's own message when the task fails, and say what happened                                        | Leave a bar at its last figure, or tint it, when the task fails: the eye reads it as still running, and colour tells no screen reader     |
| Give `getAriaValueText` the fuller words when the figure shows them, such as "3 of 12 files" through `slotProps.value.children` | Change the shown figure and leave the ear on the percentage: the eye and the ear then hear different numbers                              |
| Use DataStatePanel's loading status for a view whose data has not arrived                                                       | Put an indeterminate Progress in place of a data view's content: DataStatePanel's calm "Loading" message is the library's answer for that |
