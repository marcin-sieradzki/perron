# SearchField

The field that finds a line or a stop: a labelled text input with the search icon, a clear button while it holds text, and a list of suggestions under it that narrows as the person types.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens and the Base UI reference for `Field` and `Autocomplete` (`@base-ui/react` 1.9.0, installed). The extracted prototype component is not in any branch this run can reach.

## Anatomy

Penpot page `Components/SearchField`. Family: Fields, for the input group; Popups, for the list's popup; Rows, for its suggestions. Shared parts: `VisuallyHidden`, for a hidden label; `CloseButton`, for the clear button.

SearchField is a text field whose value is the words typed, with suggestions under it: Base UI's Autocomplete, not its Combobox, which keeps a chosen item as its value. It composes the parts the registry entry lists, `Field.Root`, `Field.Label` and the ten `Autocomplete` parts from `Autocomplete.Root` to `Autocomplete.Empty`, and none of Autocomplete's others: no `Autocomplete.Trigger` or `Autocomplete.Icon`, since the list opens as the person types; no `Group`, `GroupLabel`, `Separator`, `Row` or `Collection`, since the suggestions are one flat list; no `Status`, `Backdrop` or `Arrow`. Groups can join later, as an optional prop, without a break.

The suggestions are data, `items`, and SearchField draws each row, so the caller never writes a row and there is no `SearchFieldItem` component: the contract's rule of a component per child applies to a child the caller writes many times.

`Autocomplete.Root` groups the Autocomplete parts and holds the value and the open state; it renders no element, so it has no layer, class or `slotProps` key. The item's inner spans are named for the item fields they show, `itemLabel` rather than `label`, since `label` is the field's own part.

The clear button composes the `CloseButton` shared part, rendered through `Autocomplete.Clear`'s `render` as `<Autocomplete.Clear render={<CloseButton label={strings.clear} />} />`. It keeps the part's own `size.control` square and looks, SearchField's CSS sets only its place in the row, it is left out entirely while the field is disabled, and the build adds `Autocomplete.Clear` to the part's "Composed in" cell in the contract's Shared parts table. The contract's `shared-parts` check keeps the `close` icon inside `CloseButton`'s folder, so SearchField can't draw a cross of its own; a 34 px square sits inside the 38 px box with a pixel to spare above and below; and the part has no disabled look (Dialog CR-6), while a disabled field takes no clearing, so the button is not rendered rather than shown live.

Base UI already does: it filters `items` against the typed words, as the person types, with a collator in the runtime's locale that ignores case and accents (`contains`), matching each item's `label`; it opens the list when the person types words that aren't blank (reason `'input-change'`) or presses an arrow key (`'list-navigation'`), and closes it when the input is emptied (`'input-clear'`), on Esc (`'escape-key'`), on a press outside the field and the list (`'outside-press'`), when focus leaves (`'focus-out'`) and when an item is chosen (`'item-press'`); it moves a virtual highlight through the rows with the arrow keys, looping back to the input, keeping focus in the input with `aria-activedescendant`, and highlights a row under the pointer; on an item's press, or Enter on a highlighted row, it fills the input with the item's label, calls the item's `onClick` and closes the list; on Enter with no row highlighted it closes the list and lets a form around it submit; on Esc with the list closed it empties the input; it shows the clear button only while the input holds text, keeps it out of the tab order and keeps focus in the input when it is pressed; it places the popup against the input group, below it, flipping above it when there is no room, and gives it `--anchor-width` and `--available-height`; it names the input by the label, puts the field's `name` on the input itself, so the typed words reach a form's `FormData`, and passes `disabled` from `Field.Root` to the input and the clear button; and it announces the empty message politely when it appears.

## Props

In MUI's layout. Every prop here gets its description as its JSDoc. Slots come last.

SearchField is a composite control: its root is `Field.Root`'s `<div>`, and its value is the typed words, reported as `onChange(event, value, details)` adapted from `Autocomplete.Root`'s `onValueChange`, not React's own `onChange` on an `<input>` root. The contract's "Native text" rule fits a value only the `<input>` changes, but Base UI also changes this one from outside the input's own events (it fills the input with a chosen item's label, empties it on Esc and on the clear button, each with a `details.reason`), which React's `onChange(event)` never reports; the contract's Forms rule names a combobox among the composite controls; and the root must hold the label as well as the input. The field's `name` still reaches the `<input>`, so a native form submits the typed words, and form libraries connect through their controller.

From `Autocomplete.Root`, SearchField offers only `items`, `filter`, `value`, `defaultValue`, `onChange`, `open`, `defaultOpen`, `onOpen` and `onClose`. It keeps Base UI's defaults for the rest (`mode` `'list'`, `autoHighlight` `false`, `openOnInputClick` `false`, `submitOnItemClick` `false`, `loopFocus` `true`, `limit` `-1`) and leaves out `readOnly`, `required`, `inline`, `grid`, `virtualized`, `modal`, `itemToStringValue`, `filteredItems`, `onItemHighlighted`, `actionsRef` and `inputRef`. These are what a search for a line or a stop needs; with `autoHighlight` off, Enter on the typed words submits a form around the field, as a search does, and a row is chosen by the arrow keys or the pointer; each prop left out can join later as an optional prop without a break.

`SearchFieldProps` extends `Field.Root.Props` without `children`, `ref`, `invalid`, `validate`, `validationMode`, `validationDebounceTime`, `actionsRef`, `dirty` and `touched`, so `name`, `disabled`, `render`, `className` and `style` are inherited with Base UI's JSDoc, and SearchField has no invalid state. The registry gives SearchField no `Field.Error` or `Field.Description`, so an invalid field could only say so by its red edge, which [Accessibility](../foundations/accessibility.md) forbids as colour alone; a search is never wrong, only empty of matches; and without `required` (left out above), Base UI never marks the field invalid on its own, so `[data-invalid]` never appears and the Fields family's invalid edge is not drawn.

A suggestion is a `SearchFieldItem`, exported from `SearchField.tsx`, of the shape `{ value: string; label: string; description?: ReactNode; startIcon?: ReactNode }`, with `items` typed `ReadonlyArray<SearchFieldItem>` and `filter` typed `((item: SearchFieldItem, query: string) => boolean) | null`. `value` identifies the item and keys its row, so two stops with the same name stay apart; Base UI reads `label` from a `{ value, label }` object on its own, for filtering and to fill the input; `description` is the Rows family's second line; and `startIcon` follows the contract's name for a mark before a label, here a [StationIcon](station-icon.md) or a [LineBadge](line-badge.md). No `disabled` per item: a suggestion that can't be chosen is left out of `items`.

A chosen suggestion is reported by `onItemSelect(event, item)`, called from the item's `onClick` with the click event and the `SearchFieldItem` itself, on a press or on Enter with the row highlighted. `onChange` then carries only the words, with `details.reason` `'item-press'` when an item filled them, and a caller who moves the map to the stop needs the item, not its label, which two items can share. `onSelect` is not used because the root's `<div>` already takes React's `onSelect`, the text-selection event, and no row is ever "selected" in the Rows family's sense: Autocomplete keeps no chosen item.

SearchField takes a required `label` (`ReactNode`) and a `hiddenLabel` boolean, default `false`, that keeps the label for the ear only, rendering it through the `VisuallyHidden` shared part. Every input needs a name, and the label is the only one that never disappears as the placeholder does; Mylder's top bar search shows only the icon and the placeholder, so `hiddenLabel` is how it keeps the name; `hiddenLabel` is MUI's own name for a field without a visible label.

SearchField takes no `variant`, `size`, `color` or `fullWidth`: its root takes its container's width and its box is `size.input` tall. There is one search field look, `size.input` is the one height the layout tokens give a search field, and the contract has a component size to its container, so a caller sets the width on the container or through `className`.

The default filter keeps Base UI's own collator, in the runtime's locale, rather than PerronProvider's locale. PerronProvider exposes no locale to components, only their owned strings, and adding a hook is a change to every component's provider for one prop; the runtime's locale is the person's own; a caller who wants another collator passes it through `filter`.

## Tokens

One row per part, state and property. The design states the deferred drawing shows are rest, hover, focus, open and disabled, for the field, and rest and highlighted, for a row. The Fields family keeps the box's rest look while the list is open, so open is the popup's look, not the box's; the Fields family's invalid edge is not drawn, since SearchField is never invalid (see Props).

The label takes `typography.label` in `color.text.primary`, `space.100` above the box, and the box holds, from its start, the search icon in `color.text.secondary` at `icon.size.400`, `space.300` in from its start edge, the input, `space.200` after the icon, and the clear button, `space.050` in from its end edge. `typography.label` is the contract's type for a name in a list or on a control, and `space.100` keeps the name with its box; `space.300` matches the inline padding of the rows below, so the icon and the rows' text start near one line; the icon is decoration beside the placeholder, so it takes the secondary ink the `CloseButton` takes at rest, and `space.050` sets the 34 px button inside the 36 px between the borders with a pixel above and below.

The list sits `space.100` below the box, as the positioner's `padding-block` rather than a `sideOffset` read in script, with the popup as wide as the box (`inline-size: var(--anchor-width)`) and at most as tall as the room left (`max-block-size: calc(var(--available-height) - 2 * var(--perron-space-100))`). Padding inside the box Base UI measures keeps the gap on whichever side the list flips to, with no script, where MapTooltip's offsets read in script would make its reader a shared helper (the contract's Shared helpers rule); a list as wide as its field reads as the field's own.

A row takes `space.150` above and below and `space.200` at its sides, with `space.200` between its start icon and its text, and the empty message takes `typography.body-sm` in `color.text.secondary`, with the same padding as a row while it holds the message and none while it is empty. Rows of `typography.label` at `space.150` stand about 29 px tall, above `size.target-min`, and a two-line row with its `typography.caption` description stays compact; the empty message is a sentence, not a row, so it takes body text in the secondary ink; and Base UI asks that `Autocomplete.Empty` stay mounted, never `display: none`, so its padding is drawn only on `:not(:empty)`, leaving no gap above the rows.

- [ ] Every shape the type accepts renders, in every variant: `label`, an item's `description` and its `startIcon` render a string, an element and a list alike; a long Danish compound wraps in the label, the rows and the empty message (CR-11).

`clear` is the key `packages/perron/src/locale/en.ts` already has, "A button that clears a field or a filter". `noMatches` is new.

The new key is `noMatches`, "No matches", described in `en.ts` as "A search field's list: shown and announced when no suggestion matches the words typed", with the Danish, Swedish and Norwegian written by the build. It says what happened in plain words and no more than the data knows, in sentence case, as [Content design](../content-design.md) asks; it doesn't address the person, since a hint such as "Try a line number such as 5C." is the caller's, in the placeholder; and it stays apart from `noData`, "No data to show", which a data view says when its data came back empty.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's Autocomplete already gives the filtering, the opening and closing with their reasons, the virtual highlight and the arrow keys, Enter and Esc, filling the box with a chosen label, the clear button's visibility and its focus keeping, the placement and its flipping, the combobox, listbox and option roles and the live empty message, so the component rebuilds none of it and adds no key or pointer handlers.
- **CR-2.** SearchField renders `Field.Root`, holding `Field.Label` and then `Autocomplete.Root`; `Autocomplete.Root` holds `Autocomplete.InputGroup` (the search icon, `Autocomplete.Input`, then `Autocomplete.Clear`) and `Autocomplete.Portal`, which holds `Autocomplete.Positioner`, `Autocomplete.Popup`, and in the popup `Autocomplete.Empty` and then `Autocomplete.List`. The list's child is a function of each matching item that renders an `Autocomplete.Item` with `value` the item and `key` its `value`, holding the start icon span (only when the item gives `startIcon`), then the text span with the label span and the description span (only when the item gives `description`).
- **CR-3.** `{...rest}` reaches `Field.Root` before SearchField's own attributes, and SearchField's own props are taken out of `rest` first (`label`, `hiddenLabel`, `placeholder`, `items`, `filter`, `value`, `defaultValue`, `onChange`, `open`, `defaultOpen`, `onOpen`, `onClose`, `onItemSelect`, `clearLabel`, `noMatchesLabel`, `slotProps`), so none reaches the `<div>`; `name`, `disabled` and `render` stay in `rest` for `Field.Root`. `ref`, `style` and `data-testid` land on the root, and `className` is merged after `pn-SearchField`.
- **CR-4.** SearchField turns `onValueChange(value, details)` into `onChange(details.event, value, details)`, and `onOpenChange(open, details)` into `onOpen(details.event, details)` when `open` is `true` and `onClose(details.event, details.reason, details)` when it is `false`, and exposes neither.
- **CR-5.** Each `slotProps` value is merged with Base UI's `mergeProps` (`@base-ui/react/merge-props`), SearchField's own props last, so a caller's handler runs beside SearchField's and its `className` joins after the part's class. Each part's class is set after the merge, as Dialog, Sheet and MapTooltip do with their own `withClass`, because `mergeProps` joins only class strings and puts the rightmost first: `pn-SearchField-<part>` first, then the caller's `className`, a string or a function of the part's state. On an item, `slotProps.item.onClick` runs, then `onItemSelect(event, item)`.
- **CR-6.** The label gets an `id` from React's `useId`, given to `Field.Label` as its own prop so Base UI registers it as the field's label; the input reads it through Base UI's `aria-labelledby`, and SearchField sets the same id as `aria-labelledby` on `Autocomplete.List`, which Base UI leaves unnamed. With `hiddenLabel`, `Field.Label` renders through `render={<VisuallyHidden />}` with `nativeLabel={false}`, keeping the id and the label's text for the ear.
- **CR-7.** The search icon is an inline `<svg>` drawn from `packages/perron/icons/search.svg`, with the classes `perron-icon` and `pn-SearchField-icon`, `aria-hidden="true"` and `focusable="false"`, in `currentColor`. The clear button is `<Autocomplete.Clear render={<CloseButton label={strings.clear} />} />`, with `const strings = useOwnedStrings({ clear: clearLabel, noMatches: noMatchesLabel })`; it is not rendered while the field is `disabled`, and SearchField's CSS sets only its place in the row (`flex: none`), never its size or colours.
- **CR-8.** The input keeps Base UI's `type="text"`, never `type="search"`, whose browser cancel button would sit beside the clear button, and SearchField gives it `enterKeyHint="search"`, so a phone's keyboard labels its Enter key as a search; `slotProps.input` replaces it.
- **CR-9.** The input group is a flex row, `align-items: center`, the input growing (`flex: 1`, `min-inline-size: 0`) and the icon and the clear button keeping their size (`flex: none`). The input draws no outline of its own (`outline: none`): the ring is the input group's, on `:has(.pn-SearchField-input:focus-visible)`, with `focus.width`, `focus.offset` and `color.border.focus`, as the contract asks of a component that draws its own ring. The group's hover lays `color.surface.hover` over its fill as a `linear-gradient` background-image, inside `@media (hover: hover)` and not while `[data-disabled]`; an open field keeps its rest look.
- **CR-10.** The positioner takes `z-index.dialog` and `padding-block: space.100`, the gap on whichever side the list sits; SearchField passes no `sideOffset` and keeps Base UI's positioning defaults, which `slotProps.positioner` replaces. The popup is `box-sizing: border-box`, `inline-size: var(--anchor-width)`, at most `calc(var(--available-height) - 2 * var(--perron-space-100))` tall, and scrolls (`overflow-y: auto`, `overscroll-behavior: contain`). It draws its `border.width.025` edge as a border, so Windows' forced colours keep an edge round it when they drop its glass and shadow.
- **CR-11.** Long words: the label, a row's label and description, and the empty message wrap (`overflow-wrap: anywhere`), since each box takes its container's width; the input keeps its words on one line (`white-space: nowrap`) and scrolls them, as a native input does.
- **CR-12.** The list opens and closes at once: no `duration.*` token fits a list under a field, so the CSS has no transition or animation and styles neither `data-starting-style` nor `data-ending-style`.
- **CR-13.** In forced colours a highlighted row draws `Highlight` with `HighlightText`, inside `@media (forced-colors: active)`, since forced colours drop `color.surface.hover` and the highlight would vanish.
- **CR-14.** The empty message is always rendered inside the popup, as Base UI asks for its live region, with the owned `noMatches` string as its child; Base UI shows that child only while no item matches. Its padding is drawn on `:not(:empty)` only, and it is never hidden with `display: none`, `hidden` or `aria-hidden`.
- **CR-15.** The portal renders nothing on the server, so the contract story's owned-strings check sees only the label, the input and its placeholder. The stories that open the list check its words in the live DOM: `expectOwnedStrings(popup.outerHTML, locale, callerWords)`, in English and in Danish with no override.
- **CR-16.** The stories' meta sets `parameters: { docs: { story: { inline: false, height: '360px' } } }`, as the contract's [Stories](README.md#stories) asks of an overlay, and each story that shows the list opens it at first render with `defaultOpen` and words in `defaultValue`, beside the field that opens it again.

The input gets `enterKeyHint="search"` from SearchField, as CR-8 says: Mylder is used on phones, the hint costs nothing on a desktop, and `slotProps.input` lets a caller change it.

The list opens and closes at once, with no transition, as CR-12 says: the motion tokens hold the sheet's, the meter's and the map's durations and none for a popup, and Dialog and MapTooltip open at once for the same reason; a new duration goes through the `design-tokens` skill when a design asks for one.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                   | Don't                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Give a `label` that names what is searched, "Search lines and stops", and hide it with `hiddenLabel` only where the icon says enough | Leave the placeholder as the field's only words: it vanishes as the person types, and it is not a name                                       |
| Put a hint in the placeholder as an instruction with an example, "Line or stop, such as 5C"                                          | Put anything the person must remember in the placeholder: it is gone once they type, and drawn in `color.text.tertiary`, below text contrast |
| Act on `onItemSelect`, which gives the item, to move the map to the stop or show the line                                            | Find the chosen item from `onChange`'s words with `'item-press'`: two stops can share a name                                                 |
| Pass `filter={null}` when the suggestions come already matched, such as from a server                                                | Leave Base UI's filter on server results: it hides a match whose label doesn't contain the words, such as a stop found by its old name       |
| Give a short `label` and a `description` that tells two rows apart, "Bus, Husum Torv to Lufthavnen"                                  | Put a link, a button or a field in a row: an option is chosen as a whole, and the keys never reach a control inside it                       |
| Use a [StationIcon](station-icon.md) or a [LineBadge](line-badge.md) as an item's `startIcon`, which carries its own text            | Use colour alone to tell a line from a stop: the mark needs its words, and the row its description                                           |
| Put the field in a `<search>` element, or a `<form role="search">`, when it is the screen's search                                   | Expect SearchField to be a landmark: it is one field, and a screen may hold more than one                                                    |
| Set the width on the container, or through `className` on the root                                                                   | Give the input or the box a width through `slotProps`: the list takes the box's width, and the label the root's                              |
| Keep the field in a `PerronProvider` with the screen's locale, so "Clear" and "No matches" speak it                                  | Translate them with `clearLabel` and `noMatchesLabel` on every instance: those are for one instance's own words                              |
