# Select

The field that picks one value from a short, fixed list: a labelled box showing the chosen option, or a placeholder, that opens a list of options under it, with the field's help and error round it.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens, the Base UI reference for `Select` (`@base-ui/react` 1.9.0, installed) and the spec of [Field](field.md), which the registry entry's `dependsOn` names. The extracted prototype component is not in any branch this run can reach.

## Anatomy

Penpot page `Components/Select`. Family: Fields, for the trigger, the box the person presses; Popups, for the list's popup; Rows, for its options. Shared parts: `VisuallyHidden`, through Field, for a hidden label; `SelectedMark`, for the tick beside the chosen option.

Select composes the [Field](field.md) component for its label, its description, its error and its optional mark, and Base UI's `Select` for the rest: the fourteen parts the registry entry lists, from `Select.Root` to `Select.Separator`. It uses none of Select's others: not `Select.Label`, since Field's label already names the trigger through Base UI's field context; not `Select.Backdrop` or `Select.Arrow`; not `Select.ScrollUpArrow` or `Select.ScrollDownArrow`, since the list scrolls as any list does, by wheel, touch and the keys.

The options are data, `items`, that Select draws as rows, with no item component: each is a `SelectItem` of the shape `{ value: string; label: string; disabled?: boolean }`, and grouped options a `SelectGroup` of the shape `{ label: string; items: ReadonlyArray<SelectItem> }`, with no `startIcon` or `description` on an item for now. SearchField takes its suggestions as data for the same reason, so the two fields read alike; the contract's rule of a component per child applies to a child the caller writes many times, and an option is a value and its words; the trigger shows the chosen option's `label`, so a `label` is a plain string, which Base UI also matches the typed letters against; a start icon and a second line can join later as optional fields without a break.

Select draws a separator between two groups, and none in a flat list or before the first group. The group labels already divide the list for the ear, and a hairline divides it for the eye at the same place; the registry lists `Select.Separator` for this; a caller never places a separator, since the list is data.

`Select.Root` groups the Select parts and holds the value and the open state; it renders no element but Base UI's hidden `<input>`, so it has no layer, class or `slotProps` key. The root carries Field's class first, since Field renders it, then `pn-Select`, then the caller's `className`. The label, the optional mark, the description and the error are Field's parts with Field's classes and looks; Select adds no class to them, and their `slotProps` keys reach Field's own `slotProps`.

The selected mark composes the `SelectedMark` shared part, rendered through `Select.ItemIndicator`'s `render`, as `<Select.ItemIndicator render={<SelectedMark />} />`. Select is the first component to compose it, so the build adds the part, `packages/perron/src/parts/<Part>/` named `SelectedMark`, with its class `pn-SelectedMark` and the set's `tick` icon, which `CheckboxIndicator` added, at `icon.size.325`, as the contract's [Shared parts](README.md#shared-parts) table says, and Select's CSS sets only its place in the row.

Field's label renders for Select as a `<div>` with `nativeLabel={false}`, given through Field's `slotProps.label` under the caller's, so pressing it focuses the trigger without opening the list. Base UI's reference for `Field.Label` advises it for a `<button>` control such as `Select.Trigger`: a native `<label>` fires its clicks on the button, opening the list from a press on its name, and gives the button its `:hover` while the pointer is on the label; the trigger stays named by the label through Base UI's `aria-labelledby`, which needs no `<label>` element; a hidden label is already a non-native span, through Field.

Base UI already does: it opens the list on a press of the trigger (on `mousedown`, so a press, a drag and a release on an option chooses it in one gesture), on Enter or Space on the trigger (`'trigger-press'`), and on ArrowDown or ArrowUp (`'list-navigation'`), and closes it when an option is chosen (`'item-press'`), on Esc (`'escape-key'`), on a press outside the trigger and the list (`'outside-press'`), on a second press of the trigger (`'trigger-press'`) and when focus leaves (`'focus-out'`); on open from the keys it highlights and focuses the chosen option, or the first, and, opened by a press or by `defaultOpen` with nothing chosen, focuses the popup and highlights no row until a key or the pointer reaches one; it moves the highlight and focus through the rows with the arrow keys, without wrapping, and to the first and last with Home and End; it highlights the row under the pointer; it moves the highlight to the next option whose label starts with the letters typed while the list is open, and chooses it at once, without opening the list, while the trigger is focused and closed; it chooses the highlighted option on Enter, Space or a press, sets it as the value, closes the list and returns focus to the trigger; it skips a disabled option when letters are typed, lets the keys reach it, and never chooses it; it keeps the value while `readOnly`, letting the list open and the person browse it; it shows the chosen option's label in the value, from `items`, and the placeholder while nothing is chosen; it names the trigger by Field's label through `aria-labelledby`, and names each group by its label; it locks the page's scroll and blocks presses outside while the list is open (`modal`, by default); it places the list against the trigger, below it, flipping above it when there is no room, and gives the positioner `--anchor-width` and `--available-height`; it puts the field's `name` and the chosen value on its hidden input, so a native form's `FormData` reads them, and marks it `required`; and, inside Field, it takes `disabled` and `name` from `Field.Root`, marks the trigger `aria-invalid` and `data-invalid` while the field is invalid, runs the field's checks on the value, and sets the field's state attributes on the trigger.

Select sets `alignItemWithTrigger={false}` on `Select.Positioner`, as its own prop that a caller's `slotProps.positioner` can't turn back on, so the list always opens under the trigger, as wide as it, as SearchField's does. Base UI's default lays the popup over the trigger with the chosen option on top of the value, for a mouse only, so the list would sit in two places by the input it was opened with; one place under the box is the Fields family's and SearchField's, and keeps the trigger in view; the Tokens table's width, gap and height are drawn for a list under the box, and Base UI ignores `sideOffset` and closes the list on a window resize while it aligns the item.

The list is named by the label, as SearchField's is: Select gives Field's label an `id` from React's `useId` through `slotProps.label`, which Base UI registers as the field's label, and sets the same id as `aria-labelledby` on `Select.List`, which Base UI leaves unnamed.

## Props

In MUI's layout. Every prop here gets its description as its JSDoc. Slots come last.

Select is a composite control: its root is Field's `<div>`, and its value is the chosen option's `value`, reported as `onChange(event, value, details)` adapted from `Select.Root`'s `onValueChange`, as the contract's [State and events](README.md#state-and-events) asks of a select. Its `name` reaches both `Field.Root` and `Select.Root`, as the contract's Forms rule asks, so Base UI's hidden input carries it and a native form submits the chosen value, and form libraries connect through their controller.

`SelectProps` extends Field's props, `FieldProps`, without `children`, `slotProps`, `onChange` and `defaultValue`, so `label`, `hiddenLabel`, `optional`, `optionalLabel`, `description`, `error`, `ref`, and Field's inherited `name`, `disabled`, `invalid`, `validate`, `validationMode`, `validationDebounceTime`, `dirty`, `touched`, `actionsRef`, `render`, `className` and `style`, come with Field's JSDoc, and `slotProps` takes Field's three keys beside Select's. `name` also reaches `Select.Root`, as the contract's Forms rule asks, so Base UI's hidden input reaches `FormData`. Select is a Field round a Base UI control, which is what `dependsOn` says; extending Field's props keeps every field's label, help, error and optional mark one API, reaching Field unchanged, and a prop Field gains reaches Select with no edit; `onChange` and `defaultValue` are a `<div>`'s with another type, and Select declares its own; `children` is the control, which is Select's own; `actionsRef` stays Field's, whose `validate` action a form library calls, and `Select.Root`'s, which closes the list, is left out, the two sharing one name.

Select takes one value only, a `string`, or `null` while nothing is chosen, leaving out Base UI's `multiple`, and leaves out `Select.Root`'s `modal`, `highlightItemOnHover`, `autoComplete`, `form`, `id`, `inputRef`, `actionsRef`, `isItemEqualToValue`, `itemToStringLabel`, `itemToStringValue` and `onOpenChangeComplete`, keeping Base UI's defaults for them. A Mylder select picks one mode, one operator or one order, and the options' values are strings, which a form submits as they are, so no comparison or conversion is needed; Base UI's `modal` default locks the page while the list is open, as a native select does; with `highlightItemOnHover` on, the pointer and the keys share one highlight, the Rows family's; a widened value type (`string[]` for `multiple`) and each prop left out can join later as an optional prop without a break.

Select declares `required` and `readOnly`, both default `false`, passed to `Select.Root`, with `required` apart from Field's `optional`: Select derives neither from the other, and a caller sets one at most. `required` lets Base UI's hidden input fail a form's check while nothing is chosen and tells the ear through `aria-required`, which `optional` can't, since it only draws words; `optional` marks the few fields a person may leave empty, which `required` can't, since Field draws no required mark; Field's own spec asks each dependent to say how the two relate, and the Do and don't says to set one at most, since a required field marked optional contradicts itself; `readOnly` shows a chosen value that the screen won't let the person change while still letting them see the options, which `disabled` hides from the keys.

`placeholder` is a `string`, the caller's, with no owned default, so the trigger shows nothing but its icon while no option is chosen and no placeholder is given. SearchField's `placeholder` is a string, and both are words in a box; a default such as "Choose" would be an owned word that says nothing about the field, which its label already names; Base UI's `Select.Value` shows it in `color.text.tertiary`, a hint beside the label, never the field's name.

Select takes no `variant`, `size`, `color` or `fullWidth`: its root takes its container's width and its trigger is `size.input` tall, the Fields family's one height. So the root carries no `data-variant`, `data-size` or `data-color`, and Base UI's state attributes are its data attributes. No name here is one the contract's [Names from other libraries](README.md#names-from-other-libraries) table bans: `onValueChange` and `onOpenChange` stay inside the component.

## Tokens

One row per part, state and property. The design states the deferred drawing shows are, for the trigger, rest, hover, focus, open, disabled and invalid, and, for a row, rest, hover, highlighted, selected and disabled. The Fields family keeps the trigger's rest look while the list is open, so open is the popup's look, not the box's. The label, the optional mark, the description and the error take Field's tokens, as [Field](field.md) gives them, and Select sets none of their properties.

The trigger takes `space.300` at its start and end, `space.200` between the value and the icon, the value in `typography.body` and `color.text.primary` on one line that ends in an ellipsis, the placeholder in `color.text.tertiary`, and the icon at `icon.size.400` in `color.text.secondary`. `space.300` is SearchField's start padding, and with the trigger's hairline it sets the value 13 px in, where a row's text starts inside the popup (its hairline, the list's `space.100` and the row's `space.200`), so the chosen word sits over its row; `typography.body` is the contract's type for a field's words; the box is one `size.input` tall, as an input is, so a long label is cut with an ellipsis rather than wrapped, its whole text still in the trigger for the ear; the chevron is decoration beside the value, so it takes the secondary ink SearchField's icon takes.

The chevron is a new icon, `chevron-down`, drawn on a 16 px grid for `icon.size.400` and joining the Actions category of `packages/perron/icons/icons.json` as "Opens a select's list". The tick the `SelectedMark` part needs is the set's `tick`, which Checkbox added, drawn on a 14 px grid for `icon.size.325`: the `SelectedMark` shows it at that size, no `check` icon is drawn, and its use in `icons.json` widens to name the chosen option in a list. The set has no chevron; [Icons](../foundations/icons.md) asks a new icon to be drawn near the size it shows at, and the chevron sits inside a control, which is `icon.size.400`'s use; a single down chevron says the list opens under the box, which it always does (see Base UI parts); the contract's shared parts name the tick in `packages/perron/icons/` as the one tick, so a second drawing of it would be a copy.

The list, not the popup, takes the Popups family's `space.100` padding, the popup taking none, so the focus ring round a row the keys reach is drawn inside the scrolling list rather than cut by it. `Select.List` is the box that scrolls, and a scroll box clips what reaches past its padding, so a row's ring, `focus.width` and `focus.offset` outside it, needs room inside the list; `space.100` is that room exactly (2 px and 2 px), so the ring is never cut and the rows' `radius.md` still nests in the popup's `radius.lg`; the popup still looks padded `space.100`, as the family asks.

A row keeps `perron.css`'s focus ring on `:focus-visible`, beside its highlight fill. Base UI moves real focus to the row the keys reach, and [Accessibility](../foundations/accessibility.md) says never to remove an outline without drawing the ring another way; the highlight fill, `color.surface.hover`, is too faint to be the only mark of focus; the pointer moves the highlight and focus too, but `:focus-visible` matches only after a key, so a pointer sees the fill alone.

The chosen row takes `color.surface.selected` with the `SelectedMark`, in `color.text.primary` at `icon.size.325` (the `tick`'s drawn size), at its end, and a highlighted chosen row lays `color.surface.hover` over that fill as a `linear-gradient` background-image. The Rows family gives a selected row `color.surface.selected` with the `SelectedMark`; at the row's end the tick never moves the labels, which all start on one line with the group labels and the value in the box, and Base UI mounts it on the chosen row only; the list opens with the highlight on the chosen row, so the highlight must show over the selected fill, and a gradient over it is how the Fields family lays the hover over a fill.

A group label takes `typography.overline` in `color.text.secondary`, padded `space.150` above, `space.100` below and `space.200` at its sides, and a separator is a `border.width.025` line in `color.border.subtle`, `space.100` above and below. A group label heads a short section, which is `typography.overline`'s use, and its capitals come from the style, so a caller writes it in sentence case, as [Content design](../content-design.md) asks; `space.200` at its sides starts it on the rows' line; the Rows family divides rows with `border.width.025` in `color.border.subtle`, and `space.100` keeps the line apart from the rows on either side.

The trigger keeps its rest look while pressed (`[data-pressed]`, `:active`) and while read-only (`[data-readonly]`), hover included, since a read-only list still opens. The Fields family has no pressed look, and a press opens the list at once, whose popup is the change the person sees; a read-only field still opens and its value reads at full strength, so a quieter look would say it is disabled when it isn't, and the ear hears `aria-readonly`; a read-only look can join later as a look, without a prop.

A disabled row takes `color.text.tertiary`, keeps the highlight look when the keys or the pointer reach it, and never takes the selected look. Disabled is a colour, never an opacity, as the contract says; Base UI lets the keys reach a disabled option so the person can hear it is there, so the place the keys are at must stay visible; a disabled option is never chosen, so it is never the selected one.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's Select already gives the opening and closing with their reasons, the highlight and focus moving through the rows, Home and End, the typed-letter matching on the closed trigger and in the open list, choosing on Enter, Space and a press, focus moving into the list and back to the trigger, the placement and its flipping, the page's scroll lock while open, the combobox, listbox, group and option roles, the hidden input for forms, and, inside Field, the field's validity on the trigger, so the component rebuilds none of it and adds no key or pointer handlers.
- **CR-2.** Select renders the [Field](field.md) component, given every Field prop it takes, holding `Select.Root` as its `children`; `Select.Root` holds `Select.Trigger` (`Select.Value`, then `Select.Icon`) and `Select.Portal`, which holds `Select.Positioner`, `Select.Popup` and, in the popup, `Select.List`. With a flat `items`, the list holds one `Select.Item` per item; with groups, one `Select.Group` per group, each holding its `Select.GroupLabel` and then its items, with a `Select.Separator` before each group but the first. Each `Select.Item` has `value` and `key` the item's `value`, `label` the item's `label` and `disabled` the item's, and holds `Select.ItemText` with the label, then `Select.ItemIndicator`. `Select.tsx` exports `SelectItem` and `SelectGroup` beside `Select` and `SelectProps`, so the package's barrel gives them to callers.
- **CR-3.** `{...rest}` reaches Field before Select's own props, and Select's own props are taken out of `rest` first (`items`, `placeholder`, `value`, `defaultValue`, `onChange`, `open`, `defaultOpen`, `onOpen`, `onClose`, `required`, `readOnly`, `slotProps`), so none reaches the `<div>`; `label`, `hiddenLabel`, `optional`, `optionalLabel`, `description`, `error`, `name`, `disabled`, `invalid`, `validate`, `validationMode`, `validationDebounceTime`, `dirty`, `touched`, `actionsRef` and `render` stay in `rest` for Field. Select also reads `name`, without taking it out of `rest`, and gives it to `Select.Root`, so the hidden input carries it whether or not Base UI's field context reaches it. `ref`, `style` and `data-testid` land on the root, and `className` reaches Field as `pn-Select` then the caller's, a string or a function of the root's state, so the root reads `pn-Field pn-Select`, then the caller's.
- **CR-4.** Select turns `onValueChange(value, details)` into `onChange(details.event, value, details)`, and `onOpenChange(open, details)` into `onOpen(details.event, details)` when `open` is `true` and `onClose(details.event, details.reason, details)` when it is `false`, and exposes neither. It gives `Select.Root` the options flattened, groups and all, into Base UI's `{ value, label }` list, so `Select.Value` shows the chosen option's label; a key Select doesn't set is left out of `Select.Root`'s props, never set to `undefined`, so `value` stays uncontrolled when the caller leaves it out.
- **CR-5.** Each `slotProps` value is merged with Base UI's `mergeProps` (`@base-ui/react/merge-props`), Select's own props last, so a caller's handler runs beside Select's and its `className` joins after the part's class. Each Select part's class is set after the merge with the shared `withClass` helper from `packages/perron/src/internal/nodes.ts`: `pn-Select-<part>` first, then the caller's `className`, a string or a function of the part's state. `slotProps.label`, `slotProps.description` and `slotProps.error` go to Field's own `slotProps`, which merges and classes them itself; Select's own props for the label, `render={<div />}`, `nativeLabel={false}` and its `id`, are merged under the caller's `slotProps.label`, so a caller's `id` or `render` wins, and Field's `hiddenLabel` wins over both.
- **CR-6.** The label gets an `id` from React's `useId`, given through Field's `slotProps.label`, so Base UI registers it as the field's label; the trigger reads it through Base UI's `aria-labelledby`, and Select sets the same id as `aria-labelledby` on `Select.List`, which Base UI leaves unnamed. With a caller's `slotProps.label.id`, the list reads that id instead.
- **CR-7.** The chevron is an inline `<svg>` drawn from the new `chevron-down.svg` in the icons folder, inside `Select.Icon`, with the classes `perron-icon`, `aria-hidden="true"` and `focusable="false"`, in `currentColor`; the build adds the file and its `icons.json` entry, following [Icons](../foundations/icons.md). The selected mark is `<Select.ItemIndicator render={<SelectedMark />} />`; the build adds the `SelectedMark` shared part, with the set's `tick.svg`, its only icon, at `icon.size.325`, as the contract's [Shared parts](README.md#shared-parts) table says, draws no `check` icon, and widens the tick's `use` in `icons.json` to name the chosen option in a list too; and Select's CSS sets only its place in the row (`flex: none`), never its size or colour.
- **CR-8.** `Select.Positioner` takes `alignItemWithTrigger={false}`, Select's own, last, and `slotProps.positioner` is typed `Omit<Select.Positioner.Props, 'alignItemWithTrigger'>`, so the list always opens under the trigger. The positioner takes `z-index.dialog` and `padding-block: space.100`, the gap on whichever side the list sits; Select passes no `sideOffset` and keeps Base UI's other positioning defaults, which `slotProps.positioner` replaces.
- **CR-9.** The trigger is a flex row, `align-items: center`, `box-sizing: border-box`, the value growing (`flex: 1`, `min-inline-size: 0`) and the icon keeping its size (`flex: none`), with `text-align: start` and `margin: 0`. Its focus ring is `perron.css`'s, on `:focus-visible`, never redrawn. Its hover lays `color.surface.hover` over its fill as a `linear-gradient` background-image, inside `@media (hover: hover)` and not while `[data-disabled]`; while open, pressed or read-only it keeps its rest look.
- **CR-10.** The popup is `box-sizing: border-box`, `inline-size: var(--anchor-width)`, at most `calc(var(--available-height) - 2 * var(--perron-space-100))` tall, and a flex column, with no padding of its own; the list fills it, scrolls (`overflow-y: auto`, `overscroll-behavior: contain`, `min-block-size: 0`) and carries the `space.100` padding and `scroll-padding-block`, so a row's focus ring is never cut. The popup draws its `border.width.025` edge as a border, so Windows' forced colours keep an edge round it when they drop its glass and shadow.
- **CR-11.** Long words: a row's text and a group label wrap (`overflow-wrap: anywhere`), since each takes the list's width; the value in the trigger keeps its words on one line (`white-space: nowrap`) and ends in an ellipsis (`overflow: hidden`, `text-overflow: ellipsis`), as an input's words stay on one line. The label, the description and the error wrap, as Field's do.
- **CR-12.** The list opens and closes at once, and the chevron doesn't turn: no `duration.*` token fits a list under a field, as SearchField's CR-12 says, so the CSS has no transition or animation and styles neither `data-starting-style` nor `data-ending-style`.
- **CR-13.** A row is a flex row, `align-items: center`: the item text grows (`flex: 1`, `min-inline-size: 0`) and the selected mark sits after it at the row's end. Each row keeps `perron.css`'s focus ring on `:focus-visible`; the hover and highlight fill is `color.surface.hover`, on `:hover` inside `@media (hover: hover)` and on `[data-highlighted]`, disabled rows included; the chosen row's fill is `color.surface.selected`, and a highlighted chosen row lays `color.surface.hover` over it as a `linear-gradient` background-image. In forced colours a highlighted row draws `Highlight` with `HighlightText`, inside `@media (forced-colors: active)` and with `forced-color-adjust: none`, as SearchField's CR-13 does, since forced colours drop `color.surface.hover`; the chosen row keeps its tick.
- **CR-14.** A rule that styles a part inside another reads one class under its part's class and attribute, as Field's CR-13 allows: the icon's disabled colour is `.pn-Select-trigger[data-disabled] .pn-Select-icon`, and the placeholder's colour is `.pn-Select-value[data-placeholder]`.
- **CR-15.** The portal renders nothing on the server, so the contract story's owned-strings check sees only the label, the trigger and its placeholder. The stories that open the list check its words in the live DOM: `expectOwnedStrings(popup.outerHTML, locale, callerWords)`, from `packages/perron/src/testing/owned-strings.ts`, in English. The `Optional` story's render gets its own test, which runs `expectOwnedStrings` on its server-rendered markup in `en`, `da`, `sv` and `nb`, as Field's CR-12 does.
- **CR-16.** The stories' meta sets `parameters: { docs: { story: { inline: false, height: '360px' } } }`, as the contract's [Stories](README.md#stories) asks of an overlay, and each story that shows the list opens it at first render with `defaultOpen`, beside the trigger that opens it again. The `Disabled` story turns off axe's `color-contrast` rule for itself alone, with its reason, as Field's does: axe flags the disabled trigger's `color.text.tertiary`, which [Accessibility](../foundations/accessibility.md) lists as a deliberate miss and WCAG 1.4.3 exempts for an inactive control.

## Stories

The deferred drawing has no variant property and a `State` property with the values `default`, `hover`, `focus`, `open`, `disabled` and `invalid`, so its variants, and the stories that carry their names, are `Default`, `Hover`, `Focus`, `Open`, `Disabled` and `Invalid`. These are the CSS states the trigger's parts produce that change its look, and, in `Open`, the rows' rest, highlighted and selected looks; whether an option is chosen is the value, not a state, so `Filled` is a story beside them, as are the stories of content and behaviour; the Penpot conventions name a variant by its property values, and a `State` of `default` gives `Default`, the subject story.

The stories render the field on its own in a 320 px wide container, in a `PerronProvider` in English, with `fn()` handlers for `onChange`, `onOpen` and `onClose`, the label "Transport mode", the placeholder "Choose a transport mode" and these items unless the story says otherwise: "Metro" (`metro`), "S-tog" (`s-tog`), "Bus" (`bus`), "Regional train" (`regional`) and "Harbour bus" (`harbour-bus`) ([Content design](../content-design.md)). The `Default` story's args, which the contract story renders, hold every word the caller gives. The `Hover` and `Focus` stories render at rest; their `play` tests drive the state. Each `play` that opens the list finds it through `screen`, outside `canvasElement`, and ends with it closed and focus where it started.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                       | Don't                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Use Select for one choice from a short, fixed list, such as a transport mode or an order                                                 | Use it to find a line or a stop among hundreds: use [SearchField](search-field.md), which narrows the list as the person types           |
| Give a `label` that names the value, "Transport mode", and hide it with `hiddenLabel` only where the screen already says it              | Let the placeholder stand in for the label: it is gone once an option is chosen, and drawn in `color.text.tertiary`, below text contrast |
| Write the placeholder as an instruction, "Choose a transport mode"                                                                       | Put an option's words in the placeholder: the person reads it as a value already chosen                                                  |
| Give short `label`s that the person can tell apart by their first letters, so typing on the closed box finds them                        | Start every option with the same word ("Line M1", "Line M2"): typing finds nothing, and the box's ellipsis cuts the words that differ    |
| Group options with `SelectGroup` when the list mixes kinds, such as metro and S-tog lines, and write each group's label in sentence case | Write a group label in capitals: its style sets the capitals, and the ear hears the words as written                                     |
| Set `required` or `optional`, whichever the form needs                                                                                   | Set both: the field is marked optional while the form refuses it empty                                                                   |
| Give `error` whenever the field is `invalid`                                                                                             | Set `invalid` with no message: the trigger's red edge alone tells only the eye, and only by its colour                                   |
| Leave an option that can't be chosen out of `items`, or give it `disabled` when the person should see it is there                        | Disable the whole field to say one option isn't available                                                                                |
| Keep the field in a `PerronProvider` with the screen's locale, so "(optional)" speaks it                                                 | Translate it with `optionalLabel` on every instance: that is for one instance's own words                                                |
