# Link

A link in text: words, in a sentence or standing alone, that take the reader to another page or place, such as "Departures from Rejseplanen" or "Show all departures", underlined in the colour of the text around them.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens, Base UI's `useRender` and `mergeProps` (`@base-ui/react` 1.9.0, installed) and the two merged components that already draw links: [LinkButton](link-button.md), the link shaped like a button, whose root, `href` and answers Link shares, and [Attribution](attribution.md), whose rule for the caller's links (`.pn-Attribution :any-link` in `packages/perron/src/components/Attribution/Attribution.css`) gives Link its ink and underline. Its registry entry, in the Navigation category, has no `baseUiParts` and no `dependsOn`. No ROADMAP line names Link, and the extracted prototype component is not in any branch this run can reach, so nothing here rests on it. No component of its family or category is on a branch. MUI's `Link` (9.5.0) takes `color`, `underline` and a typography `variant`; Link takes none of them (see Props). The factory's brief for this slot asked for a minimal API, Attribution's treatment under the contract's [Pointer feedback](README.md#pointer-feedback), a decision on an "opens in a new tab" affordance, a decision on whether Attribution should later use Link, and a `play` step for every Keyboard row.

## Anatomy

Penpot page `Components/Link`. Family: none: the contract's [Families](README.md#families) have no row for text, and Link takes the type and colour of the text it sits in. Shared parts: none.

The drawing has one board, `root`, holding the link's words as one underlined text run, shown in a sentence of `typography.body`. Its one variant property is `State`, with the values `default`, `hover` and `focus`, so its variants are `Default`, `Hover` and `Focus`; the code map lands the text and the focus ring on `root`, since the words are the caller's `children` with no element of their own.

Link has no Base UI part: the registry gives it none, and Base UI's only candidate, `Button`, would give the link a button's role. Its root renders through Base UI's `useRender` hook (`@base-ui/react/use-render`), which gives it the `render` prop, as LinkButton's does.

| Part (Penpot layer) | What it is                                                                                                                               | Base UI part                                      | Class     | `slotProps` key |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | --------- | --------------- |
| `root`              | The native `<a href>`, inline, holding the caller's `children` as its text, in the font and colour of the text around it                 | none: an `<a>` rendered by `useRender`            | `pn-Link` | none            |
| `focusRing`         | The keyboard focus ring: the `:focus-visible` outline `perron.css` draws on the root, round each line the link runs over; not an element | none: the browser's `:focus-visible` on the `<a>` | none      | none            |

## Base UI parts

Link imports no Base UI component. It uses two Base UI utilities, at the version pinned in `packages/perron/package.json` (1.9.0): `useRender` (`@base-ui/react/use-render`) for the root and `mergeProps` (`@base-ui/react/merge-props`) to merge the caller's props with its own.

| Base UI part                     | Renders                              | Perron sets                                                                                      | Passed through                                                                                                                                                                     |
| -------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useRender` (a hook, not a part) | `<a>`, or the element `render` gives | `defaultTagName: 'a'`, `className` (`pn-Link`, then the caller's), `href` from `href` when given | `render`, `ref`, `children`, `className`, `style`, `target`, `rel`, `download`, `hrefLang`, `aria-current`, `onClick` and every other prop of a native `<a>`, through `mergeProps` |

Base UI already does: swapping the root element for the one `render` gives (a router's link component, for one), keeping the class and the children; merging the caller's `ref` with the element's; and merging event handlers, `className` and `style` through `mergeProps`. Everything a link does, the browser does: Enter follows it, a middle click or a modifier opens it in a new tab or window, the context menu offers to copy it, and assistive technology lists it among the page's links.

## Props

In MUI's layout. Every prop here gets this description as its JSDoc. Link has no `slotProps`, because the contract keys `slotProps` by inner Base UI part and Link has none; a caller restyles it through `className`. It owns no strings, so it has no label-override props. The `<a>` element's other attributes (`target`, `rel`, `download`, `aria-current`) reach the root and get no row, as the contract's [Props](README.md#props) says.

Link takes no `color`, `underline`, `variant` or `size` prop, and no `disabled`, so it always wears the colour and type of the text it sits in, underlined. The API stays minimal and grows without a break: Attribution's links already keep their text's colour and their underline in every state; an intent colour on a link would be its only hue in an ink interface, `color.text.brand` is "never links" ([Semantic colours](../foundations/semantic-colours.md#brand)), and a status colour already comes from the text around it; MUI's `underline` of `'hover'` or `'none'` would leave colour alone to mark the link, which [Accessibility](../foundations/accessibility.md#rules) rules out ("Colour never alone"); MUI's `variant` is a typography role, which the text around the link already sets; and an `<a>` has no `disabled`, as LinkButton's spec says. Its props type is the `<a>` element's with React's non-standard `color` attribute omitted, as LinkButton's is, so `color="brand"` is a type error rather than an attribute on the DOM.

Link declares `href` itself, optional, with its own JSDoc, as LinkButton does: it is the one attribute every Link needs, and it is optional only because a `render` such as a router's link can bring its own (`to`).

| Name                 | Type                     | Default | Base UI prop         | Description                                                                                                                                                                               |
| -------------------- | ------------------------ | ------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `href`               | `string`                 | none    | none                 | Where the link goes: a URL or a path. Give it on every Link, unless `render` gives a router's link that brings its own destination.                                                       |
| `render`             | Base UI's `render`       |         | inherited            | Allows you to replace the component's HTML element with a different tag, or compose it with another component. Accepts a `ReactElement` or a function that returns the element to render. |
| `children`           | `ReactNode`              | none    | none                 | The link's words, which name where it goes: "Rejseplanen", "Show all departures". Phrasing content only. Required in practice: a link with no words has no name.                          |
| `className`, `style` | React's                  | none    | through `mergeProps` | Reaches the root; `className` is merged after `pn-Link`.                                                                                                                                  |
| `ref`                | `Ref<HTMLAnchorElement>` | none    | `useRender`'s `ref`  | Reaches the root element.                                                                                                                                                                 |

`render` is Base UI's, inherited as it is. With none, Link renders an `<a>` (CR-1); `render` swaps it, such as for a router's link component, keeping the class and the children, and the element it gives must render an `<a>` too.

## Tokens

One row per part, state and property. Link has one part, `root`. States are the contract's design states: rest is no selector, hover is `:hover` inside `@media (hover: hover)`, pressed is `:active`, focus is `:focus-visible`. A link has no disabled, open, selected or invalid state, and `:visited` is not a design state, so a visited Link looks as it did before.

Link keeps the colour of the text around it in every state, `:visited` included, underlined in every state in that colour, as Attribution's links are. It sits in any text, a caption in `color.text.secondary`, a sentence in `color.text.primary` or a warning in `color.text.warning`, and stays that text's colour; the underline marks it where colour can't ([Accessibility](../foundations/accessibility.md#rules), "Colour never alone"); the browser's blue and purple would be the only hues in an ink interface, and `color.text.brand` is never a link; and Attribution chose the same for the same reasons.

Under the contract's [Pointer feedback](README.md#pointer-feedback), hover lays `color.surface.hover` behind the link and pressed `color.surface.selected`, the quiet part's two steps, with `radius.xs` corners drawn on each line the link runs over, rather than Attribution's step from `color.text.secondary` to `color.text.primary` on hover. A link in `color.text.primary` text has no darker ink to step to, so a colour step shows nothing there, and Attribution's rule has no pressed step at all; the quiet part's layers show on every text colour and both themes, keep text at 4.5:1 on `default` and `raised` ([Accessibility](../foundations/accessibility.md#what-the-build-checks)), and are what the shared `stateFill` and `pressedAfterHover` helpers prove. `radius.xs`, the radius of small marks, rounds the layer so it reads as a highlight on the words rather than a box.

| Part   | State                | Property                    | Token                                                                                                                                                       |
| ------ | -------------------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `root` | rest                 | `color`                     | none: `inherit`, the colour of the text around it, `:visited` included (CR-2)                                                                               |
| `root` | rest                 | `text-decoration-line`      | none: the keyword `underline`, in every state (CR-2)                                                                                                        |
| `root` | rest                 | `text-decoration-color`     | none: the browser's `currentColor`, so the underline follows the text's colour; no rule sets it                                                             |
| `root` | rest                 | `background-color`          | `transparent`                                                                                                                                               |
| `root` | rest                 | `border-radius`             | `radius.xs`, which the hover and pressed layers and the focus ring take (CR-4)                                                                              |
| `root` | rest                 | `box-decoration-break`      | none: the keyword `clone`, so a link over two lines draws its layer's corners and its ring on each line (CR-4)                                              |
| `root` | rest                 | `font`                      | none: inherited from the text around it; Link sets no typography role (CR-12)                                                                               |
| `root` | rest                 | `cursor`                    | none: the `pointer` every `<a href>` has, so no rule sets it                                                                                                |
| `root` | hover                | `background-color`          | `color.surface.hover`, inside `@media (hover: hover)` (CR-3)                                                                                                |
| `root` | pressed              | `background-color`          | `color.surface.selected`, in a rule after the hover rule and outside the query, so a touch press shows (CR-3)                                               |
| `root` | focus                | `outline`, `outline-offset` | `focus.width` in `color.border.focus`, `focus.offset`, drawn by `perron.css` (CR-6)                                                                         |
| `root` | rest, forced colours | `color`, `background-color` | none: Windows' contrast themes paint the link `LinkText` with its underline and drop the layers, so the underline alone marks it, as on Attribution's links |

The states change at once, with no transition: no `duration.*` token is given to a link's hover (CR-11).

## Keyboard and ARIA

From the browser's native link and Base UI's `useRender`, which adds no behaviour. "From" says who does it. The `Default` story's `play` presses every key in this table.

| Key         | Does                                                                                 | From        |
| ----------- | ------------------------------------------------------------------------------------ | ----------- |
| `Tab`       | Moves focus to the link, in document order                                           | The browser |
| `Shift+Tab` | Moves focus back out of the link, to the element before it                           | The browser |
| `Enter`     | Follows the link: fires `onClick`, then goes to `href` unless the click is prevented | The browser |
| `Space`     | Nothing to the link: Space scrolls the page, as on every link, and never follows it  | The browser |

| Element | Role                            | Accessible name from                                                                             | States announced                                                |
| ------- | ------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| `root`  | `link`, native, from `<a href>` | Its text content, the caller's `children`; `aria-label` or `aria-labelledby` from the caller win | Visited, by the browser; `aria-current` when the caller sets it |

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the underline tells the eye it is a link and the `link` role tells the ear; its words are its name; its colour is the text's, so it tells nothing the text doesn't.
- [ ] Every landmark and named region has an accessible name: none here; a link is neither.
- [ ] Every default label can be overridden: none here; Link owns no strings.
- [ ] Every shape the type accepts renders, in every variant: `children` renders a string, an element and a list alike, in every `State`, alone or in running text, over one line or several.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; Link keeps no hidden copy and collapses nothing.
- [ ] Native semantics first: a native `<a href>`, never `role="button"` and never Base UI's `Button` (CR-1); a `render` element renders an `<a>` too.
- [ ] Focus moves in reading order and returns on close: the link is one tab stop where it sits in the text, and opens nothing of its own to return from.
- [ ] Every target is at least `size.target-min` square: Link adds no padding or minimum height of its own, so in running text it meets WCAG 2.2's target size (2.5.8) by its inline exception, and standing alone by its spacing exception, the caller giving it `size.target-min` of room as [Accessibility](../foundations/accessibility.md#rules) allows. Padding on an inline run would overlap the lines above and below it, and a minimum height doesn't apply to an inline box; a standalone link in `typography.body` is 21 px tall, under `size.target-min` (24 px), so the room around it is the caller's, said in Do and don't.
- [ ] Loops stop when the system asks for less motion: none here; Link has no loop and no transition.

## Owned strings

No owned strings: every word comes from the caller, as `children`.

Link, like LinkButton, owns no "Opens in a new tab" string, draws no external-link icon and takes no `external` prop, leaving `target` and `rel` to the caller. [Content design](../content-design.md) gives no rule on links or new tabs, so the answer LinkButton's spec gives stands for both: a link that leaves Mylder names its destination in its words ("Rejseplanen"), and Mylder's own links open in the same tab. A caller who opens a new tab passes `target="_blank"` with `rel="noopener noreferrer"`, and both reach the `<a>` as they are. An owned string and icon can join later, as a new optional prop, without a break, and LinkButton would take the same.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** The root is a native `<a>` through `useRender` with `defaultTagName: 'a'`, never Base UI's `Button` or Perron's `Button` with `render={<a />}`: Base UI's `Button` gives a non-button element `role="button"` and Space activation, which tell a screen reader a link is a button. Each prop Link declares is taken out of `rest` before the merge, as the contract's [Root](README.md#root) says; the rest reach the root through `mergeProps`, the component's own last, so its `href` stands and the root's class reads `pn-Link`, then the caller's `className`.
- **CR-2.** The root's `color` is `inherit` and its `text-decoration-line` is `underline`, in one rule on `.pn-Link` that every state keeps: no rule sets a colour for `:hover`, `:active`, `:focus-visible` or `:visited`, and no rule sets `text-decoration-color`, `text-decoration-thickness` or `text-underline-offset`, so the underline follows the text's colour and the font's own metrics. One class beats an app's `a { text-decoration: none }`.
- **CR-3.** Pointer feedback, by the contract: hover sets `background-color` to `color.surface.hover` in `.pn-Link:hover` inside `@media (hover: hover)`, and pressed sets it to `color.surface.selected` in `.pn-Link:active` after that rule and outside the query. Neither changes any other property. The cursor is the `<a href>`'s own `pointer`.
- **CR-4.** The states keep the link's geometry: the root stays `display: inline` with no padding, margin or border and no `line-height` of its own, so it never moves the text around it, and hover, pressed and focus change colours only. `border-radius: radius.xs` and `box-decoration-break: clone` round the layer and the ring on every line the link runs over.
- **CR-5.** Link adds no keyboard handling: Enter follows the link through the browser, Space does nothing to it, and modifier clicks open it in a new tab or window, as on every link.
- **CR-6.** Focus uses the ring `perron.css` draws on `:focus-visible`; the component draws no ring of its own and never removes the outline.
- **CR-7.** The root carries no data attributes of Link's own: it has no `variant`, `color` or `size` (see Props). Its props type extends Base UI's `useRender.ComponentProps<'a'>`, as LinkButton's does, with React's non-standard `color` attribute omitted and `href`, `children`, `className`, `style` and `ref` declared with their Props rows' descriptions as their JSDoc; the `<a>` element's type already has no `disabled`.
- **CR-8.** `href` is declared in Link's own props, optional, with its Props row's description as its JSDoc, and reaches the root's `<a>` as its `href` only when given, so a router link's own destination stands.
- **CR-9.** Attribution keeps its own `.pn-Attribution :any-link` rule in this change, and a follow-up of its own decides whether it moves its credits' links to Link: its spec then naming Link in its Do and don't and its stories, and its rule giving up its hover colour step for Link's layers. It is a follow-up since a caller's Link inside Attribution today matches both rules, Attribution's hover colour (`.pn-Attribution :any-link:hover`) and Link's hover layer, which set different properties and so both show; this change touches no other component.
- **CR-10.** `target`, `rel` and `download` reach the `<a>` as the caller gives them; Link adds no word, icon or `rel` of its own when `target="_blank"` (see Owned strings).
- **CR-11.** Changes of state are immediate: no `duration.*` token fits the change, so the CSS has no transition.
- **CR-12.** Link sets no typography role, so it takes the font, size, weight, line height and tracking of the text around it, and has no long-word rule of its own: the contract's long-word rule binds a rule that sets a role, and a link wraps as the text it sits in does, at its spaces, a long word breaking by the paragraph's own `overflow-wrap`.

## Stories

The deferred design's one variant property is `State` (`default`, `hover`, `focus`), so its stories are `Default`, `Hover` and `Focus` (`penpot/README.md`, "Conventions"); the rest show Link where callers put it, the same variant in other text. Each link's click is prevented by the meta's decorator, so a `play` test never leaves the page, and each story's link has `href`, with `onClick` a spy. The hover and focus stories render at rest: the visual check drives the state itself, and their `play` tests check it.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                          | Don't                                                                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Link for a link in text, in a sentence or standing alone, and [LinkButton](link-button.md) for one shaped like a button | Put a LinkButton in running text: its height and padding break the line                                                                                                    |
| Use Link when pressing it goes somewhere: another page, another place in the app, another site                              | Use Link to run an action, such as showing a line or closing a panel, with an `onClick` that prevents the link: that is a Button                                           |
| Name where it goes, in the words of the sentence: "Departures from Rejseplanen", "Show all departures"                      | Write "Click here", "Read more" or a bare URL ([Content design](../content-design.md)): the link's words are all a screen reader hears of it in a list of links            |
| Set the colour and type on the text around the link, and let Link take them                                                 | Recolour a Link in the brand yellow or a status colour on its own: brand is never a link ([Intents](README.md#intents)), and the text's colour already carries any meaning |
| Give a standalone link `size.target-min` of room, such as a row of that height or a gap around it                           | Set a standalone link against another target, where a 21 px line leaves too small a mark to press                                                                          |
| Give a router's link through `render`, such as `render={<RouterLink to="/departures" />}`, so the app's navigation runs     | Wrap a Link in a router link, or a router link in a Link: two nested `<a>` elements are invalid and make two tab stops                                                     |
| Name a site the link leaves Mylder for, and keep Mylder's own links in the same tab                                         | Open a new tab without saying where the link goes                                                                                                                          |
| Leave a link out when there is nowhere to go yet                                                                            | Render a Link without `href` or `render`, or fake a disabled one with `opacity`: an `<a>` with no `href` is not a link, and disabled is a colour                           |
