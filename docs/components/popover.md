# Popover

A small glass panel anchored to the button that opens it, such as a short explanation of the data or a few settings, which leaves the map and the rest of the screen usable while it is open and gives focus back to its button when it closes.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the contract, the foundations, the tokens and the Base UI reference. No ROADMAP line names Popover; its registry entry, in the Overlays category with no `dependsOn`, is the source for its parts. The `CloseButton` shared part gives the close button its look, the [Dialog](dialog.md) spec the shape of the API, the [MapTooltip](map-tooltip.md) spec the positioner's defaults, and the [Button](button.md) spec the trigger in the stories.

## Anatomy

Penpot page `Components/Popover`. Family: Popups (the contract's [Families](README.md#families) names popovers there: `color.surface.overlay` glass with `shadow.panel`, a `border.width.025` edge in `color.border.subtle`, `radius.lg`). Shared parts: `CloseButton`, which the contract's [Shared parts](README.md#shared-parts) table composes in `Popover.Close`.

Popover is one component in Dialog's shape: it takes `title`, `description`, `children` and `trigger` as props and renders every Base UI part itself, with the popup as its root, and has no `actions` prop. Its sibling in Overlays, Dialog, ships that shape and the `api-consistency` skill holds siblings to one shape; `Popover.Root` renders no element, and the popup is the one element a caller styles or measures; a popover holds a few sentences or controls in `children`, and a question with actions that must be answered is a Dialog.

The popover leaves out Base UI's `Popover.Arrow`, and the build takes it out of the entry's `baseUiParts`. The Popups family draws no arrow, so a popover would be the one popup with a pointer while menus and select lists have none; a glass arrow needs its own `backdrop-filter` and border so it doesn't show the shadow through it; and the `sideOffset` gap already ties the panel to its trigger.

The close button is the `CloseButton` shared part, in `packages/perron/src/parts/CloseButton/`, rendered through `Popover.Close`'s `render`, its `label` the popover's owned "Close" or `closeLabel`. The part is a `<button>` in a `size.control` square with `radius.md`, the `close` icon at `icon.size.400` in `color.text.secondary`, `color.text.primary` on `color.surface.hover`, `color.surface.selected` while pressed, its label in the `VisuallyHidden` part.

Base UI already does: it opens the popover on a press of `Popover.Trigger`, or on hover too when the trigger's `openOnHover` is set, and gives the trigger `aria-haspopup="dialog"`, `aria-expanded` and `aria-controls`; it portals the positioner to `<body>` and renders nothing there, on the server or the client, while the popover is closed, unless the portal's `keepMounted` is set; it places the popup against the trigger, on the side asked for, flipping to the opposite side when that one has no room and, when neither has, to the end side of the other axis, the right in a left-to-right page (its positioner's default `collisionAvoidance`, `fallbackAxisSide: 'end'`, which Popover replaces with `'none'`, CR-7), and shifting it along the edge so it stays inside the viewport, and re-reads the trigger when an ancestor scrolls or either resizes; it marks the positioner `data-anchor-hidden` when the trigger is out of view; it names the popup from `Popover.Title` and describes it from `Popover.Description` through ids it generates; when the popover opens it moves focus to the first tabbable element in the popup, or to the popup itself when opened by touch, unless `initialFocus` says otherwise; while a non-modal popover is open it keeps the page usable, scrolling and pressable, traps no focus and hides nothing from assistive technology, and puts the popup in the tab order right after the trigger, so Shift+Tab from its first element goes back to the trigger and Tab from its last goes on to the element after the trigger, closing the popover with `'focus-out'`; Esc closes it; a press outside the popup and the trigger closes it; `Popover.Close` closes it; on close by Esc or the close button it returns focus to the trigger, unless `finalFocus` says otherwise; it reports each change with its reason (`trigger-press`, `trigger-hover`, `trigger-focus`, `outside-press`, `escape-key`, `close-press`, `focus-out`, `imperative-action`, `none`) and a `cancel()` that keeps the popover as it is.

## Props

In MUI's layout, as MUI's Popover takes `open` and `onClose`, with the trigger and the words as props, as [Dialog](dialog.md) takes them. Every prop the component declares gets this description as its JSDoc; the inherited rows keep Base UI's. Slots come last.

`title` is required, as Dialog's is. Base UI gives the popup the `dialog` role, which axe and screen readers need named, and the visible heading is the name a sighted reader and a screen reader share; a popover with nothing to call itself is a [MapTooltip](map-tooltip.md) or belongs in the content of something else.

Popover is always non-modal, and leaves out `Popover.Root`'s `modal`, `actionsRef`, `handle`, `onOpenChangeComplete`, `triggerId` and `defaultTriggerId` (the last two set by Popover itself from the trigger, CR-5). [Accessibility](../foundations/accessibility.md#what-a-person-checks) says only an open dialog traps focus, so a popover that must hold the screen is a Dialog; the popover has no exit animation for `actionsRef` or `onOpenChangeComplete` to wait on (CR-10), and no Mylder screen opens one popover from detached triggers through a `handle`; each can join later as a new optional prop, which the contract's [Change](README.md#change) rule allows.

`PopoverProps` extends `Popover.Popup.Props` without its `children`, `title`, `className`, `style` and `ref`, as `DialogProps` extends `Dialog.Popup.Props`. Popover has no `variant`, `color` or `size`, so its root carries no `data-variant`, `data-color` or `data-size`; Base UI's `data-open`, `data-closed`, `data-side`, `data-align` and `data-instant` are its only data attributes. None of the names is one the contract's [Names from other libraries](README.md#names-from-other-libraries) table bans; `onOpenChange` and `modal` stay inside the component.

The positioner keeps Base UI's `side` of `'bottom'` and `align` of `'center'`, defaults `collisionAvoidance` to `{ fallbackAxisSide: 'none' }`, and takes two defaults read in script, a `sideOffset` of `space.200` and a `collisionPadding` of `size.panel-gap`, read through the shared helper `positionerOffsets` in `packages/perron/src/internal/tokens.ts`, which MapTooltip and Tooltip read too and the contract's [Shared helpers](README.md#shared-helpers) table lists. MapTooltip and Tooltip already give their positioners these two lengths, so every popup sits as far from what opened it and from the screen's edge as the others; below the trigger is where a top bar's popover has room; and the contract's `shared-parts` gate fails a second copy of the reader's body. With `fallbackAxisSide: 'none'`, the popup flips between below and above its trigger but never moves to its side: when neither has room for it, it takes the one that fits it better and scrolls inside `--available-height` (CR-8), as Base UI's own menus and select lists do (its `DROPDOWN_COLLISION_AVOIDANCE`), where Base UI's popover default, `'end'`, would set it beside the trigger at the viewport's full height, away from what opened it; a caller's `slotProps.positioner.collisionAvoidance` replaces it whole.

## Tokens

One row per part, state and property. States are the contract's design states: rest is no selector, open is `[data-open]` on the positioner and the popup, hover is `:hover` inside `@media (hover: hover)`, pressed is `:active`, focus is `:focus-visible`. The trigger is the caller's element and keeps its own tokens in every state, open included: Popover styles no `[data-popup-open]`. The portal is never seen and has no tokens.

The popup takes the Popups family's fill, edge and corner ([Families](README.md#families)): `color.surface.overlay` with a `backdrop-filter` of `effect.glass-blur` and `effect.glass-saturate` and `shadow.panel`, a `border.width.025` edge in `color.border.subtle`, and `radius.lg`. [Elevation](../foundations/elevation.md) gives text-heavy panels on phones an opaque `color.surface.default`, but a component sizes to its container and has no width query ([Media queries](README.md#media-queries)), and a popover holds a few sentences, not a panel full of text.

The popup is padded `space.400`, its parts `space.200` apart, in place of the Popups family's `space.100`. The family pads `space.100` so a menu's rows, with their own `radius.md` and padding, nest inside `radius.lg`; a popover holds a heading and sentences with no row of their own, which `space.100` would put against the edge, and `space.400` is the step below a dialog's `space.600`, for a smaller panel, while `space.200` keeps the description close to its title as [Semantic spacing](../foundations/semantic-spacing.md) keeps a line under a title.

The title is in `typography.heading-sm`, the description in `typography.body-sm` in `color.text.secondary` and the content in `typography.body`. [Typography](../foundations/typography.md) gives `heading-lg` to dialog titles and `heading-md` to panel titles, and the popover is smaller than both: `heading-sm` is the card title, the size of a popover's few lines, and `body-sm` is "the line under a title", as in a dialog.

The popup's width follows its content, capped at the smaller of 320 px, written in `Popover.css` as a raw length under a `perron-allow(component-css)` comment that gives the reason, and Base UI's `--available-width`; its height is capped at `--available-height` and scrolls as a whole. Dialog keeps its 440 px measure the same way, and [Layout](../foundations/layout.md) and the `design-tokens` skill keep a measure only one component's CSS reads in that CSS; 320 px less the `space.400` padding holds about 45 characters of `typography.body` a line, a popover's short sentences, and the variables keep it inside the viewport on a 320 px screen and on whichever side Base UI flips it to.

The close button is pulled `space.200` up, down and towards the end, so its 34 px square takes no more height than the title's first line of `heading-sm` and its icon lines up with the padding's edge.

Highlighted, selected, invalid and disabled don't apply to the popover: it holds no rows, no choice and no value, and Base UI gives `Popover.Popup` no disabled state. Base UI's `data-side` and `data-align` take no look, as the popover draws no arrow, and `data-starting-style`, `data-ending-style` and `data-instant` take none, as it has no transition (CR-10).

When Base UI marks the positioner `data-anchor-hidden`, because the trigger has scrolled out of view, the popover keeps its rest look, staying where Base UI last placed it, rather than hide. The deferred design doesn't show the state; a popover may hold focus, and hiding it with `visibility: hidden` would leave focus on an element no one sees, while Esc, a press outside and Tab still close it; MapTooltip hides because it holds no focus and speaks of a point no longer in view.

## Keyboard and ARIA

From the Base UI reference for `Popover` and the installed `PopoverRoot`, `PopoverTrigger`, `PopoverPositioner`, `PopoverPopup`, `PopoverClose` and the focus manager they build on. "From" says who does it.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the popover is announced with its `title` as its name and its `description`, the close button's `aria-hidden` icon has the owned "Close" as its text, and that the popover belongs to its trigger is told by the trigger's `aria-expanded` and `aria-controls`.
- [ ] Every landmark and named region has an accessible name: the popover is named by its own heading, the `title`, through `aria-labelledby`, and `title` is required.
- [ ] Every default label can be overridden: `closeLabel`.
- [ ] Every shape the type accepts renders, in every variant: `title`, `description` and `children` render a string, an element and a list alike; a long word in the title, the description or the content wraps (CR-9).
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the closed popover renders nothing, and Base UI makes the positioner `inert` while it closes.
- [ ] Native semantics first: Base UI's `dialog` role, a native `<h2>` for the title, native `<button>`s for the trigger and the close button, and no ARIA of Perron's own.
- [ ] Focus moves in reading order and returns on close: the header comes first in the DOM, then the description and the content, as on screen; Base UI puts the popup in the tab order right after the trigger; opening moves focus into the popup, and closing by Esc or the close button returns it to the trigger, also for a popover open at first render (CR-5).
- [ ] Every target is at least `size.target-min` square: the close button, `size.control` (34 px) square.
- [ ] Loops stop when the system asks for less motion: none here; the popover has no loop and no transition (CR-10).

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's popover already gives the placement, the flip and shift at the viewport's edge, the initial focus, the tab order after the trigger, the focus return, Esc, the outside press, the close on focus out and the popup's name and description, so the component rebuilds none of it and adds no key or pointer handlers.
- **CR-2.** Popover renders `Popover.Root` around `Popover.Trigger` (only when `trigger` is given, with `render={trigger}`) and `Popover.Portal`, which holds `Popover.Positioner` and, in it, `Popover.Popup`. The popup holds, in this order: the header (`Popover.Title`, then `Popover.Close`), `Popover.Description` when `description` is given, and the content when `children` is given. The DOM order is the reading order and the order on screen. No `Popover.Arrow`, `Popover.Backdrop` or `Popover.Viewport` is rendered.
- **CR-3.** `{...rest}` reaches `Popover.Popup` before Popover's own attributes, and Popover's own props are taken out of `rest` first (`title`, `description`, `children`, `trigger`, `open`, `defaultOpen`, `onOpen`, `onClose`, `closeLabel`, `slotProps`), so none reaches the DOM; `initialFocus`, `finalFocus` and `render` stay in `rest`, keeping Base UI's defaults. `ref`, `style` and `data-testid` land on the popup, and `className` is merged after `pn-Popover`. Each `slotProps` value is merged with Base UI's `mergeProps` (`@base-ui/react/merge-props`), Popover's own props last, so a caller's class sits beside the part's `pn-Popover-<part>`; for the positioner, the caller's `sideOffset`, `collisionPadding` and `collisionAvoidance` win over the defaults (CR-7).
- **CR-4.** Popover turns Base UI's `onOpenChange(open, details)` into `onOpen(details.event, details)` when `open` is `true` and `onClose(details.event, details.reason, details)` when it is `false`, and exposes neither `onOpenChange` nor Base UI's `modal`, which stays `false`.
- **CR-5.** When `trigger` is given, Popover gives `Popover.Trigger` an id (the `trigger` element's own `id`, then `slotProps.trigger.id`, or one from React's `useId`) and passes it to `Popover.Root` as `defaultTriggerId`, or as `triggerId` when `open` is set, as the Base UI reference says for a popover open at first render or controlled, so the popover sits against the trigger and focus returns to it when such a popover closes.
- **CR-6.** The close button is always rendered, as in Dialog, though Base UI asks for `Popover.Close` only in a modal popover. Touch screen readers have no Esc and no Tab, so a close button inside is how they leave a popover; a press outside does it for sighted touch users only; and one header in every popover keeps it the Dialog's shape. Rendered as `<Popover.Close render={<CloseButton label={strings.close} />} />`, with `const strings = useOwnedStrings({ close: closeLabel })`. It is never disabled: `slotProps.close` is typed `Omit<Popover.Close.Props, 'disabled'>`, and Popover passes no `disabled` of its own, so the `CloseButton` part needs no disabled look; a popover that must stay open cancels the close in `onClose` with `details.cancel()`. `CloseButton` is the shared part of the contract's [Shared parts](README.md#shared-parts) table, and only its folder holds `pn-CloseButton` and the `close` icon.
- **CR-7.** The positioner's `sideOffset` and `collisionPadding` default to `space.200` and `size.panel-gap` as pixel numbers, read at run time from `--perron-space-200` and `--perron-size-panel-gap` through the shared `positionerOffsets` helper in `packages/perron/src/internal/tokens.ts`, which reads them with `tokenValue` once a token stylesheet gives both and keeps them; until then, as on a server, each is left out and Base UI's own default holds. MapTooltip and Tooltip read the same helper, which the contract's [Shared helpers](README.md#shared-helpers) table lists. The positioner's `collisionAvoidance` defaults to `{ fallbackAxisSide: 'none' }`, one constant in `Popover.tsx`, so the popup stays above or below its trigger and scrolls inside `--available-height` rather than fall back to the trigger's side; `slotProps.positioner.collisionAvoidance` replaces it whole.
- **CR-8.** The positioner takes `z-index.dialog`, as the contract's CSS section asks of everything that renders in a portal, so a dialog opened after the popover paints over it. The popup's width follows its content up to the smaller of 320 px and `--available-width`, and its height is at most `--available-height`, scrolling as a whole (`overflow-y: auto`, `overscroll-behavior: contain`) when its content is taller, header included, so the close button, the first tabbable element, sits inside the scrolling region. Popover's CSS never redefines a token: the portal sits outside every themed container but `<body>`.
- **CR-9.** The header is a flex row aligned to the start of the block axis, the title growing (`flex: 1`, `min-inline-size: 0`) and the close button keeping its square (`flex: none`). The title and the description have no margin of their own (the browser's `<h2>` and `<p>` margins are reset), the popup's `gap` spacing the parts. Long words wrap in the title, the description and the content (`overflow-wrap: anywhere`), so a long Danish word fits a 320 px screen wherever the caller puts it.
- **CR-10.** The popover opens and closes at once: no `duration.*` token fits a popup's entrance, so the CSS has no transition and styles neither `data-starting-style` nor `data-ending-style`.
- **CR-11.** The popup draws its `border.width.025` edge as a border, so Windows' forced colours keep an edge round the popover when they drop its glass and its shadow.
- **CR-12.** The close button keeps the `CloseButton` part's look and states; Popover's CSS sets only its margins (Tokens) and never its colours or its size.
- **CR-13.** The portal renders nothing on the server, so the contract story's owned-strings check, which renders to static markup, sees only the trigger. Popover's own stories check the open popup's words in the live DOM instead: `expectOwnedStrings(popup.outerHTML, locale, callerWords)` in English, and in Danish with no override.
- **CR-14.** The stories' meta sets `parameters: { docs: { story: { inline: false, height: '480px' } } }`, as the contract's [Stories](README.md#stories) asks of an overlay, and each story opens its popover at first render with `defaultOpen` or `open`, beside the trigger that opens it again, the trigger placed with room below it for the popup, which opens below it (`data-side="bottom"`) and, in `LongContent`, stays below it and scrolls when its content is taller than that room (CR-7).

Popover's root, the popup, portals to `<body>`, and only after the portal mounts, so it is not inside the story's canvas. Popover meets the contract story's Root rule with no exception: the contract story looks the root up in the whole document, as it does for every portalled component.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                                                                         | Don't                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Give every popover a short `title` in sentence case, such as "About the data" or "Map layers", which names it                                                                              | Leave the title empty or hide it: the popover then has no name                                                                                                                                                                                                |
| Pass the button that opens the popover as `trigger`, so the popover sits against it, is announced as opening and gives focus back                                                          | Open a popover from a button placed beside it with `open` alone, when a `trigger` would do: the button loses `aria-haspopup` and `aria-expanded`, and the popover has nothing to sit against                                                                  |
| Set `slotProps.trigger.nativeButton` to `false` when `trigger` is not a `<button>`, as Base UI warns                                                                                       | Pass a link as the trigger: a link goes somewhere, and a popover opens over the screen                                                                                                                                                                        |
| Keep it to a few sentences or a few controls that leave the map usable                                                                                                                     | Ask a question that must be answered, or put a long form in it: use a [Dialog](dialog.md), which holds focus until it is answered                                                                                                                             |
| Keep the description to one sentence, and put lists and controls in `children`                                                                                                             | Put block content, such as a list, in `description`: it renders in a `<p>`                                                                                                                                                                                    |
| Open it on a press, and add `slotProps.trigger.openOnHover` only beside that, as [Accessibility](../foundations/accessibility.md) asks of anything shown on hover                          | Use a popover for a few words on hover over the map: that is a [MapTooltip](map-tooltip.md)                                                                                                                                                                   |
| In a [Toolbar](toolbar.md), pass a `ToolbarButton` as `trigger`, and disable it with `slotProps.trigger.disabled`: it keeps its place in the arrow-key order, and is announced as disabled | Pass a [Button](button.md) as the trigger in a toolbar, or set `disabled` on the `ToolbarButton` itself: the arrow keys skip a Button, which adds a tab stop of its own, and a `ToolbarButton` disabled on its own looks disabled but is announced as enabled |
| Leave the close button's label to the locale, or override it with `closeLabel`                                                                                                             | Hide the close button with a `className`: touch screen readers leave the popover through it                                                                                                                                                                   |
| Let the popover take `z-index.dialog` and Base UI's placement, and change the side through `slotProps.positioner`                                                                          | Set a `z-index`, a position or a transform on the popup: it would fall under another overlay or leave its trigger                                                                                                                                             |
