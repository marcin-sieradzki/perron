# Tabs

A row of tabs that switches between views of one thing, one panel showing at a time, such as a stop's departures, its lines and its disruptions in the detail panel.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the contract, the foundations, the tokens, the Base UI reference and the ROADMAP line that names it (`ROADMAP.md`, "Wave 3, interactive, on Base UI"). ## Anatomy

Penpot page `Components/Tabs`. Family: none (the contract's [Families](README.md#families) have no row of tabs; a tab is ink on whatever surface holds it, marked by an underline). Shared parts: none (every word is the caller's, and the count is text the tab is named by).

The `Tabs` folder holds four components, `Tabs`, `TabsList`, `Tab` and `TabsPanel`, each exported with its props type from `Tabs.tsx`, as an exception to the contract's "one component per folder", and the indicator is drawn by `TabsList`, not offered as a component. Base UI's `Tabs.List`, `Tabs.Tab`, `Tabs.Indicator` and `Tabs.Panel` read `Tabs.Root`'s context, so they can't be built or shown apart, as Toolbar's parts can't; the caller writes many tabs and panels, so each is a component of its own; and an underline that every tab list draws the same way belongs to the list, reached through `slotProps.indicator`, not to the caller. The `props` check reads all four props types, and the `api-compatibility` check only `TabsProps`, so the review holds the other three to the contract's Change rules.

Base UI already does: one tab stop for the tab list, a roving `tabIndex` that rests on the selected tab, so Tab enters the list at the selected tab and the next Tab goes on to the open panel; the arrow keys of the list's orientation move focus between tabs, wrapping at the ends while `loopFocus` is on, and Home and End go to the first and the last tab (`enableHomeAndEndKeys` is on in the installed `TabsList`); with `activateOnFocus` off, its default, moving focus doesn't select, and Enter, Space or a click selects; the focused tab is scrolled into view; a disabled tab stays focusable and in the arrow-key order (`focusableWhenDisabled` is fixed on in the installed `TabsTab`), with `aria-disabled` in place of `disabled` and its clicks ignored; left uncontrolled with no `defaultValue`, or with the selected tab disabled or removed, the root selects the first enabled tab itself and calls `onValueChange` with the reason `'initial'`, `'disabled'` or `'missing'`, which can't be cancelled; a controlled root keeps the value it is given even when that tab is disabled or missing; each tab's `aria-controls` points at its panel and each panel's `aria-labelledby` at its tab; a hidden panel is unmounted, or with `keepMounted` kept `hidden` and `inert`; the indicator measures the selected tab and follows it when the list or a tab resizes; Left and Right swap only under Base UI's `DirectionProvider` set to `rtl`, not from the `dir` attribute, and Perron doesn't set one up yet, as all four locales run left to right.

## Props

In MUI's layout. Every prop here gets this description as its JSDoc. Slots come last.

A tab's value is a `string`, with `null` for no tab selected, rather than Base UI's untyped `Tabs.Tab.Value`. Mylder's tabs name views (`'departures'`, `'lines'`), a name survives the tabs being reordered where an index doesn't, and a string union narrows in the caller's `onChange`. Base UI's own `defaultValue` default, `0`, then never matches a tab, so leaving `defaultValue` out selects the first enabled tab, which is what the Default column says.

Tabs leaves out Base UI's `orientation`, so tabs only run horizontally. Mylder's tabs sit across the top of a 364 px detail panel or a sheet, where a vertical list leaves no room for the panel; the API only grows, so a later `orientation` costs nothing now, and leaving it out keeps the CSS to one direction.

`onChange` also fires for Base UI's automatic changes, with `details.reason` `'initial'`, `'disabled'` or `'missing'`, as well as for the user's (`'none'`). The contract passes Base UI's details through unchanged, and a caller that keeps the value elsewhere, such as in the URL, needs to hear the fallback; one that only wants the user's choices checks `details.reason`.

## Tokens

One row per part, state and property. States are the contract's design states: rest is no selector, hover is `:hover` inside `@media (hover: hover)`, pressed is `:active`, focus is `:focus-visible`, disabled is `[data-disabled]`, and selected is Base UI's `[data-active]` on the tab (Tabs sets no `data-selected`). Every `color` row on `tab` sets the tab's `color`, which the label takes.

A tab is `size.button` tall, as its least height, with no new `size.tab` token. `size.button` (36 px) is the height of a button of label text, which a tab is, and it clears `size.target-min`; `size.control` (34 px) is for icon buttons and chips, and `size.segment` (32 px) is the segmented control's, which a tab should not be mistaken for.

The tabs are underline tabs: no fill in any state, the label `color.text.secondary` at rest and `color.text.primary` on hover, pressed and selected, the selected tab marked by a `border.width.050` underline in `color.text.primary`, on a `border.width.025` hairline in `color.border.subtle` under the whole list. [Semantic spacing](../foundations/semantic-spacing.md#border-widths) gives `border.width.050` to "the selected state of a control"; `color.text.primary` is the neutral intent's mark and reaches 17:1, past the 3:1 a state mark needs, where the hairline only decorates; a fill would read as the segmented control's selected segment; and the selected tab is told by its underline, not by its colour alone.

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: which tab is selected, which the underline shows, is `aria-selected`; a disabled tab's tertiary colour is `aria-disabled`; the count is text in the tab's name, heard after the label; the underline itself is `presentation`.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's tabs already give the one tab stop, the roving `tabIndex`, the arrow, Home and End keys, the wrap, manual activation, the first-enabled fallback and the tab and panel ARIA, so the components rebuild none of it and add no key handlers.
- **CR-2.** `TabsList`, `Tab` and `TabsPanel` only render inside a `Tabs`: Base UI's parts read its context. Every story renders them in one, and the `Default` story's args hold a whole set, a list of tabs and a panel for each, so the contract story renders it alone.
- **CR-3.** Each of the four takes `{...rest}` before its own attributes and its own props out of `rest` first (`value`, `defaultValue`, `onChange`, `disabled`, `count`, `slotProps`; an inherited Base UI prop such as `activateOnFocus` or `keepMounted` stays in `rest`, keeping Base UI's default), and merges `className` after its own `pn-` class; `ref` reaches its one element.
- **CR-4.** `Tabs` adapts Base UI's `onValueChange(value, details)` into `onChange(details.event, value, details)` inside itself and exposes neither `onValueChange` nor `orientation`. It passes `defaultValue` on only when the caller gives one, so Base UI's first-enabled fallback runs when it is left out, and with no destructuring default its JSDoc says `@default The first enabled tab`, as the Props table gives it.
- **CR-5.** `TabsList` renders one `Tabs.Indicator` after its `children`, with `slotProps.indicator` merged by `mergeProps`, the component's own props last. The list is `position: relative` and the indicator `position: absolute` at the block end of the selected tab's row, so it covers the list's hairline only when that tab is on the last row (CR-11), its `left` and `width` read from Base UI's `--active-tab-left` and `--active-tab-width`, its underline drawn as a `border-block-end`, never a background, so Windows' forced colours keep it.
- **CR-6.** No rule sets `display` on the indicator or on a panel: Base UI hides both with the `hidden` attribute (the indicator until the selected tab is measured, a panel while its tab isn't selected), and a `display` would show them. The panel being left is the one exception to `hidden`: Base UI keeps it mounted, without `hidden` and with `data-ending-style`, until its exit animations end, a frame at least with none, so `.pn-TabsPanel[data-ending-style]` sets `position: absolute` and `visibility: hidden`, taking it out of the flow and out of sight meanwhile, and the new panel never paints below it.
- **CR-7.** The states keep the tab's geometry: hover, pressed, focus, selected and disabled change colours only, never the height, padding, gap, typography or weight, so selecting a tab never moves its neighbours or the underline.
- **CR-8.** Hover is read inside `@media (hover: hover)`; pressed (`:active`) takes the hover colour in a rule outside it, so a touch press shows. Neither applies to a disabled tab: both rules exclude `[data-disabled]`, since a disabled tab has `aria-disabled`, not the native `disabled`, and still matches `:hover` and `:active`. Selected is `.pn-Tab[data-active]`, one class then attributes.
- **CR-9.** Focus uses the ring `perron.css` draws on `:focus-visible`, on the tab and on the open panel; the component draws no ring of its own and never removes the outline.
- **CR-10.** Changes of state are immediate: no `duration.*` token fits a tab's state change or the underline's move, so the CSS has no transition, and the underline jumps to the selected tab.
- **CR-11.** When the tabs outrun the list's width, they wrap onto another row (`flex-wrap: wrap` on the list, each tab's label kept on one line with `white-space: nowrap`), rather than the list scrolling sideways. [Accessibility](../foundations/accessibility.md#what-a-person-checks) lets only the map scroll sideways at 320 px, Mylder's tab sets are two to four short words, and Base UI's indicator follows the selected tab onto any row.
- **CR-12.** The count is rendered only when `count` is a number, `0` included, and its text joins the tab's accessible name after the label with a space between, "Disruptions 2", which a `play` test checks; the space is in the markup, not only a CSS gap, which the name leaves out.
- **CR-13.** In `@media (forced-colors: active)`, a disabled tab and its count take `GrayText`, and the underline and the hairline keep their borders in the system colours, so the selected and disabled states still show.
- **CR-14.** Tabs sizes to its container: the root and the list are as wide as the box that holds them, and the tabs sit at the list's inline start. The panel's padding and its place in the detail panel belong to the pattern that uses it.

## Stories

The deferred design's page draws two things: the tab set, `Default`, three tabs ("Departures", "Lines", and "Disruptions" with a count of 2) over the first one's panel; and the tab, with one variant property, `State` (`default`, `hover`, `focus`, `selected`, `disabled`). Each story is named by its variant name (`penpot/README.md`, "Conventions"); the tab's are prefixed `Tab`, as `TabHover`, beside the set's `Default`, since the conventions name a variant by its property values alone.

Every story names its tab list with `aria-label` ("Stop") and gives each panel a line of text. The tab stories render a list of two tabs, "Departures" and "Lines", with the state on "Lines"; the hover and focus stories render at rest: the visual check drives the state, and their `play` tests check it. `Default` is the story the contract story renders, and its args pass every rule alone.

| Story         | Shows                                                                                         | `play` test                                                                                                                                                                                                                                                                                                                                           |
| ------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Default`     | The tab set: three tabs, the first selected, the third with a count of 2, and the first panel | Tab focuses "Departures"; ArrowRight moves focus to "Lines" without selecting it; Enter selects it, shows its panel and calls `onChange` once with `'lines'` and `details.reason` `'none'`; End and Home go to the last and first tab; ArrowLeft from the first wraps to the last; Tab moves to the open panel; Shift+Tab returns to the selected tab |
| `TabDefault`  | A tab at rest, not selected                                                                   | none                                                                                                                                                                                                                                                                                                                                                  |
| `TabHover`    | A tab, hover                                                                                  | Hovering "Lines" sets its colour to `color.text.primary`                                                                                                                                                                                                                                                                                              |
| `TabFocus`    | A tab, focus                                                                                  | Tab, then ArrowRight, gives "Lines" `:focus-visible` and the ring                                                                                                                                                                                                                                                                                     |
| `TabSelected` | A tab, selected, with the underline under it                                                  | "Lines" has `aria-selected="true"` and `data-active`, and the indicator's `left` and `width` match its box                                                                                                                                                                                                                                            |
| `TabDisabled` | A tab, disabled                                                                               | "Lines" has `aria-disabled` and `data-disabled`, the arrow keys still reach it, and a click or Enter doesn't select it or call `onChange`                                                                                                                                                                                                             |
| `Count`       | Three tabs with counts of 12, 0 and 2                                                         | Each tab's accessible name is its label, a space and its count ("Disruptions 2"), and the tab with `0` shows its count                                                                                                                                                                                                                                |
| `Controlled`  | Tabs given `value` and `onChange` from the story's state                                      | A click on "Lines" calls `onChange` with `'lines'`; the panel changes only once the story sets `value`; setting `value` from outside moves the underline                                                                                                                                                                                              |
| `Wrapping`    | Five tabs in a 320 px wide container                                                          | The tabs wrap onto a second row, the list doesn't scroll sideways (its `scrollWidth` equals its `clientWidth`), and the underline sits under the selected tab on the second row                                                                                                                                                                       |

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                                  | Don't                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Tabs to switch between views of one thing, such as a stop's departures, lines and disruptions                                                   | Use Tabs to filter or sort one view, such as departures by mode: a segmented control or filter chips change a view, tabs change which one   |
| Name the tab list with `aria-label` or `aria-labelledby`, such as the stop's name, so a screen reader tells it from the next one                    | Leave the list unnamed beside another set of tabs                                                                                           |
| Keep each label to a word or two, in sentence case: "Departures", "Planned works"                                                                   | Write a sentence on a tab, or put a count in the label's text: give it as `count`, so every count has one shape                             |
| Give every `Tab` a `TabsPanel` with the same `value`                                                                                                | Leave a tab without a panel: its `aria-controls` points at nothing, and selecting it shows nothing                                          |
| Show a tab whose view is empty, and say so in its panel with an [EmptyState](empty-state.md) or a [DataStatePanel](../patterns/data-state-panel.md) | Disable a tab because its view has no data: a disabled tab can't say why, and the empty view is what Mylder should tell                     |
| Use `keepMounted` on a panel that holds state the caller would lose, such as a scrolled list                                                        | Keep every panel mounted by default: hidden panels still render, and update with the live data                                              |
| Link to another screen with a [LinkButton](link-button.md)                                                                                          | Use tabs as navigation between pages: a tab selects a panel on this screen, and a link is what goes elsewhere                               |
| Let the tabs size to their labels and wrap on a narrow screen                                                                                       | Set the list to scroll sideways or give the tabs fixed widths: only the map scrolls sideways, and a translated label outgrows a fixed width |
