# TextArea

The box a person types several lines of words into, such as a note about what they saw on a trip, framed by the [Field](field.md) that gives it its label, its line of help and its error message.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens, the Base UI reference for `Field` (`@base-ui/react` 1.9.0, installed, and its `FieldControl` source), the [Field](field.md) spec, the entry TextArea's registry entry names in `dependsOn`, and the [TextField](text-field.md) spec, its one-line twin, whose choices TextArea keeps wherever a textarea doesn't change them. No ROADMAP line names TextArea, and the extracted prototype component is not in any branch this run can reach. The Base UI reference names no textarea: `Field.Control` renders an `<input>`, and TextArea renders it as a `<textarea>` through `render`, which the installed source handles (its Enter handling runs only on an `<input>`).

## Anatomy

Penpot page `Components/TextArea`. Family: Fields, for the box. Shared parts: `VisuallyHidden`, through Field, for a hidden label.

TextArea composes the [Field](field.md) component for the frame, and Base UI's `Field.Control`, rendered as a `<textarea>`, for the box, as Field's spec says the components that draw a text box do. The registry entry's `Field.Root`, `Field.Label`, `Field.Description` and `Field.Error` are Field's: TextArea reaches them through Field's props and `slotProps`, and never renders them itself, so the frame is drawn once, in Field's folder. Base UI's `Field.Item` and `Field.Validity` are left out, as Field leaves them out.

TextArea's root is the `<textarea>` itself, `Field.Control` with `render={<textarea />}`, taking `ref`, `className` and its declared props by name and `style` and every other prop of a `<textarea>` through `{...rest}`, with Field rendered round it as the frame. The contract's [State and events](README.md#state-and-events) rule "Native text" names the `<textarea>` beside the `<input>`: a component whose value lives in one renders that element as its root and passes React's own `onChange(event)`, `value` and `defaultValue`, so React Hook Form's `register()` works unchanged, as on TextField; and the contract story's check of `ref` and `data-testid` on one element passes on the textarea as on any root.

## Props

In MUI's layout. Every prop here gets its description as its JSDoc. Slots come last.

`TextAreaProps` extends the `<textarea>`'s own attributes, `Omit<ComponentPropsWithoutRef<'textarea'>, 'onChange' | 'value' | 'defaultValue' | 'disabled' | 'children' | 'dangerouslySetInnerHTML' | 'className' | 'style'>`, with `className` and `style` taken from `Pick<Field.Control.Props, 'className' | 'style'>`, rather than `Field.Control.Props` as TextField does. `Field.Control.Props` is typed on an `<input>`, so its base would accept `type`, `pattern`, `accept` and the rest of an input's attributes, which mean nothing on a textarea, would refuse `cols` and `wrap`, and would type every handler's `currentTarget` as an `HTMLInputElement`; the textarea's own attributes type `onBlur`, `onKeyDown` and the rest on an `HTMLTextAreaElement`, as React Hook Form's `register()` and Formik's `handleBlur` expect; and `className` and `style` keep Base UI's JSDoc and their function of the control's state, inherited as on TextField. `onValueChange` is not in this base, so the banned name never appears.

TextArea leaves out Base UI's `render`, so the root is always the `<textarea>`. TextArea is a textarea only because it sets `render={<textarea />}` on `Field.Control` itself, so a caller's `render` would either be ignored or replace the textarea with something TextArea's CSS, its `rows` and its role don't fit; the root stays one native element, as the contract's "Native text" rule asks; and `render` can join later as an optional prop without a break. The frame's `render` stays reachable through `slotProps.field`.

`rows` is a prop of TextArea's own, a `number` with the default `3`, set on the textarea in every render. `rows` is the native attribute and MUI's name for the same thing, free in the contract's [Names from other libraries](README.md#names-from-other-libraries) table; the browser's own default, 2, leaves room for barely a sentence of `typography.body` before the box scrolls; three lines hold a short note whole and show at a glance that the box takes more than one line, where two read as a tall text field; and declaring it gives the default and the JSDoc a row on the docs page.

The box keeps the height its `rows` give it, the person dragging it taller by the browser's grip, with no growing to fit the words (no `field-sizing: content`, no `minRows` or `maxRows`). `field-sizing` is not in every browser Mylder supports, so a growing box would grow in one browser and scroll in another; a box that keeps its height keeps the screen round it still while the person types; the words scroll inside it, and the grip gives more room to whoever wants it; and `minRows` and `maxRows` can join later as optional props without a break.

TextArea leaves out a count of the characters typed against `maxLength`. Mylder's screens set no limit a person meets while typing, a count would be an owned string in four locales and a live region that speaks on every key, and `maxLength` already stops the typing at the limit natively; a count can join later as an optional prop, beside the Count component, without a break.

`TextAreaProps` declares, beside Field's `label`, `hiddenLabel`, `optional`, `optionalLabel`, `description` and `error` and the contract's `disabled`, `ref` and `slotProps`, the textarea's own `name`, `rows`, `placeholder`, `required`, `value`, `defaultValue` (typed `string`) and `onChange` (React's `(event: ChangeEvent<HTMLTextAreaElement>) => void`), so each gets a row and its JSDoc on the docs page, and leaves `readOnly`, `autoComplete`, `maxLength`, `minLength`, `cols`, `wrap`, `spellCheck` and the rest of the `<textarea>`'s attributes inherited with no row, as TextField does for its input. `disabled` is declared because it goes to the frame (CR-5); `children` and `dangerouslySetInnerHTML` are left out because React takes a textarea's words from `value` and `defaultValue`, never from its children.

TextArea takes no `type`, since a `<textarea>` has none, and no `variant`, `size`, `color` or `fullWidth`, so its root carries no `data-variant`, `data-size` or `data-color`, and Base UI's state attributes are its data attributes: there is one field look in the Fields family, its height is its `rows`, and the box takes the frame's width, which takes its container's (CR-11), as TextField's does.

## Tokens

One row per part, state and property. The design states the deferred drawing shows are rest, hover, focus, disabled and invalid, for the box; the frame's parts take Field's tokens, which TextArea's CSS never writes again. Pressed, open and selected don't apply: a text box is neither pressed, opened nor chosen.

The box is the Fields family's, as TextField's is: `color.surface.raised`, a `border.width.025` edge in `color.border.control`, `radius.md`, the hover layer laid over the fill as a `linear-gradient`, and `color.status.danger` for the edge when invalid; its words are `typography.body` in `color.text.primary`, and its placeholder and its disabled words `color.text.tertiary` ([Typography](../foundations/typography.md), the contract's [Families](README.md#families)). `color.border.control` and `color.status.danger` reach 3:1 on every surface in both themes ([Accessibility](../foundations/accessibility.md)). Where TextField is `size.input` tall, the textarea is as tall as its `rows` of `typography.body` and its padding, and never less than `size.input`, so one row reads as a text field.

The box takes `space.300` on both inline sides, TextField's padding, so a TextArea under a TextField starts its words on the same line.

The box keeps its rest look while Base UI marks it focused without `:focus-visible`, filled, dirty, touched or valid, and while it is read-only, and draws the invalid edge only while it is not disabled, for TextField's reasons: none of these is a design state the contract names, a textarea matches `:focus-visible` whenever it has focus, a read-only box keeps its words selectable and focusable, and a disabled field's error turns to the tertiary ink in Field's CSS.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the label names the textarea, even hidden, with the `optional` mark inside it; the description and the error are the textarea's `aria-describedby`; an invalid field is `aria-invalid` and its error is words beside the red edge, never the edge alone; the placeholder is never the name, and a story proves the textarea is named by the label with a placeholder given; the box being several lines is its native multi-line role, heard as such.
- [ ] Every landmark and named region has an accessible name: none here; TextArea is not a landmark, and a group of fields is a Fieldset's to name.
- [ ] Every default label can be overridden: `optionalLabel` overrides "(optional)", the one owned string, Field's.
- [ ] Every shape the type accepts renders, in every variant: `label`, `description` and `error` render a string, an element and a list alike, as Field's do; a value with new lines keeps them; a long Danish compound wraps in the label, the description, the error and the box (CR-7).
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the error is unmounted while the field is valid.
- [ ] Native semantics first: a native `<textarea>` with its own `required`, `readonly`, `minlength` and `maxlength`, and a native `<label>`; Perron adds no ARIA, and Base UI only `aria-labelledby`, `aria-describedby` and `aria-invalid`.
- [ ] Focus moves in reading order and returns on close: the textarea is the field's one tab stop, between the label and description above it and the error below; Tab leaves it, since a textarea takes no Tab of its own; nothing opens or closes.
- [ ] Every target is at least `size.target-min` square: the box, at least `size.input` tall and as wide as its container; the label is a larger target for the same textarea. The resize grip is the browser's own and sized by it, which WCAG 2.2's target size (2.5.8) excepts as a user-agent control, and the box works without it, its words scrolling.
- [ ] Loops stop when the system asks for less motion: none here; TextArea has no loop and no transition (CR-8).

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's `Field.Control` and Field already name the textarea, tie the help and the error to it, run the checks, mark it invalid and keep its value and its state attributes, so TextArea rebuilds none of it and adds no key, pointer, focus or validation handler.
- **CR-2.** TextArea renders Field, from `packages/perron/src/components/Field/Field.tsx`, with `slotProps.field` spread first, then `className` (`pn-TextArea-field` before the caller's, with the shared `withClass` helper from `packages/perron/src/internal/nodes.ts`), `disabled`, `label`, `hiddenLabel`, `optional`, `optionalLabel`, `description` and `error`, and its `slotProps` `label`, `description` and `error` each with its class set the same way, `pn-TextArea-<part>` before the caller's; Field's own `pn-Field-<part>` classes come first, so a part reads `pn-Field-label pn-TextArea-label`. Field's one child is `Field.Control`, the box. TextArea never renders `Field.Root`, `Field.Label`, `Field.Description` or `Field.Error` itself, as TextField's CR-2 says for its box.
- **CR-3.** `{...rest}` reaches `Field.Control` before TextArea's own attributes, and every prop `TextAreaProps` declares is taken out of `rest` first: the frame's (`label`, `hiddenLabel`, `optional`, `optionalLabel`, `description`, `error`, `disabled`, `slotProps`), none of which reaches the `<textarea>`, and the textarea's (`name`, `rows`, `placeholder`, `required`, `value`, `defaultValue`, `onChange`), each passed to `Field.Control` by name after the spread. `ref`, `style`, `id` and `data-testid` land on the textarea, and `className` is merged after `pn-TextArea` with `withClass`, a string or a function of the control's state. A prop the caller leaves out reaches `Field.Control` as `undefined`, which Base UI reads as left out, so an uncontrolled field stays uncontrolled, and React Hook Form's `register()` reaches the textarea with its `name`, `onChange`, `onBlur` and `ref` unchanged.
- **CR-4.** `onChange` is React's own on the textarea, with no adapter: Base UI merges it with its own handler, the caller's running first. TextArea takes no `onValueChange` and never calls the caller's `onChange` itself.
- **CR-5.** `disabled` goes to Field, and so to `Field.Root`, never to the textarea directly: Base UI then disables the textarea and marks the label, the description and the error `data-disabled`, so the whole field turns to the tertiary ink together. `slotProps.field` takes no `disabled` and no `name`, so each has one place, TextArea's own prop; `name` goes on the textarea.
- **CR-6.** The textarea is the box, with no wrapper: `Field.Control` renders it through `render={<textarea />}`, set after the spread in every render so nothing replaces it, and TextArea's CSS draws the fill, the edge, the radius and the padding on `.pn-TextArea` itself, and no outline, so the page's `:focus-visible` ring from `perron.css` draws round the box at `focus.offset`.
- **CR-7.** Long words: the textarea wraps its words at its edge, as a native textarea does, and breaks a word longer than its line (`overflow-wrap: anywhere`), since the box takes its container's width; the label, the description and the error wrap, by Field's CR-8. A new line the person types is kept, the textarea's own `pre-wrap`.
- **CR-8.** Hover and invalid change the box at once: no `duration.*` token fits a field's edge or fill, so the CSS has no transition or animation.
- **CR-9.** `optional` and `required` are independent, as TextField's CR-9 says: TextArea sets neither from the other, and passes `required` to the textarea only.
- **CR-10.** `rows` is set on the textarea in every render, `3` when the caller leaves it out, so the box's height never depends on the browser's default.
- **CR-11.** The box takes the frame's width (`inline-size: 100%`, `box-sizing: border-box`), and the frame its container's, as Field's CR-7 says; TextArea sets no width of its own, and `cols` sets none either, so a caller sets it on the container, or on the frame through `slotProps.field`.
- **CR-12.** The subject story doesn't set `optional`, so the contract story's owned-strings check never sees the mark: the `Optional` story's render gets its own test, which runs `expectOwnedStrings` (`packages/perron/src/testing/owned-strings.ts`) on its server-rendered markup in `en`, `da`, `sv` and `nb`, with the label and the description as the caller's words, as Field's CR-12 does.
- **CR-13.** The `placeholder` rule sets `opacity: 1` beside `color.text.tertiary`, since Firefox dims a placeholder on its own and the tertiary ink is already the hint's colour.
- **CR-14.** The box keeps the height its `rows` and padding give it and never grows with its words: they scroll inside it (the textarea's own `overflow: auto`), and `resize: vertical` lets the person drag it taller, never wider, so it never leaves its column; `min-block-size: size.input` stops a drag below one text field's height; a disabled box takes `resize: none`. TextArea sets no `field-sizing`.
- **CR-15.** `TextAreaProps` is built on the `<textarea>`'s own attributes, `Omit<ComponentPropsWithoutRef<'textarea'>, 'onChange' | 'value' | 'defaultValue' | 'disabled' | 'children' | 'dangerouslySetInnerHTML' | 'className' | 'style'>`, with `className` and `style` from `Pick<Field.Control.Props, 'className' | 'style'>`, and never on `Field.Control.Props` whole, so every handler is typed on an `HTMLTextAreaElement`, `cols` and `wrap` are accepted, and an input's `type`, `pattern` and `accept` are refused. Base UI's `render` and `onValueChange` are not in it: the root is always the `<textarea>` CR-6 renders, and `onChange` is the one change handler (CR-4).

## Stories

The deferred drawing has no variant property and a `State` property with the values `default`, `hover`, `focus`, `disabled` and `invalid`, as TextField's, so its variants, and the stories that carry their names, are `Default`, `Hover`, `Focus`, `Disabled` and `Invalid`; a `State` of `default` gives `Default`, the subject story. Whether the box holds words is its value, not a state, so `Filled` is a story beside them, as are the stories of content and behaviour.

The stories render the field on its own in a 320 px wide container, in a `PerronProvider` in English, with the label "What happened" and the description "Say where and when, such as the stop and the time" unless the story says otherwise ([Content design](../content-design.md)), and an `fn()` handler for `onChange`. The `Default` story's args, which the contract story renders, hold every word the caller gives. The `Hover` and `Focus` stories render at rest; their `play` tests drive the state. Where a story fills the box, its words are "The 5C waited at Nørreport for 10 minutes." and, on a second line, "The display showed no delay.".

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                         | Don't                                                                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Use TextArea for words that run to sentences, such as what the person saw on a trip                                        | Use it for a name, an address or a number: TextField and NumberField take one line, its keys and its autofill                                |
| Give a `label` that names the words, "What happened", and hide it with `hiddenLabel` only where the screen already says it | Let the `placeholder` stand in for the label: it vanishes as the person types, and it is drawn in `color.text.tertiary`, below text contrast |
| Put help the person needs while typing in `description`, "Say where and when, such as the stop and the time"               | Put that help in the `placeholder`: it is gone once they type                                                                                |
| Word an `error` as what to do, "Say what happened"                                                                         | Blame the person or say only that it failed ("Invalid input"), against [Content design](../content-design.md)                                |
| Set `rows` to the length of words you expect, so most of them fit without scrolling                                        | Set `rows` to fill the screen: a tall empty box asks for more than the form needs, and the person can drag it taller                         |
| Spread React Hook Form's `register('note')` on TextArea, or pass Formik's `handleChange`, as on a native `<textarea>`      | Wrap TextArea in a controller to read its value: its `onChange` is the native one already                                                    |
| Give `error` from the form library whenever the field is invalid                                                           | Set `slotProps.field.invalid` with no message: the red edge alone tells only the eye, and only by its colour                                 |
| Set `optional` on the few fields the person may leave empty, and `required` where an empty field must fail                 | Write "(optional)", "(required)" or an asterisk into `label` yourself: it misses the locale, and an asterisk needs a legend                  |
| Let Enter start a new line, and give the form a submit button                                                              | Make Enter submit the form from a TextArea: the person loses the one key that starts a new line                                              |
| Use TextArea on its own: it already has its label, its help and its error                                                  | Wrap TextArea in Field: the textarea would be labelled twice, as Field's spec says                                                           |
| Set the width on the container, or on the frame through `slotProps.field`                                                  | Give the textarea a width through `style` or `cols`: the label and the error take the frame's width, not the box's                           |
