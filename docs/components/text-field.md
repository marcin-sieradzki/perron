# TextField

The box a person types one line of words into, such as a stop's name or an email address, framed by the [Field](field.md) that gives it its label, its line of help and its error message.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens, the Base UI reference for `Field` (`@base-ui/react` 1.9.0, installed) and the [Field](field.md) spec, the entry TextField's registry entry names in `dependsOn`. No ROADMAP line names TextField, and the extracted prototype component is not in any branch this run can reach.

## Anatomy

Penpot page `Components/TextField`. Family: Fields, for the box. Shared parts: `VisuallyHidden`, through Field, for a hidden label.

TextField composes the [Field](field.md) component for the frame, and Base UI's `Field.Control` for the box. The registry entry's `Field.Root`, `Field.Label`, `Field.Description` and `Field.Error` are Field's: TextField reaches them through Field's props and `slotProps`, and never renders them itself, so the frame is drawn once, in Field's folder. Base UI's `Field.Item` and `Field.Validity` are left out, as Field leaves them out.

TextField's root is the `<input>` itself, `Field.Control`, taking `ref`, `className`, `style` and every other prop through `{...rest}`, with Field rendered round it as the frame. The contract's [State and events](README.md#state-and-events) rule "Native text" says a component whose value lives in a native `<input>` renders that element as its root and passes React's own `onChange(event)`, `value` and `defaultValue`, so that React Hook Form's `register()`, which returns `name`, `ref`, `onChange` and `onBlur` for the input, works unchanged; SearchField's root is `Field.Root` only because Autocomplete changes its value from outside the input's own events, which TextField's never does; and the contract story's check of `ref` and `data-testid` on one element passes on the input as on any root.

The frame's `slotProps` key is `field`, typed `Omit<Field.Root.Props, 'children' | 'disabled' | 'name'>`, and the class it adds is `pn-TextField-field`; it is the way a caller reaches Base UI's `invalid`, `validate`, `validationMode`, `validationDebounceTime`, `dirty`, `touched` and `actionsRef`, which take no TextField prop of their own. The contract keys `slotProps` by the Base UI part in camelCase, which for `Field.Root` would be `root`, but the contract's root takes no key, and here the root is the input, so `root` would name the wrong element; `field` names the part by the component that draws it, as the stories and the docs call it; those seven props are the frame's, set rarely, and a form library's message needs only `error`; and `disabled` and `name` are left out of the key because TextField takes them itself (CR-5), so each has one place.

TextField takes no `startIcon` or `endIcon`, no prefix or suffix text, no clear button and no password reveal button, so the input is the whole box with no wrapper. The registry entry lists no `InputGroup`, Mylder's one field with a mark and a clear button is SearchField, and each can join later as an optional prop without a break, the box's look moving onto a wrapper then while `ref` and `className` stay on the input.

## Props

In MUI's layout. Every prop here gets its description as its JSDoc. Slots come last.

`TextFieldProps` extends `Field.Control.Props` without `onValueChange`, `ref` and `disabled`, so `className`, `style` and `render` are inherited with Base UI's JSDoc, and every attribute of an `<input>` reaches the root. `onValueChange` is left out because the contract's [Names from other libraries](README.md#names-from-other-libraries) bans it, and the native `onChange(event)` already gives the words; `disabled` is declared again because it goes to the frame (CR-5).

`TextFieldProps` declares, beside Field's `label`, `hiddenLabel`, `optional`, `optionalLabel`, `description` and `error` and the contract's `disabled`, `ref` and `slotProps`, the input's own `name`, `type`, `placeholder`, `required`, `value`, `defaultValue` (typed `string`) and `onChange` (React's `(event: ChangeEvent<HTMLInputElement>) => void`), so each gets a row and its JSDoc on the docs page, and leaves `readOnly`, `autoComplete`, `inputMode`, `maxLength`, `pattern` and the rest of the `<input>`'s attributes inherited with no row. React's own attributes get no row on the docs page, as in MUI's tables, so the words a caller needs to know (the value, its event, the form's name, the box's words and its check) would otherwise be missing from TextField's own page; `name`, `required`, `value`, `defaultValue` and `onChange` are the contract's shared names; `defaultValue` narrows Base UI's `string | number | string[]`, whose JSDoc is empty, to the words a text box holds; and the rest are native and documented by the platform.

`type` is the union `'text' | 'email' | 'password' | 'tel' | 'url'`, default `'text'`, set on the input in every render. These are the text types whose box and keys are a text field's; `'search'` is SearchField's, `'number'` NumberField's, and a date, a colour, a file or a checkbox would render a control this look doesn't draw; the union can widen later without a break.

`optional` and `required` are two props, neither set from the other, with `required` defaulting to `false`. `required` is the native check that marks an empty field invalid, and `optional` is Field's word in the label: Field marks the few fields a form doesn't ask for and never a required one, a screen may mark nothing at all, and deriving one from the other would add "(optional)" to every field that leaves the check to a form library.

TextField takes no `variant`, `size`, `color` or `fullWidth`, so its root carries no `data-variant`, `data-size` or `data-color`, and Base UI's state attributes are its data attributes. There is one field look in the Fields family, `size.input` is the one height the tokens give a field, and the box takes the frame's width, which takes its container's (CR-13), as SearchField's and Field's do.

## Tokens

One row per part, state and property. The design states the deferred drawing shows are rest, hover, focus, disabled and invalid, for the box; the frame's parts take Field's tokens, which TextField's CSS never writes again. Pressed, open and selected don't apply: a text box is neither pressed, opened nor chosen.

The box is the Fields family's: `color.surface.raised`, a `border.width.025` edge in `color.border.control`, `radius.md`, `size.input` tall, the hover layer laid over the fill as a `linear-gradient`, and `color.status.danger` for the edge when invalid; its words are `typography.body` in `color.text.primary`, and its placeholder and its disabled words `color.text.tertiary` ([Typography](../foundations/typography.md), the contract's [Families](README.md#families)). `color.border.control` and `color.status.danger` reach 3:1 on every surface in both themes, as edges that show where a control is and its state ([Accessibility](../foundations/accessibility.md)); a placeholder in `color.text.tertiary` is a hint, the tertiary ink's one use, beside a label in the primary ink.

The box takes `space.300` on both inline sides and no block padding, its words centred in the `size.input` height by the input itself. `space.300` is the inline start SearchField's box takes and the padding Field's stories give their stand-in box, so two fields stacked on one screen start their words on one line; the end matches the start, since nothing sits at the end of this box; and a native input centres one line in its height with no padding.

The box keeps its rest look while Base UI marks it focused without `:focus-visible`, filled, dirty, touched or valid, and while it is read-only, and draws the invalid edge only while it is not disabled, a disabled box keeping its `color.border.control` edge and its `color.surface.raised` fill with its words in `color.text.tertiary`. None of `data-focused`, `data-filled`, `data-dirty`, `data-touched`, `data-valid` or `:read-only` is a design state the contract names, and Field keeps its rest look in each for the same reasons, a "valid" look claiming more than a check knows; a text input matches `:focus-visible` whenever it has focus, so the ring already shows every focus; a read-only box keeps its words selectable and focusable, so it keeps the look of a box; and a disabled field's error turns to the tertiary ink in Field's CSS, so a red edge beside it would say the opposite. The SearchField box keeps its edge and fill when disabled too.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the label names the input, even hidden, with the `optional` mark inside it; the description and the error are the input's `aria-describedby`; an invalid field is `aria-invalid` and its error is words beside the red edge, never the edge alone; the placeholder is never the name, and a story proves the input is named by the label with a placeholder given.
- [ ] Every landmark and named region has an accessible name: none here; TextField is not a landmark, and a group of fields is a Fieldset's to name.
- [ ] Every default label can be overridden: `optionalLabel` overrides "(optional)", the one owned string, Field's.
- [ ] Every shape the type accepts renders, in every variant: `label`, `description` and `error` render a string, an element and a list alike, as Field's do; each of the five `type` values renders its box; a long Danish compound wraps in the label, the description and the error, and stays on one scrolling line in the box (CR-7).
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the error is unmounted while the field is valid.
- [ ] Native semantics first: a native `<input>` with its own `type`, `required` and `readonly`, and a native `<label>`; Perron adds no ARIA, and Base UI only `aria-labelledby`, `aria-describedby` and `aria-invalid`.
- [ ] Focus moves in reading order and returns on close: the input is the field's one tab stop, between the label and description above it and the error below; nothing opens or closes.
- [ ] Every target is at least `size.target-min` square: the box, `size.input` tall and as wide as its container; the label is a larger target for the same input.
- [ ] Loops stop when the system asks for less motion: none here; TextField has no loop and no transition (CR-8).

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's `Field.Control` and Field already name the input, tie the help and the error to it, run the checks, mark it invalid and keep its value and its state attributes, so TextField rebuilds none of it and adds no key, pointer, focus or validation handler.
- **CR-2.** TextField renders Field, from `packages/perron/src/components/Field/Field.tsx`, with `slotProps.field` spread first, then `className` (`pn-TextField-field` before the caller's, with the shared `withClass` helper from `packages/perron/src/internal/nodes.ts`), `disabled`, `label`, `hiddenLabel`, `optional`, `optionalLabel`, `description` and `error`, and its `slotProps` `label`, `description` and `error` each with its class set the same way, `pn-TextField-<part>` before the caller's; Field's own `pn-Field-<part>` classes come first, so a part reads `pn-Field-label pn-TextField-label`. Field's one child is `Field.Control`, the box. TextField never renders `Field.Root`, `Field.Label`, `Field.Description` or `Field.Error` itself.
- **CR-3.** `{...rest}` reaches `Field.Control` before TextField's own attributes, and TextField's own frame props are taken out of `rest` first (`label`, `hiddenLabel`, `optional`, `optionalLabel`, `description`, `error`, `disabled`, `slotProps`), so none reaches the `<input>`. `ref`, `style`, `id` and `data-testid` land on the input, and `className` is merged after `pn-TextField` with `withClass`, a string or a function of the input's state. `name`, `required`, `placeholder`, `value`, `defaultValue` and `onChange` reach the input as given, and a key the caller left out is left out, never set to `undefined`, so an uncontrolled field stays uncontrolled.
- **CR-4.** `onChange` is React's own on the input, with no adapter: Base UI merges it with its own handler, the caller's running first. TextField takes no `onValueChange` and never calls the caller's `onChange` itself, so `register()`'s `onChange`, `onBlur`, `name` and `ref`, spread on TextField, reach the `<input>` unchanged.
- **CR-5.** `disabled` goes to Field, and so to `Field.Root`, never to the input directly: Base UI then disables the input and marks the label, the description and the error `data-disabled`, so the whole field turns to the tertiary ink together. `slotProps.field` takes no `disabled` and no `name`, so each has one place, TextField's own prop; `name` goes on the input.
- **CR-6.** The input is the box, with no wrapper: TextField's CSS draws the fill, the edge, the radius and the height on `.pn-TextField` itself, and no outline, so the page's `:focus-visible` ring from `perron.css` draws round the box at `focus.offset`, as the contract's Design states table says.
- **CR-7.** Long words: the input keeps its words on one line (`white-space: nowrap`) and scrolls them, as a native input does; the label, the description and the error wrap, by Field's CR-8.
- **CR-8.** Hover and invalid change the box at once: no `duration.*` token fits a field's edge or fill, so the CSS has no transition or animation.
- **CR-9.** `optional` and `required` are independent: TextField sets neither from the other, and passes `required` to the input only.
- **CR-10.** `type` is set on the input in every render, `'text'` when the caller leaves it out, so the box's look never depends on the browser's default type.
- **CR-11.** The box takes the frame's width (`inline-size: 100%`, `box-sizing: border-box`), and the frame its container's, as Field's CR-7 says; TextField sets no width of its own, so a caller sets it on the container, or on the frame through `slotProps.field`.
- **CR-12.** The subject story doesn't set `optional`, so the contract story's owned-strings check never sees the mark: the `Optional` story's render gets its own test, which runs `expectOwnedStrings` (`packages/perron/src/testing/owned-strings.ts`) on its server-rendered markup in `en`, `da`, `sv` and `nb`, with the label and the description as the caller's words, as Field's CR-12 does.
- **CR-13.** The `placeholder` rule sets `opacity: 1` beside `color.text.tertiary`, since Firefox dims a placeholder on its own and the tertiary ink is already the hint's colour.

## Stories

The deferred drawing has no variant property and a `State` property with the values `default`, `hover`, `focus`, `disabled` and `invalid`, so its variants, and the stories that carry their names, are `Default`, `Hover`, `Focus`, `Disabled` and `Invalid`; the Penpot conventions name a variant by its property values, and a `State` of `default` gives `Default`, the subject story. Whether the box holds words is its value, not a state, so `Filled` is a story beside them, as are the stories of content and behaviour.

The stories render the field on its own in a 320 px wide container, in a `PerronProvider` in English, with the label "Stop name" and the description "As written on the stop sign" unless the story says otherwise ([Content design](../content-design.md)), and an `fn()` handler for `onChange`. The `Default` story's args, which the contract story renders, hold every word the caller gives. The `Hover` and `Focus` stories render at rest; their `play` tests drive the state.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                     | Don't                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Give a `label` that names the words, "Stop name", and hide it with `hiddenLabel` only where the screen already says it | Let the `placeholder` stand in for the label: it vanishes as the person types, and it is drawn in `color.text.tertiary`, below text contrast         |
| Put help the person needs while typing in `description`, "As written on the stop sign"                                 | Put that help in the `placeholder`: it is gone once they type                                                                                        |
| Word an `error` as what to do, "Enter a stop name"                                                                     | Blame the person or say only that it failed ("Invalid input"), against [Content design](../content-design.md)                                        |
| Spread React Hook Form's `register('stop')` on TextField, or pass Formik's `handleChange`, as on a native `<input>`    | Wrap TextField in a controller to read its value: its `onChange` is the native one already                                                           |
| Give `error` from the form library whenever the field is invalid                                                       | Set `slotProps.field.invalid` with no message: the red edge alone tells only the eye, and only by its colour                                         |
| Give `autoComplete` for the person's own details, such as `autoComplete="email"`, so the browser can fill them         | Leave a field that asks for a name, an email address or a phone number without `autoComplete`: WCAG 2.2's identify input purpose (1.3.5) asks for it |
| Set `optional` on the few fields the person may leave empty, and `required` where an empty field must fail             | Write "(optional)", "(required)" or an asterisk into `label` yourself: it misses the locale, and an asterisk needs a legend                          |
| Use SearchField to find a line or a stop, and NumberField for a number                                                 | Give TextField a `type` of `'search'` or `'number'`: the type union leaves them out, and SearchField and NumberField carry their own keys and words  |
| Use TextField on its own: it already has its label, its help and its error                                             | Wrap TextField in Field: the input would be labelled twice, as Field's spec says                                                                     |
| Set the width on the container, or on the frame through `slotProps.field`                                              | Give the input a width through `style` alone: the label and the error take the frame's width, not the box's                                          |
