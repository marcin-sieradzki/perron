# NumberField

The box a person types a number into, or steps up and down with its minus and plus buttons and the arrow keys, such as how many departures a board shows, framed by the [Field](field.md) that gives it its label, its line of help and its error message.

## Anatomy

Penpot page `Components/NumberField`. Family: Fields, for the box. Shared parts: `VisuallyHidden`, through Field, for a hidden label.

NumberField composes the [Field](field.md) component for the frame, and Base UI's `NumberField.Root`, `NumberField.Group`, `NumberField.Input`, `NumberField.Decrement` and `NumberField.Increment`, the parts its registry entry lists, for the control. Field's `Field.Root`, `Field.Label`, `Field.Description` and `Field.Error` are reached through Field's props and `slotProps`, as TextField reaches them, so the frame is drawn once, in Field's folder. Base UI's `NumberField.ScrubArea` and `NumberField.ScrubAreaCursor` are left out, as the registry entry leaves them out: dragging a label to change a number is a design tool's gesture, the cursor takes the pointer lock, and the keys and the buttons already step the value.

NumberField's root is Base UI's `NumberField.Root`, with Field rendered round it as the frame and reached through `slotProps.field`, as TextField's root is its control and its frame `slotProps.field`. `NumberField.Root` is where Base UI takes the value and every number prop (`min`, `max`, `step`, `format`, `name`, `required`, `readOnly`), so `{...rest}` reaches them with no prop of NumberField's own; the contract's "Native text" rule doesn't apply, since the value is a number Base UI keeps, submitted through its hidden `<input type="number">`, which makes NumberField a composite control whose `name` goes to Base UI's root (the contract's "Forms"); and TextField's `field` key is then the one way into the frame in both siblings.

The parts sit in the order the frame gives, label, description, the box, error, and inside the box the input, then the decrement button, then the increment button.

The frame's key is `field`, typed `Omit<Field.Root.Props, 'children' | 'disabled' | 'name'>`, as TextField's is, for the same reasons: the contract's root takes no key, `field` names the part by the component that draws it, and `disabled` and `name` each have one place, NumberField's own prop (CR-5).

Both stepper buttons sit at the end of the box, the decrement button then the increment button, each a `size.control` square, with the number at the box's start. The number then starts `space.300` in, on the line where a TextField's or a SearchField's words start in a form beside it; both buttons sit under one thumb; minus before plus is reading order, and the flex row turns them round in right-to-left text; and `size.control`, 34 px in the box's 36 px between its edges, is the square the SearchField's clear button already takes in the same box, larger than `size.target-min`.

The buttons draw the `minus` and `plus` icons the map's zoom buttons already use, and the build widens their `use` in `packages/perron/icons/icons.json` to name the number field too, rather than drawing new ones: the same shapes mean one step down and one step up in both places, they are drawn at `icon.size.400`, the step [Icons](../foundations/icons.md) gives an icon inside a control, and a second drawing of the same shape would be two files to keep alike.

Base UI already does: everything Field's spec lists for the frame, and for the number: it keeps an uncontrolled value from `defaultValue` or a controlled one from `value`, `null` while the box is empty; it lets the person type only digits, the locale's decimal and group separators, the symbols the `format` renders, a plus sign, and a minus sign only while `min` is below zero or unset, or `allowOutOfRange` is set, one of each; it parses the typed text in the locale and reports each parseable number as it is typed, clamping it to `min` and `max` unless `allowOutOfRange` is set; it formats the text in the locale with `format` when the input loses focus; it steps the value by `step` on ArrowUp and ArrowDown, by `largeStep` with Shift and by `smallStep` with Alt, and jumps to `min` on Home and to `max` on End when they are set; it steps once on a press of a button, then again every 60 ms after the press is held for 400 ms, focusing the input on a mouse or pen press so the keys go on from there; it disables the decrement button at `min` and the increment button at `max`, and both while the field is disabled or read-only; it keeps the buttons out of the tab order, since the keys do the same on the input, and keeps them in the accessibility tree for a touch screen reader; it splices a paste in at the caret; it steps on the mouse wheel only with `allowWheelScrub`; it keeps the hidden `<input type="number">` in step with the value, so a native form submits it under `name`, the browser's checks (`required`, `min`, `max`, `step`) run on it, and the browser's autofill reaches the value; and it marks the field filled, dirty, touched and focused for Field.

## Props

In MUI's layout. Every prop here that `NumberFieldProps` declares gets its description as its JSDoc, and every inherited one keeps Base UI's. Slots come last.

`NumberFieldProps` extends `NumberField.Root.Props` without `onValueChange`, `onValueCommitted`, `disabled`, `locale`, `children` and `ref`, so `value`, `defaultValue`, `name`, `min`, `max`, `step`, `smallStep`, `largeStep`, `snapOnStep`, `allowOutOfRange`, `allowWheelScrub`, `format`, `readOnly`, `required`, `id`, `form`, `inputRef`, `render`, `className` and `style` are inherited with Base UI's JSDoc and `@default`, and every attribute of a `<div>` reaches the root. `onValueChange` and `onValueCommitted` are left out because the contract's [Names from other libraries](README.md#names-from-other-libraries) bans the first, and NumberField takes each as an MUI-shaped event (CR-4); `disabled` is declared again because it goes to the frame (CR-5); `locale` is declared again because its default is the PerronProvider's, not the runtime's (CR-6); `children` is left out because the root's children are the parts.

NumberField takes Base UI's `onValueCommitted` as `onChangeCommitted(event, value, details)`, MUI's Slider name in the contract's event shape, since the contract adapts every Base UI event into MUI's names with `details` last. It declares `placeholder` and passes it to `NumberField.Input`, as TextField declares its own, since the root is a `<div>`, where a `placeholder` in `{...rest}` would mean nothing.

`value` is `number | null`, `null` while the box is empty, and `defaultValue` a `number`, Base UI's types: a number field's value is a number, so the contract's [State and events](README.md#state-and-events) "Native text" rule, a `string` and React's `onChange(event)`, is TextField's, not this one's. A form library connects through its controller, as the contract's "Forms" says.

`optional` and `required` are two props, neither set from the other, as TextField's CR-9 says: `required` is Base UI's, inherited, the check that marks an empty field invalid, and `optional` Field's word in the label.

NumberField takes no `variant`, `size`, `color` or `fullWidth`, so its root carries no `data-variant`, `data-size` or `data-color`, and Base UI's state attributes are its data attributes. There is one field look in the Fields family, `size.input` is the one height the tokens give a field, and the box takes the frame's width, which takes its container's (CR-12), as TextField's does. It takes no prop that hides the buttons: a number field whose buttons a screen doesn't want is a TextField with `inputMode`, and a prop can join later without a break.

## Tokens

One row per part, state and property. The design states the deferred drawing shows are rest, hover, focus, disabled and invalid, for the box, and rest, hover, pressed and disabled for the two buttons; the frame's parts take Field's tokens, which NumberField's CSS never writes again. Open and selected don't apply: nothing opens, and nothing is chosen.

The box is the Fields family's, drawn on the group as SearchField draws its box on its input group: `color.surface.raised`, a `border.width.025` edge in `color.border.control`, `radius.md`, `size.input` tall, the hover layer laid over the fill as a `linear-gradient`, `color.status.danger` for the edge when invalid, and the ring round the whole box while the input inside it has `:focus-visible` ([Typography](../foundations/typography.md), the contract's [Families](README.md#families)). It takes `space.300` at its inline start, where TextField's and SearchField's words start, and `space.050` at its end, so a `size.control` button sits 1 px inside the edge, as SearchField's clear button does; `space.050` between the input and the buttons and between the two buttons keeps them one pair, apart from the number.

The number is `typography.body` in `color.text.primary`, the contract's type for a field's words, rather than a `data` role: [Typography](../foundations/typography.md) keeps `data` for figures people compare down a column, and a field's number is read on its own, beside a label set in the text family.

The input sets `font-variant-numeric: tabular-nums`, so the digits keep their widths as a held button steps the number: Schibsted Grotesk's proportional figures would shift the number sideways on every step, the keyword is a CSS literal the contract allows, and it changes no token.

The buttons take the look SearchField's clear button takes from the `CloseButton` part: a `size.control` square, `radius.md`, transparent, the icon `icon.size.400` in `color.text.secondary`; `color.surface.hover` with `color.text.primary` on hover; `color.surface.selected` while pressed; and the icon in `color.text.tertiary` while disabled, with no hover and no pressed look. `color.text.secondary` reaches 4.5:1 on the raised fill in both themes, more than an icon needs ([Accessibility](../foundations/accessibility.md)); and `icon.size.400` is the step the [Icons](../foundations/icons.md) page gives an icon inside a control. NumberField's CSS draws them itself, since `CloseButton` draws the `close` icon and is named "Close" (CR-8).

The box keeps its rest look while Base UI marks it focused without `:focus-visible`, filled, dirty, touched, valid or required, and while it is read-only, for the reasons TextField's and Field's specs give; a disabled box keeps its fill and its `color.border.control` edge, with the number and both icons in `color.text.tertiary`, and draws the invalid edge only while it is not disabled. `data-scrubbing` never appears, since NumberField has no scrub area.

The buttons of a read-only field show their icons in `color.text.tertiary`, with no hover and no pressed look, as a disabled field's do, while the box and the number keep their rest look. Base UI marks both buttons `aria-disabled` while the field is read-only, so the ear hears them as unavailable, and the eye is told the same (the contract's first "What axe won't catch" line); the number stays in `color.text.primary`, since a read-only value is still read, and its words stay selectable.

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the label names the input, even hidden, with the `optional` mark inside it; the description and the error are the input's `aria-describedby`; an invalid field is `aria-invalid` and its error is words beside the red edge; each button's icon is `aria-hidden` and its name says what it does; a button the eye sees in the tertiary ink is `aria-disabled` for the ear, at a bound, read-only or disabled; the placeholder is never the name.
- [ ] Every landmark and named region has an accessible name: none here; Base UI's `group` is no landmark, and a group of fields is a Fieldset's to name.
- [ ] Every default label can be overridden: `increaseLabel`, `decreaseLabel` and `numberFieldLabel` override NumberField's three owned strings, and `optionalLabel` Field's.
- [ ] Every shape the type accepts renders, in every variant: `label`, `description` and `error` render a string, an element and a list alike, as Field's do; `value` renders a number and an empty box for `null`; a `format` with a unit or a percent sign renders inside the box; a long Danish compound wraps in the label, the description and the error, and a long number stays on one scrolling line in the box (CR-10).
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the error is unmounted while the field is valid, and Base UI's hidden input is `aria-hidden` because the visible input is the control.
- [ ] Native semantics first: a native `<input>`, a native `<label>` and two native `<button>`s; Perron adds `aria-label` on the buttons and `aria-roledescription` on the input, each in place of Base UI's English, and Base UI adds `role="group"`, `aria-labelledby`, `aria-describedby`, `aria-invalid`, `aria-controls` and `aria-disabled`.
- [ ] Focus moves in reading order and returns on close: the input is the field's one tab stop, between the label and description above it and the error below; a press on a button leaves focus on the input; nothing opens or closes.
- [ ] Every target is at least `size.target-min` square: each button is a `size.control` square, 34 px; the box is `size.input` tall and as wide as its container.
- [ ] Loops stop when the system asks for less motion: none here; a held button repeats a step, which is no animation, and the box has no transition (CR-11).

## Owned strings

The buttons' names are owned strings with the keys `increase` and `decrease`, in English "Increase" and "Decrease", set as each button's `aria-label` in place of Base UI's hard-coded English. Base UI names the buttons in English in every locale, so a Danish screen reader would hear "Increase", which the contract's [Words](README.md#words) forbids; "Increase" and "Decrease" are Base UI's own words, sentence case and plain, naming what the press does to the number whatever it stands for; and `aria-label` is how Base UI already names them, which `expectOwnedStrings` reads, where a `VisuallyHidden` span would first have to undo it.

The input's role description is an owned string, key `numberField`, in English "Number field", set as `aria-roledescription` in place of Base UI's hard-coded English rather than removed. Base UI sets `aria-roledescription="Number field"` in every locale, so a Danish screen reader would call the box a "Number field"; the description is what tells a screen reader user the arrow keys step it, since the buttons take no focus; and `packages/perron/src/testing/owned-strings.ts` reads no `aria-roledescription` today, so the build adds it to the attributes the check reads, with a test, or this word would pass the check in English on every screen (CR-9).

| ------------- | -------------- | ------------------ | ---------------------------------------------------------------------------------------------------- |
| `increase`    | "Increase"     | `increaseLabel`    | The `increment` button's `aria-label`, heard as its name; never seen                                 |
| `decrease`    | "Decrease"     | `decreaseLabel`    | The `decrement` button's `aria-label`, heard as its name; never seen                                 |
| `numberField` | "Number field" | `numberFieldLabel` | The input's `aria-roledescription`, heard in place of its role, after its name; never seen           |

`increase`, `decrease` and `numberField` are new keys in `packages/perron/src/locale/en.ts`, each with a JSDoc line saying where it is heard, and agents write their Danish, Swedish and Norwegian in the other locale files. `optional` is the key it already has, Field's: NumberField passes `optional` and `optionalLabel` to Field, which reads it. Every other word is the caller's, through `label`, `description`, `error`, `placeholder` and the units a `format` writes, or Base UI's message for a failing check: the caller's `validate` result, or the browser's own message for the hidden input's `required`, `min`, `max` and `step`, Field's known exception, which applies here unchanged ([Field](field.md#owned-strings)). The number's digits, separators and signs hold no letter, so `expectOwnedStrings` passes them in every locale; a unit a `format` writes, such as "min", is the caller's word, given in the story's caller strings.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's `NumberField` parts and Field already parse, format, clamp and step the number, name the input, tie the help and the error to it, run the checks, disable a button at its bound and keep the buttons out of the tab order, so NumberField rebuilds none of it and adds no key, pointer, wheel, focus or validation handler.
- **CR-2.** NumberField renders Field, from `packages/perron/src/components/Field/Field.tsx`, as TextField's CR-2 does: `slotProps.field` spread first, then `className` (`pn-NumberField-field` before the caller's, with the shared `withClass` helper from `packages/perron/src/internal/nodes.ts`), `disabled`, `label`, `hiddenLabel`, `optional`, `optionalLabel`, `description` and `error`, and its `slotProps` `label`, `description` and `error` each with its class set the same way. Field's one child is `NumberField.Root`. NumberField never renders `Field.Root`, `Field.Label`, `Field.Description` or `Field.Error` itself.
- **CR-3.** `{...rest}` reaches `NumberField.Root` before NumberField's own props, and every prop `NumberFieldProps` declares is taken out of `rest` first: the frame's (`label`, `hiddenLabel`, `optional`, `optionalLabel`, `description`, `error`, `disabled`), the events (`onChange`, `onChangeCommitted`), `locale`, `placeholder`, the three `*Label` props and `slotProps`, so none reaches the `<div>`. `ref`, `style` and `data-testid` land on the root, and `className` is merged after `pn-NumberField` with `withClass`, a string or a function of the root's state. Each inner part takes its `slotProps` value merged with Base UI's `mergeProps` (`@base-ui/react/merge-props`), NumberField's own props last, so its class, the owned `aria-label` and the owned `aria-roledescription` win.
- **CR-4.** NumberField turns Base UI's `onValueChange(value, details)` into `onChange(details.event, value, details)` and `onValueCommitted(value, details)` into `onChangeCommitted(details.event, value, details)`, inside itself, and exposes neither of Base UI's, as the contract's "Adapt once" says. `details` is Base UI's, unchanged, so `details.reason` and `details.cancel()` work as Base UI documents them.
- **CR-5.** `disabled` goes to Field, and so to `Field.Root`, never to `NumberField.Root` directly: Base UI then disables the input and both buttons and marks the label, the description and the error `data-disabled`, so the whole field turns to the tertiary ink together. `slotProps.field` takes no `disabled` and no `name`, so each has one place, NumberField's own prop; `name` goes to `NumberField.Root`, which gives it to the hidden input.
- **CR-6.** The number is written and read in `locale`, the caller's or, left out, the nearest PerronProvider's from `useLocale()` in `packages/perron/src/PerronProvider.tsx`, as Meter's CR-11 does ([Meter](meter.md)): Base UI's own default, the runtime's locale, would write "1,500" on a Danish screen in an English browser, and could differ between the server's render and the browser's. NumberField passes it to `NumberField.Root`'s `locale` and never formats or parses the number itself.
- **CR-7.** The group is the box: NumberField's CSS draws the fill, the edge, the radius, the height and the ring on `.pn-NumberField-group`, and the input draws none of them (`outline: none`, transparent, no border), as SearchField's CR-9 does with its input group. The ring is the group's, on `:has(.pn-NumberField-input:focus-visible)`, with `focus.width`, `focus.offset` and `color.border.focus`, as the contract asks of a component that draws its own ring. The group's hover lays `color.surface.hover` over its fill as a `linear-gradient` background-image, inside `@media (hover: hover)` and not while `[data-disabled]`.
- **CR-8.** Each button holds an inline `<svg>` drawn from its file, `packages/perron/icons/minus.svg` in the decrement button and `packages/perron/icons/plus.svg` in the increment button, with the class `perron-icon`, `aria-hidden="true"` and `focusable="false"`, in `currentColor`, as SearchField's search icon is drawn. Its `aria-label` is the owned string, `strings.decrease` or `strings.increase`. NumberField's CSS draws the buttons' look itself, from the Tokens table, since the `CloseButton` part holds the `close` icon and the name "Close". Both buttons always render; Base UI disables each at its bound. The build draws no new icon: it widens the `use` of `minus` and `plus` in `packages/perron/icons/icons.json`, "Zoom out" and "Zoom in" today, to name the number field's steps too, by [Icons](../foundations/icons.md).
- **CR-9.** NumberField reads its strings with `const strings = useOwnedStrings({ increase: increaseLabel, decrease: decreaseLabel, numberField: numberFieldLabel })`, and sets `aria-roledescription={strings.numberField}` on `NumberField.Input`. The build adds `aria-roledescription` to the attributes `expectOwnedStrings` reads in `packages/perron/src/testing/owned-strings.ts`, with a test that a render whose role description is a word outside the dictionary fails, so the contract story's owned-strings check holds the description to the dictionary in all four locales.
- **CR-10.** Long words: the input keeps the number on one line (`white-space: nowrap`) and scrolls it, as a native input does; the label, the description and the error wrap, by Field's CR-8.
- **CR-11.** Hover, pressed, disabled and invalid change the box and the buttons at once: no `duration.*` token fits a field's edge or fill, so the CSS has no transition or animation.
- **CR-12.** The root and the box take the frame's width (`inline-size: 100%`, `box-sizing: border-box` on the group), and the frame its container's, as Field's CR-7 says; NumberField sets no width of its own, so a caller sets it on the container, or on the frame through `slotProps.field`.
- **CR-13.** The subject story doesn't set `optional`, so the contract story's owned-strings check never sees the mark: the `Optional` story's render gets its own test, which runs `expectOwnedStrings` on its server-rendered markup in `en`, `da`, `sv` and `nb`, with the label and the description as the caller's words, as TextField's CR-12 does.
- **CR-14.** The `placeholder` rule sets `opacity: 1` beside `color.text.tertiary`, since Firefox dims a placeholder on its own and the tertiary ink is already the hint's colour.
- **CR-15.** A button's disabled look applies on `[data-disabled]`, which Base UI sets while the field is disabled or the value is at the button's bound, and on `[data-readonly]`, which it sets while the field is read-only; its hover and pressed rules exclude both. Inside `@media (forced-colors: active)`, a disabled or read-only button's icon is `GrayText`, as IconButton's CR-13 does, since forced colours drop the tertiary ink.
- **CR-16.** NumberField never styles Base UI's hidden `<input type="number">`: Base UI hides it with its own inline style, and it takes no class.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                 | Don't                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use NumberField for a count or an amount a person may nudge up or down, such as the departures a board shows                       | Use it for a number that is a name, such as a line number, a stop code or a phone number: no one steps those, and a separator or a dropped leading zero would change them; use TextField |
| Set `min` and `max` wherever the number has bounds, and say them in `description`, "From 1 to 20"                                  | Leave the bounds to an error after the fact: the buttons and the keys clamp to them only when they are set                                                                               |
| Pass the unit through `format`, such as `{ style: 'unit', unit: 'minute' }`, so it is written in the locale with a space before it | Write the unit into `label` alone, or into a text beside the box: the number in the box would read bare                                                                                  |
| Read the number from `onChange`'s second argument, and save or fetch on `onChangeCommitted`                                        | Read `event.target.value`: it is the formatted text, "1,500", not the number; and don't fetch on every `onChange`, which fires on each step of a held button                             |
| Connect React Hook Form through `Controller`, with `onChange={(event, value) => field.onChange(value)}`                            | Spread `register()` on NumberField: its value is a number Base UI keeps, not a native input's text                                                                                       |
| Let the PerronProvider's locale write the number, or give `locale` only where the number must be written in another language       | Format the number yourself and pass a string: `value` is a number, and Base UI parses what the person types in the same locale                                                           |
| Give `error` from the form library whenever the field is invalid, worded as what to do, "Enter a number from 1 to 20"              | Set `slotProps.field.invalid` with no message, or blame the person ("Invalid number"), against [Content design](../content-design.md)                                                    |
| Set the width on the container, or on the frame through `slotProps.field`, wide enough for the longest number and both buttons     | Squeeze the box until the number scrolls: the buttons keep their size, and the number is what the person reads                                                                           |
| Use NumberField on its own: it already has its label, its help and its error                                                       | Wrap NumberField in Field: the input would be labelled twice, as Field's spec says                                                                                                       |
