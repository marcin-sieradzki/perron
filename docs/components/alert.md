# Alert

A message set into the page, such as a panel or a sheet, that says in plain sentences what is happening and how much it matters, in one of the intents' tinted colours, with an optional title, an action and a close button.

<!-- run notes -->

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), [content design](../content-design.md), [Accessibility](../foundations/accessibility.md), the tokens, and the specs of the merged pieces it reuses or sits beside: [SeverityLabel](severity-label.md), [NormalService](normal-service.md) and [Tag](tag.md) for the intents' colours and icons, [Dialog](dialog.md) for the `CloseButton` shared part and its `closeLabel`, [Button](button.md) and [LinkButton](link-button.md) for an action, and [EmptyState](empty-state.md) and [DataStatePanel](../patterns/data-state-panel.md) for the parts' names, the tone and the live-region lessons. The registry files Alert under Feedback with no `baseUiParts` and nothing in `dependsOn`; the ROADMAP does not name it. The maintainer's scope for the batch asked for an inline banner in the success, warning, danger and info intents with an optional title, body, action and dismiss, built with `useRender`, designed so that Toast, the next component, reuses its intents, its look and its parts. The extracted prototype components are not on any branch this machine can reach.

## Anatomy

Penpot page `Components/Alert`. Family: none, since an inline message sits in the flow of a panel and joins no family's treatment (see Toast below). Shared parts: `IntentIcon`, new, for the intent's icon; `CloseButton`, and `VisuallyHidden` through it.

The drawing has one variant property, `color`, with the values the [Props](#props) table gives, so its variants are `Neutral`, `Success`, `Warning`, `Danger` and `Info`, in the union's order. There is no `State` property: the alert itself is not interactive, and its close button keeps the `CloseButton` part's states.

No part has a Base UI component, because none has behaviour for Base UI to give: the close button is a plain `<button>` whose press calls `onClose`, and nothing opens, closes on its own, traps focus or takes keys. Each part but `close` renders through Base UI's `useRender` hook, so each takes `render`, as the root does and as its `slotProps` key does for an inner part. The part names are Toast's: Base UI's Toast has `Toast.Content`, `Toast.Title`, `Toast.Description`, `Toast.Action` and `Toast.Close`, so a Toast drawn in Alert's look maps its parts one to one, as [Component rules](#component-rules) CR-12 says.

The title renders as a `p` by default, with no heading level of its own; a caller makes it a heading through `slotProps.title.render`, such as `render: <h3 />`, as EmptyState does: an Alert sits in panels whose heading levels it cannot know, and a wrong level breaks the outline where a `p` leaves it whole.

The intents' icons are the 14 px grid's, at `icon.size.325`: `check-circle` for success and `warning` for warning, both already in the set, and two new drawings on the same grid and stroke, `exclamation-circle` (an "!" in a circle) for danger and `info-circle` (the `info` glyph, an "i" in a circle, drawn again for the 14 px grid, since `info` is drawn on 18 px) for info, which join `packages/perron/icons/icons.json` under a new `Feedback` category with the uses "A danger message" and "An info message". `icon.size.325` is the step for icons beside label and body text, the two drawings already in the set say "all is well" and "take care" in the shapes SeverityLabel and NormalService use, a circle tells danger's "!" apart from warning's triangle without colour, and a 16 px set would draw four icons again for a step the foundation keeps for controls.

The intent's icon is drawn in a new shared part, `IntentIcon`, in its own folder under `packages/perron/src/parts/`, which joins the contract's Shared parts table as composed in Alert now and in Toast next: Toast shows the same icon for the same intent, the contract moves a part to `packages/perron/src/parts/` as soon as a second component needs it, and drawing it there now spares Toast's build the move. The part takes `color` and renders the inline `<svg>` with `perron-icon`, `aria-hidden="true"` and `focusable="false"`, or nothing for `neutral`.

## Props

In MUI's layout, as MUI's Alert takes `icon`, `action`, `onClose` and the message as `children`, and its `AlertTitle` here as `title`. Every prop Alert declares gets this description as its JSDoc; `render` is inherited from `useRender` with Base UI's. Slots come last.

`color` offers `'neutral' | 'success' | 'warning' | 'danger' | 'info'`, in the order Tag, Count and Meter give their intents, with the contract's default `'neutral'`, where `neutral` lays `color.surface.inset` under the words and shows no icon unless the caller gives one: a calm grey message ("Departures update every 30 seconds") is the one Toast needs most ("Link copied"), a default of `info` would colour every message the caller forgot to mark, and `brand` stays out, since the brand yellow is kept for a screen's one main action. A status intent comes with words that say it, as Tag's does.

Alert shows its close button only when `onClose` is given, calls it as `onClose(event, reason, details)` with the press's native `MouseEvent`, the reason `'close-press'` (Base UI's name for a close button's press) and `details` `{ reason: 'close-press', event }`, and never hides itself: the caller removes it in `onClose` and moves focus to the element before it. MUI's Alert shows its close button the same way, the contract names the callback `onClose(event, reason, details)` in every component, an inline message has no Base UI root to hold its open state, and the caller, who knows the panel, knows where focus belongs once the message is gone (CR-7). `open` and `defaultOpen` can join later without a break.

## Tokens

One row per part, state and property. The alert is not interactive, so every row of its own is rest, and each names the `data-color` it applies to; the close button's hover and pressed rows are the `CloseButton` part's, which draws them in its own folder, and the action's controls keep their own states.

The look is the one this table gives: the intent's tinted surface with a transparent `border.width.025` edge and `radius.lg`, padded `space.300` on the block axis and `space.400` on the inline axis; the icon `space.200` before the content and centred on the first line; the title in `typography.heading-sm` and the sentences in `typography.body-sm`, both in `color.text.primary`; the icon in the intent's mark colour, `color.status.*`, or `color.text.primary` for a caller's icon on `neutral`; the action `space.200` below the sentences, on top of the content's `space.100` gap; and the close button pulled `space.200` up, down and to the end, so it sits on the first line without making a one-line alert taller. `radius.lg` is the radius of "cards and inset boxes", the tinted surfaces are the tokens' own "tinted background for a … message", ink text keeps the brand calm and reads at 11.2:1 or more on every tint in both themes while the intent's colour stays on the icon and the surface, the icon takes the mark colour the contract's [Intents](README.md#intents) table gives and [Semantic colours](../foundations/semantic-colours.md) keeps for icons, `heading-sm` is the role for card titles and `body-sm` for "disruption details", and Toast takes the same rows with the shadow of a floating panel added.

## Keyboard and ARIA

The alert takes no focus and has no keys of its own. The caller's action and the close button are reached in reading order; Esc does nothing, since an inline message is not a layer that closes ([Accessibility](../foundations/accessibility.md#rules), Keys).

| Key              | Does                                                                                 | From                                |
| ---------------- | ------------------------------------------------------------------------------------ | ----------------------------------- |
| `Tab`            | Moves to the action's first control, then to the close button, after the sentences   | The browser                         |
| `Shift+Tab`      | Moves back through them, and out to whatever came before the alert                   | The browser                         |
| `Enter`, `Space` | On the close button, presses it: `onClose` is called with the reason `'close-press'` | The browser; Perron calls `onClose` |

| Element       | Role                                                                    | Accessible name from                                             | States announced |
| ------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------- | ---------------- |
| `root`        | `status`, a polite live region, unless the caller passes another `role` | None: a status needs no name                                     | None             |
| `icon`        | Hidden: `aria-hidden="true"`                                            | None                                                             | None             |
| `title`       | Paragraph, or a heading when `slotProps.title.render` makes it one      | Its text, from `title`                                           | None             |
| `description` | None (generic `div`)                                                    | None                                                             | None             |
| `action`      | None (generic `div`); the caller's controls carry their own roles       | The caller's controls' own names                                 | Theirs           |
| `close`       | `button`                                                                | The owned "Close", or `closeLabel`, in the `VisuallyHidden` part | None             |

The root carries `role="status"` by default, for every `color`, unless the caller gives a `role`, so a caller can pass `role="alert"` for a danger message that stops the task the person is in; it is never `alert` by default. [Accessibility](../foundations/accessibility.md#what-a-person-checks) asks for a polite live region that announces changes of state only, a `status` on a message present when the page loads is not read out and does no harm, a message whose words change while it stays mounted is read once, politely, and an `alert` on every danger message would interrupt whatever the person is hearing. A message added to the page with its words already in it is not reliably announced by a `status` (DataStatePanel keeps its region mounted for that reason), so CR-8 tells the caller what to do when one must be heard as it appears.

Alert adds no hidden word for its intent, such as "Warning" before the title; the caller's words say what the colour and the icon show, as Tag's and EmptyState's do: content design asks for plain sentences that say what is happening, a title such as "Could not load departures" already says it failed, and a fixed word before it would be read on every message, in four languages, and repeat what the sentence says ("Warning: Signal fault …").

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the colour, the tint and the icon repeat what the caller's words say, and the icon is `aria-hidden`; the `color` JSDoc and CR-2 ask for words that say the intent, and the stories hold to it. In forced colours the tint goes, and the edge, the icon's shape and the words stay.
- [ ] Every landmark and named region has an accessible name: none here; a `status` is a live region, not a landmark, and needs no name.
- [ ] Every default label can be overridden: `closeLabel`.
- [ ] Every shape the type accepts renders, in every variant: `title`, `children`, `icon` and `action` each render a string, an element and an array; `description` and `action` are `div`s, so block content such as a list is valid inside them, and the title takes phrasing content as a `p` or a heading does; `icon` as `null` or `false` renders no icon part (CR-3).
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; nothing animates or collapses.
- [ ] Native semantics first: a `p` for the title, made a native `h2` to `h6` through `render`; the close button is a native `<button type="button">`; the action holds the caller's own `button` or `a href`; the one ARIA is the root's `role="status"`, which no element says.
- [ ] Focus moves in reading order and returns on close: the action follows the sentences and the close button comes last, in the DOM and in the tab order; Alert never moves focus when it appears, and once the caller removes it in `onClose` the caller moves focus to the element before it (CR-7).
- [ ] Every target is at least `size.target-min` square: the close button is `size.control`, 34 px; the action's targets are the caller's components, a small Button `size.button-sm`.
- [ ] Loops stop when the system asks for less motion: none here; nothing moves.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** The root always carries `data-color` with the `color` value, default included, written in Alert's own props after the caller's so it cannot be overwritten, and the CSS reads every colour from it: `.pn-Alert[data-color='danger']`. The text colour is set once, on the root; the icon part sets its own `color` and the icon takes it through `currentColor`, as [Icons](../foundations/icons.md#style) asks.
- **CR-2.** A status `color` comes with words that say it, such as "Could not load departures" on `danger`. Alert can't hold this for the caller, so the JSDoc of `color` says it and the review holds the stories to it.
- **CR-3.** The optional parts render only when given: no `title` part without `title`, no `description` part without `children`, no `action` part without `action`, no `close` part without `onClose`. The `icon` part renders the caller's `icon` when it is given, the intent's icon when `icon` is left out (`undefined`), and nothing when `icon` renders nothing (`null`, `false`, `''`, or an array of only such values) or when `color` is `neutral` and `icon` is left out, so no empty wrapper takes up a gap.
- **CR-4.** The intent's icon is drawn by the `IntentIcon` shared part, never in Alert's own folder, and is the icon file's own drawing, inlined as JSX: the file's `viewBox`, `fill`, `stroke`, `stroke-width`, `stroke-linecap` and `stroke-linejoin` and its child elements, unchanged, with no `width` or `height`, the class `perron-icon`, `aria-hidden="true"` and `focusable="false"`, as SeverityLabel's CR-3 does. The build adds `info-circle` and `exclamation-circle` to `packages/perron/icons/` following [Icons](../foundations/icons.md), joins them to `icons.json`, and runs `npm run tokens` to rebuild the set's table. `IntentIcon` joins the contract's Shared parts table, composed in Alert and Toast, with `pn-IntentIcon` and the two icons drawn for it, `info-circle` and `exclamation-circle`, as what only its folder holds: SeverityLabel and NormalService draw `warning` and `check-circle` too, so those two stay the set's; and Alert joins `CloseButton`'s row there.
- **CR-5.** The `icon` part always carries `aria-hidden="true"`, after the caller's `slotProps.icon` props, so those props cannot make the icon speak; the words say what it shows. A `render` element's own props are the caller's: `useRender` merges them last, as Base UI does, so a caller that swaps the icon's element leaves `aria-hidden` off it.
- **CR-6.** The close button is the `CloseButton` shared part, in `packages/perron/src/parts/CloseButton/`, never a button drawn again: Alert composes it with `label` from `useOwnedStrings({ close: closeLabel })` (`packages/perron/src/PerronProvider.tsx`) and the class `pn-Alert-close`, and its CSS sets only the two margins. It is never disabled: `slotProps.close` is typed `Omit<ComponentPropsWithRef<'button'>, 'children' | 'disabled'>`, as Dialog's and Popover's close slots leave `disabled` out, and Alert passes no `disabled` of its own, so the `CloseButton` part needs no disabled look; a message that must stay leaves `onClose` out. Its props are `mergeProps(slotProps.close, { onClick, className: 'pn-Alert-close' })`, the component's own last: Base UI's `mergeProps` runs the rightmost handler first, so Alert calls `onClose(event.nativeEvent, 'close-press', { reason: 'close-press', event: event.nativeEvent })` first and the caller's `onClick` runs after it, and the class comes first in the string. The caller cannot stop `onClose` from its `onClick`, and does not need to: Alert never hides itself, and the caller removes it in `onClose`.
- **CR-7.** Alert never hides or unmounts itself and never moves focus: pressing close only calls `onClose`. The caller removes the alert there and moves focus to the element before it, or to the heading of the panel it sat in, so focus is not dropped to `<body>`; the stories' `play` tests do so to show the pattern.
- **CR-8.** The root's role is `status` unless the caller gives one, `rest.role ?? 'status'` among the own props merged after the caller's, so the caller's `role` wins: `role="alert"` for a danger message that stops the task in hand, such as a failed save. A message that must be heard as it appears is added inside a live region already on the page, or kept mounted with its words changed, since a `status` inserted with its words already in it is not reliably announced; a message present when the page loads needs nothing.
- **CR-9.** Alert sizes to its container, with no width or max-width of its own, and long words wrap (`overflow-wrap: anywhere` on the root and on the title and the sentences, `min-inline-size: 0` on the content), so a long Danish stop name fits a 320 px screen and the close button stays at the row's end.
- **CR-10.** The root keeps a `border.width.025` edge, `transparent`, so Windows' forced colours draw an edge round the alert when they drop the tint, as Tag's CR-4 does. No `(forced-colors: active)` rule is needed.
- **CR-11.** `color`, `title`, `icon`, `action`, `onClose`, `closeLabel`, `children`, `slotProps` and `render` are taken out of the rest props before they reach the root, so the HTML `title` attribute never reaches the element. Each inner part's props are its `slotProps` value merged with `mergeProps`, the component's own props last, so its class, `aria-hidden`, children and the close button's `onClick` stay while the caller's `className` and `onClick` join and its `render` swaps the element (CR-6).
- **CR-12.** Alert is drawn so Toast can take it whole: the parts are named as Base UI's Toast names them (`content`, `title`, `description`, `action`, `close`), the intents and their surfaces, icons and colours are the same `color` values and rows, and the icon is the `IntentIcon` shared part. Toast's spec reuses the [Tokens](#tokens) rows for its own parts and adds what a floating message needs; Alert itself takes no Toast behaviour, such as a timeout or swiping.

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                                                                                                                                                       | Don't                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Say what is happening, then how sure we are, in plain sentences: a title such as "Signal fault at Danshøj" above a sentence such as "Trains between Flintholm and Ny Ellebjerg run slower than planned. We don't know yet when the fault will be fixed." | Write "Error!" or "Something went wrong": content design has no exclamation marks, and the title should say what failed                   |
| Pick the `color` the words say: `success` for something that went well, `warning` for something to take care with, `danger` for something that failed                                                                                                    | Let the colour or the icon be the only sign: every message says its meaning in words too                                                  |
| Use SeverityLabel or a DisruptionCard for a disruption on a line, and NormalService for a line running normally                                                                                                                                          | Use an Alert for each disruption: a disruption has its own words, icons and colours, and a list of tinted boxes is not calm               |
| Use DataStatePanel or EmptyState when a data view is loading, empty or could not load                                                                                                                                                                    | Put an Alert in place of the data view's content: it sits beside content, it doesn't stand in for it                                      |
| Give one action at most, a `small` `outline` `neutral` Button or a LinkButton                                                                                                                                                                            | Add a `brand` action: a screen has one brand action at most, and the message is not it                                                    |
| Remove the alert in `onClose` and move focus to the element before it                                                                                                                                                                                    | Leave focus on a close button that is gone: it drops to the top of the page                                                               |
| Add a message that must be heard as it appears inside a live region already on the page, or pass `role="alert"` for a failure that stops the task                                                                                                        | Pass `role="alert"` on every danger message, or add a live region of your own around an Alert shown on load: it interrupts, or adds noise |
| Show a message that comes and goes on its own, such as "Link copied", as a Toast                                                                                                                                                                         | Make an Alert disappear on a timer: an inline message stays until the person or the data says otherwise                                   |
