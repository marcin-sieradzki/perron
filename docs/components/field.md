# Field

The frame round one form control: its label above it, a line of help, and the error message under it when the value is wrong, all tied to the control for the ear by Base UI.

The design is deferred (ADR 0010, `docs/adr/0010-unattended-runs-with-design-deferred.md`): there is no read-back, code map or export, and this spec decides what the drawing would, from the [contract](README.md), the [foundations](../foundations/README.md), the tokens and the Base UI reference for `Field` (`@base-ui/react` 1.9.0, installed). The extracted prototype component is not in any branch this run can reach.

## Anatomy

Penpot page `Components/Field`. Family: Fields, as the frame every member's label, help and error share; Field draws no box of its own, since the box is the control's (the Fields family's fill, edge and invalid edge are drawn by TextField, TextArea, NumberField and Select). Shared parts: `VisuallyHidden`, for a hidden label.

Field composes the parts the registry entry lists, `Field.Root`, `Field.Label`, `Field.Description` and `Field.Error`, and none of Base UI's others: not `Field.Control`, since the control is the caller's `children`, and the components that draw a text box (TextField, TextArea) compose Field with `Field.Control` themselves; not `Field.Item`, which groups the options of a checkbox or radio group (CheckboxGroup, RadioGroup); not `Field.Validity`, since the error part already shows Base UI's message.

The parts stack in the order label, description, control, error. The help is read before the box, as a hint about what to type should be, and stays where it is when an error appears; the error sits under the box it is about, beside the box's red edge; and Base UI announces both through the control's `aria-describedby` in that order, whatever their place.

Base UI already does: it gives the control an id and points the label's `htmlFor` at it, names the control by the label through `aria-labelledby`, and focuses the control when a hidden or non-native label is pressed; it joins the description's and the mounted error's ids into the control's `aria-describedby`, keeping any the caller gave; it marks the control `aria-invalid` while the field is invalid and not disabled; it runs the control's native checks (`required`, `pattern`, `minLength` and the rest) and the caller's `validate` when `validationMode` says (on submit by default, then on every change after a submit), and shows the first failing message in the error part, or a list of them; it keeps the field invalid while the caller's `invalid` is `true`, disabled or not; it passes `disabled` and `name` to the control; it takes `disabled` from a `Fieldset` round it; and it sets the root's and every part's state attributes from the field's state.

## Props

In MUI's layout. Every prop here gets its description as its JSDoc. Slots come last.

Field takes a required `label` (`ReactNode`), a `hiddenLabel` boolean (default `false`), an optional `description` (`ReactNode`), an optional `error` (`ReactNode`), an `optional` boolean (default `false`, see Owned strings) and a required `children`, the control, and inherits the rest of `Field.Root`'s props. `label` and `hiddenLabel` are SearchField's names for the same thing, so the two read alike, and MUI's `hiddenLabel` is a field without a visible label; `description` is Base UI's name for the part, plain where MUI's `helperText` is a library's word; `error` holds the words, where MUI's `error` is a boolean, because Base UI's `invalid` already is that boolean and the words are what [Accessibility](../foundations/accessibility.md) asks for, never the colour alone; inheriting `validate`, `validationMode`, `dirty`, `touched` and `actionsRef` lets TextField, Select and the other dependents, and a form library's controller, reach Base UI's validation with no prop of Field's own.

A given `error` marks the field invalid and shows at once, whatever Base UI's own checks say, while a left-out `error` lets the error part show Base UI's own message (the caller's `validate` result, or the control's native check) when the control fails. Field passes `invalid={invalid ?? true}` to `Field.Root` when `error` is given and `invalid` as given otherwise, and gives `Field.Error` `match={true}` and `error` as children only when `error` is given. This is Base UI's own pattern for React Hook Form (`invalid` on the root, `match={!!error}` on the error), so a form library's message needs one prop; a caller's `invalid={false}` still wins; and a field with `validate` and no `error` shows its own messages with no prop at all.

`FieldProps` extends `Field.Root.Props` without `children` and `ref`, which it declares itself, so `name`, `disabled`, `invalid`, `validate`, `validationMode`, `validationDebounceTime`, `dirty`, `touched`, `actionsRef`, `render`, `className` and `style` are inherited with Base UI's JSDoc. Field takes no `variant`, `size`, `color` or `fullWidth`: it has one look, its root takes its container's width, and the control's size is the control's; so the root carries no `data-variant`, `data-size` or `data-color`, and Base UI's state attributes are its data attributes. No name here is one the contract's [Names from other libraries](README.md#names-from-other-libraries) table bans.

## Tokens

One row per part, state and property. The design states the deferred drawing shows are rest, disabled and invalid: Field draws no box, so hover, focus, pressed, open and selected are the control's looks, never Field's.

The label takes `typography.label` in `color.text.primary`, as SearchField's does, rather than `typography.label-sm`, whose description names field labels. SearchField is the one field shipped, and two fields side by side on one screen, one through Field and one not, must name themselves alike; `typography.label` is the contract's type for a name on a control; and the token's description is a Direction finding to settle in the `design-tokens` skill, not a reason for two label looks.

The description and the error take `typography.body-sm`, the description in `color.text.secondary` and the error in `color.text.danger`, with `space.100` between every part. Both are supporting sentences under a name, which is what `typography.body-sm` is for, and an error must be read in full, where `typography.caption` is for notes; `color.text.danger` reaches 4.5:1 on every surface in both themes ([Accessibility](../foundations/accessibility.md)); and `space.100` is SearchField's gap between its label and its box, so each part stays with the control it belongs to.

Field keeps its rest look while the field is focused, filled, dirty, touched or valid, and shows invalid only by mounting the error, the label keeping `color.text.primary`. Base UI sets `data-focused`, `data-filled`, `data-dirty`, `data-touched` and `data-valid` on every part, and none of them is a design state the contract names; the control already shows focus with its ring and invalid with its red edge, and a label that also turned red would say the same thing a third time in colour alone; a "valid" look would claim more than a check knows, which the brand's "honest" forbids.

The error is its words alone, with no `warning` icon before them. The words already carry the meaning, so colour is never alone (the red edge is the control's, beside them); an icon adds a second mark that needs its own text equivalent for the ear; and an icon can join later as a look, without a prop.

The error stays a plain `<div>`, read through the control's `aria-describedby`, with no live region of Field's own. Base UI mounts the error only with its message, and a live region inserted with its content is not reliably announced; a `role="alert"` would interrupt on every keystroke with `validationMode="onChange"`; and the person hears the error when focus reaches the control, as Base UI's `Form` moves focus to the first invalid control on submit.

What axe won't catch, from the contract, each with how this component meets it:

- [ ] Everything the eye is told, the ear is told, for every shape each prop accepts: the label names the control, even hidden; the description and the error are the control's `aria-describedby`, so the ear hears both with the control; an invalid field is `aria-invalid` and its error is words, never only the control's red edge.
- [ ] Every landmark and named region has an accessible name: none here; Field is not a landmark, and a group of fields is a Fieldset's to name.
- [ ] Every default label can be overridden: none here; Field owns no string (see Owned strings).
- [ ] Every shape the type accepts renders, in every variant: `label`, `description` and `error` render a string, an element and a list alike; a long Danish compound wraps in each (CR-8); Base UI's several messages render as a list.
- [ ] A hidden copy kept for animation is `aria-hidden`, and a collapsed region is `inert`: none here; the error is unmounted while the field is valid, and the description while it is not given.
- [ ] Native semantics first: a native `<label>` with `htmlFor`, a `<p>` for the description, and the control's own semantics; Perron adds no ARIA, and Base UI only `aria-labelledby`, `aria-describedby` and `aria-invalid`.
- [ ] Focus moves in reading order and returns on close: the control is the field's one tab stop, and the label, description and error sit around it in reading order; nothing opens or closes.
- [ ] Every target is at least `size.target-min` square: the control's, which is the control's own; the label is a larger target for the same control, with no size of its own to meet.
- [ ] Loops stop when the system asks for less motion: none here; Field has no loop and no transition (CR-9).

## Owned strings

One owned string, `optional`: "(optional)", shown after the label's words when `optional` is set and overridden by `optionalLabel`. Every other word is the caller's, through `label`, `description` and `error`, or Base UI's message for a failing check, which is the caller's `validate` result or the browser's own.

Field marks an optional field, never a required one. `optional` (default `false`) adds the owned "(optional)" after the label's words, inside the label element, in `color.text.secondary`, so it is part of the control's name for the ear as well as the eye; `optionalLabel` overrides it on one instance. Most fields in a form are asked for, so the few that aren't carry the mark, and the words need no legend, where an asterisk does. Field can't read `required`, which is the control's prop, so it draws no required marker: TextField, Select and the other dependents take `optional` and pass it through, and a screen whose label already says it writes nothing more.

Field keeps Base UI's showing of the browser's own message for a failing native check, such as `required`, when the caller gives no `error`, as a known exception to the owned strings. The browser writes that message in its own interface language, which may not be `PerronProvider`'s; owning one string per check would take a new key for each of the ten native checks for messages a screen should word for its own field ("Enter a stop name", not "Please fill in this field"); a caller who wants the field's own words gives `error`, or `slotProps.error.match` with its own children; and the message appears only after a check fails in the browser, never in the server-rendered markup the contract story's owned-strings check reads.

## Component rules

Rules for this component alone, numbered so the build and the review can cite them.

- **CR-1.** Base UI's Field already ties the label, the description and the error to the control, runs the checks, marks the control invalid and shows the message, so Field rebuilds none of it and adds no key, pointer or validation handler.
- **CR-2.** Field renders `Field.Root`, holding `Field.Label`, then `Field.Description` (only when `description` is given, by the shared `given` helper from `packages/perron/src/internal/nodes.ts`), then `children` as given, with no wrapper, then `Field.Error`, always rendered, since Base UI mounts it only while there is a message to show.
- **CR-3.** `{...rest}` reaches `Field.Root` before Field's own attributes, and Field's own props are taken out of `rest` first (`label`, `hiddenLabel`, `description`, `error`, `children`, `invalid`, `slotProps`), so none reaches the `<div>`; `name`, `disabled`, `validate`, `validationMode`, `validationDebounceTime`, `dirty`, `touched`, `actionsRef` and `render` stay in `rest` for `Field.Root`. `ref`, `style` and `data-testid` land on the root, and `className` is merged after `pn-Field`.
- **CR-4.** With `error` given, Field passes `invalid={invalid ?? true}` to `Field.Root`, and `match={true}` and `error` as children to `Field.Error`; with `error` left out, it passes `invalid` as given and sets neither `match` nor children, so a caller's `slotProps.error` `match` and children reach the part, and with neither Base UI shows its own message. A key Field doesn't set is left out of its props, never set to `undefined`, so it never overrides the caller's.
- **CR-5.** Each `slotProps` value is merged with Base UI's `mergeProps` (`@base-ui/react/merge-props`), Field's own props last, and each part's class is set after the merge with the shared `withClass` helper from `packages/perron/src/internal/nodes.ts`: `pn-Field-<part>` first, then the caller's `className`, a string or a function of the part's state.
- **CR-6.** With `hiddenLabel`, `Field.Label` renders through `render={<VisuallyHidden />}` with `nativeLabel={false}`, as SearchField's does, keeping its id and its text for the ear; the control stays named through `aria-labelledby`.
- **CR-7.** The root is a flex column (`display: flex`, `flex-direction: column`, `gap: space.100`, `min-inline-size: 0`) that takes its container's width; the control stretches across it, and Field sets no size on it.
- **CR-8.** Long words: the label, the description and the error wrap (`overflow-wrap: anywhere`), since each takes the field's width.
- **CR-9.** The error appears and goes at once: no `duration.*` token fits a message under a field, so the CSS has no transition or animation and styles neither `data-starting-style` nor `data-ending-style`.
- **CR-10.** The control must be one built on Base UI, which registers with the field: Base UI gives the label's `htmlFor` and the control's `aria-labelledby`, `aria-describedby` and `aria-invalid` only to a control that reads the field's context. A plain `<input>` gets none of them, so the stories and the Do and don't say so.

## Stories

The deferred drawing has no variant property and a `State` property with the values `default`, `disabled` and `invalid`, so its variants, and the stories that carry their names, are `Default`, `Disabled` and `Invalid`; the Penpot conventions name a variant by its property values, and a `State` of `default` gives `Default`, the subject story. The rest are stories of content and behaviour beside them.

The stories render Base UI's `Input` (`@base-ui/react/input`) as the control, styled in the story with the Fields family's tokens through a `style` object, until TextField ships. Field's control must register with the field (CR-10), Perron has no text control before TextField, which depends on Field, and Base UI's `Input` is its `Field.Control`; the story's style gives it the family's `size.input` height, fill, edge and `radius.md`, so the field looks as it will, while Field's own CSS stays free of the box.

The stories render the field on its own in a 320 px wide container, in a `PerronProvider` in English, with the label "Stop name" and the description "As written on the stop sign" unless the story says otherwise ([Content design](../content-design.md)). The `Default` story's args, which the contract story renders, hold every word the caller gives and the control as `children`.

| `NoDescription` | The label and the control alone, with no `description`                                                                                              | No description is rendered, and the control has no `aria-describedby`                                                                                                                                                                        |
| `RichContent`   | The label, description and error given as elements and lists, such as a description holding a [Kbd](kbd.md)                                         | Each renders its element and list, and the control's name and description hold their text                                                                                                                                                    |
| `LongWords`     | The label, the description and the error each hold a long Danish compound, in the 320 px container                                                  | Each wraps onto more than one line and stays inside the field; nothing overflows                                                                                                                                                             |

## Do and don't

For a caller using the component, with the reason.

| Do                                                                                                                     | Don't                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Use a field component that composes Field, such as TextField or Select, where there is one                             | Wrap such a component in Field again: it already has its label, and the control would be named twice                                  |
| Put a control built on Base UI inside, which registers with the field                                                  | Put a plain `<input>` inside: it gets no `htmlFor`, `aria-labelledby` or `aria-describedby`, so it is unnamed for the ear (CR-10)     |
| Give a `label` that names the value, "Stop name", and hide it with `hiddenLabel` only where the screen already says it | Leave the field without a label, or let a placeholder stand in for one: it vanishes as the person types                               |
| Word an `error` as what to do, "Enter a stop name"                                                                     | Blame the person ("You forgot the stop") or say only that it failed ("Invalid input"), against [Content design](../content-design.md) |
| Give `error` whenever the field is `invalid`                                                                           | Set `invalid` with no message: the control's red edge alone tells only the eye, and only by its colour                                |
| Put help the person needs while typing in `description`, such as "As written on the stop sign"                         | Put the help in the `error`: it appears only after a mistake                                                                          |
| Label a checkbox or a switch beside it, by its own label                                                               | Use Field for a checkbox or a switch: Field's label sits above the control, where theirs sits beside it                               |
