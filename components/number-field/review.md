## P1

## P2

- **P2-1.** `packages/perron/src/components/NumberField/NumberField.stories.tsx:262` The `Steppers` play checks the pressed fill with `stateFill` but never calls `pressedAfterHover` on either button. The contract's [Pointer feedback](docs/components/README.md#pointer-feedback) asks every play to check that the `:active` rule comes after the `(hover: hover)` rule, so a later reorder of `NumberField.css` would go unnoticed. The spec's `Steppers` row (`docs/components/number-field.md:284`) leaves this check out as well and needs it added.
- **P2-2.** `docs/components/number-field.md:200` The Keyboard table's `Tab` row says leaving the input "formats the number, clamps it, calls `onChangeCommitted`" every time. Base UI's `NumberFieldInput` `onBlur` (`node_modules/@base-ui/react/number-field/input/NumberFieldInput.mjs`, `shouldCommit = hadManualInput || shouldUpdateValue || hadPendingProgrammaticChange`) commits only after an edit, a clamp or a pending programmatic change, and never while read-only. The `onChangeCommitted` Props row (line 85) and its JSDoc (`NumberField.tsx:72`, "when they leave the box after typing") are correct and hold, so the Keyboard row should be rewritten to match them.

## P3

- **P3-1.** `packages/perron/src/components/NumberField/NumberField.css:60` `font-variant-numeric: tabular-nums` (spec Tokens, answer 6) gives the group separator and the decimal point a full figure's width. The Danish story's box reads "1 . 500" next to the description's proportional "5.000", and LongWords reads "100 , 000". Should the maintainer keep tabular figures, which hold the digits still while a button is held, or use proportional figures?
- **P3-2.** `packages/perron/src/components/NumberField/NumberField.css:38` A mouse press on a stepper makes Base UI's `focusInput` focus the input, and a text input always matches `:focus-visible`. The box therefore keeps the focus ring after every pointer press (measured: `fv=true`, a solid 2 px outline after the mouse moves away). TextField and SearchField behave the same way. Should the ring show after a pointer press?
- **P3-3.** `packages/perron/src/components/NumberField/NumberField.tsx:76` `onChangeCommitted(event, value, details)` is the first commit event in the library (answer 4), but the contract's [State and events](docs/components/README.md#state-and-events) does not name it. Slider will copy whatever NumberField sets here, so it may belong in that list.
- **P3-4.** `packages/perron/src/components/NumberField/NumberField.tsx:16` `name`, `required` and `readOnly` keep Base UI's JSDoc, as the contract's [Props](docs/components/README.md#props) rule asks, so they read differently from TextField's own JSDoc for the same props (for example "Identifies the field when a form is submitted." against "The name the words are submitted under in a form's `FormData`."). That breaks api-consistency's "one prop, one description" rule. The two rules conflict, and only the maintainer can settle which one wins.
- **P3-5.** `docs/components/number-field.md:125` The spec says `space.050` at the box's end puts a `size.control` button "1 px inside the edge". As rendered, the increment button sits 2 px inside the edge at the inline end and 1 px at top and bottom (group 320 × 38, button right edge at 333 against the inner edge at 335). This is the same geometry as SearchField's clear button, so the prose should say so.
- **P3-6.** `docs/components/number-field.md:105` The `numberFieldLabel` Props row ends with "(Owned strings)", but its JSDoc at `packages/perron/src/components/NumberField/NumberField.tsx:103` does not. The spec's Props section says each declared prop takes its row's description as its JSDoc, so the dangling section reference should come out of the row.
