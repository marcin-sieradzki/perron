## P2

- **P2-1.** `packages/perron/src/components/FilterChip/FilterChip.stories.tsx:269` The `Controlled` play test never shows that the chip follows `selected`. Its only click that leaves `selected` alone calls `details.cancel()`, and that keeps an uncontrolled Toggle's state too, while every other click lets `ControlledChip` set `selected`. So the test would still pass if `pressed={selected}` were dropped (`FilterChip.tsx:88`). This breaks the contract's Stories rule ("A `play` test for every behaviour the component promises", `docs/components/README.md:264`) and the spec's `Controlled` row (`docs/components/filter-chip.md:199`, "`aria-pressed` changes only once the story sets `selected`"). The test needs one click that the caller ignores without cancelling, after which `aria-pressed` must stay `"false"`.
- **P2-2.** `packages/perron/src/components/FilterChip/FilterChip.stories.tsx:292` No `play` test renders a `count` of `NaN` or `Infinity`. The `count` Props row (`docs/components/filter-chip.md:56`, "left out when `undefined` or not a finite number") and the checklist line at `docs/components/filter-chip.md:156` ("nothing for `undefined`, `NaN` or `Infinity`") promise that behaviour, and the contract's Stories rule (`docs/components/README.md:264`) asks for a test of it. `LabelOnly` checks only `undefined`.
- **P2-3.** `docs/components/filter-chip.md:129` The prose says a disabled selected chip's count loses its pill "as on a disabled tab". A disabled Tab keeps its count's `color.surface.inset` pill on the tab's transparent fill (`packages/perron/src/components/Tabs/Tabs.css:49`, `:63` and `:91`), so the precedent this line gives is false. The line needs to drop the comparison or give one that holds.
- **P2-4.** `docs/components/filter-chip.md:175` CR-5 says the transparent border lets "Windows' forced colours draw an edge round each chip". A selected chip, disabled or not, keeps a transparent border under `forced-color-adjust: none` (`FilterChip.css:52`, `:94` and `:112`). I measured `rgba(0, 0, 0, 0)` on `components-filterchip--selected` and `--selected-disabled` in forced colours, light and dark. The Forced colours rows at lines 121 and 125 and CR-11 say the same as the code, so they hold, and CR-5's sentence needs to say that only an off chip gets the system edge, while a selected one shows by its fill.
- **P2-5.** `docs/components/filter-chip.md:66` "Every `color` row sets the root's `color`" contradicts the `count` rows of the same tables. Line 88 sets the Count's own `color` to `color.text.tertiary`, and line 127 sets it to `GrayText`, matching `FilterChip.css:82` and `:123`. The rows hold, and the sentence needs to name the `count` rows as the exception.

## P3

- **P3-1.** `docs/components/filter-chip.md:68` The spec reads Toggle's `[data-pressed]` as the selected state (CR-4). The contract's Design states table files `[data-pressed]` under Pressed. Base UI's Toggle means "on" by it, so the contract row is the one to change, as the brief noted. This is still open for the maintainer.
- **P3-2.** `docs/components/filter-chip.md:210` The label stays the same on and off, and only `aria-pressed` tells the ear the state. `docs/foundations/accessibility.md` asks that "Toggles say their state in words as well as in looks". No rule decides whether `aria-pressed` alone is enough for a chip whose label never changes, so the maintainer decides.
- **P3-3.** `packages/perron/src/components/FilterChip/FilterChip.tsx:36` `selected`, `defaultSelected` and `onChange(event, value: boolean, details)` are the first boolean-state names in the Inputs family, and HighlightChip and Switch will copy them. The contract's State and events section names only `value`, and MUI's ToggleButton pairs `selected` with an `onChange` that passes the button's own `value`. The maintainer can either name the boolean case in the contract or keep `value` for every control.
- **P3-4.** `packages/perron/src/components/FilterChip/FilterChip.tsx:107` FilterChip and Tab take the same `count?: number` prop but draw it two ways. FilterChip composes Count and leaves out numbers that are not finite. Tab draws its own `pn-Tab-count` pill in `color.text.secondary` and shows `NaN` or `Infinity` as text (`packages/perron/src/components/Tabs/Tabs.tsx:155`). Their JSDoc first lines differ too. Moving Tab onto Count would give one look and one rule.
- **P3-5.** `docs/components/filter-chip.md:112` The disabled selected chip's `color.surface.inset` fill is the same colour as the Count's pill: `rgb(235, 238, 235)` in light and `rgb(40, 50, 55)` in dark, on `components-filterchip--selected-disabled`. The pill disappears and only the tertiary figure is left. This is a design question: a different pill for the count when the chip is disabled, or a different fill for the chip.
- **P3-6.** `packages/perron/src/components/FilterChip/FilterChip.stories.tsx:244` The comment spells "canceled" in American English. The library writes "Cancelled" (`docs/components/tag.md:3`), and the content-audit skill asks for British spelling. The `isCanceled` on line 255 is Base UI's API and stays.
