## P2

- **P2-1.** `packages/perron/src/components/Alert/Alert.tsx:46` The `icon` JSDoc, and the Props row it copies at `docs/components/alert.md:73`, never say that a caller's icon renders at 13 px, `icon.size.325` (Tokens row `docs/components/alert.md:120`), or how to set another step. Its one Feedback sibling with an `icon` prop does say this: EmptyState's `icon` JSDoc (`packages/perron/src/components/EmptyState/EmptyState.tsx:22`) gives its size and how to change it through `slotProps.icon`. So a caller who passes a 16 px icon from Actions, such as `search`, gets it scaled down to 13 px. That breaks the Icons foundation ("A larger icon is a new drawing, not a scaled one") and the api-consistency rule that one prop is described the same way in every member that has it. Fix: say "It renders at 13 px, `icon.size.325`, so give an icon drawn on the 14 px grid, or set `--perron-icon-size` through `slotProps.icon`" in both the JSDoc and the Props row.

## P3

- **P3-1.** `docs/components/alert.md:122` The icon rows (122 to 125, and `packages/perron/src/components/Alert/Alert.css:57`) draw the intent icon in `color.text.*`. The contract's Intents table and Semantic colours give icons the Mark column, `color.status.*`, which measures 3.7:1 or more on each tint here. Question 6 approved the look in the Tokens table, so the maintainer chooses: keep `color.text.*` and give the reason in the spec, or move to the Mark column. Carried from round 1.
- **P3-2.** `packages/perron/src/components/Alert/Alert.css:50` The icon part is `1lh` of `body-sm` (19.5 px), but a title's line is `heading-sm` (18.2 px). In the Danger and Success stories the icon's centre therefore measures 38.75 px against the title line's 38.1 px. Tokens row `docs/components/alert.md:118` ("the icon sits on the middle of the first line") holds only when there is no title. The gap is under a pixel, but Toast inherits it. Carried from round 1.
- **P3-3.** `packages/perron/src/components/Alert/Alert.css:106` The close button is pulled up `space.200`, so its focus ring reaches exactly the alert's top edge. It is flush in the Success story in both themes, and an `overflow: hidden` container would clip it. The pull is part of the approved Tokens table; a smaller pull such as `space.150` is the maintainer's call. Carried from round 1.
- **P3-4.** `docs/components/alert.md:211` CR-6 merges Alert's `onClick` first, so the caller's handler runs first. Base UI's `mergeProps` source (`mergeEventHandlers`) confirms that order. But it goes against the contract's Customising rule, "the component's own props last". Also, `slotProps.close` is typed with React's button props, so `event.preventBaseUIHandler()` is not in the caller's type without a cast. The contract should say which order handlers merge in and how a close slot's handler is typed when there is no Base UI root. Carried from round 1.
- **P3-5.** `packages/perron/src/parts/IntentIcon/IntentIcon.tsx:18` The contract's Shared parts section says each part is drawn in `<Part>.tsx` and `<Part>.css`. IntentIcon has no `IntentIcon.css`, and its `pn-IntentIcon` class styles nothing. Either the contract allows a part with no CSS, or the class has no job yet. Carried from round 1.
- **P3-6.** `docs/components/alert.md:157` The line gives "the close icon on its hover layer 6.1:1 and 4.8:1", which is `color.text.secondary` on `color.surface.hover`. But Tokens row `:151` and `CloseButton.css` turn the close icon to `color.text.primary` on hover, which measures 13.9:1 in light and 9.5:1 in dark on the lowest tint. The Tokens row holds, so the contrast line should quote the pair that actually renders.
- **P3-7.** `docs/components/alert.md:210` CR-5 ends "so a caller that swaps the icon's element leaves `aria-hidden` off it". Base UI's `useRender` merges a `render` element's props over the part's own, so a plain `render: <span />` keeps `aria-hidden="true"`, as measured. Only an element that sets `aria-hidden={false}` itself drops it. EmptyState CR-2 and StationIcon CR-3 use the same words, so the shared wording could say "can take `aria-hidden` off it with its own props".
