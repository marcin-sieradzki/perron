## P2

- **P2-1.** `packages/perron/src/components/Alert/Alert.tsx:79` `slotProps.close` is typed `Omit<ComponentPropsWithRef<'button'>, 'children'>`, so a caller can pass `disabled`, and the spec says the same at `docs/components/alert.md:56` and `:86`. But `docs/components/alert.md:155` says "The close button is never disabled", and the siblings Dialog and Popover type their close slot `Omit<…Close.Props, 'disabled'>` (dialog.md CR-6). A disabled close button would keep the `CloseButton` part's `pointer` cursor and its hover and pressed fills, because that part has no disabled rule. This breaks the contract's Pointer feedback rule (cursor `default` while disabled, and no hover or press on a disabled part) and the api-consistency sibling form. The contract holds: leave `disabled` out of the type and out of the Props and Base UI parts rows, so line 155 stays true.
- **P2-2.** `docs/components/alert.md:237` The first Do line reads "Say what is happening, then how sure we are, in plain sentences: \"Signal fault at Danshøj\" over \"Trains between Flintholm and Ny Ellebjerg run slower than planned.\"" Neither example says how sure we are, and "over" reads as "rather than", so a caller can take it to mean the title is preferred to the sentence. This is a content-audit Polish finding against content design's plain, unambiguous sentences. Better: "a title such as … above a sentence such as …", with an example that does say how sure we are.

## P3

- **P3-1.** `docs/components/alert.md:122` The icon rows (122 to 125, and `packages/perron/src/components/Alert/Alert.css:57`) draw the intent icon in `color.text.*`. The contract's Intents table gives icons the Mark column, `color.status.*`, and Semantic colours says "`color.status.<status>` fills dots, meters, icons and counts". NormalService's reason for text colour (the icon takes its words' colour) does not apply here, because Alert's words are ink. `color.status.*` reaches at least 3:1 on each tint (for example light warning about 3.9:1). The brief's question 6 approved the Tokens table's look, so this is the maintainer's call: keep `color.text.*` and state the reason in the spec, or move to the Mark column.
- **P3-2.** `packages/perron/src/components/Alert/Alert.css:50` The icon part is `1lh` of `typography.body-sm` (19.5 px). With a title, whose line is `heading-sm` (18.2 px), the icon's centre measures 38.75 px against the title line's 38.1 px in the Danger and Success stories. So Tokens row `docs/components/alert.md:118` ("the icon sits on the middle of the first line") holds only without a title. Under a pixel and not visible at 2x, but Toast inherits it. The icon could take the title's line height when a title is present.
- **P3-3.** `packages/perron/src/components/Alert/Alert.css:106` The close button is pulled up `space.200`, so its top is 5 px inside the alert's outer edge. The `focus.width` plus `focus.offset` ring (5 px) then reaches exactly the alert's top edge: it is flush in the Danger story in both themes, and an `overflow: hidden` container would clip it. The pull is part of the Tokens table approved in question 6; the maintainer may want a smaller pull, such as `space.150`.
- **P3-4.** `docs/components/alert.md:211` CR-6 merges Alert's `onClick` first, so the caller's runs first and can call `preventBaseUIHandler()`. Base UI's `mergeProps` source confirms that order. But it contradicts the contract's Customising rule, "the component's own props last". Also, `slotProps.close` is typed with React's button props, so `event.preventBaseUIHandler()` is not in the caller's type without a cast. The build raised the handler order as a direction note. The contract should say which order handlers merge in, and whether a close slot's handler is typed as Base UI's event.
- **P3-5.** `docs/components/alert.md:94` The prose says "the action `space.300` below the sentences". Tokens row `:141` and the CSS give it as `margin-block-start: space.200` plus the content's `space.100` gap. Both come to 12 px, but the prose names a token no rule sets; Toast will reuse these rows, so the prose should name the row's tokens.
- **P3-6.** `packages/perron/src/parts/IntentIcon/IntentIcon.tsx:18` The contract's Shared parts section says each part is drawn in its folder as `<Part>.tsx` and `<Part>.css`. IntentIcon has no `IntentIcon.css`, and its `pn-IntentIcon` class styles nothing. Either the contract allows a part with no CSS, or the class has no job yet.
