## P2

- **P2-1.** `docs/components/slider.md:72` The `label` Props row, and its JSDoc at `packages/perron/src/components/Slider/Slider.tsx:31`, says the label is "the name of the slider and of each thumb". Lines 15 and 25 say Field's label "names the group and every thumb", and line 47 says its id "names the group and each thumb". In a range that is not true: CR-7 (`slider.md:218`) and the ARIA table (`slider.md:176`) name each of a range's thumbs by `aria-label` alone, as "Minimum" and "Maximum". Base UI then drops the thumb's `aria-labelledby` (`node_modules/@base-ui/react/slider/thumb/SliderThumb.mjs:243`), and `components-slider--range` lists `slider "Minimum"` and `slider "Maximum"`. CR-7 and the ARIA row hold, so the Props row, the JSDoc and lines 15, 25 and 47 should say the label names the group and a single thumb.
- **P2-2.** `docs/components/slider.md:169` The `Home`, `End` row says that in a range the upper thumb's `Home` and the lower thumb's `End` "stop at the other thumb, less `minStepsBetweenValues`", and the "Base UI already does" line (`slider.md:56`) says the same. Base UI's `HOME` case is `sliderValues[index - 1] + step * minStepsBetweenValues` (`SliderThumb.mjs`), so the upper thumb's `Home` stops above the lower thumb, not below it. The gap is also `minStepsBetweenValues` times `step`, not `minStepsBetweenValues` itself. The spec's own `Range` play cell (`slider.md:245`) has `Home` on "Maximum" making "4 – 6". Base UI's code and the play cell hold, so both lines should say each thumb stops `minStepsBetweenValues` steps short of the other.
- **P2-3.** `docs/components/slider.md:190` The "Native semantics first" checklist line says "Perron adds no ARIA, and sets only `aria-label` through Base UI's `getAriaLabel` for a range's thumbs". The code sets two more: `aria-hidden="true"` on the two sizers (`packages/perron/src/components/Slider/Slider.tsx:285`, CR-8), and a range thumb's `aria-valuetext` through `getAriaValueText` (`Slider.tsx:200`, CR-7). The same checklist's lines 185 and 189 say both. CR-7 and CR-8 hold, so the line should name all three.

## P3

- **P3-1.** `packages/perron/src/components/Slider/Slider.tsx:198` In a range, `getAriaLabel` names each thumb "Minimum" or "Maximum" alone, so the field's label is no longer part of the thumb's name. `components-slider--in-form` lists `slider "Minimum"` and `slider "Maximum"`, so two range sliders on one screen would show up in a screen reader's list of controls as two "Minimum" sliders. The answer to question 9 binds this, but the maintainer may want each thumb named by the field's label together with the owned word.
- **P3-2.** `packages/perron/src/components/Slider/Slider.css:78` The thumb's hover and pressed layers (`color.surface.hover`, then `color.surface.selected`) render at 5% and 9% alpha in light and at 6% and 9% in dark, over a disc about 14 px across inside its edge (`components-slider--default`, both themes, measured with a real pointer hover and press). This meets Pointer feedback as written, but the design is deferred, and the maintainer may want a stronger step on a part this small.
- **P3-3.** `packages/perron/src/components/Slider/Slider.css:47` The empty part of the track, `color.surface.inset` (rgb(235, 238, 235) in light), is about 1.2:1 against the white page, so it is hard to see where the range ends and how far the thumb is from `max` (`components-slider--default` light). The spec argues this from Elevation and Meter's track (`slider.md:115`), and the thumb and the fill pass 3:1. Since the design is deferred, the maintainer may want an edge or a stronger track, so the range's end meets the 3:1 that Accessibility asks of a control's parts.
- **P3-4.** `docs/components/sheet.md:214` This diff rewrote Sheet's Do and don't row, and it still tells callers to mark a horizontal carousel with a bare `data-base-ui-swipe-ignore`. Slider's CR-11 (`slider.md:222`) and its Don't row (`slider.md:264`) explain, as Base UI's Drawer reference does, that a bare value turns off the sheet's swipe for every touch that starts on the element. The maintainer may want the carousel advice to give `="x"`, as Slider's control does.
