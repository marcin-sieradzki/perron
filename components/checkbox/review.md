## P2

- **P2-1.** `packages/perron/src/components/Checkbox/Checkbox.tsx:39` `slotProps.indicator` is typed as the whole `BaseCheckbox.Indicator.Props`, so `keepMounted` and `render` type-check but Checkbox drops them without a word (`mergeProps` puts Checkbox's own last). The siblings remove from a slot's type each member they own: Dialog's `close?: Omit<BaseDialog.Close.Props, 'disabled'>` and SearchField's `clear?: Omit<Autocomplete.Clear.Props, 'disabled'>`. Removing a member once Checkbox is `stable` would break the API (contract, Change). The slot type should be `Omit<BaseCheckbox.Indicator.Props, 'keepMounted' | 'render'>`, and the spec's Props row at `docs/components/checkbox.md:64` should give the same type (api-consistency, slotProps column; JSDoc rule).
- **P2-2.** `docs/components/checkbox.md:74` The spec says "The contract says the first part that needs the tick adds it", and line 15 says the same ("and says the first part that needs the tick adds it"). This diff replaced that contract sentence: `docs/components/README.md:220` now reads "The tick and the dash are in `packages/perron/icons/`, added with `CheckboxIndicator`". The contract holds over the spec, so both spec lines should cite the note as it now reads.

## P3

- **P3-1.** `docs/components/checkbox.md:84` The spec says `overflow-wrap: anywhere` is set "as the contract's Long words rule asks". The contract (`docs/components/README.md:165`) gives `break-word` to a content-sized box beside others in a flex row, and Checkbox's root is a content-sized inline-flex row. I measured two checkboxes in a 320 px `display: flex` row: with `anywhere` and with `break-word` alike, "driftsforstyrrelsesmeddelelser" breaks mid-word, because the label's `min-inline-size: 0` (`packages/perron/src/components/Checkbox/Checkbox.css:32`) lets it shrink below its longest word. Answer 9 binds the choice, but no rule settles which Long words case a checkbox label is. The maintainer, or CheckboxGroup's spec, should decide.
- **P3-2.** `docs/components/README.md:220` The new note says "`SelectedMark` draws the same tick", but there is no `packages/perron/src/parts/SelectedMark/` yet. Two rows of the table above it (lines 215 and 216) each say only their own folder holds the tick icon. The note could say SelectedMark will draw the tick, and how the two folders share it, so the SelectedMark build is not misled.
- **P3-3.** `packages/perron/src/parts/CheckboxIndicator/CheckboxIndicator.css:75` A disabled unticked box has a `color.border.subtle` edge (rgba(235, 238, 235, 0.1) in dark) and a `transparent` fill, so in dark it all but vanishes (story `components-checkbox--disabled`, dark). Only grey words are left, with nothing to show that they belong to a checkbox. WCAG exempts disabled controls, and answer 6 chose FilterChip's treatment. A chip keeps its pill shape when disabled; a checkbox's box is its only shape. The maintainer may want to reconsider this.
- **P3-4.** `packages/perron/src/components/Checkbox/Checkbox.tsx:14` The Inputs category now has two names for an on/off state: FilterChip's `selected`/`defaultSelected` and Checkbox's `checked`/`defaultChecked`, which are Base UI's and MUI's names. Switch and the menu's checkbox item will copy one of them. The contract could say which name goes with which kind of control (api-consistency Direction; MUI uses `checked` for Checkbox and Switch, and `selected` for ToggleButton).
- **P3-5.** `docs/components/checkbox.md:183` The checklist says `children` renders a string, an element and a list alike, and that it renders nothing when it renders nothing. Every story passes a string or `undefined`. I rendered `<strong>`/`<em>` children, an array, `false`, `''` and `[null, false]` outside the stories: all render correctly, with the right names, and the empty ones drop the label span. No story keeps this from regressing, as Surface's `Shapes` and MapTooltip's element-and-list story do for their components.
- **P3-6.** `docs/components/checkbox.md:5` The spec page ships as `Specs/Checkbox`, but it carries notes about how this run went: "No ROADMAP wave line names Checkbox", "The extracted prototype component is not in any branch this run can reach", and, at line 74, "since its unit test pins the row and a component branch leaves shared tooling as it is". These belong in `pipeline.yaml` notes, not in the spec's prose (content audit, house voice).
