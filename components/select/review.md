# Review: Select, round 1

## P1

- **P1-1.** `packages/perron/src/components/Select/Select.tsx:234` Select's own label props (`id`, `render={<div />}`, `nativeLabel={false}`) are merged under the caller's `slotProps.label` rather than last, so a caller's `render` or `nativeLabel` undoes the non-native label Base UI asks for on a `<button>` control and a caller's `id` renames the label, which breaks the contract's Customising rule (each slot merged with `mergeProps`, the component's own props last; SearchField's label puts its `id` last); the contract holds over CR-5 (`docs/components/select.md:287`), CR-6's last sentence (`:288`), the Field.Label row (`:54`) and the Anatomy prose (`:45`), which all say "under the caller's" and need rewriting, and `Select.tsx:181` should read only its own id.

## P2

- **P2-1.** `packages/perron/src/components/Select/Select.tsx:257` Seven parts that get nothing from Select but their class are passed through `mergeProps(slotProps?.<part>, undefined)` rather than spread as they are: trigger `:257`, itemText `:213`, portal `:270`, popup `:281`, separator `:296`, group `:308` and groupLabel `:312`, which breaks the contract's Customising rule ("a part the component sets nothing on but its class is spread as it is, `{...slotProps?.portal}`"), the rule retro 8 just applied to Popover; CR-5 (`docs/components/select.md:287`, "Each `slotProps` value is merged with Base UI's `mergeProps`") contradicts the contract, which holds, so the spec line needs rewriting too.
- **P2-2.** `docs/components/select.md:103` The `onClose` row, and the JSDoc copied from it at `Select.tsx:77`, say `reason` is one of five values, but Base UI 1.9.0's `SelectTrigger` also closes with `'cancel-open'` when the person presses the trigger, drags off and releases outside the trigger and the list (seen in Storybook), and line 71's list of close reasons leaves it out too; this breaks rubric 6 (the spec against Base UI's source on which reasons an event gives), and the fix is to name it or say "or another of Base UI's reasons", as Popover does.
- **P2-3.** `docs/components/select.md:71` The line "on open from the keys it highlights and focuses the chosen option, or the first" is wrong for ArrowUp: on a closed trigger with nothing chosen, ArrowUp highlights and focuses the last option ("Harbour bus" in the Hover story), so the spec disagrees with Base UI's behaviour; line 71 should say so, and the ArrowDown, ArrowUp Keyboard row (`:235`) could say it too.
- **P2-4.** `packages/perron/src/components/Select/Select.css:191` With forced colours on, the disabled row (`[data-disabled]`, `:183`) and the placeholder (`[data-placeholder]`, `:58`) lose `color.text.tertiary` and render in `CanvasText`, so "Harbour bus" looks the same as the options a person can choose and "Choose a transport mode" looks like a chosen value (components-select--disabled-item, forced colours); Checkbox's CR-11 gives its non-native disabled label `GrayText` for this reason, and the forced-colours block should give both of these `GrayText`.

## P3

- **P3-1.** `packages/perron/src/components/Select/Select.stories.tsx:60` The build's question 1 recommended one `color-contrast` exception for `[data-placeholder]` in `.storybook/preview.ts`, but CR-16 (`docs/components/select.md:298`) puts it in Select's meta instead, so each later Field dependent that draws a text placeholder (Combobox, and TextField's direction note) will repeat it; the maintainer may want to settle where it lives.
- **P3-2.** `docs/components/select.md:239` The Tab, Shift+Tab row says Tab in the open list closes it (`'focus-out'`), but not that Base UI then returns focus to the trigger rather than moving it on, so a second Tab is needed to leave the field (seen in Storybook); the row could say where focus goes.
- **P3-3.** `docs/components/select.md:99` The `onChange` row (and `Select.tsx:56`) names `'none'` only for letters typed on the closed box, while Base UI's hidden input also calls `onValueChange` with `'none'` when the browser autofills the field.
- **P3-4.** `docs/components/select.md:298` CR-16 sets the docs frame to `360px`, but the `Groups` list needs about 435 px, so on the docs page it opens cut short and scrolls with E, F and H out of view; the contract's Stories rule asks for "a height that fits the open overlay" (its example is `480px`).
- **P3-5.** `docs/components/select.md:313` The `Invalid` story's error, "Choose a transport mode", repeats the placeholder shown in the box above it word for word, so the eye reads it twice and the ear hears it as both the value and the description; an error that says what is wrong (content design's "what is wrong and how to put it right") would read better.
- **P3-6.** `packages/perron/src/components/Select/Select.tsx:85` `required` and `readOnly` have JSDoc of Select's own, while Checkbox and Switch inherit Base UI's wording for the same props (the api-consistency rule "one prop is described the same way in every member that has it"); as the build's direction note says, the Inputs family could settle on one wording.
