## P1

## P2

- **P2-1.** `docs/components/radio-group.md:29` The spec says a root `Field.Label` becomes the group's `aria-labelledby` before the legend's id. In Perron's composition that is false. `Fieldset.Root` passes `aria-labelledby: legendId` to the rendered `RadioGroup` as an element prop (`node_modules/@base-ui/react/fieldset/root/FieldsetRoot.js:36`), and the group's `elementProps` override its own `labelId ?? legendId` default (`node_modules/@base-ui/react/radio-group/RadioGroup.js:164,214`). So inside a Field the group keeps its legend as its name and only each radio is renamed. The same wrong claim is at `:42`, CR-12 (`:214`) and the Don't row at `:252`. The installed source holds, so the build should rewrite all four lines (rubric 6, the spec against Base UI's source).
- **P2-2.** `docs/components/radio-group.md:107` The spec says Checkbox's box is "still designing" and "is to take" `icon.size.400`, "so the two marks agree". Lines `:15`, `:109` and `:113` repeat this. But Checkbox is `stable` in this branch, sized by `size.checkbox`, with its own disabled look (`packages/perron/src/parts/CheckboxIndicator/CheckboxIndicator.css:14,74-83`). The build should rewrite these lines against the shipped Checkbox, which holds over the spec's forecast (rubric 6, the spec against the branch).
- **P2-3.** `packages/perron/src/components/RadioGroup/RadioGroup.css:136` With forced colours on, a disabled radio's words and the disabled legend render in `CanvasText`, the same as enabled text. Only the indicator's `GrayText` shows the disabled state. Checkbox meets the same case (a `<span>` the system can't tell is disabled) by giving its disabled root `GrayText` (Checkbox CR-11, `packages/perron/src/components/Checkbox/Checkbox.css:47-51`). The radio should take the sibling's form, and spec CR-11 (`docs/components/radio-group.md:213`) should name it (api-consistency, a difference from the sibling form).
- **P2-4.** `packages/perron/src/components/RadioGroup/RadioGroup.tsx:193` `slotProps.indicator` is typed as the full `BaseRadio.Indicator.Props`, so it accepts a `keepMounted` that Perron always overrides without a word. Checkbox types the same slot `Omit<Checkbox.Indicator.Props, 'keepMounted' | 'render'>`. Once RadioGroup is `stable`, narrowing the type would be a break under the contract's Change rules, so it should match Checkbox's form now, with the spec's Props row at `docs/components/radio-group.md:97` (api-consistency, slotProps).
- **P2-5.** `packages/perron/src/components/RadioGroup/RadioGroup.stories.tsx:517` `LabelShapes` names its group "Theme" over "Planned works", "Diversions" and "Data feed problems", and `LongLabels` (`:550`) puts "Theme" over "Realtidsdataforsinkelser". On the docs page the label names a question these choices don't answer, which breaks the spec's own Do row (`docs/components/radio-group.md:247`). The spec's Stories prose (`:220`) also says every story names "Theme" and gives the three themes, which contradicts its `LabelShapes` and `LongLabels` rows (`:235-236`). The rows hold: each story should get a label that fits its choices, and `:220` should be rewritten (content-audit).
- **P2-6.** `docs/components/radio-group.md:188` The checklist line says `label` renders a string, an element and a list alike, "as the `LabelShapes` story shows". But `LabelShapes` (`RadioGroup.stories.tsx:517`) only varies the radios' `children`, and no story ever renders the group's `label` as an element or a list. This leaves the contract's "every shape the type accepts renders" line unchecked for a `ReactNode` prop (What axe won't catch).
- **P2-7.** `docs/components/radio-group.md:177` The ARIA table's `root` row lists `aria-disabled`, `aria-readonly` and `aria-required` as the states announced. Inside an invalid Base UI `Field.Root`, the group also carries `aria-invalid="true"` and the field's `aria-describedby`; the `Invalid` story's `role="radiogroup"` shows both. The Base UI parts row at `:38` names only `data-invalid` (rubric 6, the Keyboard and ARIA table against what renders).
- **P2-8.** `docs/components/radio-group.md:38` The Base UI parts table says `style` reaches `RadioGroup` (`:38`) and `Radio.Root` (`:39`) through `{...rest}`. The code takes `style` out of `rest` and sets it itself (`RadioGroup.tsx:117,151` and `:206,220`). CR-4 (`:206`) leaves `style`, and Radio's `ref`, off its lists of what each component takes out of `rest` (rubric 6, the Base UI parts table and a `CR-n` against the code).

## P3

- **P3-1.** `packages/perron/src/components/RadioGroup/RadioGroup.css:119` With forced colours on, an invalid radio's edge keeps the theme's `color.status.danger` under `forced-color-adjust: none`. On a checked invalid radio, hover and press turn that edge `Highlight` (`:154`). CR-11 names no invalid look, and Switch has the same gap. Should the edge be a system colour such as `Highlight` or `Mark`, for both controls?
- **P3-2.** `packages/perron/src/components/RadioGroup/RadioGroup.css:105` The disabled radio follows Switch: an inset circle with a subtle edge unchecked, and a `color.text.tertiary` fill with a raised dot checked. Checkbox and FilterChip draw disabled as a transparent fill with a subtle edge, and an inset fill with a tertiary mark when selected. The two choice marks now differ when disabled. Which disabled look should the maintainer keep for both?
- **P3-3.** `packages/perron/src/components/RadioGroup/RadioGroup.css:23` The radio's row, and so its focus ring, takes `radius.md`, where Checkbox's matching row of mark and words takes `radius.xs`. Should the two choice controls ring the same way?
- **P3-4.** `packages/perron/src/components/RadioGroup/RadioGroup.css:33` The circle is sized by `icon.size.400`, an icon size ("Inside controls: search, zoom, locate, close"), for a mark that is not an icon. This was the answered brief question 6, made on the premise that Checkbox would share it, but Checkbox's 16 px box took `size.checkbox`. Should one choice-mark size token cover both, through the `design-tokens` skill?
- **P3-5.** `docs/components/fieldset.md:141` Fieldset's Do row still says RadioGroup takes its description and error "through a Field round it" (and `:22` says the same). RadioGroup's CR-12 and Don't row (`docs/components/radio-group.md:214,252`) forbid wrapping the group in Perron's Field. Fieldset's spec needs a correction once Field gains a group mode, or now.
