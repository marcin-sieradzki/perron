# Review: Menu, round 1

## P1

- **P1-1.** `packages/perron/src/components/Menu/Menu.tsx:185` The portal, both group labels (`:452`, `:549`), the submenu's portal (`:658`) and the submenu's popup (`:669`) set nothing of their own except a class, but they pass their slot through `mergeProps(slotProps?.x, undefined)` where it should be a plain spread, `{...slotProps?.x}`; the contract's [Customising](docs/components/README.md#customising) rule asks for a spread, and Popover, Dialog and Checkbox have used it since retro 8 (api-consistency, contract rule broken).
- **P1-2.** `packages/perron/src/components/Menu/Menu.stories.tsx:50` The stories show the `monitor` and `info` icons, which `icons.json` and `docs/foundations/icons.md` draw on an 18 px grid for `icon.size.450`, at the menu's `icon.size.400` (`Menu.css:133`). Scaled down to 16 px, their 1.6 px stroke renders at about 1.42 px, under the 1.5 px floor, and icons.md says "a larger icon is a new drawing, not a scaled one" (design-qa Token use: `icon.size.400` used outside its role for these icons). The spec asks for this in the Stories prose (`docs/components/menu.md:397`) and in MenuItem's `startIcon` row (`docs/components/menu.md:115`, "such as `monitor`"), so the rerun fixes the spec and the stories together: 16 px icons for the examples, or new 16 px drawings.

## P2

- **P2-1.** `packages/perron/src/components/Menu/Menu.tsx:190` Menu leaves the positioner's `collisionPadding` at Base UI's untokenised 5 px. Every positioned sibling in Overlays (Popover, Tooltip, MapTooltip) sets it to `size.panel-gap` through `positionerOffsets()`, and the spec's Tokens prose (`docs/components/menu.md:231`) leans on Base UI's default with no reason given (api-consistency: differs from the form the siblings share).
- **P2-2.** `packages/perron/src/components/Menu/Menu.css:51` A row's `align-items: center` centres the start icon, the box, the tick and the chevron across a wrapped label (LongLabel, both themes) instead of on its first line. Checkbox lines up the same `CheckboxIndicator` with its label's first line through `1lh` (`Checkbox.css:28`), and the spec's Tokens section has no line on it (design-qa Alignment; the build's own direction note).
- **P2-3.** `packages/perron/src/components/Menu/Menu.stories.tsx:456` In the Submenu and LinkItems stories (`:511`), rows with no start icon ("Language", "Data sources", "Privacy") sit under rows that have one. Their labels start 24 px left of the others in light and dark, against the spec's "every label in a menu then starts at one edge" (`docs/components/menu.md:239`) and design-qa Alignment. Give every row in a story an icon, or none, and add that to Do and don't.
- **P2-4.** `docs/components/menu.md:358` The checklist line says "the stories give every group a label", but the Submenu story's `MenuRadioGroup` (`Menu.stories.tsx:457`) has none and renders an unnamed `group`. MenuRadioGroup's `label` row (`:160`) allows leaving it out when something else names the choice, and that row holds over the prose, so the checklist line should say so.
- **P2-5.** `packages/perron/src/components/Menu/Menu.css:189` The separator's `margin-inline: calc(-1 * space.100)`, which runs it across the popup's padding, has no row in the Tokens table (`docs/components/menu.md:310-311` give only `border-block-start` and `margin-block`), so the spec and the CSS disagree on a length (design-qa Spacing; review area 6).
- **P2-6.** `packages/perron/src/components/Menu/Menu.tsx:486` `slotProps.radioItemIndicator` is typed as the whole `Menu.RadioItemIndicator.Props`, yet the merge at `:510-512` silently drops a caller's `render`. The sibling slot `checkboxItemIndicator` and Checkbox's `indicator` both type it `Omit<…, 'render'>`. Narrow the type, and the spec's row (`docs/components/menu.md:184`) and Base UI parts line (`:66`) with it (api-consistency).

## P3

- **P3-1.** `packages/perron/src/components/Menu/Menu.css:197` Two problems in the forced-colours block. First, the highlighted row's `forced-color-adjust: none` keeps `perron.css`'s focus ring in `color.border.focus`, so a light-themed page under a dark system palette draws it near-black on a black Canvas. The Highlight fill still marks the row. Second, the checked-and-highlighted gradient rule (`:112`, specificity 0,4,0) beats this block's `background-image: none` (0,3,0), so a faint author tint lies over Highlight (CR-13).
- **P3-2.** `docs/components/menu.md:382` CR-8 says Menu's CSS never sets the parts' colours, but `Menu.css:215-218` gives the unticked box `forced-color-adjust: auto` inside a highlighted row; that is needed for CR-13 and worth a line in CR-8.
- **P3-3.** `docs/components/menu.md:389` CR-15 says each `play` ends "with focus on the trigger", but every play asserts it and then calls `trigger.blur()` (`Menu.stories.tsx:101`, `:168`), which follows the contract's "focus back where it started"; the CR's wording should match.
- **P3-4.** `packages/perron/src/components/Menu/Menu.stories.tsx:33` Base UI's typeahead reads a row's raw `textContent`, so a start icon inlined with the shared `icon` helper (or any raw SVG with white space) stops typed letters matching. The local `glyph` hides this; trimming in `packages/perron/src/testing/stories.ts`'s `icon` would fix it for every story, as the build's direction note says.
- **P3-5.** `packages/perron/src/components/Menu/Menu.tsx:26` `pixels` and the module-level `offsets` cache repeat `positionerOffsets`'s `px` closure and cache in `packages/perron/src/internal/tokens.ts`. Extending that helper to give `space.100` and the submenu's `alignOffset` would keep one reader of positioner tokens.
- **P3-6.** `packages/perron/src/components/Menu/Menu.tsx:189` The positioner merges Menu's own props first and the caller's last so that CR-9's caller wins. The contract's Customising rule puts the component's props last, and Popover meets both by merging `positioner?.x ?? default` last (`Popover.tsx:160-164`).
