- **P3-1.** `packages/perron/src/components/Menu/Menu.tsx:72` New this round: `MenuProps`, `MenuItemProps` (`:218`), `MenuLinkItemProps` (`:265`), `MenuCheckboxItemProps` (`:308`), `MenuRadioItemProps` (`:481`) and `MenuSubmenuProps` (`:600`) now omit `id` from their Base UI part and declare it again with Perron's own JSDoc, and the spec agrees (`docs/components/menu.md:88`, with rows at `:104`, `:123`, `:135`, `:152`, `:182` and `:219` reading `id` under Base UI prop). The rubric lists a redeclared Base UI prop as a P1, and the contract's [Props](docs/components/README.md#props) rule (`README.md:59`) says a props type "declares only its own members". The cause, though, is shared tooling: Base UI marks `id` `@ignore`, `scripts/lib/docgen.ts:100` copies that tag into the description, and the docs page then drops the row the same contract rule requires. The docs stage asked for this workaround, it changes no type, and earlier reviews (LinkButton, Switch, Meter, SeverityLabel) kept justified redeclarations at P3. So this is a question for the maintainer: strip `@ignore` from `id` in `propDoc` for every component and let these six inherit `id` again, or write the exception into the contract.

The docs page's row will be empty while the spec shows words, so the maintainer may want the row left empty, or the tooling to fall back to the spec's text.
