## P2

- **P2-1.** `packages/perron/src/components/Menu/Menu.tsx:491` The JSDoc for `slotProps.radioItemIndicator` and the spec (`docs/components/menu.md:66`, `:184`) both give `keepMounted` as the example prop, but neither `SelectedMark.css` nor `Menu.css:163` hides an indicator marked `[data-unchecked]`. Base UI renders a kept-mounted indicator on every radio item (`MenuRadioItemIndicator.js`, `enabled: keepMounted || mounted`), so a caller who follows the example sees a tick on every option while only one row has `aria-checked="true"`. That breaks the checklist line "Everything the eye is told, the ear is told" (`docs/components/menu.md:368`) and the Anatomy row "rendered only while the item is chosen" (`:33`). The fix is either to hide the unchecked tick (with `visibility: hidden`, so the space stays reserved) or to leave `keepMounted` out of the slot, with the spec rows and JSDoc changed to match.
- **P2-2.** `docs/components/menu.md:285` Several rules in `Menu.css` have no row in the Tokens table. The first is the `color.surface.hover` gradient that hover lays over a checked row (`Menu.css:104-111`), where the hover row at `:276` says only "not while disabled" but the CSS also leaves checked rows out of the plain fill. The others are the forced-colours rules: `GrayText` on a disabled row (`Menu.css:232-240`), the chevron in `HighlightText` on a highlighted row (`:223-225`), and the unticked box set back to `forced-color-adjust: auto` (`:227-230`). This breaks the Tokens rule of one row per part, state and property (review area 6, design-qa Token use).

## P3

- **P3-1.** `docs/components/menu.md:256` The `alignOffset` row and CR-9 (`:394`) say "minus `space.100` plus `border.width.025`", which read literally gives -3 px. The code (`Menu.tsx:42`) computes `-(space.100 + border.width.025)`, -5 px, and that does put the submenu's first item level with its row (measured: row top 156.7, first item top 157). The code comment at `Menu.tsx:33` repeats the wording. All three should say "minus the sum of `space.100` and `border.width.025`".
- **P3-2.** `docs/components/menu.md:394` Because CR-9 keeps the submenu's `sideOffset` at 0 against the row, the submenu's glass sits over the parent popup's padding and right edge by `space.100` + `border.width.025` (Submenu story, both themes). The spec never says so. The maintainer may want that overlap stated, or the submenu offset by the same amount so the two popups' edges meet.
- **P3-3.** `packages/perron/src/components/Menu/Menu.css:217` Two forced-colours problems from round 1 are still there. First, `forced-color-adjust: none` on a highlighted row keeps `perron.css`'s ring in `color.border.focus`, which is near-black on a dark system palette when the page uses the light theme. Second, the checked-and-highlighted gradient rule (`:113`, specificity 0,4,0) still beats this block's `background-image: none` (0,3,0): measured under forced colours, a `color.surface.hover` tint stays over `Highlight` (CR-13).
- **P3-4.** `packages/perron/src/components/Menu/Menu.stories.tsx:33` From round 1: the local `glyph` helper hides the fact that the shared `icon` helper in `packages/perron/src/testing/stories.ts` keeps the SVG file's white space, so Base UI's typeahead never matches a typed letter. Trimming it in the shared helper would fix this for every story.
- **P3-5.** `packages/perron/src/components/Menu/Menu.tsx:26` From round 1: `pixels` and the module-level `offsets` cache repeat the `px` closure and the cache in `positionerOffsets` (`packages/perron/src/internal/tokens.ts:32`). Menu now calls both helpers, and one helper that also reads `space.100` and the submenu's `alignOffset` would keep a single reader of positioner tokens.
- **P3-6.** `docs/components/menu.md:408` The Stories prose gives "`fn()` handlers for `onOpen`, `onClose` and every `onClick` and `onChange`", but the Submenu story's `MenuRadioGroup` (`Menu.stories.tsx:464`) and the LinkItems story's link items (`:518-519`) have no handler. Either the prose should say "where the story checks one", or the stories should add the handlers.
