# Review: SearchField, round 2

## P1

None.

## P2

- **P2-1.** `docs/components/search-field.md:58` The "Base UI already does" line says Base UI closes the list "when the input is emptied (`'input-clear'`)", but pressing the clear button while the list is open empties the box and leaves the list open, now showing every item, with no `onClose`. Driven in the Default story: type "Nør", ArrowDown, press Clear, and the only call is `onChange` with `''` and `'clear-press'`, while the listbox stays mounted. In Base UI 1.9.0, `ComboboxClear.mjs` calls only `setInputValue('', clearPress)` and never `setOpen`; only the input's own `onChange` closes on `'input-clear'` (`ComboboxInput.mjs:246`). A caller who controls `open` and trusts this line expects a close that never comes. The line breaks the rubric's spec-against-Base-UI check: Base UI's source holds, so the build rewrites line 58 to say the list closes when typing empties the box, and stays open when the clear button empties it. The Typing row at line 188 is already scoped to typing and stays as it is.

## P3

- **P3-1.** `docs/components/search-field.md:47` The Base UI parts row says `Autocomplete.Root` renders "No element", and so does Anatomy line 35. In Base UI 1.9.0, `AriaCombobox.mjs:1283` renders a hidden `<input id="…-hidden-input" tabindex="-1" aria-hidden="true">` without a `name`, used for autofill, as the root `<div>`'s last child (seen in every story's DOM). Nothing breaks, but the tables describe the DOM wrongly.
- **P3-2.** `packages/perron/src/components/SearchField/SearchField.tsx:112` (carried from round 1) `onItemSelect(event, item)` is a new event name that later list components will copy, while MUI's Autocomplete reports a chosen option through `onChange`. The contract could settle what choosing a row is called in a list that keeps no selection.
- **P3-3.** `packages/perron/src/components/SearchField/SearchField.tsx:55` (carried from round 1) `hiddenLabel`, MUI's boolean, gets past the props gate's `<key>Label` rule only through `perron-allow(props)`. The contract's Props table could name it as an exception, so the next field doesn't need the same allowance.
- **P3-4.** `docs/components/README.md:219` (carried from round 1) The Shared parts row now lists `Autocomplete.Clear` under `CloseButton`, but the bullet below it still says the part's label is the owned "Close" overridden by `closeLabel`; SearchField gives "Clear" through `clearLabel`. The `close` icon's `use` in `packages/perron/icons/icons.json` also still says only "Close a panel, a dialog or a highlight".
- **P3-5.** `docs/components/search-field.md:78` (carried from round 1) The default filter uses Base UI's collator in the runtime's locale, which ignores accents. In an English runtime it treats ø as o, so "Nør" also matches "Nordhavn St." (seen again this round), which a Danish reader wouldn't expect. Only a PerronProvider locale that reaches components, or a caller's `filter`, avoids it; Base UI's `Autocomplete.Root` takes a `locale` prop for this.
- **P3-6.** `docs/components/search-field.md:83` (carried from round 1) With `hiddenLabel`, the placeholder is the only text that names the field for the eye. It is drawn in `color.text.tertiary`, about 4.0:1 on `color.surface.raised` in light and about 3.8:1 in dark, which `docs/foundations/accessibility.md:7` keeps for hints next to stronger text. Yet the spec recommends this setup for the top bar.
- **P3-7.** `packages/perron/src/components/SearchField/SearchField.stories.tsx:393` (carried from round 1) In `WithMarks`, a LineBadge `startIcon` repeats the item's label, so the option is heard as "5C 5C Bus, Husum Torv to Lufthavnen". The spec's Do and don't could tell callers how to avoid saying the same words twice.
- **P3-8.** `packages/perron/src/components/SearchField/SearchField.tsx:237` (carried from round 1) The clear button is left out only when SearchField's own `disabled` prop is set. If a Base UI `Fieldset` around the field disables it instead, Base UI still renders the `CloseButton`, disabled but with no disabled look (Dialog CR-6).
- **P3-9.** `packages/perron/src/components/SearchField/SearchField.tsx:105` `onClose` takes Base UI's whole `Autocomplete.Root.ChangeEventReason`, which also allows reasons SearchField never sends (`'trigger-press'`, `'input-press'`, `'imperative-action'`, `'chip-remove-press'`). A narrower union of the seven its JSDoc lists would let a caller's `switch` be checked for missing cases. Dialog takes the whole Base UI type too, so this is a library-wide choice.
