# Review: HighlightChip, round 1

## P1

- **P1-1.** `packages/perron/src/components/HighlightChip/HighlightChip.css:91` In forced colours, the selected rule `.pn-HighlightChip[data-pressed]` (specificity 0,2,0) loses to the selected `:hover` and `:active` rules at lines 63 and 69 (0,4,0). Because `forced-color-adjust: none` keeps the theme's colours, a hovered or pressed selected chip shows `color.surface.inverse-hover` under `HighlightText`. Rendered in dark, that is white on rgb(162, 173, 177), so the label can't be read (story `components-highlightchip--selected-hover`, dark, forced colours, root). This breaks CR-5 ("the system keeps the fill") and the Forced colours line of the accessibility foundation. FilterChip covers it with `:is(:hover, :active)` in its forced-colours selector list.

## P2

- **P2-1.** `packages/perron/src/components/HighlightChip/HighlightChip.css:102` In forced colours, a selected disabled chip draws `GrayText` words on a `Highlight` fill. That is not a system colour pair, and the rendered label is barely legible (story `components-highlightchip--selected-disabled`, forced colours). Both sibling toggles use one other form: a `GrayText` fill with `Canvas` words (`FilterChip.css:110-115`, `SegmentedControl.css:94-98`). CR-5 at `docs/components/highlight-chip.md:146` prescribes the odd pairing, so the spec line and the CSS should both change to the siblings' form (api-consistency: the form most siblings share).
- **P2-2.** `docs/components/highlight-chip.md:99` The Tokens table has no `selected, pressed` / `background-image` row, but the CSS sets `background-image: none` there (`HighlightChip.css:71`). Without that rule, the rest `:active` layer would lie over the inverse fill. This breaks spec section 6: every property the CSS sets per state has its row.
- **P2-3.** `docs/components/highlight-chip.md:20` The `label` row says the label has no element or class of its own "as Tag's and Segment's are". Segment does wrap its label, in `pn-Segment-label` (`SegmentedControl.tsx:137`), and so do FilterChip (`pn-FilterChip-label`) and Button. The cited precedent is false. Either cite only label-less siblings such as Tag and LineBadge and give the reason, which is the flex `gap` between the nodes of `children`, or adopt the siblings' `-label` span.
- **P2-4.** `docs/components/highlight-chip.md:149` CR-8 says `size.panel-gap` is kept for patterns by the contract's Token families. The component row there grants all of `size.*` (`docs/components/README.md:181`), and only the `z-index.*` tokens are kept for patterns. The contract holds, so the line should name only `z-index.highlight` as the patterns' token and keep the placement reason for `size.panel-gap`.
- **P2-5.** `packages/perron/src/components/HighlightChip/HighlightChip.tsx:68` `style` is declared in `HighlightChipProps` (line 50) but is not taken out of `rest` before the spread. This breaks the contract's Root rule ("Every prop the props type declares is taken out of `rest` before the spread") and FilterChip's form, which destructures `style` and passes it after `{...rest}`.

## P3

- **P3-1.** `packages/perron/src/components/HighlightChip/HighlightChip.css:25` The chip writes the glass fill, `backdrop-filter` and `shadow.panel` itself, as Toolbar does. The contract's Glass line (`docs/components/README.md:206`) exempts only "a Base UI popup or panel" from composing Surface with `variant='glass'`. The maintainer may widen that line to cover any element Base UI renders, such as a Toggle, or ask the chip to compose Surface through `render`.
- **P3-2.** `docs/components/highlight-chip.md:58` The spec reads Base UI's `[data-pressed]` as the Selected design state, as FilterChip does. The contract's Design states table (`docs/components/README.md:147-150`) lists `[data-pressed]` under Pressed and only `[data-selected]` and `[data-checked]` under Selected. The contract could name a Toggle's `[data-pressed]` under Selected, so the two Toggle chips and SegmentedControl rest on a written rule.
- **P3-3.** `docs/components/highlight-chip.md:43` The spec says "The chip takes no `name`", but `HighlightChipProps` inherits the native button's `name` through `Toggle.Props`, and it reaches the `<button>`. It does nothing on a `type="button"`, so the sentence could say the chip takes no form `name` and renders no hidden input.
