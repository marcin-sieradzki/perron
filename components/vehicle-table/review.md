## P2

- **P2-1.** `packages/perron/src/patterns/VehicleTable/VehicleTable.css:75` (and the Tokens row at `docs/patterns/vehicle-table.md:154`) `overflow-wrap: anywhere` sets the destination column's min-content width to a single letter. In the automatic table layout, that makes the destination the column that gives up width first, so ordinary destinations break mid-word at the 320 px reflow width. In the subject story `patterns-vehicletable--default` at a 320 px viewport (light and dark), "Lufthavnen" renders as "Lufthavne / n". In `LongDestination`, "Københavns" renders as "Københav / ns" and "Lufthavnsterminalen" as "Lufthavnsterminale / n". This is the squeeze the contract's CSS "Long words" rule describes ("`anywhere` lets the row squeeze that box to one letter a line, where `break-word` keeps whole words at its narrowest"), applied to a box sized to its content beside other boxes, which an auto-layout column is. VehicleDotLabel's CR-5 chose `break-word` for this reason. Plain `break-word` is no fix on its own: tried in the browser, it makes `LongDestination`'s table 329 px wide in a 256 px container. So CR-8 and this row need a choice that keeps short words whole and still fits 320 px, such as a least width for the destination column or hyphenation (design-qa Text line, Polish).
- **P2-2.** `docs/patterns/vehicle-table.md:231` CR-8 says each row "grows only when its destination wraps", and line 107 opens with the same claim ("a row grows only when a long destination wraps"). Both disagree with the render. In `Default` at a 320 px viewport, "Husum Torv", "Lufthavnen" and "Kokkedal St." each wrap onto two lines, and every row stays at 52 px (`size.vehicle-row`). Line 107's later sentence ("every row whose destination fits one or two lines is exactly that tall") agrees with the render and holds. Rewrite CR-8 and the opening of line 107 to say a row grows only when its content is taller than `size.vehicle-row` (rubric 6).
- **P2-3.** `docs/patterns/vehicle-table.md:175` The ARIA table says a `row`'s accessible name comes from "Its row headers' text, the line and the destination". The rendered tree names each row from all of its cells: `row "5C Husum Torv Live On time"`, `row "RE Helsingør Timetable only Delay unknown"`. The row's name is the content of all four cells. The row headers are what a screen reader adds when it moves down a column, as line 181 describes. The row should say that (rubric 6, the spec's Keyboard and ARIA table against the render).
- **P2-4.** `docs/patterns/vehicle-table.md:186` The checklist line says the table takes its name "through `aria-labelledby`, as every story gives it". Every story names it with `aria-label` instead: "Vehicles" in the meta's args at `packages/perron/src/patterns/VehicleTable/VehicleTable.stories.tsx:93`, as the Stories prose at line 236 says, and `aria-label` in each `mounted` render. No story uses `aria-labelledby`. Line 236 holds, so rewrite line 186, or add a step that names a table from a heading through `aria-labelledby` (rubric 6, What axe won't catch).
- **P2-5.** `docs/patterns/vehicle-table.md:238` These lines of the coverage checklist have no `play` step that proves them (rubric 7; contract Stories, "a `play` test for every behaviour the component promises"):
  1. `delay: null` on a `live`, `ageing` or `estimated` vehicle rendering "—", heard as "Delay unknown" (CR-4). The checklist at line 188 promises "`delay` a number, `null` and left out, in every `variant`", but no story or step passes `null`.
  2. A `timetable-only` vehicle given a numeric `delay` still showing an unknown delay (CR-4, "whatever `delay` holds"). Only the `no-signal` vehicle is given a number (4). The timetable-only one gives no `delay` at all.
  3. CR-5's "the table owns no name": a table rendered without `aria-label` or `aria-labelledby` has no accessible name and no `<caption>`. Every render passes a name, so nothing proves the table adds none of its own.
  4. CR-7's "VehicleTable is not a live region": no step checks that the root and its parts carry no `aria-live`, and no `role` of `status`, `log` or `alert`.
  5. CR-8's "a header breaks only a word longer than its column" (`overflow-wrap: break-word` on `headerCell`). No step renders a long header label, such as a long `delayColumnLabel`, in a narrow table.

## P3

- **P3-1.** `docs/patterns/vehicle-table.md:11` The Anatomy line puts VehicleTable in the Rows family, without Rows' `color.surface.hover`, because its rows are not pressed (CR-7). DepartureRow's Anatomy line (`docs/patterns/departure-row.md:11`) says "Family: none" for that same reason. The contract's Families table doesn't say whether a row that isn't pressed takes Rows' hover. The maintainer could settle that once, so the two siblings name their family the same way.
- **P3-2.** `packages/perron/src/patterns/VehicleTable/VehicleTable.css:56` Every cell is `vertical-align: middle`. In `LongDestination`'s M3 row (84 px), the badge, the state and the delay centre on the four-line destination block, not on its first line, the same question DepartureRow's round-1 P3-2 raised. In single-line rows, the baselines of the destination, the state's word and the delay coincide: all three measure 30.5 px down each 52 px row in `Default`. The "about 1 px below" in the build's direction note did not show here. Choosing middle or first-line alignment for both patterns is a question for the design run.
