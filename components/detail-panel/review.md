## P2

- **P2-1.** `packages/perron/src/patterns/DetailPanel/DetailPanel.stories.tsx:86` The stories declare their own `mount` helper, which does `createRoot`, render and then unmount. It is a copy of the shared helper `mounted` from `packages/perron/src/testing/stories.ts`, which reached this branch with the merge of main, and every other story now imports it. The copy also breaks the helper's promise: `mounted` cleans up in a `finally` block, but at lines 142-149 (`expectEveryShape`) and 190-197 (the CR-8 `da` step) the copy unmounts only when the step passes. So one failing assertion leaves a second open panel in `<body>` for every later `screen` query and story. This breaks the contract's Shared helpers rule (`docs/components/README.md:222`): a story imports a helper from its file. The `shared-parts` gate misses it only because the copy has a different name.

## P3

- **P3-1.** `packages/perron/src/patterns/DetailPanel/DetailPanel.tsx:9` Still open from rounds 1 and 2. The `perron-allow(patterns)` reason says "the contract does not yet say whether a pattern may compose another". But the contract's Patterns section (`docs/components/README.md:275`) lists what a pattern may import, and other patterns are not on that list, while `dependsOn` and CR-1 name DetailHeader. No rule settles which side holds. The maintainer either extends the Patterns line to the patterns an entry's `dependsOn` names, or rewords the reason to say this is a departure from that line.
- **P3-2.** `packages/perron/src/patterns/DetailPanel/DetailPanel.tsx:154` Still open. The Sheet's title part, rendered as a `div`, passes `.pn-Sheet-title`'s `typography.heading-md` down to the action row. In WithAction and LongTitle the action `div` and the Button element compute to 600 20px/23px; only the Button's own label span resets to `typography.label`. So a plain-string `action`, a shape the WithAction `play` test renders, shows as a second heading. Neither spec gives the action a typography role, so the maintainer may want the panel or DetailHeader to give it one.
- **P3-3.** `packages/perron/src/patterns/DetailPanel/DetailPanel.tsx:56` Still open. The `children` JSDoc (lines 56-59) and the `anchor` JSDoc (lines 65-67) end with design reasoning copied from the spec's Props rows (`docs/patterns/detail-panel.md:57`, `:58`), and that reasoning lands in the docs page's props table. The maintainer may prefer to keep it in the spec's prose.
- **P3-4.** `packages/perron/src/patterns/DetailHeader/DetailHeader.tsx:42` Still open. DetailHeader's `action` JSDoc, and its spec's Anatomy and Props rows (`docs/patterns/detail-header.md:19`, `:50`), still put the panel's controls "at the end of the row". DetailPanel moves them into a fifth grid row (`DetailPanel.css:25`), which depends on DetailHeader's internal four-row template (`DetailHeader.css:13`). The maintainer may want DetailHeader to have an action-below layout of its own, documented on its side, instead of DetailPanel overriding its grid from outside.
- **P3-5.** `docs/patterns/detail-panel.md:24` Still open. The Anatomy note still ends with an instruction to the build ("The build then rewrites what still says otherwise...") and cites DetailHeader's spec by line numbers 19, 50, 63, 123 and 158. That work is done, and the note ships on the `Specs/DetailPanel` page, where the line numbers will go stale. The maintainer may want it cut down to the decision alone.
- **P3-6.** `docs/patterns/detail-panel.md:131` The checklist line says the `Line` and `Stop` stories' `play` tests open the panel with `title`, `lineName`, `subheader`, `action` and `children` in every shape. The Stories table holds, so this line should name `WithAction` for `action`.
